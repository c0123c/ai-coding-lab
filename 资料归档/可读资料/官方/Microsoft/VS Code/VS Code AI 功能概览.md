使用 Visual Studio Code 中的 AI 来理解不熟悉的代码、修复错误和构建功能。对于跨文件和工具的任务，agent 可以查找相关代码、进行更改并运行检查，而无需您指导每次搜索、编辑和测试运行。您描述结果、检查更改并验证结果。

在与编辑器、终端、测试和调试器相同的工作区中使用 agent。您可以检查其更改并调查故障，而无需将代码和命令输出移动到单独的聊天应用程序。对于问题或重点编辑，请使用聊天、内联聊天或建议，而无需委派整个任务。

对于日常编码和 agent 任务，请从 Copilot 工具开始探索代码、计划更改、实现功能和运行测试。该线束基于 GitHub Copilot SDK 构建，有助于在 VS Code、GitHub Copilot、CLI 和 GitHub Copilot 应用程序中提供更一致的行为。您可以在聊天视图或 Agents 窗口中继续相同的实时会话，并发现并继续在 GitHub Copilot CLI 或 GitHub Copilot 应用程序中创建的受支持会话。

当您需要工具或工作流程时，选择另一个 agent 工具，或者将独立任务委托给云 agent。
尝试您的第一个 agent 任务
在聊天视图中构建并验证一个小型应用程序，然后查看结果。启动 agents快速入门

如果您对 VS Code 和 AI 都不熟悉，请首先安装编辑器并打开工作区。如果您已经使用 agents，请跳过示例项目并遵循经验丰富的 agent 快速通道。如需无需委派任务的 AI 帮助，请在建议、重点编辑、问题和 agents 之间进行选择。

快速入门使用 GitHub Copilot 线束。有关帐户、使用情况和数据处理要求，请参阅 Copilot 设置指南。如果提供商、登录或执行位置影响您的设置，请了解会话控制并选择 agent 工具。

你可以用AI做什么

根据任务选择工作流程，从单行帮助到整个项目的协调变更。

您的目标
AI如何提供帮助

实现功能、修复错误或跨文件重构
使用agent查找相关代码、进行更改并运行测试。

了解代码库或探索方法
在聊天中提出问题以获得基于代码的解释并讨论替代方案。

在编辑
之前研究复杂的变更agent计划并在实施之前审查建议的方法。

无需留下代码即可进行集中编辑
使用内联聊天来描述编辑器中的更改。

键入时获取代码建议
使用内联建议完成并建议下一步编辑。

完成常见的开发任务
使用智能操作来执行任务，例如生成提交消息或解释所选代码。

您可以使用聊天来提问和指导 agents。您可以在编辑之前要求 Agent 提出一种方法，或者选择“规划”（如果可用）以获得专用规划工作流程。

为了进行紧凑比较，请使用 AI 功能备忘单来选择适合您任务的自主性最低的选项。

您如何使用 agent

agent 使用语言模型来推理您的请求并使用工具来对您的开发环境进行操作。它收集上下文，例如代码、错误消息和测试结果，而不是仅依赖提示中的单词。

例如，要求 agent 修复失败的测试，同时保留预期的行为：

agent找到测试并读取相关代码以了解故障。

它根据任务和您的约束来编辑实施或测试。

它运行测试、检查结果并根据需要修改其更改。

您查看差异和验证结果，亲自验证行为，并决定保留哪些更改。

这种重复的推理、行动和验证就是agent循环。您可以提供更多上下文、重定向工作或停止 agent。详细了解 agents 的工作原理。

任务的对话和工作属于会话。会话将相关上下文和更改保存在一起，以便您可以返回任务或单独管理独立任务。了解会话和切换。

使用 agents 的方式

从适合您想要的工作方式的界面开始。您可以在聊天视图和 Agents 窗口之间继续支持的会话，而不是为每项任务选择一个界面。

与您的代码一起工作

在打开的项目中工作时使用聊天视图。将对话保留在编辑器旁边，检查发生的更改，并使用调试器、终端和测试作为同一工作流程的一部分。这是 agents 快速入门的起点。

对于键盘、屏幕阅读器和低视力工作流程，了解如何使用辅助视图和其他辅助功能。

委派和管理任务

当您的重点是分配任务并查看其结果时，请使用 Agents 窗口。跨项目管理多个会话，跟踪其进度，并在您想要直接使用代码时打开编辑器。

其他访问方式agents

对于基于终端的工作，请使用 GitHub Copilot CLI。 GitHub Copilot 应用程序提供专用的桌面体验。您可以打开并继续在 VS Code 中的任一应用程序中创建的受支持的本地会话。要在 CLI 中继续 Copilot 会话，请右键单击该会话并选择在终端中恢复。

要远离计算机进行工作，请探索返回拉取请求或远程会话和浏览器访问的云 agents。

选择您的型号、agents 和工具

从快速入门的建议设置开始，然后调整各个选择以适合您的任务和项目：

模型：根据任务所需的推理能力、速度和成本选择语言模型。

Agent 线束：为其工具和工作流程使用受支持的 agent 线束，例如 Copilot、Anthropic Claude 或 OpenAI Codex。线束将模型连接到工具并管理会话，因此更改线束与切换模型不同。

模型访问：使用您的 GitHub Copilot 计划中的模型，携带您自己的 API 密钥 (BYOK)，或连接支持的本地模型。这些选项允许您使用现有的模型提供商帐户或将模型处理保留在本地。

工具和定制：通过项目说明分享您的编码标准和测试命令。通过 Model Context Protocol (MCP) 服务器连接外部系统，将重复任务打包为 agent skills，或安装捆绑工具和工作流程的插件。比较 agent 自定义概念中的选项。

可用的模型、工具和自定义项取决于所选的工具、您的帐户和组织的策略。

工具运行的位置和模型托管的位置是单独的选择。 agent 可以编辑您计算机上的文件，同时向托管提供商发送模型请求。

保持控制

AI 可能会生成不正确的代码或误解您的意图。您仍然负责决定哪些更改会到达您的代码库。

集成前进行审查。 Agents可以将编辑直接保存到会话文件夹或工作树中。在提交或合并更改之前检查差异并验证结果。

控制行动并重定向工作。使用权限和批准来决定哪些操作需要确认。您可以引导或停止请求，但停止不会撤消已完成的操作或对外部服务的更改。

了解隔离。 Git 工作树将代码更改分开，但不是安全边界。有关 agent 运行终端命令的文件系统和网络限制，请查看特定于平台的沙箱选项。

在现有项目上使用 agents 之前，请查看建议的安全基线。在托管设备上，您的组织可能通过企业 AI 策略限制可用的 agents、模型和工具。如果 agents 未出现在聊天中，请查看可用性故障排除步骤。

后续步骤

VS Code 和 AI 新增功能：安装编辑器，打开工作区，然后选择第一个任务。

已使用 VS Code，但对 agents 不熟悉：使用建议的起始配置完成第一个 agent 任务。

已使用 AI agents：按照经验丰富的 agent 快速通道在您自己的存储库中工作。

喜欢轻量级 AI：选择 AI 功能来提供建议、重点编辑、问题或委派工作。

准备好改进项目工作流程：根据您的项目调整 agents，然后比较质量、可靠性和使用情况。

Use AI in Visual Studio Code to understand unfamiliar code, fix bugs, and build features. For a task that spans files and tools, an agent can find relevant code, make changes, and run checks without you directing each search, edit, and test run. You describe the outcome, review the changes, and verify the result.

Work with an agent in the same workspace as your editor, terminal, tests, and debugger. You can inspect its changes and investigate failures without moving code and command output to a separate chat application. For a question or focused edit, use chat, inline chat, or suggestions without delegating an entire task.

For day-to-day coding and agent tasks, start with the Copilot harness to explore code, plan changes, implement features, and run tests. Built on the GitHub Copilot SDK, the harness helps provide more consistent behavior across VS Code, GitHub Copilot CLI, and the GitHub Copilot app. You can continue the same live session in the Chat view or Agents window, and discover and continue supported sessions created in GitHub Copilot CLI or the GitHub Copilot app.

Choose another agent harness when you need its tools or workflows, or delegate an independent task to a cloud agent.

Build and validate a small app in the Chat view, then review the result.Start the agents quickstart

If you're new to both VS Code and AI, first install the editor and open a workspace. If you already use agents, skip the sample project and follow the experienced-agent fast track. For AI help without delegating a task, choose between suggestions, focused edits, questions, and agents.

The quickstart uses the GitHub Copilot harness. See the Copilot setup guide for account, usage, and data-handling requirements. If provider, sign-in, or execution location affects your setup, understand the session controls and choose an agent harness.

How you work with an agent

An agent uses a language model to reason about your request and tools to act on your development environment. It gathers context, such as code, error messages, and test results, rather than relying only on the words in your prompt.

For example, ask an agent to fix a failing test while preserving the intended behavior:

The agent finds the test and reads the related code to understand the failure.

It edits the implementation or tests based on the task and your constraints.

It runs the tests, inspects the results, and revises its changes if needed.

You review the diff and validation results, verify the behavior yourself, and decide which changes to keep.

This repeated reasoning, action, and validation is the agent loop. You can provide more context, redirect the work, or stop the agent along the way. Learn more about how agents work.

The conversation and work for a task belong to a session. Sessions keep related context and changes together so you can return to a task or manage independent tasks separately. Learn about sessions and handoff.

Ways to work with agents

Start with the interface that fits how you want to work. You can continue supported sessions between the Chat view and the Agents window, rather than choosing one interface for every task.

Work alongside your code

Use the Chat view when you're working in an open project. Keep the conversation beside your editor, inspect changes as they happen, and use the debugger, terminal, and tests as part of the same workflow. This is the starting point for the agents quickstart.

For keyboard, screen reader, and low-vision workflows, learn how to use the Accessible View and other accessibility features.

Delegate and manage tasks

Use the Agents window when your focus is assigning tasks and reviewing their results. Manage multiple sessions across projects, follow their progress, and open the editor when you want to work directly with the code.

Other ways to access agents

For terminal-based work, use GitHub Copilot CLI. The GitHub Copilot app provides a dedicated desktop experience. You can open and continue supported local sessions created in either application in VS Code. To continue a Copilot session in the CLI, right-click the session and select Resume in Terminal.

For work away from your machine, explore cloud agents that return pull requests or remote sessions and browser access.

Choose your models, agents, and tools

Start with the quickstart's recommended setup, then adjust individual choices to fit your task and project:

Models: choose a language model based on the reasoning capabilities, speed, and cost your task requires.

Agent harnesses: use a supported agent harness, such as Copilot, Anthropic Claude, or OpenAI Codex, for its tools and workflows. The harness connects a model to tools and manages the session, so changing harnesses is different from switching models.

Model access: use models from your GitHub Copilot plan, bring your own API key (BYOK), or connect a supported local model. These options let you use an existing model provider account or keep model processing local.

Tools and customization: share your coding standards and test commands through project instructions. Connect external systems through Model Context Protocol (MCP) servers, package recurring tasks as agent skills, or install plugins that bundle tools and workflows. Compare the options in agent customization concepts.

Available models, tools, and customizations depend on the selected harness, your account, and your organization's policies.

Where tools run and where the model is hosted are separate choices. An agent can edit files on your machine while sending model requests to a hosted provider.

Stay in control

AI can produce incorrect code or misunderstand your intent. You remain responsible for deciding which changes reach your codebase.

Review before integrating. Agents can save edits directly to the session folder or worktree. Review the diff and validate the result before you commit or merge changes.

Control actions and redirect work. Use permissions and approvals to decide which actions require confirmation. You can steer or stop a request, but stopping doesn't undo completed actions or changes to external services.

Understand isolation. A Git worktree keeps code changes separate, but isn't a security boundary. For file system and network restrictions on agent-run terminal commands, review the platform-specific sandboxing options.

Before using agents on an existing project, review the recommended security baseline. On a managed device, your organization might restrict available agents, models, and tools through enterprise AI policies. If agents don't appear in chat, review the availability troubleshooting steps.
