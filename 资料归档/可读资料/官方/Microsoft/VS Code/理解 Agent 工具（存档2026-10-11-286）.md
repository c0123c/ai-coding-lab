---

工具是一种让[agent](<https://code.visualstudio.com/docs/agents/concepts/agents>)收集信息或采取行动的能力。如果没有工具，[语言模型](<https://code.visualstudio.com/docs/agents/concepts/language-models>)只能生成文本。通过工具，agent 可以读取文件、编辑代码、运行终端命令、搜索代码库以及连接到外部服务。

当 agent 使用工具时，它会使用该工具所需的输入进行 ** 工具调用 **。该工具运行并返回 ** 工具输出 **，该输出成为 [ 上下文 ](<https://code.visualstudio.com/docs/agents/concepts/context>) 的一部分，用于 [agent 循环 ](<https://code.visualstudio.com/docs/agents/concepts/agents#_agent-loop>) 中的下一步。

本文介绍了工具如何适应 agent 循环、VS Code 中可用的工具类型以及如何控制它们的使用。

## agent 循环中的工具

例如，当您要求 agent 修复失败的测试时，它可能：

1. 调用搜索和文件读取工具来查找测试和相关代码。
2. 使用返回的文件内容来决定要更改的内容。
3. 调用编辑工具来应用更改。
4. 调用终端工具运行测试。
5. 使用测试输出来决定任务是否已完成或需要进行其他更改。

每次调用都会给agent提供新信息或更改开发环境。根据您的 [ 权限级别 ](<https://code.visualstudio.com/docs/agents/run/approvals#_permission-levels>)，VS Code 可能会要求您在工具调用运行之前批准它。

## 工具类型

VS Code支持三种类型的工具：

* **内置工具**：VS Code附带的工具，用于常见的开发任务，例如读取和写入文件、运行终端命令、搜索代码库以及导航编辑器。这些无需任何设置即可立即使用。
* **MCP工具**：[Model Context Protocol（MCP）](<https://modelcontextprotocol.io/>)服务器提供的工具，用于将AI模型连接到外部工具和数据源的开放标准。 MCP 服务器可以在您的计算机上本地运行或远程托管。使用 MCP 工具连接到数据库、API 和其他外部服务。
* **扩展工具**：VS Code扩展通过语言模型工具API提供的工具。扩展工具与编辑器深度集成，并且在安装扩展时可用。

## agents如何选择工具

默认情况下，agent 根据您的请求和当前上下文从启用的工具中进行选择。您可以给 agent 一个高级目标，而无需命名它应该使用的每个工具。

要将 agent 定向到特定工具或工具组，请在提示中添加 `#` 引用。了解如何[在请求中使用工具](<https://code.visualstudio.com/docs/agents/run/tools#_use-tools-in-a-request>)。

## 控制哪些工具可用

可用工具来自 VS Code、MCP 服务器或已安装的扩展。启用的工具是允许 agent 为请求选择的工具。

将启用的工具限制为与您的任务相关的功能。集中设置有助于 agent 选择适当的工具，减少不必要操作的机会，并限制添加到 [ 上下文窗口 ](<https://code.visualstudio.com/docs/agents/concepts/language-models#_context-window>) 的工具输出。

工具选择的范围取决于 agent 会话的运行位置。对于扩展主机上的本地线束，该选择适用于一个聊天请求。对于 Agent 主机上的 Copilot 线束，该选择将保留在您的 [ 用户配置文件 ](<https://code.visualstudio.com/docs/configure/profiles>) 中。工具也可以修复为可重复使用的[自定义agent](<https://code.visualstudio.com/docs/agent-customization/custom-agents>)。

## 工具认可和信任

工具可以编辑文件、修改环境或访问外部服务。 VS Code 提供用于审查和限制这些操作的控件：

* **批准提示**：根据您的权限级别，工具调用在运行之前可能需要确认。
* **URL批准**：当工具访问URL时，两步过程会验证请求和响应内容。
* **权限级别**：[权限选择器](<https://code.visualstudio.com/docs/agents/run/approvals#_permission-levels>)控制agent拥有多少自主权，从需要手动批准到完全自主操作。

在批准呼叫之前，请检查工具名称和输入。详细了解 [ 信任和安全 ](<https://code.visualstudio.com/docs/agents/concepts/trust-and-safety>)。

---

A tool is a capability that lets an [agent](<https://code.visualstudio.com/docs/agents/concepts/agents>) gather information or take an action. Without tools, a [language model](<https://code.visualstudio.com/docs/agents/concepts/language-models>) can only generate text. With tools, an agent can read files, edit code, run terminal commands, search your codebase, and connect to external services.

When the agent uses a tool, it makes a **tool call** with the inputs that the tool needs. The tool runs and returns **tool output**, which becomes part of the [context](<https://code.visualstudio.com/docs/agents/concepts/context>) for the next step in the [agent loop](<https://code.visualstudio.com/docs/agents/concepts/agents#_agent-loop>).

This article explains how tools fit into the agent loop, the types of tools available in VS Code, and how you control their use.

## Tools in the agent loop

For example, when you ask an agent to fix a failing test, it might:

1. Call search and file-reading tools to find the test and related code.
2. Use the returned file contents to decide what to change.
3. Call an editing tool to apply the change.
4. Call the terminal tool to run the test.
5. Use the test output to decide whether the task is complete or another change is needed.

Each call gives the agent new information or changes the development environment. Depending on your [permission level](<https://code.visualstudio.com/docs/agents/run/approvals#_permission-levels>), VS Code might ask you to approve a tool call before it runs.

## Types of tools

VS Code supports three types of tools:

* **Built-in tools**: tools that ship with VS Code for common development tasks, like reading and writing files, running terminal commands, searching your codebase, and navigating the editor. These are available immediately without any setup.
* **MCP tools**: tools provided by [Model Context Protocol (MCP)](<https://modelcontextprotocol.io/>) servers, an open standard for connecting AI models to external tools and data sources. MCP servers can run locally on your machine or be hosted remotely. Use MCP tools to connect to databases, APIs, and other external services.
* **Extension tools**: tools contributed by VS Code extensions through the Language Model Tools API. Extension tools integrate deeply with the editor and are available when you install the extension.

## How agents choose tools

By default, the agent chooses from the enabled tools based on your request and the current context. You can give the agent a high-level goal without naming each tool that it should use.

To direct the agent to a specific tool or group of tools, add a `#` reference to your prompt. Learn how to [use tools in a request](<https://code.visualstudio.com/docs/agents/run/tools#_use-tools-in-a-request>).

## Control which tools are available

An available tool comes from VS Code, an MCP server, or an installed extension. An enabled tool is one that the agent is permitted to choose for a request.

Limit enabled tools to the capabilities that are relevant to your task. A focused set helps the agent choose appropriate tools, reduces the chance of unnecessary actions, and limits the tool output added to the [context window](<https://code.visualstudio.com/docs/agents/concepts/language-models#_context-window>).

The scope of a tool selection depends on where the agent session runs. For the Local harness on the extension host, the selection applies to one chat request. For the Copilot harness on the Agent Host, the selection persists in your [user profile](<https://code.visualstudio.com/docs/configure/profiles>). Tools can also be fixed for a reusable [custom agent](<https://code.visualstudio.com/docs/agent-customization/custom-agents>).

## Tool approval and trust

Tools can edit files, modify your environment, or access external services. VS Code provides controls for reviewing and limiting these actions:

* **Approval prompts**: based on your permission level, a tool call can require confirmation before it runs.
* **URL approval**: when a tool accesses a URL, a two-step process verifies both the request and the response content.
* **Permission levels**: the [permissions picker](<https://code.visualstudio.com/docs/agents/run/approvals#_permission-levels>) controls how much autonomy the agent has, from requiring manual approval to fully autonomous operation.

Review the tool name and inputs before you approve a call. Learn more about [trust and safety](<https://code.visualstudio.com/docs/agents/concepts/trust-and-safety>).
