# 使用具有 agents 的工具

工具可以让 agent 检查您的项目并检查结果，而不仅仅是建议您应用的代码或命令。例如，它可以读取失败测试背后的实现，进行更改，然后运行测试以检查更改是否有效。

从会话中已有的工具开始。 {% data variables.product.prodname_vscode %}支持内置工具、Model Context Protocol（MCP）工具和扩展工具。当任务需要可用工具无法提供的功能时，添加 [MCP 服务器 ](<https://github.com/docs/agent-customization/mcp-servers.md>) 或扩展。

有关工具类型的背景知识以及工具如何在 agent 循环中工作，请参阅[工具概念](<https://github.com/docs/agents/concepts/tools.md>)。

本文介绍如何使用工具完成请求、将 agent 定向到特定工具、控制哪些工具可用以及查看工具调用。

* [打开于{% data variables.product.prodname_vscode_shortname %}](<vscode://GitHub.Copilot-Chat/chat?agent=agent%26prompt=Summarize%20the%20latest%20VS%20Code%20updates%20%23web>)

## 在请求中使用工具

默认情况下，agent 根据您的请求和当前上下文从启用的工具中进行选择。在开始之前，您无需命名或选择每个工具。

要使用工具完成请求：

1. 在聊天输入中，从 agent 选择器中选择 **Agent**。

1. 输入一个提示，描述您的目标以及 agent 应如何验证其工作。例如：

    ```prompt
    Find the cause of the failing tests in this project, fix it, and run the relevant tests to verify the change.
    ```

1. 在 agent 工作时检查每个工具调用。如果出现批准提示，请展开工具详细信息以查看其输入，然后选择 ** 允许 ** 运行它。

1. 展开对话中的工具摘要以检查呼叫及其输出。任务完成后，查看 agent 的响应、代码更改和验证结果。

要控制哪些调用需要批准以及 agent 拥有多少自主权，请参阅[管理批准和权限](<https://github.com/docs/agents/run/approvals.md>)。



<summary>更改工具调用在聊天中的分组方式</summary>

默认情况下，工具调用详细信息会折叠在聊天对话中。使用 `setting(chat.agent.thinking.collapsedTools)`（实验性）更改分组行为。使用 `off` 将工具调用分开，使用 `withThinking` 将工具与可用的思考进行分组，或者使用 `always` 始终对工具进行分组。当 `setting(chat.agent.thinkingStyle)` 设置为 `collapsed` 时，推理和分组工具调用可以出现在单独的可折叠部分中。




## 明确引用工具

在聊天输入中键入 `#` 以引用特定工具或工具集。当您想要将 agent 定向到特定功能而不是让它选择时，请使用显式引用。

例如，使用`#web/fetch`工具检索特定网页：

```prompt
Summarize the latest release notes at code.visualstudio.com/updates with #web/fetch.
```

使用工具集，例如`#web`，使一组相关工具可用：

```prompt
Research how Next.js handles routing. Use #web tools and summarize the relevant guidance.
```

`#` 菜单还包含上下文项，例如文件、文件夹和编辑器选择。上下文项提供请求的信息，而工具则提供 agent 收集信息或采取操作的功能。详细了解 [向聊天提示添加上下文 ](<https://github.com/docs/chat/chat-overview.md#add-context-to-your-prompts>)。

要将相关工具分组并在提示、提示文件和自定义 agents 中重复使用它们，[创建一个工具集 ](<https://github.com/docs/agent-customization/tool-sets.md>)。

### 管理 Copilot 的工具可用性

默认情况下，所有客户端工具均可用于 Copilot 线束。在**工具**选项卡中，工具被组织成可折叠的组。您可以：

* 在搜索框中输入文本以过滤工具组和单个工具。
* 选择工具组复选框以启用或禁用组中的每个工具。
* 展开一个组并选择单个工具。当仅启用某些工具时，组复选框显示混合状态。
* 查看每组显示的已启用工具数量和总工具数量。

自定义导航中 ** 工具 ** 旁边的计数包括已启用的客户端工具，但不包括 Copilot 线束中内置的只读工具。

**Copilot** 组列出了线束的内置工具。这些工具在 Copilot 运行时运行，并且在 ** 工具 ** 选项卡中为只读。其他工具在 {% data variables.product.prodname_vscode_shortname %} 客户端中运行，并且仅在客户端连接时可供 agent 使用。

工具可用性与工具批准是分开的。启用工具使其可供 agent 使用，但不会绕过配置的 [ 批准和权限控制 ](<https://github.com/docs/agents/run/approvals.md>)。

### 添加Copilot的扩展工具

在主{% data variables.product.prodname_vscode_shortname %}窗口中，您可以找到提供语言模型工具的扩展：

1. 打开**工具**选项卡并选择**浏览市场**。

1. 搜索扩展并选择它以查看其详细信息和贡献的工具。

1. 安装扩展。然后，其工具将显示在工具列表中，您可以在其中管理它们的可用性。

{% data variables.copilot.agents_window %} 显示工具可用性列表，但不包括市场浏览。

要从工具列表中删除扩展，请右键单击其工具组并选择**卸载扩展**。

> [！CAUTION]
> 卸载工具扩展会删除整个扩展，包括非工具的贡献。

## 编辑工具参数

对于需要批准的工具调用，您可以展开确认对话框以查看其输入参数。参数编辑取决于会话和确认类型：

* 在 Agent 主机会话中，通用和终端工具确认是只读的。
* 来自本地线束和扩展贡献工具的确认可以支持参数编辑。

要编辑支持的确认中的参数：

1. 当出现工具确认对话框时，选择工具名称旁边的 V 形以展开其详细信息。

1. 根据需要编辑任何工具输入参数。

1. 选择**允许**使用修改后的参数运行工具。

## 常见的内置工具工作流程

### 使用浏览器工具

浏览器工具为 agents 提供了一种验证 Web 应用程序的交互式方式。 agent 不仅可以检查源代码，还可以运行您的应用程序，在集成浏览器中打开它，执行用户流程，检查页面内容和控制台错误，并修复它发现的问题。

浏览器工具内置于 {% data variables.product.prodname_vscode_shortname %} 中，不需要外部 MCP 服务器。当任务在 Web 界面中具有可观察结果时使用它们，例如验证表单、重现视觉错误、检查响应行为或测试完整的用户旅程。

```prompt
Start the app, open it in the browser, and test the password reset flow.
Fix any issues you find and repeat the flow to verify the fix.
```

了解如何[通过agents](<https://github.com/docs/agents/run/browser-tools.md>)使用浏览器工具，包括浏览器会话、页面共享、隐私控制和有效的提示模式。

### 运行终端命令

在所有内置工具中，终端工具是最常用的工具之一。 agent 使用它来运行命令作为其工作流程的一部分，例如安装依赖项、运行构建或执行测试。由于终端命令可以更改您的环境，因此 {% data variables.product.prodname_vscode_shortname %} 提供了用于查看、运行和监视它们的附加控件，这些控件建立在前面描述的 [ 批准 ](<https://github.com/docs/agents/run/approvals.md>) 行为的基础上。

当agent决定运行命令时，它会使用内置终端工具在{% data variables.product.prodname_vscode_shortname %}内的集成终端中执行该命令。

在聊天对话中，agent 显示它运行的命令。您可以通过选择命令旁边的 **显示输出 ** (`>`) 来查看聊天中内联命令的输出。您还可以通过选择**显示终端**来查看集成终端中的完整输出。

![显示聊天中终端命令输出的屏幕截图。](<https://raw.githubusercontent.com/microsoft/vscode-docs/7dde535199826fdb8e278bdf6f0c3bff0aae0138/docs/agents/images/chat-tools/terminal-command-output.png>)



<summary>更改终端输出出现的位置</summary>

使用 `setting(chat.tools.terminal.outputLocation)`（实验性）在聊天中内联或直接在集成终端中显示终端命令输出。




默认情况下，终端输出预览重排以适应可用的聊天宽度。关闭 `setting(chat.tools.terminal.outputReflow)` 以保留终端的列宽并对长行使用水平滚动。此设置仅更改聊天中的预览，而不更改运行命令的终端。

#### Continue 后台终端命令

当agent运行长时间运行的终端命令时，例如启动开发服务器或在监视模式下运行构建，您可以将该命令推送到后台。这允许 agent 继续执行其他任务，而无需等待命令完成。

命令运行时，聊天对话中终端命令旁边会出现一个后台 ** 按钮中的 **Continue。选择此按钮可将命令移至后台。命令继续运行，agent 可以稍后检查其输出或使用终端执行其他任务。

agent 还可以指定运行终端命令时的超时。当达到超时时，agent停止等待命令并返回到目前为止收集的输出。使用 `setting(chat.tools.terminal.enforceTimeoutFromModel)` 设置来控制是否强制执行 agent 指定的超时值。

agent 还可以选择直接在后台运行命令，无需用户交互。当命令完成时，您未显示的后台终端会自动清理，这可以防止过时的终端在长时间会话中累积。要显示后台终端并在命令完成后保持其打开状态，请选择聊天工具调用标题中的 **Show** 链接。即使终端被清理后，终端输出在聊天对话中仍然可见。

> [!TIP]
> 要自动批准终端命令或限制 agent 命令的文件系统和网络访问，请参阅[管理批准和权限](<https://github.com/docs/agents/run/approvals.md>)。

## 常见问题



<summary>我如何知道哪些工具可用？</summary>

在聊天输入字段中键入 `#` 以浏览可用的工具、工具集和上下文项。您还可以使用聊天中的工具选择器来查看和管理已启用的工具。

对于 Copilot 会话，打开 Agent 自定义编辑器并选择 ** 工具 ** 选项卡以查看和管理启用的工具。






<summary>我收到一条错误消息，提示“每个请求不能拥有超过 128 个工具。”</summary>

聊天请求一次最多可以启用 128 个工具。如果您看到有关每个请求超出 128 工具的错误：

* 打开{% data variables.copilot.chat_view %}中的工具选择器并取消选择某些工具或整个MCP服务器以减少计数。

* 或者，通过 `setting(github.copilot.chat.virtualTools.threshold)` 设置启用虚拟工具以自动管理大型工具集。






<summary>为什么agent不使用我配置的终端shell？</summary>

agent 使用您为终端配置的默认 shell，Windows 上的 `cmd`（命令提示符）和 macOS/Linux. 上的 `sh` 除外。这是因为这些 shell 不支持 [shell 集成 ](<https://github.com/docs/terminal/shell-integration.md>)，这意味着agent 对终端内部发生的情况的可见性非常有限。 agent 需要依赖超时并监视终端空闲才能继续，而不是获取命令正在运行或已完成运行的直接信号。这会导致缓慢且不稳定的体验。

您仍然可以将 agent 配置为通过终端配置文件设置来使用这些 shell，但是与在 Windows 上使用 PowerShell 或在 macOS/Linux. 上使用 `bash`/`zsh` 相比，这会导致体验较差

* `setting(chat.tools.terminal.terminalProfile.windows)` - 覆盖 Windows 上的 shell
* `setting(chat.tools.terminal.terminalProfile.osx)` - 覆盖 macOS 上的 shell
* `setting(chat.tools.terminal.terminalProfile.linux)` - 覆盖 Linux 上的 shell






<summary>我可以创建自己的工具吗？</summary>

是的。您可以通过两种方式创建工具：

* **开发一个 {% data variables.product.prodname_vscode_shortname %} 扩展 **，该扩展使用 [ 语言模型工具 API](<https://github.com/api/extension-guides/ai/tools.md>) 提供工具
* **创建一个提供工具的MCP服务器**。请参阅[MCP工具扩展性概述](<https://github.com/api/extension-guides/ai/ai-extensibility-overview.md#mcp-tool>)。

# Use tools with agents

Tools let an agent inspect your project and check results instead of only suggesting code or commands for you to apply. For example, it can read the implementation behind a failing test, make a change, and run the test to check whether the change works.

Start with the tools already available in your session. {% data variables.product.prodname_vscode %} supports built-in tools, Model Context Protocol (MCP) tools, and extension tools. Add an [MCP server](<https://github.com/docs/agent-customization/mcp-servers.md>) or extension when the task needs a capability the available tools don't provide.

For background on tool types and how tools work in the agent loop, see [Tools concepts](<https://github.com/docs/agents/concepts/tools.md>).

This article shows how to complete a request with tools, direct the agent to specific tools, control which tools are available, and review tool calls.

## Use tools in a request

By default, the agent chooses from the enabled tools based on your request and the current context. You don't need to name or select each tool before you start.

To complete a request with tools:

1. In the chat input, select **Agent** from the agent picker.

1. Enter a prompt that describes your goal and how the agent should verify its work. For example:

    ```prompt
    Find the cause of the failing tests in this project, fix it, and run the relevant tests to verify the change.
    ```

1. Review each tool call as the agent works. If an approval prompt appears, expand the tool details to review its inputs, and then select **Allow** to run it.

1. Expand a tool summary in the conversation to inspect the call and its output. When the task is complete, review the agent's response, code changes, and validation results.

To control which calls require approval and how much autonomy the agent has, see [Manage approvals and permissions](<https://github.com/docs/agents/run/approvals.md>).



<summary>Change how tool calls are grouped in chat</summary>

By default, tool call details are collapsed in the chat conversation. Use `setting(chat.agent.thinking.collapsedTools)` (experimental) to change the grouping behavior. Use `off` to keep tool calls separate, `withThinking` to group tools with thinking when available, or `always` to always group tools. When `setting(chat.agent.thinkingStyle)` is set to `collapsed`, reasoning and grouped tool calls can appear in separate collapsible sections.




## Reference a tool explicitly

Type `#` in the chat input to reference a specific tool or tool set. Use an explicit reference when you want to direct the agent to a particular capability instead of letting it choose.

For example, use the `#web/fetch` tool to retrieve a specific web page:

```prompt
Summarize the latest release notes at code.visualstudio.com/updates with #web/fetch.
```

Use a tool set, such as `#web`, to make a group of related tools available:

```prompt
Research how Next.js handles routing. Use #web tools and summarize the relevant guidance.
```

The `#` menu also contains context items, such as files, folders, and editor selections. Context items provide information for the request, while tools give the agent capabilities to gather information or take actions. Learn more about [adding context to chat prompts](<https://github.com/docs/chat/chat-overview.md#add-context-to-your-prompts>).

To group related tools and reuse them across prompts, prompt files, and custom agents, [create a tool set](<https://github.com/docs/agent-customization/tool-sets.md>).

Manage tools for the Copilot harness from the Agent Customizations editor:

### Manage tool availability for Copilot

All client-side tools are available to the Copilot harness by default. In the **Tools** tab, tools are organized into collapsible groups. You can:

* Enter text in the search box to filter tool groups and individual tools.
* Select a tool group checkbox to enable or disable every tool in the group.
* Expand a group and select individual tools. The group checkbox shows a mixed state when only some tools are enabled.
* Review the enabled and total tool counts shown for each group.

The count beside **Tools** in the customization navigation includes enabled client-side tools and excludes the read-only tools built into the Copilot harness.

The **Copilot** group lists the harness's built-in tools. These tools run in the Copilot runtime and are read-only in the **Tools** tab. Other tools run in the {% data variables.product.prodname_vscode_shortname %} client and are available to the agent only while the client is connected.

Tool availability is separate from tool approval. Enabling a tool makes it available to the agent, but doesn't bypass the configured [approval and permission controls](<https://github.com/docs/agents/run/approvals.md>).

### Add extension tools for Copilot

In the main {% data variables.product.prodname_vscode_shortname %} window, you can find extensions that contribute language model tools:

1. Search for an extension and select it to view its details and contributed tools.

1. Install the extension. Its tools then appear in the tool list, where you can manage their availability.

The {% data variables.copilot.agents_window %} shows the tool availability list but doesn't include Marketplace browsing.

To remove an extension from the tool list, right-click its tool group and select **Uninstall Extension**.

> Uninstalling a tool extension removes the entire extension, including contributions that aren't tools.

## Edit tool parameters

For a tool call that requires approval, you can expand the confirmation dialog to review its input parameters. Parameter editing depends on the session and confirmation type:

* In Agent Host sessions, generic and terminal tool confirmations are read-only.
* Confirmations from the Local harness and extension-contributed tools can support parameter editing.

To edit parameters in a supported confirmation:

1. When the tool confirmation dialog appears, select the chevron next to the tool name to expand its details.

1. Edit any tool input parameters as needed.

1. Select **Allow** to run the tool with the modified parameters.

## Common built-in tool workflows

### Use browser tools

Browser tools give agents an interactive way to validate web applications. Instead of inspecting only the source code, an agent can run your app, open it in the integrated browser, exercise a user flow, inspect page content and console errors, and fix problems it discovers.

Browser tools are built into {% data variables.product.prodname_vscode_shortname %} and don't require an external MCP server. Use them when a task has an observable result in a web interface, such as verifying a form, reproducing a visual bug, checking responsive behavior, or testing a complete user journey.

```prompt
Start the app, open it in the browser, and test the password reset flow.
Fix any issues you find and repeat the flow to verify the fix.
```

Learn how to [use browser tools with agents](<https://github.com/docs/agents/run/browser-tools.md>), including browser sessions, page sharing, privacy controls, and effective prompting patterns.

### Run terminal commands

Of all the built-in tools, the terminal tool is one of the most frequently used. The agent uses it to run commands as part of its workflow, for example to install dependencies, run a build, or execute tests. Because terminal commands can change your environment, {% data variables.product.prodname_vscode_shortname %} provides additional controls for reviewing, running, and monitoring them, building on the [approval](<https://github.com/docs/agents/run/approvals.md>) behavior described earlier.

When the agent decides to run a command, it uses the built-in terminal tool to execute it in an integrated terminal within {% data variables.product.prodname_vscode_shortname %}.

In the chat conversation, the agent displays the commands it ran. You can view the output of the command inline in chat by selecting **Show Output** (`>`) next to the command. You can also view the full output in the integrated terminal by selecting **Show Terminal**.

![Screenshot showing terminal command output in chat.](<https://raw.githubusercontent.com/microsoft/vscode-docs/7dde535199826fdb8e278bdf6f0c3bff0aae0138/docs/agents/images/chat-tools/terminal-command-output.png>)



<summary>Change where terminal output appears</summary>

Use `setting(chat.tools.terminal.outputLocation)` (experimental) to show terminal command output inline in chat or directly in the integrated terminal.




Terminal output previews reflow to fit the available chat width by default. Turn off `setting(chat.tools.terminal.outputReflow)` to preserve the terminal's column width and use horizontal scrolling for long lines. This setting changes only the preview in chat, not the terminal that runs the command.

#### Continue terminal commands in background

When the agent runs a long-running terminal command, such as starting a development server or running a build in watch mode, you can push the command to the background. This allows the agent to continue with other tasks without waiting for the command to finish.

While a command is running, a **Continue in Background** button appears next to the terminal command in the chat conversation. Select this button to move the command to the background. The command continues running, and the agent can check its output later or use the terminal for other tasks.

The agent can also specify a timeout when running terminal commands. When the timeout is reached, the agent stops waiting for the command and returns the output collected so far. Use the `setting(chat.tools.terminal.enforceTimeoutFromModel)` setting to control whether to enforce the timeout value that the agent specifies.

The agent can also choose to run commands directly in the background, without user interaction. Background terminals that you have not revealed are automatically cleaned up when their command finishes, which prevents stale terminals from accumulating over a long session. To reveal a background terminal and keep it open after the command completes, select the **Show** link in the chat tool invocation header. The terminal output remains visible in the chat conversation even after a terminal is cleaned up.

> [!TIP]
> To automatically approve terminal commands or restrict file system and network access for agent commands, see [Manage approvals and permissions](<https://github.com/docs/agents/run/approvals.md>).

## Frequently asked questions



<summary>How do I know which tools are available?</summary>

Type `#` in the chat input field to browse available tools, tool sets, and context items. You can also use the tools picker in chat to view and manage the enabled tools.

For Copilot sessions, open the Agent Customizations editor and select the **Tools** tab to view and manage enabled tools.






<summary>I'm getting an error that says "Cannot have more than 128 tools per request."</summary>

A chat request can have a maximum of 128 tools enabled at a time. If you see an error about exceeding 128 tools per request:

* Open the tools picker in the {% data variables.copilot.chat_view %} and deselect some tools or entire MCP servers to reduce the count.

* Alternatively, enable virtual tools with the `setting(github.copilot.chat.virtualTools.threshold)` setting to automatically manage large tool sets.






<summary>Why isn't the agent using my configured terminal shell?</summary>

The agent uses the shell you have configured as the default for the terminal, except for `cmd` (Command Prompt) on Windows and `sh` on macOS/Linux. This is because [shell integration](<https://github.com/docs/terminal/shell-integration.md>) is not supported with these shells, which means the agent has very limited visibility into what's going on inside the terminal. Instead of getting direct signals for when commands are being run or have finished running, the agent needs to rely on timeouts and watching for the terminal to idle to continue. This leads to a slow and flaky experience.

You can still configure the agent to use these shells with the terminal profile settings, however this will result in an inferior experience compared to using PowerShell on Windows or `bash`/`zsh` on macOS/Linux.

* `setting(chat.tools.terminal.terminalProfile.windows)` - Override the shell on Windows
* `setting(chat.tools.terminal.terminalProfile.osx)` - Override the shell on macOS
* `setting(chat.tools.terminal.terminalProfile.linux)` - Override the shell on Linux






<summary>Can I create my own tools?</summary>

Yes. You can create tools in two ways:

* **Develop a {% data variables.product.prodname_vscode_shortname %} extension** that contributes tools using the [Language Model Tools API](<https://github.com/api/extension-guides/ai/tools.md>)
* **Create an MCP server** that provides tools. See the [MCP tool extensibility overview](<https://github.com/api/extension-guides/ai/ai-extensibility-overview.md#mcp-tool>).
