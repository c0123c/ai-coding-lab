Visual Studio Code中的Agents可以编辑文件、运行终端命令、调用外部工具。 VS Code 使用两个安全层来帮助您控制这些操作：

* **批准**确定操作是自动运行还是需要您的确认。
* **沙箱**限制agent终端命令可以访问的文件系统和网络资源，即使命令获得批准也是如此。

本文介绍了这些层如何协同工作以及如何配置权限级别、工具和 URL 批准、终端自动批准和沙箱。有关这些控制背后的安全概念，请参阅[信任和安全](<https://code.visualstudio.com/docs/agents/concepts/trust-and-safety>)。

### 自动驾驶仪的工作原理

## 工具审批

有些工具可以修改您的环境或访问外部服务。他们的结果还可能包含即时注射尝试。工具批准可以防止这两种风险。

当需要批准时，检查工具名称和输入参数，然后批准单次使用或批准会话、工作区或所有未来的调用。

![工具确认对话框的屏幕截图，显示工具详细信息和批准选项。](<https://code.visualstudio.com/assets/docs/agents/approvals/chat-approve-tool.png>)

对于包含机密或敏感配置的文件，需要明确批准 [编辑敏感文件](<https://code.visualstudio.com/docs/agents/run/review-code-edits#_edit-sensitive-files>).

重要

在批准之前务必仔细检查工具参数，特别是对于修改文件、运行命令或访问外部服务的工具。有关在VS Code中使用AI的信息，请参阅[安全注意事项](<https://code.visualstudio.com/docs/agents/run/security>)。

## URL批准

当工具访问 URL 时，例如 `#web/fetch` 工具，VS Code 将批准分为两个决策：

|步骤|您认可的内容|保护|
| --- | --- | --- |
|**请求批准**|联系 URL 或域|防止数据发送到不受信任的站点。|
|**回复批准**|将获取的内容添加到聊天上下文中|有助于防止来自不受信任内容的即时注入。|

![URL 批准对话框的屏幕截图，显示 URL 详细信息和批准选项。](<https://code.visualstudio.com/assets/docs/agents/approvals/chat-approve-url.png>)

对于每个步骤，您可以批准一次，也可以自动批准以后针对 URL 或域的请求或响应。批准请求并不批准其响应。

请求批准使用 [ 受信任域 ](<https://code.visualstudio.com/docs/editing/editingevolved#_outgoing-link-protection>) 列表。受信任的域不需要请求批准，但其响应仍然需要审核，除非您单独自动批准该域的响应。

## 自动批准终端命令

agent使用一种工具来运行任何[终端命令](<https://code.visualstudio.com/docs/agents/run/tools#_run-terminal-commands>)。为了避免授予该工具无限制的批准，VS Code 单独评估每个命令。

默认情况下，常见的只读命令会自动运行，而`rm`和`del`等有风险的命令需要批准。添加规则到


聊天工具.终端。autoApprove

在 VS Code
中打开 在 VS Code 内部人员 
 中打开以更改此行为：

* 将命令设置为 `true` 以自动批准。
* 将命令设置为 `false` 以要求批准。
* 将正则表达式包含在 `/` 字符中以匹配命令模式。

例如：

```
{
  // Allow the `mkdir` command
  "mkdir": true,
  // Allow `git status` and commands starting with `git show`
  "/^git (status|show\\b.*)$/": true,

  // Always require approval for the `del` command
  "del": false,
  // Always require approval for commands containing "dangerous"
  "/dangerous/": false
}
```

`false` 规则需要批准。它不会阻止该命令。要阻止本地线束中的终端工具调用，请使用返回 `permissionDecision: "deny"` 的 [Preview `PreToolUse` 挂钩 ](<https://code.visualstudio.com/docs/agents/reference/hooks-reference#_pretooluse>)。

默认情况下，规则与每个子命令匹配。仅当复合命令的所有子命令都匹配 `true` 规则并且没有一个子命令匹配 `false` 规则时，复合命令才会被自动批准。 `false` 规则始终优先。

要评估完整的命令行，请使用对象语法并将 `matchCommandLine` 设置为 `true`。

Agents in Visual Studio Code can edit files, run terminal commands, and call external tools. VS Code uses two security layers to help you control these actions:

* **Approvals** determine whether an action runs automatically or requires your confirmation.
* **Sandboxing** restricts the file system and network resources that agent terminal commands can access, even after the commands are approved.

This article explains how these layers work together and how to configure permission levels, tool and URL approvals, terminal auto-approval, and sandboxing. ## Permission levels

Permission levels control how the agent handles approvals for the current chat session. Select a level from the permissions dropdown in the chat input. You can change it at any time.

**Assisted permissions** is available only for supported sessions that run on the [Agent Host](<https://code.visualstudio.com/docs/agents/concepts/agent-host>). For the Copilot harness, choose **Folder** isolation because worktree sessions always use **Allow all**.

Enable the

Open in VS Code

| Permission level | Description |
| --- | --- |
| **Manual permissions** (default) | Uses your tool, URL, and terminal approval settings. Actions that are not auto-approved require your confirmation. |
| **Assisted permissions** | Uses an LLM judge to assess each tool call. Calls that the judge does not approve require your confirmation. |
| **Allow all** | Runs all tool calls without confirmation. |

Sandboxing is independent of the permission level. **Allow all** and **Autopilot** skip approval prompts, but an enabled sandbox still restricts terminal file system and network access. Because sandboxing applies only to terminal commands, use tool and URL approvals to control other actions with **Manual permissions**.

Important

**Assisted permissions** reduces approval interruptions but does not replace your judgment. The model-based risk assessment can make mistakes. The first time you select this level, a warning dialog asks you to confirm.

Caution

**Allow all** and **Autopilot** skip confirmation for potentially destructive actions, including file edits, terminal commands, and external tool calls. The first time you select either option, a warning dialog asks you to confirm. Use these options only when you trust the workspace and understand the [security implications](<https://code.visualstudio.com/docs/agents/run/security>).

### How Autopilot works

**Autopilot** is an agent mode, not a permission level. Select it from the mode picker in the chat input to let the agent work autonomously until it determines that the task is complete. Autopilot:

* Auto-approves all tools, like **Allow all**.
* Retries when it encounters errors.
* Responds automatically to questions that would otherwise block progress.

## Tool approval

Some tools can modify your environment or access external services. Their results can also contain prompt injection attempts. Tool approval protects against both risks.

When approval is required, review the tool name and input parameters, then approve a single use or grant approval for the session, workspace, or all future invocations.

## URL approval

When a tool accesses a URL, such as the `#web/fetch` tool, VS Code separates approval into two decisions:

| Step | What you approve | Protection |
| --- | --- | --- |
| **Request approval** | Contacting the URL or domain | Prevents data from being sent to an untrusted site. |
| **Response approval** | Adding the fetched content to the chat context | Helps prevent prompt injection from untrusted content. |

![Screenshot of a URL approval dialog showing URL details and approval options.](<https://code.visualstudio.com/assets/docs/agents/approvals/chat-approve-url.png>)

For each step, you can approve once or automatically approve future requests or responses for the URL or domain. Approving a request does not approve its response.

Request approval uses the [Trusted Domains](<https://code.visualstudio.com/docs/editing/editingevolved#_outgoing-link-protection>) list. A trusted domain does not require request approval, but its response still requires review unless you separately auto-approve responses for that domain.

Use 


chat.tools.urls.autoApprove

Open in VS Code
Open in VS Code Insiders
 to store exact URLs, glob patterns, or wildcards. Set a pattern to a boolean to control both steps, or use `approveRequest` and `approveResponse` to control them separately.

URL auto-approval examples:

```
{
  "chat.tools.urls.autoApprove": {
    "https://www.example.com": false,
    "https://*.contoso.com/*": true,
    "https://example.com/api/*": {
      "approveRequest": true,
      "approveResponse": false
    }
  }
}
```

## Automatically approve terminal commands

The agent uses one tool to run any [terminal command](<https://code.visualstudio.com/docs/agents/run/tools#_run-terminal-commands>). To avoid granting that tool unrestricted approval, VS Code evaluates each command separately.

By default, common read-only commands run automatically, while risky commands such as `rm` and `del` require approval. Add rules to 


chat.tools.terminal.autoApprove

Open in VS Code
Open in VS Code Insiders
 to change this behavior:

* Set a command to `true` to auto-approve it.
* Set a command to `false` to require approval.
* Wrap a regular expression in `/` characters to match a command pattern.

For example:

```
{
  // Allow the `mkdir` command
  "mkdir": true,
  // Allow `git status` and commands starting with `git show`
  "/^git (status|show\\b.*)$/": true,

  // Always require approval for the `del` command
  "del": false,
  // Always require approval for commands containing "dangerous"
  "/dangerous/": false
}
```

A `false` rule requires approval. It does not block the command. To block a terminal tool call in the Local harness, use a [Preview `PreToolUse` hook](<https://code.visualstudio.com/docs/agents/reference/hooks-reference#_pretooluse>) that returns `permissionDecision: "deny"`.

By default, rules match each subcommand. A compound command is auto-approved only when all its subcommands match a `true` rule and none match a `false` rule. A `false` rule always takes precedence.

To evaluate the full command line instead, use object syntax and set `matchCommandLine` to `true`.

* Disable

   to require approval for every command.

Caution

Terminal auto-approval is a best-effort convenience, not a security boundary. Command detection has these limitations:

* The PowerShell and bash tree-sitter grammars might not identify every subcommand.
* zsh and fish commands are parsed with the bash grammar, which can miss syntax differences.
* File write detection is limited, and obfuscated commands can evade matching.

If prompt injection is a concern or you work in a high-risk environment, [sandbox agent commands](<#_sandbox-agent-commands>) or run VS Code in a container.
