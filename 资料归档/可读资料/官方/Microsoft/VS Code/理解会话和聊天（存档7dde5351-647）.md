# 了解会话和聊天

会话是 {% data variables.product.prodname_vscode %} 中的 agent 的工作单元。它将任务的工作区和代码更改汇集在一起​​。聊天是该会话中的对话，并且当线束支持时，会话可以包含多个聊天。

本文帮助您在开始新聊天、分叉对话和创建新会话之间进行选择。它解释了聊天共享的内容、如何完成个人对话以及如何继续跨平台工作或将其移交给另一个 agent。

要创建和组织会话，请参阅[管理agent会话](<https://github.com/docs/agents/run/sessions/manage-sessions.md>)。

## 什么是会话？

一个会话包含一个或多个聊天。每次聊天都会记录您的提示、agent 的响应、工具调用它所进行的操作以及它在此过程中积累的 [ 上下文 ](<https://github.com/docs/agents/concepts/context.md>)。其对话历史记录有助于语言模型的 [ 上下文窗口 ](<https://github.com/docs/agents/concepts/language-models.md#context-window>)，并且不会自动与其他聊天或会话共享。

使用会话来组织相关对话、跟踪其进度并查看其综合结果。

会话的[执行环境](<https://github.com/docs/agents/concepts/agent-harnesses.md#relate-execution-environments-and-code-isolation>)决定了它在代码上的工作位置。 Agent 主机会话可以使用您计算机上的工作区、连接的主机或任一主机上的开发容器内的工作区，具体取决于可用的工具。容器改变了开发环境，而不是会话组织对话和任务的方式。

## 会话中的聊天

一个会话可以包含多个聊天。每个聊天都是一个独立的对话，具有自己的历史记录、标题、状态和 agent 或模型选择，但会话中的所有聊天共享相同的工作区和代码隔离。新聊天开始时是空白的，并且不会继承会话中其他聊天的对话历史记录。

会议有一个主要的聊天内容。其他交互式对话称为 ** 同伴聊天 **。您可以独立提示每个同伴聊天。这与 [ 子代理 ](<https://github.com/docs/agents/run/subagents.md>) 不同，agent 开始执行委派的工作。

在一个会话中运行多个聊天可以让您同时针对同一代码库处理相关任务，而无需切换会话。此功能在 [Agent 主机 ](<https://github.com/docs/agents/concepts/agent-host.md>) 上运行，并且可用于支持它的线束，例如 Copilot 和 Claude。了解如何[在会话中运行多个聊天](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>)。

例如，您要添加登录表单。使用一个聊天来构建表单，并在同一会话中使用另一个聊天来编写测试。测试编写聊天可以在保存后读取实现文件，但它不会继承第一个聊天的对话。在第二次聊天的提示中包含诸如拒绝空电子邮件地址之类的要求，而不是依赖于您之前的讨论。

两个聊天可以编辑相同的文件。当您需要单独的工作目录时，请使用带有[工作树隔离](<https://github.com/docs/agents/run/agent-harnesses.md#choose-code-isolation>)的单独会话（如果可用）。

## 选择新的聊天、分叉或新会话

Continue 在同一个聊天中，当您处理同一个任务并且其对话历史记录仍然相关时。当您需要单独的对话时，请根据是否要保留该历史记录并共享同一工作区进行选择。

|选择|何时使用它|对话历史记录|工作区和代码更改|
|--------|----------------|----------------------|----------------------------|
|[同一会话中的新聊天](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>)|通过新的对话来完成相关任务，例如为另一个聊天正在实现的功能编写测试。|在没有其他聊天历史记录的情况下开始。|共享会话的工作区和工作树。|
|[分叉对话](<https://github.com/docs/agents/run/sessions/manage-sessions.md#fork-a-chat-session>)|探索替代方法，同时保留迄今为止的要求和讨论。|将源对话继承到分叉点。原始对话仍然可用。|可以共享原始会话和工作树。分叉不保证单独的代码更改。|
|[新会话](<https://github.com/docs/agents/run/sessions/manage-sessions.md#start-an-agent-session>)|启动不相关的任务、在另一个项目中工作或选择单独的执行环境或工作树。|开始时没有先前的聊天历史记录。|使用为新会话选择的文件夹或工作树。|

分叉可以作为同一会话中的另一个聊天或作为新会话打开，具体取决于线束。分叉对话与创建 Git 分支或单独的工作树不同。例如，Copilot 工作树会话的分支继续使用原始工作树。

> [！IMPORTANT]
> 单独的对话不能保证单独的文件。如果两个聊天或会话使用相同的文件夹或工作树，则它们的编辑会影响相同的文件。当更改必须保持独立时，如果可用，请使用具有 [ 工作树隔离 ](<https://github.com/docs/agents/run/agent-harnesses.md#choose-code-isolation>) 的单独会话。

会话可以并行运行，并在您在会话之间切换时继续运行。要将现有对话和受影响的工作区文件返回到较早的点而不是分支对话，请参阅[恢复检查点](<https://github.com/docs/agents/run/review-code-edits.md#restore-a-checkpoint>)。

## 跨表面的会话

您可以在 [{% data variables.copilot.chat_view %}](<https://github.com/docs/agents/run/chat-view.md>) 或 [{% data variables.copilot.agents_window %}](<https://github.com/docs/agents/run/agents-window.md>) 中继续受支持的 Agent 主机会话。切换窗口不会创建会话、分叉对话或更改其线束、工作区或工作树。

这两个界面都提供对会话的主聊天和交互式对等聊天的访问，但它们的导航和管理控件不同。有关每个界面中的步骤，请参阅[在会话中运行多个聊天](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>)。

{% data variables.product.prodname_vscode_shortname %} 还可以发现在 {% data variables.copilot.copilot_cli_short %}、{% data variables.copilot.github_copilot_app %}、Claude Code 和 Codex 中创建的受支持的本地会话。在您从 {% data variables.product.prodname_vscode_shortname %} 发送消息之前，发现的会话是外部会话。然后，Agent 主机采用该会话，并且外部会话过滤器不再控制它是否出现。了解如何[查看来自其他应用程序的会话](<https://github.com/docs/agents/run/sessions/manage-sessions.md#view-sessions-from-other-applications>)。

在 [Agent 主机 ](<https://github.com/docs/agents/concepts/agent-host.md>) 上，agent 还可以协调跨会话的工作。它可以列出会话、创建新会话或聊天、读取另一个会话的最近上下文以及在会话之间发送后续消息。

## 移交会话

切换继续使用不同的 agent 配置进行持续的工作，并携带完整的对话历史记录和上下文。切换可以更改 [ 工具 ](<https://github.com/docs/agents/concepts/agent-harnesses.md>)、执行环境或 agent 角色。当另一种配置更适合任务的下一部分时，请使用切换。

常见的切换包括：

* **利用**：继续与Claude或Codex进行Copilot会话以使用特定于提供商的功能。
* **计划到实施**：使用[计划agent](<https://github.com/docs/agents/run/planning.md>)制定经过审查的计划，然后移交给实施agent。
* **Continue 在云中**：将范围明确的任务移交给[云目标](<https://github.com/docs/agents/run/agent-harnesses.md#start-a-cloud-session>)以进行远程执行和拉取请求工作流程。

了解如何[切换正在进行的会话](<https://github.com/docs/agents/run/agent-harnesses.md#hand-off-a-session>)。

## 远程和同步会话

会话不必在本地计算机上运行，也不必保留在一台设备上：

* **远程会话**在您工作的计算机以外的计算机上运行。您可以通过 SSH 或开发隧道将 {% data variables.copilot.agents_window %} 连接到远程主机，或使用 Copilot 远程控制 (`/remote on`) 从 GitHub 监控和引导正在运行的 Copilot 会话。了解有关 [连接到远程计算机 ](<https://github.com/docs/agents/run/remote-agent-sessions.md>) 和 [Copilot 会话远程控制 ](<https://github.com/docs/agents/run/agent-harnesses.md#remote-control-copilot-sessions>) 的详细信息。
* **同步会话** 已备份到您的GitHub 帐户，以便您可以跨设备访问它们。了解有关 [ 同步会话 ](<https://github.com/docs/agents/run/sessions/session-history.md>) 的更多信息。
* **会话见解**可让您查询会话历史记录以查看您所做的工作。了解有关 [ 会话见解 ](<https://github.com/docs/agents/run/sessions/session-history.md#query-session-history-with-chronicle>) 的更多信息。

## 关闭聊天或完成工作

关闭、标记为完成和删除有不同的目的：

* **关闭聊天选项卡**：从聊天区域隐藏聊天而不删除其对话。您可以稍后重新打开它。
* **将聊天标记为已完成**：从活动会话列表中删除已完成的对话，同时保留其标题和历史记录。当您想继续时恢复它。
* **删除聊天**：永久删除对话。与关闭或标记为完成不同，删除无法撤消。

在{% data variables.copilot.agents_window %}中，支持的附加聊天可以标记为独立完成。这不会将主聊天、其他聊天或所属会话标记为已完成。主聊天、副聊天和子代理聊天不支持标记为独立完成。

有关步骤和可用操作，请参阅[管理会话中的聊天](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>)和[将单个聊天标记为已完成](<https://github.com/docs/agents/run/sessions/manage-sessions.md#mark-an-individual-chat-as-done>)。

# Understand sessions and chats

A session is the unit of work with an agent in {% data variables.product.prodname_vscode %}. It brings together the workspace and code changes for a task. A chat is a conversation within that session, and a session can contain multiple chats when the harness supports them.

This article helps you choose between starting a new chat, forking a conversation, and creating a new session. It explains what chats share, how to finish individual conversations, and how to continue work across surfaces or hand it off to another agent.

To create and organize sessions, see [Manage agent sessions](<https://github.com/docs/agents/run/sessions/manage-sessions.md>).

## What is a session?

A session contains one or more chats. Each chat records your prompts, the agent's responses, the tool calls it makes, and the [context](<https://github.com/docs/agents/concepts/context.md>) it accumulates along the way. Its conversation history contributes to the language model's [context window](<https://github.com/docs/agents/concepts/language-models.md#context-window>) and isn't automatically shared with other chats or sessions.

Use a session to organize related conversations, follow their progress, and review their combined results.

The session's [execution environment](<https://github.com/docs/agents/concepts/agent-harnesses.md#relate-execution-environments-and-code-isolation>) determines where it works on code. An Agent Host session can use a workspace on your machine, a connected host, or inside a Dev Container on either host, depending on the available harness. A container changes the development environment, not how the session organizes the conversation and task.

## Chats within a session

A session can contain more than one chat. Each chat is an independent conversation with its own history, title, status, and agent or model selection, but all chats in a session share the same workspace and code isolation. A new chat starts blank and doesn't inherit the conversation history of the other chats in the session.

The session has a main chat. Additional interactive conversations are called **peer chats**. You can prompt each peer chat independently. This differs from a [subagent](<https://github.com/docs/agents/run/subagents.md>), which an agent starts to perform delegated work.

Running several chats in one session lets you work on related tasks against the same codebase at the same time without switching sessions. This capability runs on the [Agent Host](<https://github.com/docs/agents/concepts/agent-host.md>) and is available for harnesses that support it, such as Copilot and Claude. Learn how to [run multiple chats in a session](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>).

For example, you're adding a sign-in form. Use one chat to build the form and another chat in the same session to write tests. The test-writing chat can read the implementation files once they're saved, but it doesn't inherit the first chat's conversation. Include requirements such as rejecting an empty email address in the second chat's prompt, rather than relying on your earlier discussion.

Both chats can edit the same files. When you need separate working directories, use separate sessions with [worktree isolation](<https://github.com/docs/agents/run/agent-harnesses.md#choose-code-isolation>), where available.

## Choose a new chat, a fork, or a new session

Continue in the same chat when you're working on the same task and its conversation history is still relevant. When you need a separate conversation, choose based on whether you want to retain that history and share the same workspace.

| Choose | When to use it | Conversation history | Workspace and code changes |
|--------|----------------|----------------------|----------------------------|
| [New chat in the same session](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>) | Work on a related task with a fresh conversation, such as writing tests for the feature another chat is implementing. | Starts without the other chats' history. | Shares the session's workspace and worktree. |
| [Fork a conversation](<https://github.com/docs/agents/run/sessions/manage-sessions.md#fork-a-chat-session>) | Explore an alternative approach while retaining the requirements and discussion so far. | Inherits the source conversation up to the fork point. The original conversation remains available. | Can share the original session and worktree. Forking doesn't guarantee separate code changes. |
| [New session](<https://github.com/docs/agents/run/sessions/manage-sessions.md#start-an-agent-session>) | Start an unrelated task, work in another project, or choose a separate execution environment or worktree. | Starts without the previous chat's history. | Uses the folder or worktree selected for the new session. |

A fork can open as another chat in the same session or as a new session, depending on the harness. Forking a conversation isn't the same as creating a Git branch or a separate worktree. For example, a fork of a Copilot worktree session continues to use the original worktree.

> [!IMPORTANT]
> Separate conversations don't guarantee separate files. If two chats or sessions use the same folder or worktree, their edits affect the same files. Use separate sessions with [worktree isolation](<https://github.com/docs/agents/run/agent-harnesses.md#choose-code-isolation>), where available, when changes must stay separate.

Sessions can run in parallel and keep running when you switch between them. To return an existing conversation and affected workspace files to an earlier point instead of branching the conversation, see [Restore a checkpoint](<https://github.com/docs/agents/run/review-code-edits.md#restore-a-checkpoint>).

## Sessions across surfaces

You can continue a supported Agent Host session in the [{% data variables.copilot.chat_view %}](<https://github.com/docs/agents/run/chat-view.md>) or the [{% data variables.copilot.agents_window %}](<https://github.com/docs/agents/run/agents-window.md>). Switching windows doesn't create a session, fork the conversation, or change its harness, workspace, or worktree.

Both interfaces provide access to the session's main chat and interactive peer chats, but their navigation and management controls differ. For the steps in each interface, see [Run multiple chats in a session](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>).

{% data variables.product.prodname_vscode_shortname %} can also discover supported local sessions created in {% data variables.copilot.copilot_cli_short %}, the {% data variables.copilot.github_copilot_app %}, Claude Code, and Codex. A discovered session is external until you send a message from {% data variables.product.prodname_vscode_shortname %}. The Agent Host then adopts the session, and the external-session filter no longer controls whether it appears. Learn how to [view sessions from other applications](<https://github.com/docs/agents/run/sessions/manage-sessions.md#view-sessions-from-other-applications>).

On the [Agent Host](<https://github.com/docs/agents/concepts/agent-host.md>), an agent can also coordinate work across sessions. It can list sessions, create new sessions or chats, read another session's recent context, and send follow-up messages between sessions.

## Hand off a session

Handoff continues ongoing work with a different agent configuration and carries the full conversation history and context with it. A handoff can change the [harness](<https://github.com/docs/agents/concepts/agent-harnesses.md>), execution environment, or agent role. Use handoff when another configuration is a better fit for the next part of the task.

Common handoffs include:

* **Harness to harness**: continue a Copilot session with Claude or Codex to use provider-specific capabilities.
* **Plan to implementation**: use the [Plan agent](<https://github.com/docs/agents/run/planning.md>) to produce a reviewed plan, then hand off to an implementation agent.
* **Continue in the cloud**: hand off a well-scoped task to the [Cloud target](<https://github.com/docs/agents/run/agent-harnesses.md#start-a-cloud-session>) for remote execution and a pull request workflow.

Learn how to [hand off an ongoing session](<https://github.com/docs/agents/run/agent-harnesses.md#hand-off-a-session>).

## Remote and synced sessions

A session doesn't have to run on your local machine, and it doesn't have to stay on one device:

* **Remote sessions** run on a machine other than the one you work from. You can connect the {% data variables.copilot.agents_window %} to a remote host over SSH or a dev tunnel, or use Copilot remote control (`/remote on`) to monitor and steer a running Copilot session from GitHub. Learn more about [connecting to a remote machine](<https://github.com/docs/agents/run/remote-agent-sessions.md>) and [remote control for Copilot sessions](<https://github.com/docs/agents/run/agent-harnesses.md#remote-control-copilot-sessions>).
* **Synced sessions** are backed up to your GitHub account so you can access them across devices. Learn more about [syncing sessions](<https://github.com/docs/agents/run/sessions/session-history.md>).
* **Session insights** let you query your session history to review what you worked on. Learn more about [session insights](<https://github.com/docs/agents/run/sessions/session-history.md#query-session-history-with-chronicle>).

## Close a chat or finish work

Closing, marking done, and deleting serve different purposes:

* **Close a chat tab**: hide the chat from the chat area without deleting its conversation. You can reopen it later.
* **Mark a chat as done**: remove a completed conversation from the active sessions list while retaining its title and history. Restore it when you want to continue.
* **Delete a chat**: permanently remove the conversation. Unlike closing or marking done, deletion can't be undone.

In the {% data variables.copilot.agents_window %}, supported additional chats can be marked as done independently. This doesn't mark the main chat, other chats, or the owning session as done. Main chats, side chats, and subagent chats don't support being marked as done independently.

For the steps and available actions, see [Manage chats within a session](<https://github.com/docs/agents/run/sessions/manage-sessions.md#run-multiple-chats-in-a-session>) and [Mark an individual chat as done](<https://github.com/docs/agents/run/sessions/manage-sessions.md#mark-an-individual-chat-as-done>).
