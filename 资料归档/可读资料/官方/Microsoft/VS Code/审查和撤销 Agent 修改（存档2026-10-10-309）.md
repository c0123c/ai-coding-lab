# 查看并恢复 agent 更改

当您使用 {% data variables.product.prodname_vscode %} 中的 agent 时，它可以更改项目中的多个文件。本文介绍如何检查、修改、集成或放弃这些 AI- 生成的更改。

> [！NOTE]
> 您可以在[{% data variables.copilot.chat_view %}](<https://raw.githubusercontent.com/docs/agents/run/chat-view.md>)和[{% data variables.copilot.agents_window %}](<https://raw.githubusercontent.com/docs/agents/run/agents-window.md>)中查看AI-生成的更改。审阅体验遵循相同的概念，但两个表面之间的用户界面有所不同。

## 查看 agent 更改

Agents可以通过编辑工具、终端命令、脚本和[MCP工具](<https://raw.githubusercontent.com/docs/agent-customization/mcp-servers.md>)更改工作区文件。编辑者维护的待编辑状态可能并不代表通过这些路径所做的每个更改，因此 Agent 主机和本地线束之间的审核工作流程有所不同。

在 Agent 主机会话中，agent 应用编辑并将其直接保存在会话的文件夹或隔离的 Git 工作树中。这些编辑没有待审核状态，因此在提交或集成它们之前检查差异和源代码管理更改。您可以[恢复检查点](<#恢复检查点>)来恢复受影响的工作区文件和聊天历史记录，但它不会反转已完成的命令或外部效果。 **手动权限** 不需要确认您的批准设置已允许的编辑。如需在编辑特定文件之前要求确认，请配置[敏感文件审批](<#编辑敏感文件>)。

**Local** 线束在 {% data variables.product.prodname_vscode_shortname %} 扩展主机中运行，并将支持的文件编辑标记为待处理，以便您可以单独保留或撤消它们。 Agent 主机 ** 更改 ** 视图不提供相同的每次编辑保留和撤消工作流程。展开**查看下面的本地控件的分机主机更改**。

通过 diff 视图、源代码管理或拉取请求工作流程查看 agent 更改，就像查看其他工作区或分支更改一样。

要通过键盘和屏幕阅读器访问差异，请使用[可访问差异查看器](<https://raw.githubusercontent.com/docs/configure/accessibility/accessibility.md#diff-editor-accessibility>)，它以统一的补丁格式显示更改。

1. 在 agent 的响应中选择已更改的文件以打开其差异或从源代码管理视图中选择它。

1. 要在每个完成的请求后查看摘要，请将 `setting(chat.checkpoints.showFileChanges)` 设置为 `true`。展开已更改文件摘要以查看文件和差异统计信息，或选择 **查看所有文件更改** 以打开多文件差异。

1. 如果您想进行进一步更改，请发送后续提示或直接编辑文件。要恢复请求和所有后续更改，[恢复检查点](<#恢复检查点>)。

1. 运行测试并使用调试器或其他编辑器工具来验证结果。

1. 当您对更改感到满意时：

    * 对于文件夹隔离的会话，使用源代码管理暂存并提交更改。

    * 对于工作树隔离的会话，将工作树更改应用或合并到主工作区中。

    * 对于云会话，请查看拉取请求或在本地查看其分支。

默认情况下，{% data variables.copilot.agents_window %} 在侧面板中显示这些视图：

* **文件**：会话工作区的文件资源管理器。
* **更改**：agent更改、添加或删除的文件。使用 ** 分支更改 ** 下拉列表选择要查看的变更集。

**更改**视图将工作区外部的编辑分组到**其他文件**下。这些文件（例如会话状态文件夹中的计划）不会随工作区更改一起提交。仅通过终端命令或脚本更改的文件可能不会出现在特定于工具的更改跟踪中。在提交或集成更改之前，还要在源代码管理中查看会话的文件夹或工作树，包括未跟踪的文件。

### 在 diff 编辑器中配置自动换行

`feature(agents-window-word-wrap)`

控制 **Changes** 视图中的 diff 编辑器如何使用 `setting(sessions.diffEditor.wordWrap)` 换行长行。此设置具有以下值：

* `inherit`（默认）：遵循`setting(editor.wordWrap)`设置。
* `on`：以编辑器视口宽度换行。
* `off`：切勿换行。

此设置仅影响 diff 编辑器，不影响 {% data variables.copilot.agents_window %} 中的代码编辑器。要在代码编辑器中配置自动换行，请参阅[为代码编辑器配置自动换行](<https://raw.githubusercontent.com/docs/agents/run/agents-window-configuration.md#configure-word-wrap-for-code-editors>)。

要从差异编辑器更改此设置，请选择 **更多操作 ** (**...**) > **自动换行**。此操作独立于代码编辑器设置更新 `setting(sessions.diffEditor.wordWrap)`。

要查看并整合更改：

1. 在 ** 更改 ** 视图中选择一个文件，以打开 agent 编辑的差异视图。

![显示 {% data variables.copilot.agents_window %} 中“更改”面板的屏幕截图，突出显示已编辑文件列表和差异视图。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/agents-window-diff-view.png>)

默认情况下，选择一个文件会打开一个包含所有会话更改的多文件差异编辑器。要打开聚焦的单文件差异，请启用 `setting(sessions.changes.openSingleFileDiff)`。

使用 diff 工具栏可以与聊天并排显示编辑器或在模式窗口中显示编辑器。

要更改比较布局，请选择 **更多操作** (**...**) > **比较视图**，然后选择**内联**、**并排**或**自动**。使用 ** 自动 **，更改编辑器在有足够空间时并排显示文件，并在编辑器狭窄时切换到内联。

1. 选择已更改文件中的代码范围，选择 ** 添加反馈 **，然后输入描述所需更改的注释。对其他选择或文件添加更多评论，然后选择**提交反馈**将其发送到agent。

![显示“更改差异”视图中“添加反馈”按钮的屏幕截图。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/agents-window-add-feedback.png>)

Markdown 文件遵循相同的反馈流程。从 **Changes** 选项卡打开工作区文件，并在 Markdown 编辑器中使用 **Locked** 模式来添加基于范围的反馈。如果您在文本编辑器中重新打开文件，反馈将保持同步。

agent 读取您的评论，进行所请求的编辑，并解决每条评论。已解决的注释将从差异视图中消失。

1. 在文件工具栏中选择 ** 标记为已审阅 **，以跟踪您在 ** 分支更改 ** 变更集中审阅的文件。如果您或agent再次更改文件，已审阅的状态将被清除。

1. 使用 **Commit**、**Merge**、**Checkout** 或 **Discard** 操作来执行编辑。

创建会话时，请使用 **Files** 面板中的同步按钮在 agent 启动之前从基础分支拉取上游更改。当您集成结果时，从最新的分支状态开始可以减少合并冲突。

### 添加拉取请求审核评论

`feature(agents-window-pr-comments)`

对于与开放的 GitHub 拉取请求关联的 Agent 主机会话，您可以直接从 **Changes** 视图向拉取请求添加审核评论。这与agent反馈不同，后者要求agent修改其更改。

1. 启用 `setting(chat.experimental.agentsWindowPRComments)` 设置。
1. 从 **Changes** 视图中打开更改的文件并选择代码范围。
1. 选择**添加反馈**并输入您的评论。
1. 选择 **添加 PR 评论 ** 将审核评论添加到拉取请求中。如果会话与多个拉取请求关联，则该操作将目标标识为 `owner/repository#number`。

所选范围必须仅包含属于拉取请求差异一部分的行。如果该范围不符合条件，{% data variables.product.prodname_vscode_shortname %} 会报告无法将拉取请求评论添加到该行。

**添加PR评论**将评论添加到GitHub，但不会将其发送到agent。要要求 agent 更改代码，请添加注释作为反馈，然后选择 **提交反馈**。

### 查看单窗格布局中的更改（实验）

当您启用 [ 实验性单窗格编辑器面板 ](<https://raw.githubusercontent.com/docs/agents/run/agents-window-configuration.md#use-the-single-pane-editor-panel-experimental>) 时，** 更改 ** 视图和 diff 编辑器共享一个停靠窗格。

使用**展开所有差异**或**折叠所有差异**一次控制所有文件。 `kb(toggle.diff.renderSideBySide)` 键绑定切换 {% data variables.copilot.agents_window %} 中的首选差异视图。

当您切换会话或重新加载窗口时，更改编辑器会恢复每个文件的展开或折叠状态。编辑器选项卡标题显示下一个集成操作，例如 **Create Pull Request**，并在空间有限时切换到图标。

## 集成工作树更改

工作树会话将 agent 的分支和工作文件与主工作树分开。查看并验证结果后，选择如何继续：

* **应用或迁移更改**：将工作树更改传输到当前工作区以进行进一步编辑，并将其与现有工作一起提交。
* **提交或合并分支**：保留会话分支上的工作并将其合并到目标分支中。
* **查看分支**：在编辑器窗口中打开会话分支以继续手动处理它。
* **放弃更改**：删除您不想保留的更改。

在应用或合并更改之前：

1. 确认主工作区中会话的基础分支和目标分支。
1. 在目标工作区中提交或隐藏不相关的更改。
1. 查看所有更改的文件，包括未跟踪的文件，并运行相关测试。
1. 选择集成操作并解决任何合并冲突。
1. 在存档或删除会话之前测试集成结果。

可用的操作和标签取决于会话工具以及您使用的是 {% data variables.copilot.chat_view %} 还是 {% data variables.copilot.agents_window %}。保留会话，直到您验证更改是否存在于预期的目标分支上。

有关分别查看两个结果、一次集成一个结果以及测试组合更改的演练，请遵循 [委派两项任务而不混合其更改](<https://raw.githubusercontent.com/docs/agents/guides/delegate-two-tasks.md>)。

## 编辑请求并恢复检查点

如需帮助决定是修改请求、恢复更改还是重新开始，请参阅 [让 agent 回到正轨 ](<https://raw.githubusercontent.com/docs/agents/guides/get-agent-back-on-track.md#choose-a-recovery-action>)。

使用请求编辑和检查点来修改或撤消一批更改：

* **编辑之前的请求**：修改您已发送的提示。 {% data variables.product.prodname_vscode_shortname %} 恢复该请求和所有后续请求所做的更改，然后重新发送编辑后的提示。
* **恢复检查点**：将所有文件更改回滚到对话中的特定点，而不更改提示。

### 编辑之前的聊天请求

对话历史记录中的每个请求都是可编辑的。当您编辑先前的请求时，{% data variables.product.prodname_vscode_shortname %} 会还原原始请求和后续请求所做的文件更改，然后将更新的请求发送到语言模型。

在对话中选择请求，修改它，然后重新发送。使用 `setting(chat.editRequests)` 配置或关闭请求编辑。

### 恢复检查点

默认情况下，为支持的聊天会话启用检查点。在处理每个请求之前，{% data variables.product.prodname_vscode_shortname %} 创建受影响的工作区文件的快照。设置`setting(chat.checkpoints.enabled)`来控制检查点。

要将工作区恢复到较早的检查点：

1. 导航到对话中的上一个请求。

1. 将鼠标悬停在请求上并选择 ** 恢复检查点 **。

![显示 {% data variables.copilot.chat_view %}.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-restore-checkpoint.png>) 中恢复检查点操作的屏幕截图

1. 确认您要恢复检查点。

{% data variables.product.prodname_vscode_shortname %} 从对话历史记录中删除后续请求，并将工作区文件恢复到检查点时的状态。

> [！IMPORTANT]
> 检查点恢复受影响的工作区文件和聊天历史记录。它不会反转已完成的终端命令、网络请求、部署或工具对外部服务所做的更改。使用 Git 和外部服务的恢复控制来实现这些效果。

#### 恢复后重做

恢复检查点后，选择**重做**以恢复已撤消的更改。

![显示恢复检查点后重做按钮的屏幕截图。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-redo-checkpoint.png>)

#### 查看检查点中的文件更改

设置`setting(chat.checkpoints.showFileChanges)`以显示每个请求更改的文件以及添加或删除的行数。使用此摘要可在恢复其检查点之前了解请求的效果。

![显示与聊天检查点关联的文件更改的屏幕截图。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-checkpoint-changed-files.png>)

#### 从检查点分叉

将鼠标悬停在请求上并选择 **Fork Conversation** 以创建一个独立会话，其中包括截至该检查点的对话。了解有关 [ 分叉 agent 会话 ](<https://raw.githubusercontent.com/docs/agents/run/sessions/manage-sessions.md#fork-a-chat-session>) 的更多信息。

> [!NOTE]
> 检查点是临时的，不会取代 Git 版本控制。使用 Git 实现永久版本历史记录和协作。



<summary>查看分机主机更改</summary>

如果 [Agent 主机 ](<https://raw.githubusercontent.com/docs/agents/concepts/agent-host.md>) 未启用，或者您正在使用较旧的会话，则 agent 使用扩展主机进行编辑，该主机具有不同的审查更改的工作流程。

agent 编辑并保存文件后，{% data variables.product.prodname_vscode_shortname %} 将编辑标记为待处理。待处理意味着您可以保留或撤消已保存的编辑。这并不意味着编辑正在等待写入磁盘。待编辑的文件在资源管理器视图和编辑器选项卡中具有方点指示器。当您重新打开 {% data variables.product.prodname_vscode_shortname %} 时，将恢复挂起状态。

![显示 {% data variables.copilot.chat_view %} 的屏幕截图，突出显示已更改的文件列表以及资源管理器视图和编辑器选项卡中的指示器。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/copilot-edits-changed-files-full.png>)

要查看待处理的编辑：

1. 从 {% data variables.copilot.chat_view %} 中的已更改文件列表或从资源管理器视图打开文件。

![显示编辑器建议更改的屏幕截图，突出显示编辑器覆盖控件中的审阅控件。](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/copilot-edits-file-review-controls.png>)

1. 使用编辑器叠加层中的 `kbstyle(Up)` 和 `kbstyle(Down)` 控件在编辑之间导航。

1. 对于每次编辑，请选择以下操作之一：

    * 选择**保留**接受编辑。
    * 选择**撤消**以拒绝编辑并恢复更改。
    * 将鼠标悬停在内联更改上即可接受或拒绝该特定更改，而不影响文件中的其他编辑。

您还可以接受或拒绝来自 {% data variables.copilot.chat_view %} 的所有待处理编辑。当您解决编辑时，编辑器会自动打开下一个包含待编辑的文件。要保留在当前文件中，请将 `setting(chat.editing.revealNextChangeOnResolve)` 设置为 `false`。

### 源代码控制集成

如果您在源代码管理视图中暂存更改，任何待处理的编辑都会自动接受。如果您放弃更改，则所有待处理的编辑也会被放弃。

### 自动接受编辑

使用 `setting(chat.editing.autoAcceptDelay)` 在可配置的延迟后自动接受待处理的编辑。将鼠标悬停在编辑器覆盖控件上可停止倒计时。

> [!IMPORTANT]
> 如果您自动接受所有编辑，请在将更改提交到源代码管理之前检查更改。了解更多关于 [使用的安全考虑 AI 在 {% data variables.product.prodname_vscode_shortname %}](<https://raw.githubusercontent.com/docs/agents/run/security.md>).




## 编辑敏感文件

敏感文件审批与 agent 保存后更改的审核是分开的。为了防止无意中编辑工作区配置或环境设置等文件，{% data variables.product.prodname_vscode_shortname %} 可以显示差异并要求您在应用编辑之前批准或拒绝编辑。

使用 `setting(chat.tools.edits.autoApprove)` 设置来配置哪些文件需要批准。该设置使用全局模式来匹配工作区中的文件路径。

以下示例配置自动允许编辑除 `.vscode` 文件夹中的 JSON 文件和名为 `.env` 的文件（系统将提示您批准这些文件）之外的所有文件：

```json
"chat.tools.edits.autoApprove": {
  "**/*": true,
  "**/.vscode/*.json": false,
  "**/.env": false
}
```

## 查看会话列表中的更改

当会话完成并对项目进行代码更改时，[会话列表](<https://raw.githubusercontent.com/docs/agents/run/sessions/manage-sessions.md#sessions-list>)会显示该会话的文件更改统计信息。要查看更改，请从列表中选择会话以打开会话详细信息。

# Review and revert agent changes

When you work with an agent in {% data variables.product.prodname_vscode %}, it can change multiple files in your project. This article explains how to inspect, revise, integrate, or discard these AI-generated changes.

> [!NOTE]
> You can review AI-generated changes in both the [{% data variables.copilot.chat_view %}](<https://raw.githubusercontent.com/docs/agents/run/chat-view.md>) and the [{% data variables.copilot.agents_window %}](<https://raw.githubusercontent.com/docs/agents/run/agents-window.md>). The review experience follows the same concepts, but the user interface differs between the two surfaces.

## Review agent changes

Agents can change workspace files through editing tools, terminal commands, scripts, and [MCP tools](<https://raw.githubusercontent.com/docs/agent-customization/mcp-servers.md>). An editor-maintained pending-edit state might not represent every change made through these paths, so the review workflow differs between Agent Host and the Local harness.

In Agent Host sessions, the agent applies and saves edits directly in the session's folder or isolated Git worktree. These edits don't have a pending review state, so inspect the diff and Source Control changes before you commit or integrate them. You can [restore a checkpoint](<#restore-a-checkpoint>) to recover affected workspace files and chat history, but it doesn't reverse completed commands or external effects. **Manual permissions** doesn't require confirmation for edits that your approval settings already allow. To require confirmation before specific files are edited, configure [sensitive-file approval](<#edit-sensitive-files>).

The **Local** harness runs in the {% data variables.product.prodname_vscode_shortname %} extension host and marks supported file edits as pending so you can keep or undo them individually. The Agent Host **Changes** view doesn't provide the same per-edit Keep and Undo workflow. Expand **Review extension-host changes** below for Local's controls.

Review agent changes as you would other workspace or branch changes through the diff view, Source Control, or pull request workflow.

For keyboard and screen reader access to a diff, use the [Accessible Diff Viewer](<https://raw.githubusercontent.com/docs/configure/accessibility/accessibility.md#diff-editor-accessibility>), which presents changes in a unified patch format.

{% tabs id="chat-surface" %}
{% tab label="{% data variables.copilot.chat_view %}" %}

1. Select a changed file in the agent's response to open its diff or select it from the Source Control view.

1. To see a summary after each completed request, set `setting(chat.checkpoints.showFileChanges)` to `true`. Expand the changed-files summary to see the files and diff statistics, or select **View All File Changes** to open a multi-file diff.

1. If you want to make further changes, send a follow-up prompt or edit the files directly. To revert a request and all later changes, [restore a checkpoint](<#restore-a-checkpoint>).

1. Run tests and use the debugger or other editor tools to validate the result.

1. When you're satisfied with the changes:

    * For folder-isolated sessions, stage and commit the changes with Source Control.

    * For worktree-isolated sessions, apply or merge the worktree changes into your main workspace.

    * For cloud sessions, review the pull request or check out its branch locally.

{% /tab %}
{% tab label="{% data variables.copilot.agents_window %}" %}

By default, the {% data variables.copilot.agents_window %} shows these views in a side panel:

* **Files**: a file explorer for the session workspace.
* **Changes**: files that the agent changed, added, or deleted. Use the **Branch Changes** dropdown to choose which changeset to review.

The **Changes** view groups edits outside the workspace under **Other Files**. These files, such as plans in the session-state folder, aren't committed with workspace changes. Files changed only through terminal commands or scripts might not appear in tool-specific change tracking. Review the session's folder or worktree in Source Control as well, including untracked files, before committing or integrating changes.

### Configure word wrap in diff editors

`feature(agents-window-word-wrap)`

Control how diff editors in the **Changes** view wrap long lines with `setting(sessions.diffEditor.wordWrap)`. This setting has the following values:

* `inherit` (default): Follow the `setting(editor.wordWrap)` setting.
* `on`: Wrap lines at the editor viewport width.
* `off`: Never wrap lines.

This setting only affects diff editors and doesn't affect code editors in the {% data variables.copilot.agents_window %}. To configure word wrapping in code editors, see [Configure word wrap for code editors](<https://raw.githubusercontent.com/docs/agents/run/agents-window-configuration.md#configure-word-wrap-for-code-editors>).

To change this setting from a diff editor, select **More Actions** (**...**) > **Word Wrap**. This action updates `setting(sessions.diffEditor.wordWrap)` independently of the code editor setting.

To review and integrate the changes:

1. Select a file in the **Changes** view to open a diff view of the agent's edits.

    ![Screenshot showing the Changes panel in the {% data variables.copilot.agents_window %}, highlighting the list of edited files and the diff view.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/agents-window-diff-view.png>)

    By default, selecting a file opens a multi-file diff editor with all the session changes. To open a focused single-file diff, enable `setting(sessions.changes.openSingleFileDiff)`.

    Use the diff toolbar to show the editor side by side with chat or in a modal window.

    To change the diff layout, select **More Actions** (**...**) > **Diff View**, and then select **Inline**, **Side by Side**, or **Automatic**. With **Automatic**, the Changes editor shows files side by side when there is enough space and switches to inline when the editor is narrow.

1. Select a range of code in a changed file, select **Add Feedback**, and enter a comment that describes the change you want. Add more comments on other selections or files, and then select **Submit Feedback** to send them to the agent.

    ![Screenshot showing the Add Feedback button in the Changes diff view.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/agents-window-add-feedback.png>)

    Markdown files follow the same feedback flow. Open a workspace file from the **Changes** tab and use **Locked** mode in the Markdown editor to add range-based feedback. Feedback stays in sync if you reopen the file in the text editor.

    The agent reads your comments, makes the requested edits, and resolves each comment. Resolved comments disappear from the diff view.

1. Select **Mark as Reviewed** in a file's toolbar to track files you've reviewed in the **Branch Changes** changeset. The reviewed state clears if you or the agent changes the file again.

1. Use the **Commit**, **Merge**, **Checkout**, or **Discard** actions to act on the edits.

When you create a session, use the sync button in the **Files** panel to pull upstream changes from the base branch before the agent starts. Starting from the latest branch state reduces merge conflicts when you integrate the result.

### Add pull request review comments

`feature(agents-window-pr-comments)`

For an Agent Host session associated with an open GitHub pull request, you can add a review comment to the pull request directly from the **Changes** view. This is different from agent feedback, which asks the agent to revise its changes.

1. Enable the `setting(chat.experimental.agentsWindowPRComments)` setting.
1. Open a changed file from the **Changes** view and select a range of code.
1. Select **Add Feedback** and enter your comment.
1. Select **Add PR Comment** to add the review comment to the pull request. If the session is associated with multiple pull requests, the action identifies the target as `owner/repository#number`.

The selected range must contain only lines that are part of the pull request diff. If the range isn't eligible, {% data variables.product.prodname_vscode_shortname %} reports that a pull request comment can't be added to the line.

**Add PR Comment** adds the comment to GitHub and doesn't send it to the agent. To ask the agent to change the code instead, add the comment as feedback and select **Submit Feedback**.

### Review changes in the single-pane layout (Experimental)

When you enable the [experimental single-pane editor panel](<https://raw.githubusercontent.com/docs/agents/run/agents-window-configuration.md#use-the-single-pane-editor-panel-experimental>), the **Changes** view and diff editor share one docked pane.

Use **Expand All Diffs** or **Collapse All Diffs** to control all files at once. The `kb(toggle.diff.renderSideBySide)` keybinding toggles the preferred diff view in the {% data variables.copilot.agents_window %}.

The Changes editor restores each file's expanded or collapsed state when you switch sessions or reload the window. The editor tab title shows the next integration action, such as **Create Pull Request**, and switches to an icon when space is limited.

## Integrate worktree changes

A worktree session keeps the agent's branch and working files separate from your primary worktree. After you review and validate the result, choose how to continue:

* **Apply or migrate the changes**: transfer the worktree changes into your current workspace for further editing and commit them with your existing work.
* **Commit or merge the branch**: preserve the work on the session branch and merge it into the destination branch.
* **Check out the branch**: open the session branch in an editor window to continue working on it manually.
* **Discard the changes**: remove changes that you don't want to keep.

Before you apply or merge changes:

1. Confirm the session's base branch and the destination branch in your primary workspace.
1. Commit or stash unrelated changes in the destination workspace.
1. Review all changed files, including untracked files, and run the relevant tests.
1. Select the integration action and resolve any merge conflicts.
1. Test the integrated result before you archive or delete the session.

The available actions and labels depend on the session harness and whether you use the {% data variables.copilot.chat_view %} or {% data variables.copilot.agents_window %}. Keep the session until you verify that the changes are present on the intended destination branch.

For a walkthrough of reviewing two results separately, integrating them one at a time, and testing the combined change, follow [Delegate two tasks without mixing their changes](<https://raw.githubusercontent.com/docs/agents/guides/delegate-two-tasks.md>).

## Edit requests and restore checkpoints

For help deciding whether to revise a request, restore changes, or start fresh, see [Get an agent back on track](<https://raw.githubusercontent.com/docs/agents/guides/get-agent-back-on-track.md#choose-a-recovery-action>).

Use request editing and checkpoints to revise or undo a batch of changes:

* **Edit a previous request**: modify a prompt you already sent. {% data variables.product.prodname_vscode_shortname %} reverts changes made by that request and all subsequent requests, then resends the edited prompt.
* **Restore a checkpoint**: roll back all file changes to a specific point in the conversation without changing the prompt.

### Edit a previous chat request

Each request in your conversation history is editable. When you edit a previous request, {% data variables.product.prodname_vscode_shortname %} reverts file changes made by the original request and subsequent requests, and then sends the updated request to the language model.

Select the request in the conversation, modify it, and resend it. Configure or turn off request editing with `setting(chat.editRequests)`.

### Restore a checkpoint

Checkpoints are enabled by default for supported chat sessions. Before processing each request, {% data variables.product.prodname_vscode_shortname %} creates a snapshot of affected workspace files. Set `setting(chat.checkpoints.enabled)` to control checkpoints.

To restore your workspace to an earlier checkpoint:

1. Navigate to a previous request in the conversation.

1. Hover over the request and select **Restore Checkpoint**.

    ![Screenshot showing the Restore Checkpoint action in the {% data variables.copilot.chat_view %}.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-restore-checkpoint.png>)

1. Confirm that you want to restore the checkpoint.

{% data variables.product.prodname_vscode_shortname %} removes subsequent requests from the conversation history and restores the workspace files to their state at the checkpoint.

> [!IMPORTANT]
> A checkpoint restores affected workspace files and chat history. It doesn't reverse completed terminal commands, network requests, deployments, or changes that tools made to external services. Use Git and the external service's recovery controls for those effects.

#### Redo after restoring

After restoring a checkpoint, select **Redo** to recover the changes that were undone.

![Screenshot showing the Redo button after restoring a checkpoint.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-redo-checkpoint.png>)

#### View file changes in checkpoints

Set `setting(chat.checkpoints.showFileChanges)` to show the files changed by each request and the number of lines added or removed. Use this summary to understand the effect of a request before restoring its checkpoint.

![Screenshot showing file changes associated with a chat checkpoint.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/chat-checkpoints/chat-checkpoint-changed-files.png>)

#### Fork from a checkpoint

Hover over a request and select **Fork Conversation** to create an independent session that includes the conversation up to that checkpoint. Learn more about [forking agent sessions](<https://raw.githubusercontent.com/docs/agents/run/sessions/manage-sessions.md#fork-a-chat-session>).

> [!NOTE]
> Checkpoints are temporary and don't replace Git version control. Use Git for permanent version history and collaboration.



<summary>Review extension-host changes</summary>

If [Agent Host](<https://raw.githubusercontent.com/docs/agents/concepts/agent-host.md>) is not enabled or you are working with an older session, the agent uses the extension host to make edits, which has a different workflow for reviewing changes.

After the agent edits and saves a file, {% data variables.product.prodname_vscode_shortname %} marks the edits as pending. Pending means that you can keep or undo the saved edit. It doesn't mean that the edit is waiting to be written to disk. Files with pending edits have a squared-dot indicator in the Explorer view and editor tabs. The pending state is restored when you reopen {% data variables.product.prodname_vscode_shortname %}.

![Screenshot showing the {% data variables.copilot.chat_view %}, highlighting the changed files list and the indicator in the Explorer view and editor tabs.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/copilot-edits-changed-files-full.png>)

To review pending edits:

1. Open a file from the changed-files list in the {% data variables.copilot.chat_view %} or from the Explorer view.

    ![Screenshot showing the Editor with proposed changes, highlighting the review controls in the editor overlay controls.](<https://raw.githubusercontent.com/microsoft/vscode-docs//docs/agents/images/review-code-edits/copilot-edits-file-review-controls.png>)

1. Use the `kbstyle(Up)` and `kbstyle(Down)` controls in the editor overlay to navigate between edits.

1. For each edit, choose one of the following actions:

    * Select **Keep** to accept the edit.
    * Select **Undo** to reject the edit and revert the change.
    * Hover over an inline change to accept or reject that specific change without affecting other edits in the file.

You can also accept or reject all pending edits from the {% data variables.copilot.chat_view %}. When you resolve an edit, the editor automatically opens the next file with pending edits. To stay in the current file, set `setting(chat.editing.revealNextChangeOnResolve)` to `false`.

### Source Control integration

If you stage your changes in the Source Control view, any pending edits are automatically accepted. If you discard your changes, any pending edits are also discarded.

### Auto-accept edits

Use `setting(chat.editing.autoAcceptDelay)` to automatically accept pending edits after a configurable delay. Hover over the editor overlay controls to stop the countdown.

> [!IMPORTANT]
> If you automatically accept all edits, review the changes before you commit them in source control. Learn more about the [security considerations of using AI in {% data variables.product.prodname_vscode_shortname %}](<https://raw.githubusercontent.com/docs/agents/run/security.md>).




## Edit sensitive files

Sensitive-file approval is separate from reviewing changes after the agent saves them. To prevent inadvertent edits to files such as workspace configuration or environment settings, {% data variables.product.prodname_vscode_shortname %} can show a diff and ask you to approve or reject the edit before it is applied.

Use the `setting(chat.tools.edits.autoApprove)` setting to configure which files require approval. The setting uses glob patterns to match file paths in your workspace.

The following example configuration automatically allows edits to all files except for JSON files in the `.vscode` folder and files named `.env`, which you are prompted to approve:

```json
"chat.tools.edits.autoApprove": {
  "**/*": true,
  "**/.vscode/*.json": false,
  "**/.env": false
}
```

When a session completes and makes code changes to your project, the [sessions list](<https://raw.githubusercontent.com/docs/agents/run/sessions/manage-sessions.md#sessions-list>) shows the file change statistics for that session. To review the changes, select the session from the list to open the session details.
