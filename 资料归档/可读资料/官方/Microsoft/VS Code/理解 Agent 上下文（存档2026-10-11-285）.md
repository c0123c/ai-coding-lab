---

上下文是 AI agent 及其语言模型在处理您的请求时可用的信息。它可以包括对话历史记录、工作区中的文件、工具输出、自定义说明以及添加到提示中的引用。

语言模型根据这些信息进行推理，以决定下一步要说什么或做什么。 agent 可以使用 [ 工具 ](<https://code.visualstudio.com/docs/agents/concepts/tools>) 收集更多上下文、采取行动并评估结果。本文解释了 VS Code 如何组装和发现上下文，以及如何在上下文窗口限制内工作。

## 为什么背景很重要

包含相关文件、清晰说明和重点历史记录的提示比没有上下文的模糊提示会产生更好的结果。语言模型只能对当前上下文中包含的信息进行推理。

您无需在开始之前识别每个相关文件。在 [agent 循环 ](<https://code.visualstudio.com/docs/agents/concepts/agents#_agent-loop>) 期间，agent 可以搜索您的工作区、读取文件、运行命令并将结果添加到上下文中以供下一步使用。当您已经知道 agent 应考虑哪些信息时，显式引用非常有用。

对话历史记录仅限于聊天，不会自动与其他聊天或会话共享。上下文可以显式传递，例如在委托任务或 [ 切换 ](<https://code.visualstudio.com/docs/agents/concepts/sessions#_hand-off-a-session>) 中。持久源，例如 [ 自定义指令 ](<https://code.visualstudio.com/docs/agent-customization/custom-instructions>) 或 [agent 内存 ](<https://code.visualstudio.com/docs/agents/concepts/agents#_memory>)，也可以跨对话提供信息。

## VS Code 如何组装上下文

每次 agent 向语言模型发送请求时，VS Code 都会从多个来源组装提示：

![该图将上下文窗口显示为具有七层的容器：系统指令、自定义、用户消息、对话历史记录、隐式上下文、显式引用和工具输出，并使用箭头将组装的提示发送到语言模型。](<https://code.visualstudio.com/assets/docs/agents/concepts/context-assembly.png>)

* **系统指令**：定义agent行为的内置准则。
* **自定义项**：您设置的AI自定义项，包括自定义agents、技能和自定义指令。
* **用户消息**：您发送给agent的当前请求或后续消息。
* **对话历史记录**：当前聊天中到目前为止交换的消息。
* **隐式上下文**：您正在编辑的文件、当前选择、可见错误和 git 状态。
* **显式引用**：文件、编辑器上下文、Web 内容以及您通过 `#` 提及引用的其他来源。
* **工具输出**：agent会话期间文件读取、终端命令、代码库搜索结果和其他工具调用的结果。

上下文随着 agent 的工作而变化。例如，代码搜索的输出可以引导 agent 读取文件，然后该文件可以通知下一个模型请求。模型无法获取未包含在请求中的信息，但 agent 可以使用工具来发现和添加更多信息。

## 工作区索引

VS Code 使用语义索引通过含义而不是仅通过确切的关键字来查找代码。该索引有助于 agent 快速定位相关片段，尤其是在大型代码库中。它不会将您的整个工作区添加到每个模型请求中。

VS Code自动构建和维护索引。如果语义索引尚不可用，agent 仍然可以通过使用文本搜索、文件搜索和语言智能来查找上下文。

了解有关 [ 工作区索引 ](<https://code.visualstudio.com/docs/agents/reference/workspace-context>) 的更多信息。

## 隐式上下文

VS Code 使用您当前的活动为提示提供上下文或建议您可能添加的上下文：

* 活动编辑器中当前选定的文本。
* 活动编辑器的文件名或笔记本名称。
* 当您使用**询问**agent时，活动文件的内容。
* 当您使用 **Agent** 时，活动文件作为建议附件添加到上下文中。

隐式上下文减少了您需要指定的信息量。如果特定源对任务很重要，请显式添加它，而不是依赖 agent 来推断它是相关的。

## 显式上下文

当您想要确保 agent 考虑特定文件、文件夹、符号、图像、网页或其他源时，请添加显式上下文。在聊天输入中键入 `#` 以选择上下文项目，或在聊天输入字段中选择 **添加上下文 **（`+` 图标）。

显式上下文引导 agent 获取相关信息，但仍计入上下文窗口。仅添加帮助 agent 完成当前任务的源。了解有关 [向聊天添加上下文 ](<https://code.visualstudio.com/docs/chat/copilot-chat-context>) 的更多信息。

提示

预先提供重点上下文可能会减少 agent 需求的搜索和文件读取，从而降低 AI 信用使用量。避免添加不相关或大型源，因为它们也会消耗上下文窗口令牌。了解有关 [ 优化 AI 积分使用 ](<https://code.visualstudio.com/docs/agents/guides/optimize-usage>) 的更多信息。

## 上下文窗口和压缩

上下文窗口是语言模型在一次请求中可以处理的最大信息量。用户消息、对话历史记录、说明、参考文件和工具输出所有使用空间都在此窗口中。

当对话接近限制时，VS Code 会自动将对话的较旧部分压缩为摘要。压缩为新信息腾出了空间，但早期消息的详细信息可能会被总结或省略。您还可以在聊天输入中输入 `/compact` 以手动压缩对话。

当您切换到不相关的任务时开始新的会话。如果指令应跨请求或会话应用，请将其存储在 [ 自定义指令 ](<https://code.visualstudio.com/docs/agent-customization/custom-instructions>) 中，而不是依赖对话历史记录。详细了解 [ 管理对话上下文 ](<https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#_compact-conversation-context>)。

## 与子代理的上下文隔离

agent 可以将重点任务委托给 [ 子代理 ](<https://code.visualstudio.com/docs/agents/concepts/agents#_subagents>)，该子代理在其自己的上下文中工作并返回结果。这使得中间工作与主要对话分开。相比之下，压缩总结了该对话中已有的内容。

上下文隔离不是代码隔离。它本身不会创建单独的工作树或沙箱。 agent对文件和工具的访问取决于[执行环境](<https://code.visualstudio.com/docs/agents/concepts/agent-harnesses#_relate-execution-environments-and-code-isolation>)和[权限控制](<https://code.visualstudio.com/docs/agents/concepts/trust-and-safety>)。

了解如何[将工作委派给子代理](<https://code.visualstudio.com/docs/agents/run/subagents>)。

## 结合上下文有效工作

* **描述目标和约束。**解释您想要的结果以及agent应遵循的任何要求。
* **让agent发现上下文。**agent可以搜索您的工作空间并在工作时读取相关文件。您不需要附加整个代码库。
* **参考重要来源。**明确添加agent必须考虑的文件、符号、错误或文档。
* **保持每个会话的重点。**对不相关的任务使用单独的会话，以便其历史记录不会争夺上下文。

### 上下文如何改善响应

考虑询问 agent 来解释身份验证在您的项目中如何工作。

没有相关的工作空间上下文：

```
How does authentication work?
```

该模型无法知道您指的是哪个项目，并给出有关身份验证模式的通用答案。

将 `src/auth.ts` 作为上下文附加到请求后：

```
Explain the authentication flow and identify where tokens are validated.
```

引用的文件为 agent 提供了一个起点。然后agent可以搜索相关代码并解释具体功能和配置值的实现。

---

Context is the information available to an AI agent and its language model while they work on your request. It can include conversation history, files from your workspace, tool outputs, custom instructions, and references you add to your prompt.

The language model reasons over this information to decide what to say or do next. The agent can use [tools](<https://code.visualstudio.com/docs/agents/concepts/tools>) to gather more context, take actions, and evaluate the results. This article explains how VS Code assembles and discovers context, and how to work within context window limits.

## Why context matters

A prompt with relevant files, clear instructions, and focused history produces better results than a vague prompt with no context. The language model can only reason over information included in its current context.

You don't need to identify every relevant file before you start. During the [agent loop](<https://code.visualstudio.com/docs/agents/concepts/agents#_agent-loop>), the agent can search your workspace, read files, run commands, and add the results to the context for its next step. Explicit references are useful when you already know which information the agent should consider.

Conversation history is scoped to a chat and isn't automatically shared with other chats or sessions. Context can be passed explicitly, such as in a delegated task or a [handoff](<https://code.visualstudio.com/docs/agents/concepts/sessions#_hand-off-a-session>). Persistent sources, such as [custom instructions](<https://code.visualstudio.com/docs/agent-customization/custom-instructions>) or [agent memory](<https://code.visualstudio.com/docs/agents/concepts/agents#_memory>), can also provide information across conversations.

## How VS Code assembles context

Each time the agent sends a request to the language model, VS Code assembles a prompt from multiple sources:

![Diagram showing the context window as a container with seven layers: system instructions, customizations, user message, conversation history, implicit context, explicit references, and tool outputs, with an arrow sending the assembled prompt to the language model.](<https://code.visualstudio.com/assets/docs/agents/concepts/context-assembly.png>)

* **System instructions**: built-in guidelines that define the agent's behavior.
* **Customizations**: AI customizations you set up, including custom agents, skills, and custom instructions.
* **User message**: the current request or follow-up message you send to the agent.
* **Conversation history**: the messages exchanged so far in the current chat.
* **Implicit context**: the file you're editing, your current selection, visible errors, and git state.
* **Explicit references**: files, editor context, web content, and other sources you reference with `#`-mentions.
* **Tool outputs**: results from file reads, terminal commands, codebase search results, and other tool calls during agent sessions.

The context changes as the agent works. For example, the output of a code search can lead the agent to read a file, and that file can then inform the next model request. Information that isn't included in a request is unavailable to the model, but the agent can use tools to discover and add more information.

## Workspace indexing

VS Code uses a semantic index to find code by meaning rather than only by exact keywords. The index helps the agent locate relevant snippets quickly, especially in a large codebase. It doesn't add your entire workspace to every model request.

VS Code builds and maintains the index automatically. If a semantic index isn't available yet, the agent can still find context by using text search, file search, and language intelligence.

Learn more about [workspace indexing](<https://code.visualstudio.com/docs/agents/reference/workspace-context>).

## Implicit context

VS Code uses your current activity to provide context to the prompt or suggest context you might add:

* The currently selected text in the active editor.
* The file name or notebook name of the active editor.
* When you use the **Ask** agent, the contents of the active file.
* When you use **Agent**, the active file as a suggested attachment that you can add to the context.

Implicit context reduces how much information you need to specify. If a particular source is important to the task, add it explicitly instead of relying on the agent to infer that it is relevant.

## Explicit context

Add explicit context when you want to ensure that the agent considers a specific file, folder, symbol, image, web page, or other source. Type `#` in the chat input to choose a context item, or select **Add Context** (`+` icon) in the chat input field.

Explicit context guides the agent toward relevant information but still counts toward the context window. Add only the sources that help the agent complete the current task. Learn more about [adding context to chat](<https://code.visualstudio.com/docs/chat/copilot-chat-context>).

Tip

Providing focused context up front might reduce the searches and file reads the agent needs, which can lower AI credit use. Avoid adding unrelated or large sources because they also consume context window tokens. Learn more about [optimizing AI credit usage](<https://code.visualstudio.com/docs/agents/guides/optimize-usage>).

## Context window and compaction

The context window is the maximum amount of information a language model can process in one request. The user message, conversation history, instructions, referenced files, and tool outputs all use space in this window.

When a conversation approaches the limit, VS Code automatically compacts older parts of the conversation into a summary. Compaction makes room for new information, but details from earlier messages might be summarized or omitted. You can also enter `/compact` in the chat input to compact the conversation manually.

Start a new session when you switch to an unrelated task. If an instruction should apply across requests or sessions, store it in [custom instructions](<https://code.visualstudio.com/docs/agent-customization/custom-instructions>) instead of relying on conversation history. Learn more about [managing conversation context](<https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#_compact-conversation-context>).

## Context isolation with subagents

An agent can delegate a focused task to a [subagent](<https://code.visualstudio.com/docs/agents/concepts/agents#_subagents>) that works in its own context and returns a result. This keeps intermediate work separate from the main conversation. Compaction, by contrast, summarizes content already in that conversation.

Context isolation is not code isolation. It doesn't by itself create a separate worktree or sandbox. An agent's access to files and tools depends on the [execution environment](<https://code.visualstudio.com/docs/agents/concepts/agent-harnesses#_relate-execution-environments-and-code-isolation>) and [permission controls](<https://code.visualstudio.com/docs/agents/concepts/trust-and-safety>).

Learn how to [delegate work to subagents](<https://code.visualstudio.com/docs/agents/run/subagents>).

## Working effectively with context

* **Describe the goal and constraints.** Explain the outcome you want and any requirements the agent should follow.
* **Let the agent discover context.** The agent can search your workspace and read related files as it works. You don't need to attach the entire codebase.
* **Reference important sources.** Explicitly add files, symbols, errors, or documentation that the agent must consider.
* **Keep each session focused.** Use a separate session for an unrelated task so that its history doesn't compete for context.

### How context improves a response

Consider asking an agent to explain how authentication works in your project.

Without relevant workspace context:

```
How does authentication work?
```

The model has no way to know which project you mean and gives a generic answer about authentication patterns.

After attaching `src/auth.ts` to the request as context:

```
Explain the authentication flow and identify where tokens are validated.
```

The referenced file gives the agent a starting point. The agent can then search for related code and explain the implementation with specific functions and configuration values.
