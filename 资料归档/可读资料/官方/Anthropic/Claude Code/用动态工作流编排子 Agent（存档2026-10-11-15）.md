# 通过动态工作流程大规模编排子代理

> 动态工作流程根据 Claude 编写的脚本编排许多子代理，并且您可以重新运行。将它们用于代码库审计、大型迁移和交叉检查研究。



**注释：**

动态工作流程适用于所有付费计划（具有 Anthropic API 访问权限）以及 Amazon Bedrock、Google Cloud 的 Agent 平台和 Microsoft Foundry。在 Pro 上，从 `/config` 中的动态工作流程行将其打开。


动态工作流程是一个 JavaScript 脚本，它可以同时协调许多 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>)。 Claude 为您描述的任务编写脚本，运行时在后台执行它，同时您的会话保持响应。

当一项任务需要的 agents 超出一个对话可以协调的范围时，或者当您希望将编排编码为可以读取和重新运行的脚本时，请使用工作流程。示例包括代码库范围内的错误扫描、500 文件迁移、需要相互交叉检查源的研究问题，以及值得在提交之前从多个独立角度起草的硬计划。

## 何时使用工作流程

[子代理](<https://code.claude.com/docs/en/sub-agents>)、[技能](<https://code.claude.com/docs/en/skills>)、[agent团队](<https://code.claude.com/docs/en/agent-teams>)和工作流都可以运行多步骤任务。区别在于谁持有该计划：

| |子代理|技能|Agent 团队|工作流程|
| :- | :- | :- | :- | :- |
|它是什么|生成一名工人 Claude|说明 Claude 如下|领导 agent 监督同行会议|运行时执行的脚本|
|谁决定接下来运行什么|Claude，依次|Claude，按照提示操作|领先 agent，依次|剧本|
|中间结果所在的地方|Claude 的上下文窗口|Claude 的上下文窗口|共享任务列表|脚本变量|
|什么是可重复的|工人的定义|说明|团队定义|编排本身|
|规模|每轮委派一些任务|与子代理相同|一些长期运行的同行|每次运行数十到数百个 agents|
|中断|重新开始回合|重新开始回合|队友继续奔跑|可在同一会话中恢复|

工作流程将计划转化为代码。对于子代理、技能和 agent 团队，Claude 是协调器：它轮流决定下一步生成或分配什么，每个结果都会进入上下文窗口。工作流脚本保存循环、分支和中间结果本身，因此 Claude 的上下文仅保存最终答案。

将计划转移到代码中还可以让工作流程应用可重复的质量模式，而不仅仅是运行更多 agents：它可以让独立的 agents 在报告之前对彼此的发现进行对抗性审查，或者从多个角度起草计划并相互权衡，这样您就可以获得比单次传递更可靠的结果。

## 运行捆绑的工作流程

查看正在运行的工作流程的最快方法是运行 `/deep-research`，[ 内置工作流程 ](<#捆绑的工作流程>) Claude Code 包括用于跨多个来源调查问题。您将看到 agents 在后台完成一系列阶段，同时您的会话保持空闲，并在最后获得一份报告，而不是逐个记录。



  

#### 运行工作流程

运行 `/deep-research` 并提出您想要调查的问题。它从多个角度展开网络搜索，获取并交叉检查找到的来源，并综合引用的报告。

    ```text wrap theme={null}
    /deep-research What changed in the Node.js permission model between v20 and v22?
    ```
  


  

#### 允许工作流程

Claude Code询问是否允许工作流程。选择**是**继续。具体提示取决于您的权限模式。有关每种模式的选项，请参阅 [在运行之前批准计划 ](<#在运行之前批准计划>)。
  


  

#### 观看进度

运行在后台开始。运行`/workflows`打开其进度视图：

    ```text wrap theme={null}
    /workflows
    ```

如果 `/workflows` 显示运行列表，请选择您刚刚开始的运行并按 Enter。该视图显示每个阶段及其 agent 计数。深入研究任何阶段以查看其 agents 以及每个阶段的发现。请参阅[观看跑步](<#观看跑步>)以了解全套控件。

您还可以从输入框下方的任务面板中进行观看：运行过程中会出现一行进度摘要。按向下箭头将其聚焦，然后按 Enter 展开。
  


  

#### 阅读报告

运行完成后，报告将显示在您的会话中。它引用了每个声明的来源，未通过交叉检查的声明已经被过滤掉。

当验证者 agents 无法检查声明时，例如在速率限制或 API 错误之后，报告会将该声明列为未经验证，而不是将其计为已驳斥。
  


要为您自己的任务运行工作流程，[让Claude编写一个](<#让-claude-编写一个工作流程>)，一旦运行完成您想要的操作，您可以[将其保存](<#保存工作流程以供重复使用>)作为您自己的命令。

### 捆绑的工作流程

Claude Code 包括 `/deep-research` 作为内置工作流程：

|命令|它的作用|
| :- | :- |
| `/deep-research <question>` |从多个角度展开针对某个问题的网络搜索，获取并交叉检查其找到的来源，对每个声明进行投票，然后返回引用的报告，其中未通过交叉检查的声明将被过滤掉。需要 [WebSearch 工具 ](<https://code.claude.com/docs/en/tools-reference#websearch-tool-behavior>) 可用|

`/deep-research` 仅在您调用它时运行。

[您自己保存的工作流程](<#保存工作流程以供重复使用>)会以同样的方式成为命令，并与捆绑的流程一起出现在`/`自动完成中。

### 观看跑步

工作流程在后台运行，因此会话在 agents 工作时保持响应。随时运行 `/workflows` 以列出正在运行和已完成的工作流程，然后选择一个以打开其进度视图。当会话只有一次运行时，`/workflows` 会跳过列表并打开该运行。要停止列表中正在运行的工作流程而不打开它，请选择它并按 `x`。

进度视图显示每个阶段及其 agent 计数。页脚列出了每个操作的键：

|钥匙|行动|
| :- | :- |
| `↑` / `↓` |选择一个相或 agent|
|`Enter` 或 `→`|深入研究选定的阶段，然后深入研究 agent 的详细信息。详细信息，`Enter` 展开或折叠它|
|`Esc` 或 `←`|退出一级。在v2.1.203到v2.1.205中，`←`没有退出阶段或agent；在这些版本上使用 `Esc`|
| `j` / `k` |当 agent 详细信息溢出时，在其内滚动|
| `f` |按状态过滤所选阶段中的 agent 列表。再按一次即可循环|
| `p` |暂停或恢复运行|
| `x` |停止选定的 agent，或当焦点位于运行时停止整个工作流程|
| `r` |重新启动选定的运行agent|
| `s` |[将](<#保存工作流程以供重复使用>)运行脚本保存为命令|

agent 详细信息列出了 agent 的提示、其最近的工具调用及其结果。每个调用都会显示其状态，例如仍在运行或失败。当 agent 保留自己的任务列表时，也会显示详细信息以及每个任务的状态。

按`Enter`展开详细信息。然后，提示和结果会完整显示，并且每个列出的调用都会显示其输入及其结果的开头。

## 让 Claude 编写一个工作流程

您可以让 Claude 通过两种方式为您的任务编写工作流程：

* [在提示中请求工作流程](<#在提示中询问工作流程>)，可以用您自己的话，也可以通过包含关键字`ultracode`，然后Claude为该任务编写一个工作流程。
* [让Claude用超码决定](<#让-claude-用超码来决定>)：设置`/effort ultracode`和Claude为会话中的每个实质性任务规划工作流程。

您还可以运行已存在的工作流程命令：[捆绑的工作流程](<#捆绑的工作流程>)（例如`/deep-research`），或您已[保存的工作流程](<#保存工作流程以供重复使用>)。

### 在提示中询问工作流程

要作为工作流运行单个任务而不更改会话的工作级别，请在提示中包含关键字 `ultracode`。用您自己的话询问，例如“使用工作流程”或“运行工作流程”，也有效：Claude 将直接请求视为相同的选择加入。

```text wrap theme={null}
ultracode: audit every API endpoint under src/routes/ for missing auth checks
```

Claude Code 突出显示输入中的关键字，Claude 为任务编写工作流程脚本，而不是依次执行它。该关键字仅选择 Claude 如何构建工作：agents' 工具调用与会话中的任何其他工具调用一样接收相同的权限检查和 [ 沙箱 ](<https://code.claude.com/docs/en/sandboxing>)。

如果运行符合您的要求，您可以随后[将其保存为命令](<#保存工作流程以供重复使用>)。如果您已经有以其他方式构建的编排器，例如子代理提示的文件夹或粉丝练习的技能，您可以将 Claude 指向它并请求执行相同操作的工作流程。

#### 忽略或关闭关键字

如果您不想启动工作流程，请在 Windows 和 Linux 上的 macOS 或 `Alt+W` 上按 `Option+W` 以消除此提示的突出显示，或者在 cursor 位于突出显示的关键字之后时按退格键。要完全阻止关键字触发，请在 `/config` 中关闭 Ultracode 关键字触发。

#### 关键字起作用的地方

该关键字仅在您自己键入的提示中是选择加入：在交互式提示中、在 IDE 扩展面板中、在 [ 远程控制 ](<https://code.claude.com/docs/en/remote-control>) 客户端中或在将键盘输入的 [`origin`](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkmessageorigin>) 标记为的 Agent SDK 应用程序中`{ kind: "human" }`。当它以另一种方式到达会话时，它不会启动工作流：

* 提示通过 `-p`
* Agent SDK 应用程序发送的提示，但未将其标记为人工输入
* 计划任务提示
* 转发到对话中的 Webhook 有效负载或拉取请求评论



**注释：**

在 v2.1.210 之前，关键字也从任何这些路由启动工作流程，包括转发到对话中的 Webhook 负载或拉取请求评论。


### 让 Claude 用超码来决定

Ultracode 是一种 Claude Code 设置，可在会话运行的 [ 工作级别 ](<https://code.claude.com/docs/en/model-config#adjust-effort-level>) 上打开会话的自动工作流程编排。有了它，Claude 就会为每项实质性任务规划工作流程，而不是等待您提出要求。在 Claude Code 提示符下将其打开：

```text wrap theme={null}
/effort ultracode
```

要在已启用超码的情况下启动会话，请使用 `claude --effort ultracode` 启动，这也会将工作级别设置为 `xhigh`。需要 Claude Code v2.1.203 或更高版本。

要从 `/effort` 滑块打开它，请按 `Tab` 翻转 **Ultracode** 切换，然后按 `Enter` 应用它。 [调整努力级别](<https://code.claude.com/docs/en/model-config#adjust-effort-level>)列出了打开超级代码的路线。

启用超级代码后，Claude 决定任务何时需要工作流程。一个请求可以连续变成多个工作流程：一个用于理解代码，一个用于进行更改，一个用于验证代码。这适用于会话中的每个任务，因此每个请求使用更多令牌，并且比没有工作流的相同请求花费更长的时间。在订阅计划中，这些令牌会利用您的使用限制，因此启用超码的会话比关闭超码的会话更快达到会话或每周限制。

打开超级代码已经选择您进行大规模运行，因此这些检查在其打开时不适用：

* [`Large workflow` 警告 ](<#成本>) 不会出现在工作流程运行中
* 使用 Agent 工具生成的子代理 Claude 不会强制执行会话的 [ 并发子代理限制 ](<https://code.claude.com/docs/en/sub-agents#concurrent-subagent-limit>)
* 在自动权限模式下，系统不会要求您[批准首次工作流程启动](<#在运行之前批准计划>)

`/effort ultracode` 持续当前会话；要让每个会话都以此开始，请设置 [`ultracode`](<https://code.claude.com/docs/en/settings-reference#ultracode>) 设置。将其关闭 `/effort ultracode off` 当你回到日常工作时。的 `/effort` 滑块仅提供切换功能 [当超码可用时](<https://code.claude.com/docs/en/model-config#when-ultracode-is-available>).

### 在运行之前批准计划

在 CLI 中，每次运行提示显示计划的阶段和这些选项：

* **是，运行它**：开始运行
* **是的，并且不再询问`<path>`**中的`<name>`：启动，并从现在起跳过此项目中此工作流程的提示。当您按名称运行捆绑、保存或插件工作流程时，Claude Code 提供此选项，而不是为当前任务编写的脚本 Claude 提供此选项。
* **查看原始脚本**：先阅读脚本再决定
* **否**：取消

`Ctrl+G` 在编辑器中打开脚本。选择**是，运行它**或**否**，按`Tab`到[添加评论](<https://code.claude.com/docs/en/permissions#add-a-comment-when-you-answer-a-permission-prompt>)到您的答案。

是否看到此提示取决于您的[权限模式](<https://code.claude.com/docs/en/permission-modes>)：

|权限模式|当系统提示您时|
| :- | :- |
|汽车|仅首次启动。任何 ** 是 ** 在您的用户设置中记录同意，稍后启动时不会出现提示。当超级代码开启时完全跳过|
|手动，接受编辑|每次运行，除非您已选择 ** 是，并且不再询问 ** 本项目中的该工作流程|
|绕过权限|Claude Code 不会提示您。跑步立即开始|
| `claude -p`, Agent SDK |Claude Code 不提示您|

在`claude -p`和AgentSDK中，Claude Code从不显示此提示。它通过与会话的其余部分相同的 [ 权限评估 ](<https://code.claude.com/docs/en/agent-sdk/permissions#how-permissions-are-evaluated>) 运行工作流工具调用，因此拒绝规则、询问规则和 `dontAsk` 模式适用于启动，就像它们适用于每个工具调用一样。要让工作流程在这些运行中启动，请使用以下选项之一：

* **权限规则**：允许规则中的`Workflow`批准每个工作流程，`Workflow(<name>)`按名称批准一个已保存的工作流程。
* **自动许可模式**：[分类器](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>)审查呼叫并可以批准它。
* **绕过权限模式**：Claude Code批准呼叫。
* **钩子**：允许调用批准的[`PreToolUse`](<https://code.claude.com/docs/en/hooks#pretooluse>)钩子。
* **您的主机**：[`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>)，或者使用Agent SDK，[`canUseTool`](<https://code.claude.com/docs/en/agent-sdk/permissions>)回调批准它。

在桌面应用程序中，审批卡显示工作流名称、阶段列表和令牌使用警告，以及 **Once**、**Always** 和 **Deny** 操作。进度视图显示在后台任务侧窗格中。

工作流生成的子代理使用您的 [ 权限规则 ](<https://code.claude.com/docs/en/settings-reference#permission-settings>)，并且 Claude Code 根据 [ 子代理在 ](<https://code.claude.com/docs/en/sub-agents#permission-modes>) 中运行的权限模式下的规则选择其权限模式。为了避免长时间运行时出现提示，请在开始之前将 agents 所需的工具添加到您的允许规则中。

### 保存工作流程以供重复使用

当 Claude 为您将重复的任务编写工作流程时，您可以将该运行的脚本保存为命令。像在每个分支上运行的审核这样的流程每次都会运行相同的编排。

运行`/workflows`，选择要保留的运行，然后按`s`。在保存对话框中，按 Tab 键在两个保存位置之间切换：

* `.claude/workflows/` 在您的项目中：与克隆存储库的每个人共享
* `~/.claude/workflows/` 在您的主目录中：在每个项目中都可用，仅对您可见。如果设置[`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>)，则该位置是该路径下的`workflows/`目录。

保存对话框显示个人位置的解析路径。

按 Enter 保存。工作流在未来的会话中从任一位置作为 `/<name>` 运行。

Claude Code 在写入之前检查符号链接的保存位置，并显示错误而不是直接写入。它检查的内容取决于您保存的位置：

* 项目位置：如果 `.claude`、`.claude/workflows` 或目标文件是符号链接，则 Claude Code 会拒绝。
* 个人位置：仅当目标文件本身是符号链接时，Claude Code 才会拒绝，因此由 dotfiles 工具管理的 `~/.claude` 目录仍然有效。

在v2.1.216之前，Claude Code点击了链接，这可能会将文件放置在您选择的位置之外。

在具有多个 `.claude/` 目录的 monorepo 中，您可以将工作流程与其应用的包一起保留。保存到项目位置会写入工作目录和存储库根目录之间已存在的最近的 `.claude/workflows/` 目录，如果尚不存在，则写入存储库根目录。项目工作流程也会从该路径上的每个 `.claude/workflows/` 加载，并且当多个定义相同名称时 Claude Code 运行最接近工作目录的一个。

如果项目工作流程和个人工作流程共享名称，则项目运行。

### 在插件中分发工作流程

要跨团队或存储库共享工作流程，请将其包含在 [ 插件 ](<https://code.claude.com/docs/en/plugins/overview>) 中。将脚本放置在插件根目录的 `workflows/` 目录中，或使用 [`workflows` 清单字段 ](<https://code.claude.com/docs/en/plugins/manifest-reference#fields>) 指向不同的位置。

插件工作流程由插件名称命名。名为 `acme-tools` 的插件包含 `meta.name` 为 `release-audit` 的脚本，以 `/acme-tools:release-audit` 运行。

### 将输入传递到已保存的工作流程

保存的工作流程可以通过 `args` 参数接受输入。该脚本将其读取为名为 `args` 的全局变量。使用它在调用时提供研究问题、目标路径列表或配置对象，而不是为每次运行编辑脚本。

以下提示运行已保存的工作流程以及问题编号列表：

```text wrap theme={null}
Run /triage-issues on issues 1024, 1025, and 1030
```

Claude 将列表作为结构化数据传递，因此脚本可以直接调用 `args` 上的数组和对象方法，而无需先解析它。如果省略 `args`，则脚本内的全局为 `undefined`。

## 工作流程提示示例

当任务大于上下文中可以容纳的 agent 时，或者当同一步骤需要跨多个项目运行时，工作流最适合。下面的提示显示了常见的形状。每个人都要求 Claude 为该任务编写并运行工作流程；你自己不写脚本。

### 审核多个文件是否存在同一问题

每个文件扇出一个 agent，然后收集并验证结果。

```text wrap theme={null}
use a workflow to audit every route handler under src/routes/ for missing authentication checks, and adversarially verify each finding before reporting it
```

### 继续修复直到检查通过

运行检查器，修复失败的问题，然后重复，直到通过或停止进展。

```text wrap theme={null}
use a workflow to run npx tsc --noEmit and keep fixing the reported errors until the type check passes or two rounds in a row make no progress
```

### 并行迁移许多文件

发现要迁移的文件，将每个文件转换为独立的副本，以便编辑不会发生冲突，并验证每个结果。

```text wrap theme={null}
use a workflow to migrate every component under src/components/ from JavaScript to TypeScript, working on each file in its own isolated copy
```

### 检查每个更改的文件并写一份摘要

每个文件运行一个审阅者，然后将所有结果传递给一个 agent，对它们进行排名和删除重复。

```text wrap theme={null}
use a workflow to review every file changed in this PR for correctness issues, then merge the per-file findings into one ranked summary
```

### 通过多种来源研究一个主题

将读者分散到变更日志、问题和文档中，然后进行综合。捆绑的 `/deep-research` 工作流程可以执行此操作；您还可以描述一个更窄的版本。

```text wrap theme={null}
use a workflow to research how our three competitors handle rate limiting: read their public docs and recent changelog entries in parallel, then compare the approaches
```

### 查找问题，直到列表停止增长

继续进行轮次搜索，当新轮次没有发现任何新内容时就停止。

```text wrap theme={null}
use a workflow to find flaky tests in this repo: run the suite repeatedly, record which tests fail intermittently, and stop once two rounds in a row find nothing new
```

### 保存的脚本是什么样子的

当您[保存工作流程](<#保存工作流程以供重复使用>)时，`.claude/workflows/`中的文件包含一个`meta`块，后跟一个编排子代理的脚本主体。您通常不需要编辑它，但这是一个小形状，以便您可以识别 Claude 生成的内容：

```javascript theme={null}
export const meta = {
  name: 'audit-routes',
  description: 'Audit every route handler for missing auth checks',
}

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
})

const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }),
)

return audits.filter(Boolean)
```

机身为素色【JavaScript】，顶级【`await`】。 `agent()` 生成一个子代理，`pipeline()` 为列表中的每个项目运行一个子代理，`parallel()` 同时运行一组 agent 任务并等待所有这些任务。

安 `agent()` 调用解析为 `null` 如果你在运行中停止或者它遇到了不可恢复的情况 API 错误。 `pipeline()` 保留每个 `null` 在结果数组中，这就是示例以以下结尾的原因 `.filter(Boolean)` 删除这些条目，包括插槽 [一个 agent 每次尝试都停滞不前](<#当-agent-停止并重新启动时>).

在 [ 自动模式 ](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) 中，当分类器检查该子代理的操作时，脚本传递给 `agent()` 的提示不会被视为来自您的请求，因为 Claude Code 将其标记为脚本计算的文本。

如果您在 `agent()` 调用上传递 `schema`，则该子代理将返回与形状匹配的 JSON，而不是散文。 Claude Code 在启动子代理之前检查模式：当它可以证明模式与自身相矛盾时，调用会失败并出现命名矛盾的错误，并且子代理永远不会启动。它可以证明的一个矛盾是`required`密钥被`additionalProperties: false`排除。

如果子代理的输出在五次尝试后仍然无法通过验证，则调用将失败并显示包含最后一次验证失败的错误。要更改尝试次数，请设置 [`MAX_STRUCTURED_OUTPUT_RETRIES`](<https://code.claude.com/docs/en/env-vars>)。

### 编辑已保存的脚本

要更改您保存的 [ 工作流程 ](<#保存工作流程以供重复使用>)，请编辑其 `.js` 文件或要求 Claude 进行更改。在编辑或询问之前，请运行`/workflow-authoring` [捆绑技能](<https://code.claude.com/docs/en/skills#bundled-skills>)来加载脚本编写参考Claude的工作来源。该技能需要 Claude Code v2.1.248 或更高版本。

要在当前会话中运行编辑后的版本，请运行 [`/reload-skills`](<https://code.claude.com/docs/en/commands#all-commands>) 重新读取工作流目录，然后再次运行 `/<name>`。

Claude Code 在加载和运行脚本时将这些规则应用于文件的每个部分：

* **`meta`块**：将`export const meta`保留为第一个语句，并将其保留为带有`name`和`description`的普通对象文字。如果它包含文字值以外的任何内容，例如变量、函数调用或展开，则 Claude Code 会从 `/` 自动完成中删除 `/<name>`。
* **Body**：除了`agent()`、`pipeline()`和`parallel()`之外，还可以调用`phase()`将进度视图中标题下的agents分组，调用`log()` 在阶段上方显示消息，并读取 [`args`](<#将输入传递到已保存的工作流程>) 全局。如果正文存在语法错误，Claude Code 会在您运行工作流程时报告该错误。
* **`phases`**：如果您在 `meta` 中列出它们，请为每个条目提供您传递给 `phase()` 的标题。没有条目的 `phase()` 标题会获得自己的进度组。
* **时间戳和随机性**：Claude Code使`Date.now()`、`Math.random()`和无参数`new Date()`抛出脚本内，以便重新启动[ run](<#暂停后继续>) 重复相同的 `agent()` 调用。通过 `args` 传递时间戳。

您还可以编辑[单次运行的脚本](<#工作流程如何运行>)而不是保存的副本。 [暂停后恢复](<#暂停后继续>)涵盖了当您重新启动已编辑的脚本时再次运行的agents。有关工作流工具的输入，请参阅 [Agent SDK 参考文献 ](<https://code.claude.com/docs/en/agent-sdk/typescript#workflow>) 中的条目。

## 工作流程如何运行

工作流运行时在独立于您的对话的隔离环境中执行脚本。中间结果保留在脚本变量中，而不是登陆到 Claude 的上下文中。

每次运行都会将其脚本写入会话目录 `~/.claude/projects/` 下的文件中。 Claude 在运行开始时收到路径，因此您可以询问它。您可以打开该文件来读取 Claude 编写的编排，将其与之前运行的脚本进行比较，或者对其进行编辑并要求 Claude 从编辑后的版本重新启动。

Claude 只能从会话已允许读取的脚本文件启动工作流程。要运行保存在工作目录之外的脚本，请首先使用 [`/add-dir`](<https://code.claude.com/docs/en/permissions#working-directories>) 或 [ 读取允许规则 ](<https://code.claude.com/docs/en/permissions#read-and-edit>) 添加其目录。

随着运行的进行，运行时会跟踪每个 agent 的结果，这使得运行 [ 可在同一会话中恢复 ](<#暂停后继续>)。

### 在扇出中提示缓存

Agents在同一次运行中可以读取对方的[提示缓存](<https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache>)。使用相同模型、工作级别、agent 类型、工具、输出模式和工作目录运行的两个 agents 构建相同的工具和系统提示前缀，因此在匹配同级的响应开始后启动的 agent 在其第一个请求时读取该同级的缓存。

工作流 agent 的请求不在主对话的 [ 缓存 TTL 存储桶 ](<https://code.claude.com/docs/en/prompt-caching#which-ttl-each-request-gets>) 范围内，因此其缓存默认保留五分钟，包括在 Claude 订阅上。要保留一小时，请将 [`subagentPromptCacheTtl`](<https://code.claude.com/docs/en/settings-reference#subagentpromptcachettl>) 设置为 `1h`。 API 以更高的速率计费 1 小时的缓存写入。

当扇出同时启动多个匹配的 agents 时，Claude Code 将保留除第一个之外的所有内容，直到第一个 agent 的响应开始，然后一起释放所保留的 agents，以便它们的第一个请求读取共享前缀，而不是每次都处理未缓存的前缀。 Claude Code 将保持上限限制为 [`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`](<https://code.claude.com/docs/en/env-vars>) 毫秒，默认为 `5000`。将其设置为 `0` 以禁用保持。

### 行为和限制

运行时应用以下约束：

|约束|为什么|
| :- | :- |
|没有中间运行用户输入|仅当出现 agent 权限提示和 [ 使用限制等待 ](<#当跑步达到您的使用限制时>) 时，运行才会自行暂停。对于阶段之间的签核，将每个阶段作为自己的工作流程运行|
|工作流程本身无法直接访问文件系统或 shell|Agents 读取、写入和运行命令。该脚本协调 agents|
|没有模块加载：包含 `import()` 的脚本在运行开始之前失败|脚本主体很简单JavaScript。将需要库的工作放入 agent 的任务中|
|默认情况下，最多 16 并发 agents，当 Claude Code 可用 CPU 较少时，并发数量会更少，包括在 CPU- 有限容器内。要更改限制，请将 [`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`](<https://code.claude.com/docs/en/env-vars#variables>) 设置为 1 到 256 之间的值，这需要 Claude Code v2.1.269 或更高版本|限制本地资源的使用|
|在扇出中，共享第一个 agent 的提示缓存前缀的 agents 默认在其后 5 秒启动|除了第一个读取 [ 前缀之外的所有内容都将第一个 agent 缓存](<#在扇出中提示缓存>)，而不是每次处理它时都未缓存|
|单个 `parallel()` 或 `pipeline()` 调用中最多 4,096 项：运行时拒绝更长的列表并出现错误|静默上限会在不告诉脚本的情况下减少部分工作负载|
|1,000 agents 每次运行总计|防止失控循环|

## 管理运行

运行开始后，您可以从 `/workflows` 视图进行管理，或者通过在输入框下方的任务面板中展开其进度线来管理它。

当您停止运行时，它会保留在任务面板中，而其任何 agents' 进程仍在运行。如果您再次停止它，Claude Code 会重新向这些进程发出信号。

### 暂停后继续

恢复暂停的跑步 `/workflows` 通过选择它并按 `p`。对于您停止的跑步，询问 Claude 使用相同的脚本重新启动工作流程。如果 agents 从停止的运行中还没有退出， Claude Code 拒绝重新启动，直到他们重新启动，所以这些的第二个副本 agents 不能和他们一起跑。

Claude Code 按照 agents 开始的顺序重播运行，每个 agent 要么返回其保存的结果，要么再次运行：

* **已完成**：返回其保存的结果。第一个 agent 的提示与之前的运行不同，因为您编辑了脚本或之前的 agent 返回了不同的内容，再次运行，之后的每个 agent 也是如此，即使是那些已完成的。
* **停止时仍在运行**：重新开始。停止整个运行不会将任何 agent 视为失败。
* **失败**：再次运行，之后开始的每个agent也是如此，甚至是那些已完成的。通过在[`/workflows`](<#观看跑步>)中选择它并按`x`单独停止一个agent，算作失败。

最后一种情况意味着扇出重新运行已完成的工作时发生故障。如果脚本按顺序启动 A、B、C 和 D，并且 B 失败，则重新启动会从缓存中返回 A，并再次运行 B、C 和 D。

您可以在同一 Claude Code 会话中恢复运行。当您离开会话时，正在运行的工作流程会发生什么情况取决于您离开的方式：

* 如果您 [ 将会话 ](<https://code.claude.com/docs/en/agent-view#what-carries-over-when-you-background>) 置于后台，Claude Code 将以相同方式在后台会话中重播运行并继续。
* 如果在工作流程正在运行且 [agent 视图处于 ](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>) 上时退出 Claude Code，则退出对话框将提供 `Move to background and exit`，它以相同的方式进行运行。如果您选择 `Exit and stop tasks`，或者未提供该选项，则运行将随会话停止。 Claude Code 将运行保存的结果保留在 `~/.claude/projects/` 中该会话的目录下，因此当您要求 Claude 重新启动工作流程时，您使用 `claude --resume` 恢复的会话可以重播这些结果。在您重新开始的会话中，Claude 没有之前的运行需要重新启动，并作为新运行启动工作流程。

在 [ 云会话 ](<https://code.claude.com/docs/en/claude-code-on-the-web>) 中，Claude Code 还会将运行结果与会话的对话历史记录一起保存，这些历史记录在会话的 VM 被回收时仍然存在。当您[重新打开此类会话](<https://code.claude.com/docs/en/claude-code-on-the-web#environment-expired>)并要求Claude重新启动工作流程时，已完成的agents仍返回其保存的结果。

在本地和云会话中，当 Claude 重新启动较早的运行并且 Claude Code 根本找不到该运行的已保存结果时，重新启动会失败并出现 `nothing to resume` 错误，而不是自行开始运行。要求 Claude 重新启动工作流程作为新的运行。

### 当跑步达到您的使用限制时

当 agent 达到 claude.ai [ 使用限制 ](<https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset>) 时，运行会暂停而不是失败 agent：达到限制的 agents 等待重置，并且不会启动新的 agents。限制重置后不久，等待的 agents 再次运行，并且运行自行继续。需要 Claude Code v2.1.271 或更高版本；在早期版本中，受影响的 agents 会失败。

当运行等待时，任务面板中的进度线和 [`/workflows`](<#观看跑步>) 标题会在限制重置时显示。

仅当所有这些都成立时，运行才会暂停；如果不这样做，受影响的 agent 就会失败：

* 该会话是交互式的，并使用 claude.ai 订阅登录。跑步不会暂停 [非交互模式](<https://code.claude.com/docs/en/headless>) 与 `claude -p` 或 [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>)，在一个 [后台会话](<https://code.claude.com/docs/en/agent-view>)，或者在一个 [远程控制](<https://code.claude.com/docs/en/remote-control>) 或 [agent 团队](<https://code.claude.com/docs/en/agent-teams>) 队友会议。
* [`autoContinueAtUsageLimit`](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>) 已打开，与让会话本身 [ 等待使用限制重置的设置相同 ](<https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset>)。如果在等待期间将其关闭，则等待结束并且等待agents失败。
* 限制会在 24 小时内重置。每周的限制可以进一步重置。
* 跑步还没等两次。当第三次达到限制时，agent失败。

### 当 agent 停止并重新启动时

输出停止到达足够长的时间的 agent 从相同的提示重新开始。在[`/workflows`](<#观看跑步>)中，其名称获得`(retry 1)`后缀，其详细信息显示`attempt 2 (stalled)`。重新启动是自动的，因此您无需执行任何操作。

新的尝试开始时没有停止的尝试的记录。已停止的尝试已更改的文件仍保持更改，并且其花费的令牌仍保留在运行总数中。停顿窗口是 Claude Code 在结束尝试之前等待 agent 输出的时间。 agent 等待其自己的工具调用或 [ 使用限制重置 ](<#当跑步达到您的使用限制时>) 所花费的时间不计入停顿窗口。

agent 最多重新启动五次，计算您使用 `r` 请求的重新启动。如果第六次尝试也停止，则 `agent()` 调用失败，并且错误的开头说明了原因：

* `agent stalled on all 6 attempts`：每次尝试都经过整个窗口而没有输出。如果agent的工作让它沉默了那么久，就拉长窗口
* `agent lost its reply on all 6 attempts`：每次尝试的响应流都变得沉默，Claude Code放弃等待。延长停顿窗口并没有帮助，因为 [ 流空闲看门狗 ](<https://code.claude.com/docs/en/network-config#streaming-idle-watchdogs>) 首先结束了响应，并且 `CLAUDE_STREAM_IDLE_TIMEOUT_MS` 设置了该看门狗的超时
* `agent abandoned after 6 attempts`：尝试以不同的方式结束，错误按顺序列出

要在窗口结束之前给予 agent 更多时间来生成输出：

* **一个agent**：在其`agent()`调用上以毫秒为单位传递`stallMs`，例如`agent(prompt, { stallMs: 1800000 })`持续30分钟
* **Every agent**：设置[`CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`](<https://code.claude.com/docs/en/env-vars#variables>)，这也适用于工作流程之外的子代理

失败后是否继续运行取决于您的脚本如何调用agent：

* **在[`parallel()`或`pipeline()`](<#保存的脚本是什么样子的>)**内：运行以`null`代替agent的结果进行
* **直接等待**：运行因错误而结束

要重试，请要求 Claude 重新启动工作流程。 [暂停后恢复](<#暂停后继续>)涵盖再次运行的内容。

### 成本

工作流程会产生许多 agents，因此单次运行可以使用比在对话中完成相同任务更多的令牌。运行次数计入您的计划的使用量和速率限制。

要在提交大型任务之前衡量支出，请首先在一小部分上运行工作流程：一个目录而不是整个存储库，或者一个狭窄的问题而不是广泛的问题。 `/workflows` 视图显示每个 agent 在运行过程中的令牌使用情况，您可以随时在那里停止运行，通常不会丢失已完成的工作。 [暂停后恢复](<#暂停后继续>)涵盖了停止运行所保留的内容。运行时的 [agent caps](<#行为和限制>) 限制单次运行可以生成的 agents 数量，这限制了失控脚本的成本。要减少运行次数 agents，请选择 `small` [ 大小准则 ](<#设定尺寸指南>)。

Claude Code 还标记了异常大的运行。当工作流计划的时间超过 25 agents，或其预计令牌总数超过 1.5 万时，输入框下方任务面板中的进度线会显示 `Large workflow` 警告。该警告会将您指向 [`/workflows`](<#观看跑步>)，您可以在其中停止运行。

该警告是建议性的：它不会暂停或限制运行。当您看到它时，两个设置会发生变化：

* 如果您自己选择 [ 大小准则 ](<#设定尺寸指南>)，则其 agent 计数将替换 25-agent 阈值。内置默认准则将阈值保留在 25。
* 启用 [ultracode](<#让-claude-用超码来决定>) 的会话不会显示警告，因为打开 ultracode 已经让您选择进行大规模运行。

Claude Code 选择每个工作流程 agent的型号相同 [用于子代理的顺序](<https://code.claude.com/docs/en/sub-agents#choose-a-model>)。阶段的脚本命名的模型按该顺序算作每次调用模型。当没有其他东西分配时， agent 在您的会话模型上运行。

控制模型成本：

* 如果您通常切换到较小的型号进行日常工作，请在大型跑步之前检查 `/model`
* 在描述任务时，要求 Claude 对不需要最强模型的阶段使用较小的模型

当您的组织的 [`availableModels` 允许名单](<https://code.claude.com/docs/en/model-config#restrict-model-selection>) 阻止脚本请求的模型 agent, 那 agent 相反，在替代模型上运行，遵循相同的规则 [作为子代理的替换规则](<https://code.claude.com/docs/en/sub-agents#choose-a-model>).

### 设定尺寸指南

大小指南告诉 Claude 在编写动态工作流程时要瞄准多少 agents。 Claude Code 将指南发送到 Claude 作为建议，而不是上限，因此要求不同比例的提示仍然会覆盖它。需要 Claude Code v2.1.202 或更高版本。

每个值映射到一个 agent 计数：

|价值|Agent计数Claude以|
| :- | :- |
| `unrestricted` |无指导：Claude 根据任务调整工作流程|
| `small` |小于 5 agents|
| `medium` |小于 10 agents|
| `large` |小于 50 agents|

当您使用 Claude Code v2.1.271 或更高版本登录 Pro 套餐时，默认值为 `medium` 或 `small`。在您选择值之前，`/config` 行会将该值标记为默认值，工作流程的 `Running in background` 行会命名有效的大小。需要 Claude Code v2.1.219 或更高版本；早期版本默认为 `unrestricted`。

要更改准则，请在 `/config` 中为动态工作流程大小设置选择一个值，或运行 `/config workflowSizeGuideline=small`。在v2.1.219及更高版本上，您还可以在任何设置文件中设置[`workflowSizeGuideline`键](<https://code.claude.com/docs/en/settings-reference#workflowsizeguideline>)；该值优先于 `/config`，并且 Claude Code 隐藏 `/config` 行，而设置文件提供了这一行。

更改将在下一个提示时生效。无论设置如何，[运行时agent上限](<#行为和限制>)仍然适用。

### 关闭工作流程

工作流程可在 CLI、桌面应用程序、IDE 扩展、[非交互模式 ](<https://code.claude.com/docs/en/headless>) 和 `claude -p` 以及 [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) 中使用。相同的禁用设置适用于每个表面。

要自行关闭工作流程：

* 在 `/config` 中关闭动态工作流程。跨会话持续存在。
* 在`~/.claude/settings.json`中设置`"disableWorkflows": true`。跨会话持续存在。
* 设置`CLAUDE_CODE_DISABLE_WORKFLOWS=1`。在启动时读取，因此它适用于您设置的任何位置。

要关闭整个组织的工作流程，请在 [ 托管设置 ](<https://code.claude.com/docs/en/server-managed-settings>) 中设置 `"disableWorkflows": true`，或使用 [Claude Code 管理设置 ](<https://claude.ai/admin-settings/claude-code>) 页面上的开关。

当工作流程被禁用时：

* `/workflows`、工作流命令和`/workflow-authoring`技能不可用
* `ultracode` 关键字不再触发运行，并且 **Ultracode** 切换已从 `/effort` 中删除

已经在进行的跑步仍在继续。

关闭工作流程也会使 [ultracode](<#让-claude-用超码来决定>) 不可用。没有托管设置单独排除超级代码：无论[可用](<https://code.claude.com/docs/en/model-config#when-ultracode-is-available>)，用户都可以使用`/effort ultracode`将其打开。 [ 工作量上限 ](<https://code.claude.com/docs/en/model-config#organization-effort-limits>) 会降低运行超码的会话的工作量级别，但不会关闭超码。

# Orchestrate subagents at scale with dynamic workflows

> Dynamic workflows orchestrate many subagents from a script Claude writes and you can rerun. Use them for codebase audits, large migrations, and cross-checked research.



**注释：**

  Dynamic workflows are available on all paid plans, with Anthropic API access, and on Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry. On Pro, turn them on from the Dynamic workflows row in `/config`.


A dynamic workflow is a JavaScript script that orchestrates many [subagents](<https://code.claude.com/docs/en/sub-agents>) at once. Claude writes the script for the task you describe, and a runtime executes it in the background while your session stays responsive.

Reach for a workflow when a task needs more agents than one conversation can coordinate, or when you want the orchestration codified as a script you can read and rerun. Examples include a codebase-wide bug sweep, a 500-file migration, a research question that needs sources cross-checked against each other, and a hard plan worth drafting from several independent angles before you commit to one.

## When to use a workflow

[Subagents](<https://code.claude.com/docs/en/sub-agents>), [skills](<https://code.claude.com/docs/en/skills>), [agent teams](<https://code.claude.com/docs/en/agent-teams>), and workflows can all run a multi-step task. The difference is who holds the plan:

| | Subagents | Skills | Agent teams | Workflows |
| :- | :- | :- | :- | :- |
| What it is | A worker Claude spawns | Instructions Claude follows | A lead agent supervising peer sessions | A script the runtime executes |
| Who decides what runs next | Claude, turn by turn | Claude, following the prompt | The lead agent, turn by turn | The script |
| Where intermediate results live | Claude's context window | Claude's context window | A shared task list | Script variables |
| What's repeatable | The worker definition | The instructions | The team definition | The orchestration itself |
| Scale | A few delegated tasks per turn | Same as subagents | A handful of long-running peers | Dozens to hundreds of agents per run |
| Interruption | Restarts the turn | Restarts the turn | Teammates keep running | Resumable in the same session |

A workflow moves the plan into code. With subagents, skills, and agent teams, Claude is the orchestrator: it decides turn by turn what to spawn or assign next, and every result goes into a context window. A workflow script holds the loop, the branching, and the intermediate results itself, so Claude's context holds only the final answer.

Moving the plan into code also lets a workflow apply a repeatable quality pattern, not just run more agents: it can have independent agents adversarially review each other's findings before they're reported, or draft a plan from several angles and weigh them against each other, so you get a more trustworthy result than a single pass.

## Run a bundled workflow

The quickest way to see a workflow in action is to run `/deep-research`, the [built-in workflow](<#bundled-workflows>) Claude Code includes for investigating a question across many sources. You'll see agents work through a set of phases in the background while your session stays free, and get one report at the end instead of a turn-by-turn transcript.



  

#### Run the workflow

    Run `/deep-research` with a question you want investigated. It fans out web searches across several angles, fetches and cross-checks the sources it finds, and synthesizes a cited report.

    ```text wrap theme={null}
    /deep-research What changed in the Node.js permission model between v20 and v22?
    ```
  


  

#### Allow workflows

    Claude Code asks whether to allow the workflow. Select **Yes** to continue. The exact prompt depends on your permission mode. See [Approve the plan before it runs](<#approve-the-plan-before-it-runs>) for the per-mode options.
  


  

#### Watch progress

    The run starts in the background. Run `/workflows` to open its progress view:

    ```text wrap theme={null}
    /workflows
    ```

    If `/workflows` shows a list of runs instead, select the run you just started and press Enter. The view shows each phase with its agent count. Drill into any phase to see its agents and what each one found. See [Watch the run](<#watch-the-run>) for the full set of controls.

    You can also watch from the task panel below the input box: a one-line progress summary appears there while the run is going. Press the down arrow to focus it, then Enter to expand.
  


  

#### Read the report

    When the run finishes, the report appears in your session. It cites the sources each claim came from, with claims that didn't survive cross-checking already filtered out.

    When the verifier agents can't check a claim, such as after a rate limit or API error, the report lists that claim as unverified instead of counting it as refuted.
  


To run a workflow for your own task, [have Claude write one](<#have-claude-write-a-workflow>), and once a run does what you wanted you can [save it](<#save-the-workflow-for-reuse>) as a command of your own.

### Bundled workflows

Claude Code includes `/deep-research` as a built-in workflow:

| Command | What it does |
| :- | :- |
| `/deep-research <question>` | Fans out web searches on a question across several angles, fetches and cross-checks the sources it finds, votes on each claim, and returns a cited report with claims that didn't survive cross-checking filtered out. Requires the [WebSearch tool](<https://code.claude.com/docs/en/tools-reference#websearch-tool-behavior>) to be available |

`/deep-research` runs only when you invoke it.

[Workflows you save](<#save-the-workflow-for-reuse>) yourself become commands the same way and appear in `/` autocomplete alongside the bundled ones.

### Watch the run

Workflows run in the background, so the session stays responsive while agents work. Run `/workflows` at any time to list running and completed workflows, then select one to open its progress view. When the session has only one run, `/workflows` skips the list and opens that run. To stop a running workflow from the list without opening it, select it and press `x`.

The progress view shows each phase with its agent counts. The footer lists the key for each action:

| Key | Action |
| :- | :- |
| `↑` / `↓` | Select a phase or agent |
| `Enter` or `→` | Drill into the selected phase, then into an agent's detail. In the detail, `Enter` expands or collapses it |
| `Esc` or `←` | Back out one level. In v2.1.203 through v2.1.205, `←` didn't step back out of a phase or agent; use `Esc` on those versions |
| `j` / `k` | Scroll within the agent detail when it overflows |
| `f` | Filter the agent list in the selected phase by status. Press again to cycle |
| `p` | Pause or resume the run |
| `x` | Stop the selected agent, or stop the whole workflow when focus is on the run |
| `r` | Restart the selected running agent |
| `s` | [Save](<#save-the-workflow-for-reuse>) the run's script as a command |

The agent detail lists the agent's prompt, its recent tool calls, and its result. Each call shows its state, such as still running or failed. When the agent keeps a task list of its own, the detail shows it too, with each task's status.

Press `Enter` to expand the detail. The prompt and result then show in full, and each listed call shows its input and the start of its result.

## Have Claude write a workflow

You can have Claude write a workflow for your task in two ways:

* [Ask for a workflow](<#ask-for-a-workflow-in-your-prompt>) in your prompt, either in your own words or by including the keyword `ultracode`, and Claude writes one for the task.
* [Let Claude decide with ultracode](<#let-claude-decide-with-ultracode>): set `/effort ultracode` and Claude plans a workflow for every substantive task in the session.

You can also run a workflow command that already exists: a [bundled workflow](<#bundled-workflows>) like `/deep-research`, or one you've [saved](<#save-the-workflow-for-reuse>).

### Ask for a workflow in your prompt

To run a single task as a workflow without changing the session's effort level, include the keyword `ultracode` in your prompt. Asking in your own words, for example "use a workflow" or "run a workflow", also works: Claude treats a direct request as the same opt-in.

```text wrap theme={null}
ultracode: audit every API endpoint under src/routes/ for missing auth checks
```

Claude Code highlights the keyword in your input and Claude writes a workflow script for the task instead of working through it turn by turn. The keyword only chooses how Claude structures the work: the agents' tool calls receive the same permission checks and [sandboxing](<https://code.claude.com/docs/en/sandboxing>) as any other tool call in the session.

If the run does what you wanted, you can [save it as a command](<#save-the-workflow-for-reuse>) afterward. If you already have an orchestrator built another way, such as a folder of subagent prompts or a skill that fans work out, you can point Claude at it and ask for a workflow that does the same thing.

#### Dismiss or turn off the keyword

If you didn't mean to start a workflow, press `Option+W` on macOS or `Alt+W` on Windows and Linux to dismiss the highlight for this prompt, or press backspace while the cursor is right after the highlighted keyword. To stop the keyword from triggering at all, turn off Ultracode keyword trigger in `/config`.

#### Where the keyword works

The keyword is an opt-in only in a prompt you type yourself: at the interactive prompt, in an IDE extension panel, in a [Remote Control](<https://code.claude.com/docs/en/remote-control>) client, or in an Agent SDK application that stamps your keyboard input's [`origin`](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkmessageorigin>) as `{ kind: "human" }`. It doesn't start a workflow when it reaches the session another way:

* a prompt passed with `-p`
* a prompt an Agent SDK application sends without stamping it as human input
* a scheduled task prompt
* a webhook payload or pull request comment relayed into the conversation



**注释：**

  Before v2.1.210, the keyword started a workflow from any of these routes too, including a webhook payload or pull request comment relayed into the conversation.


### Let Claude decide with ultracode

Ultracode is a Claude Code setting that turns on automatic workflow orchestration for the session, at whichever [effort level](<https://code.claude.com/docs/en/model-config#adjust-effort-level>) the session runs at. With it on, Claude plans a workflow for each substantive task instead of waiting for you to ask. Turn it on at the Claude Code prompt:

```text wrap theme={null}
/effort ultracode
```

To start a session with ultracode already on, launch with `claude --effort ultracode`, which also sets the effort level to `xhigh`. Requires Claude Code v2.1.203 or later.

To turn it on from the `/effort` slider, press `Tab` to flip the **Ultracode** toggle, then `Enter` to apply it. [Adjust effort level](<https://code.claude.com/docs/en/model-config#adjust-effort-level>) lists the routes that turn ultracode on.

With ultracode on, Claude decides when a task warrants a workflow. A single request can turn into several workflows in a row: one to understand the code, one to make the change, and one to verify it. This applies to every task in the session, so each request uses more tokens and takes longer than the same request without a workflow. On a subscription plan those tokens draw on your usage limits, so a session with ultracode on reaches a session or weekly limit sooner than the same work with it off.

Turning ultracode on already opts you in to large runs, so these checks don't apply while it's on:

* The [`Large workflow` warning](<#cost>) doesn't appear on a workflow run
* The session's [concurrent subagent limit](<https://code.claude.com/docs/en/sub-agents#concurrent-subagent-limit>) isn't enforced for the subagents Claude spawns with the Agent tool
* In auto permission mode, you aren't asked to [approve the first workflow launch](<#approve-the-plan-before-it-runs>)

`/effort ultracode` lasts for the current session; to have every session start with it, set the [`ultracode`](<https://code.claude.com/docs/en/settings-reference#ultracode>) setting. Turn it off with `/effort ultracode off` when you return to routine work. The `/effort` slider offers the toggle only [when ultracode is available](<https://code.claude.com/docs/en/model-config#when-ultracode-is-available>).

### Approve the plan before it runs

In the CLI, the per-run prompt shows the planned phases and these options:

* **Yes, run it**: start the run
* **Yes, and don't ask again for `<name>` in `<path>`**: start, and skip this prompt for this workflow in this project from now on. Claude Code offers this option when you run a bundled, saved, or plugin workflow by name, not for a script Claude wrote for the current task.
* **View raw script**: read the script before deciding
* **No**: cancel

`Ctrl+G` opens the script in your editor. With **Yes, run it** or **No** selected, press `Tab` to [add a comment](<https://code.claude.com/docs/en/permissions#add-a-comment-when-you-answer-a-permission-prompt>) to your answer.

Whether you see this prompt depends on your [permission mode](<https://code.claude.com/docs/en/permission-modes>):

| Permission mode | When you're prompted |
| :- | :- |
| Auto | First launch only. Any **Yes** records consent in your user settings, and later launches start without prompting. Skipped entirely when ultracode is on |
| Manual, accept edits | Every run, unless you've selected **Yes, and don't ask again** for that workflow in this project |
| Bypass permissions | Claude Code doesn't prompt you. The run starts immediately |
| `claude -p`, Agent SDK | Claude Code doesn't prompt you |

In `claude -p` and the Agent SDK, Claude Code never shows this prompt. It runs the Workflow tool call through the same [permission evaluation](<https://code.claude.com/docs/en/agent-sdk/permissions#how-permissions-are-evaluated>) as the rest of the session, so deny rules, ask rules, and `dontAsk` mode apply to the launch as they apply to every tool call. To let the workflow start in these runs, use one of these:

* **Permission rule**: `Workflow` in your allow rules approves every workflow, and `Workflow(<name>)` approves one saved workflow by name.
* **Auto permission mode**: the [classifier](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) reviews the call and can approve it.
* **Bypass permissions mode**: Claude Code approves the call.
* **A hook**: a [`PreToolUse`](<https://code.claude.com/docs/en/hooks#pretooluse>) hook that allows the call approves it.
* **Your host**: a [`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) or, with the Agent SDK, a [`canUseTool`](<https://code.claude.com/docs/en/agent-sdk/permissions>) callback approves it.

In the Desktop app, an approval card shows the workflow name, the phase list, and a token-usage caution, with **Once**, **Always**, and **Deny** actions. The progress view appears in the Background tasks side pane.

The subagents the workflow spawns use your [permission rules](<https://code.claude.com/docs/en/settings-reference#permission-settings>), and Claude Code picks their permission mode by the rules under [which permission mode a subagent runs in](<https://code.claude.com/docs/en/sub-agents#permission-modes>). To avoid prompts on a long run, add the tools the agents need to your allow rules before starting.

### Save the workflow for reuse

When Claude writes a workflow for a task you'll repeat, you can save that run's script as a command. A process like a review you run on every branch then runs the same orchestration each time.

Run `/workflows`, select the run you want to keep, and press `s`. In the save dialog, Tab toggles between the two save locations:

* `.claude/workflows/` in your project: shared with everyone who clones the repo
* `~/.claude/workflows/` in your home directory: available in every project, visible only to you. If you set [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>), this location is the `workflows/` directory under that path.

The save dialog shows the resolved path for the personal location.

Press Enter to save. The workflow runs as `/<name>` in future sessions from either location.

Claude Code checks the save location for symlinks before writing, and shows an error instead of writing through one. What it checks depends on where you save:

* Project location: Claude Code refuses if `.claude`, `.claude/workflows`, or the target file is a symlink.
* Personal location: Claude Code refuses only if the target file itself is a symlink, so a `~/.claude` directory managed by a dotfiles tool still works.

Before v2.1.216, Claude Code followed the link, which could place the file outside the location you chose.

In a monorepo with several `.claude/` directories, you can keep workflows alongside the package they apply to. Saving to the project location writes to the closest `.claude/workflows/` directory that already exists between your working directory and the repository root, or to the repository root if none exists yet. Project workflows also load from every `.claude/workflows/` along that path, and when more than one defines the same name Claude Code runs the one closest to the working directory.

If a project workflow and a personal workflow share a name, the project one runs.

### Distribute a workflow in a plugin

To share a workflow across teams or repositories, include it in a [plugin](<https://code.claude.com/docs/en/plugins/overview>). Place the script in a `workflows/` directory at the plugin root, or point to a different location with the [`workflows` manifest field](<https://code.claude.com/docs/en/plugins/manifest-reference#fields>).

Plugin workflows are namespaced by the plugin name. A plugin called `acme-tools` containing a script whose `meta.name` is `release-audit` runs as `/acme-tools:release-audit`.

### Pass input to a saved workflow

A saved workflow can accept input through the `args` parameter. The script reads it as a global named `args`. Use this to supply a research question, a list of target paths, or a configuration object at invocation time instead of editing the script for each run.

The following prompt runs a saved workflow with a list of issue numbers:

```text wrap theme={null}
Run /triage-issues on issues 1024, 1025, and 1030
```

Claude passes the list as structured data, so the script can call array and object methods on `args` directly without parsing it first. If `args` is omitted, the global is `undefined` inside the script.

## Example workflow prompts

A workflow fits best when the task is larger than one agent can hold in context, or when the same step needs to run across many items. The prompts below show common shapes. Each one asks Claude to write and run a workflow for that task; you don't write the script yourself.

### Audit many files for the same issue

Fan out one agent per file, then collect and verify the findings.

```text wrap theme={null}
use a workflow to audit every route handler under src/routes/ for missing authentication checks, and adversarially verify each finding before reporting it
```

### Keep fixing until a check passes

Run a checker, fix what failed, and repeat until it passes or stops making progress.

```text wrap theme={null}
use a workflow to run npx tsc --noEmit and keep fixing the reported errors until the type check passes or two rounds in a row make no progress
```

### Migrate many files in parallel

Discover the files to migrate, transform each one in an isolated copy so edits don't conflict, and verify each result.

```text wrap theme={null}
use a workflow to migrate every component under src/components/ from JavaScript to TypeScript, working on each file in its own isolated copy
```

### Review every changed file and write one summary

Run a reviewer per file, then pass all the findings to one agent that ranks and deduplicates them.

```text wrap theme={null}
use a workflow to review every file changed in this PR for correctness issues, then merge the per-file findings into one ranked summary
```

### Research a topic across many sources

Fan out readers across changelogs, issues, and docs, then synthesize. The bundled `/deep-research` workflow does this; you can also describe a narrower version.

```text wrap theme={null}
use a workflow to research how our three competitors handle rate limiting: read their public docs and recent changelog entries in parallel, then compare the approaches
```

### Find issues until the list stops growing

Keep searching in rounds and stop when new rounds turn up nothing new.

```text wrap theme={null}
use a workflow to find flaky tests in this repo: run the suite repeatedly, record which tests fail intermittently, and stop once two rounds in a row find nothing new
```

### What the saved script looks like

When you [save a workflow](<#save-the-workflow-for-reuse>), the file in `.claude/workflows/` holds a `meta` block followed by a script body that orchestrates subagents. You usually don't need to edit it, but here is the shape of a small one so you can recognize what Claude generated:

```javascript theme={null}
export const meta = {
  name: 'audit-routes',
  description: 'Audit every route handler for missing auth checks',
}

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
})

const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }),
)

return audits.filter(Boolean)
```

The body is plain JavaScript with top-level `await`. `agent()` spawns one subagent, `pipeline()` runs one per item in a list, and `parallel()` runs a set of agent tasks at the same time and waits for all of them.

An `agent()` call resolves to `null` if you stop it mid-run or it hits an unrecoverable API error. `pipeline()` keeps each `null` in the results array, which is why the example ends with `.filter(Boolean)` to drop those entries, including the slot of [an agent that stalled on every attempt](<#when-an-agent-stalls-and-restarts>).

In [auto mode](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>), the prompt your script passes to `agent()` doesn't count as a request from you when the classifier reviews that subagent's actions, because Claude Code marks it as text the script computed.

If you pass a `schema` on an `agent()` call, that subagent returns JSON matching the shape instead of prose. Claude Code checks the schema before starting the subagent: when it can prove the schema contradicts itself, the call fails with an error naming the contradiction, and the subagent never starts. One contradiction it can prove is a `required` key that `additionalProperties: false` rules out.

If the subagent's output still fails validation after five attempts, the call fails with an error that includes the last validation failure. To change the attempt count, set [`MAX_STRUCTURED_OUTPUT_RETRIES`](<https://code.claude.com/docs/en/env-vars>).

### Edit a saved script

To change a [workflow you saved](<#save-the-workflow-for-reuse>), edit its `.js` file or ask Claude to make the change. Before you edit or ask, run the `/workflow-authoring` [bundled skill](<https://code.claude.com/docs/en/skills#bundled-skills>) to load the script-writing reference Claude works from. The skill requires Claude Code v2.1.248 or later.

To run the edited version in the current session, run [`/reload-skills`](<https://code.claude.com/docs/en/commands#all-commands>) to re-read the workflow directories, then run `/<name>` again.

Claude Code applies these rules to each part of the file when it loads and runs the script:

* **`meta` block**: keep `export const meta` as the first statement, and keep it a plain object literal with a `name` and a `description`. If it contains anything other than literal values, such as a variable, a function call, or a spread, Claude Code drops `/<name>` from `/` autocomplete.
* **Body**: besides `agent()`, `pipeline()`, and `parallel()`, you can call `phase()` to group the agents that follow under a title in the progress view, call `log()` to show a message above the phases, and read the [`args`](<#pass-input-to-a-saved-workflow>) global. If the body has a syntax error, Claude Code reports it when you run the workflow.
* **`phases`**: if you list them in `meta`, give each entry exactly the title you pass to `phase()`. A `phase()` title with no entry gets a progress group of its own.
* **Timestamps and randomness**: Claude Code makes `Date.now()`, `Math.random()`, and a no-argument `new Date()` throw inside the script, so that a [relaunched run](<#resume-after-a-pause>) repeats the same `agent()` calls. Pass a timestamp in through `args` instead.

You can also edit [the script of a single run](<#how-a-workflow-runs>) rather than the saved copy. [Resume after a pause](<#resume-after-a-pause>) covers which agents run again when you relaunch an edited script. For the Workflow tool's inputs, see its entry in the [Agent SDK reference](<https://code.claude.com/docs/en/agent-sdk/typescript#workflow>).

## How a workflow runs

The workflow runtime executes the script in an isolated environment, separate from your conversation. Intermediate results stay in script variables instead of landing in Claude's context.

Every run writes its script to a file under your session's directory in `~/.claude/projects/`. Claude receives the path when the run starts, so you can ask for it. You can open that file to read the orchestration Claude wrote, diff it against a previous run's script, or edit it and ask Claude to relaunch from the edited version.

Claude can start a workflow only from a script file the session is already allowed to read. To run a script kept outside your working directory, add its directory with [`/add-dir`](<https://code.claude.com/docs/en/permissions#working-directories>) or a [Read allow rule](<https://code.claude.com/docs/en/permissions#read-and-edit>) first.

The runtime tracks each agent's result as the run progresses, which is what makes a run [resumable](<#resume-after-a-pause>) within the same session.

### Prompt caching in a fan-out

Agents in the same run can read each other's [prompt cache](<https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache>). Two agents that run with the same model, effort level, agent type, tools, output schema, and working directory build the same tools-and-system-prompt prefix, so an agent that starts after a matching sibling's response has begun reads that sibling's cache on its first request.

A workflow agent's requests fall outside the main conversation's [cache TTL bucket](<https://code.claude.com/docs/en/prompt-caching#which-ttl-each-request-gets>), so its cache holds for five minutes by default, including on a Claude subscription. To keep it for an hour, set [`subagentPromptCacheTtl`](<https://code.claude.com/docs/en/settings-reference#subagentpromptcachettl>) to `1h`. The API bills 1-hour cache writes at a higher rate.

When a fan-out starts several matching agents at once, Claude Code holds all but the first until the first agent's response begins, then releases the held agents together so their first requests read the shared prefix instead of each processing it uncached. Claude Code caps the hold at [`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`](<https://code.claude.com/docs/en/env-vars>) milliseconds, `5000` by default. Set it to `0` to disable the hold.

### Behavior and limits

The runtime applies the following constraints:

| Constraint | Why |
| :- | :- |
| No mid-run user input | A run pauses on its own only for agent permission prompts and a [usage-limit wait](<#when-a-run-hits-your-usage-limit>). For sign-off between stages, run each stage as its own workflow |
| No direct filesystem or shell access from the workflow itself | Agents read, write, and run commands. The script coordinates the agents |
| No module loading: a script that contains `import()` fails before the run starts | The script body is plain JavaScript. Put work that needs a library in an agent's task |
| Up to 16 concurrent agents by default, fewer when Claude Code has fewer CPUs available, including inside a CPU-limited container. To change the limit, set [`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`](<https://code.claude.com/docs/en/env-vars#variables>) to a value from 1 to 256, which requires Claude Code v2.1.269 or later | Bounds local resource use |
| In a fan-out, agents that share the first agent's prompt-cache prefix start up to 5 seconds after it by default | All but the first read the [prefix the first agent cached](<#prompt-caching-in-a-fan-out>) instead of each processing it uncached |
| Up to 4,096 items in a single `parallel()` or `pipeline()` call: the runtime rejects a longer list with an error | A silent cap would drop part of the workload without telling the script |
| 1,000 agents total per run | Prevents runaway loops |

## Manage runs

Once a run starts, you manage it from the `/workflows` view, or by expanding its progress line in the task panel below the input box.

When you stop a run, it stays in the task panel while any of its agents' processes are still running. If you stop it again, Claude Code re-signals those processes.

### Resume after a pause

Resume a paused run from `/workflows` by selecting it and pressing `p`. For a run you stopped, ask Claude to relaunch the workflow with the same script. If agents from the stopped run haven't exited yet, Claude Code refuses the relaunch until they have, so a second copy of those agents can't run alongside them.

Claude Code replays the run in the order agents started, and each agent either returns its saved result or runs again:

* **Completed**: returns its saved result. The first agent whose prompt differs from the previous run, because you edited the script or an earlier agent returned something different, runs again, and so does every agent after it, even ones that completed.
* **Still running when you stopped**: starts over. Stopping the whole run doesn't count any agent as failed.
* **Failed**: runs again, and so does every agent that started after it, even ones that completed. Stopping one agent alone, by selecting it in [`/workflows`](<#watch-the-run>) and pressing `x`, counts as failing.

That last case means a failure in the middle of a fan-out reruns work that already finished. If a script starts A, B, C, and D in that order and B fails, relaunching returns A from cache and runs B, C, and D again.

You can resume a run within the same Claude Code session. What happens to a running workflow when you leave the session depends on how you leave:

* If you [background the session](<https://code.claude.com/docs/en/agent-view#what-carries-over-when-you-background>), Claude Code replays the run the same way in the background session and continues it.
* If you exit Claude Code while a workflow is running and [agent view is on](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>), the exit dialog offers `Move to background and exit`, which carries the run over the same way. If you choose `Exit and stop tasks` instead, or the option isn't offered, the run stops with the session. Claude Code keeps the run's saved results under that session's directory in `~/.claude/projects/`, so a session you resume with `claude --resume` can replay them when you ask Claude to relaunch the workflow. In a session you start fresh, Claude has no earlier run to relaunch and starts the workflow over as a new run.

In a [cloud session](<https://code.claude.com/docs/en/claude-code-on-the-web>), Claude Code also saves the run's results with the session's conversation history, which survives when the session's VM is reclaimed. When you [reopen such a session](<https://code.claude.com/docs/en/claude-code-on-the-web#environment-expired>) and ask Claude to relaunch the workflow, completed agents still return their saved results.

In local and cloud sessions alike, when Claude relaunches an earlier run and Claude Code can't find that run's saved results at all, the relaunch fails with a `nothing to resume` error instead of starting the run over on its own. Ask Claude to start the workflow over as a new run.

### When a run hits your usage limit

When an agent hits your claude.ai [usage limit](<https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset>), the run pauses rather than failing that agent: the agents that hit the limit wait for the reset, and no new agents start. Shortly after the limit resets, the waiting agents run again and the run continues on its own. Requires Claude Code v2.1.271 or later; on earlier versions, the affected agents fail.

While the run waits, its progress line in the task panel and the [`/workflows`](<#watch-the-run>) header show when the limit resets.

The run pauses only when all of these hold; when one doesn't, the affected agent fails instead:

* The session is interactive and signed in with a claude.ai subscription. A run doesn't pause in [non-interactive mode](<https://code.claude.com/docs/en/headless>) with `claude -p` or the [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>), in a [background session](<https://code.claude.com/docs/en/agent-view>), or in a [Remote Control](<https://code.claude.com/docs/en/remote-control>) or [agent team](<https://code.claude.com/docs/en/agent-teams>) teammate session.
* [`autoContinueAtUsageLimit`](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>) is on, the same setting that lets the session itself [wait for a usage limit to reset](<https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset>). If you turn it off during a wait, the wait ends and the waiting agents fail.
* The limit resets within 24 hours. A weekly limit can reset further out.
* The run hasn't already waited twice. When it hits the limit a third time, the agent fails.

### When an agent stalls and restarts

An agent whose output stops arriving for long enough starts over from the same prompt. In [`/workflows`](<#watch-the-run>), its name gains a `(retry 1)` suffix and its detail shows `attempt 2 (stalled)`. The restart is automatic, so you don't need to do anything.

The new attempt starts without the stalled attempt's transcript. Files the stalled attempt already changed stay changed, and the tokens it spent stay in the run's total. The stall window is how long Claude Code waits for output from an agent before it ends the attempt. Time the agent spends waiting on its own tool calls or on a [usage-limit reset](<#when-a-run-hits-your-usage-limit>) doesn't count toward the stall window.

An agent restarts at most five times, counting any restart you ask for with `r`. If the sixth attempt stalls as well, the `agent()` call fails, and the start of the error says why:

* `agent stalled on all 6 attempts`: every attempt went the whole window without output. If the agent's work keeps it silent that long, lengthen the window
* `agent lost its reply on all 6 attempts`: every attempt's response stream went silent and Claude Code gave up waiting on it. Lengthening the stall window doesn't help, since a [streaming idle watchdog](<https://code.claude.com/docs/en/network-config#streaming-idle-watchdogs>) ended the response first and `CLAUDE_STREAM_IDLE_TIMEOUT_MS` sets that watchdog's timeout
* `agent abandoned after 6 attempts`: the attempts ended in different ways, which the error lists in order

To give an agent more time to produce output before the window ends:

* **One agent**: pass `stallMs` in milliseconds on its `agent()` call, such as `agent(prompt, { stallMs: 1800000 })` for 30 minutes
* **Every agent**: set [`CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS`](<https://code.claude.com/docs/en/env-vars#variables>), which also applies to subagents outside workflows

Whether the run continues after the failure depends on how your script called the agent:

* **Inside [`parallel()` or `pipeline()`](<#what-the-saved-script-looks-like>)**: the run carries on with `null` in place of the agent's result
* **Awaited directly**: the run ends with the error

To try again, ask Claude to relaunch the workflow. [Resume after a pause](<#resume-after-a-pause>) covers what runs again.

### Cost

A workflow spawns many agents, so a single run can use meaningfully more tokens than working through the same task in conversation. Runs count toward your plan's usage and rate limits.

To gauge the spend before committing to a large task, run the workflow on a small slice first: one directory instead of the whole repo, or a narrow question instead of a broad one. The `/workflows` view shows each agent's token usage as the run progresses, and you can stop the run there at any time, usually without losing completed work. [Resume after a pause](<#resume-after-a-pause>) covers what a stopped run keeps. The runtime's [agent caps](<#behavior-and-limits>) limit how many agents a single run can spawn, which bounds the cost of a runaway script. To keep runs to fewer agents, choose the `small` [size guideline](<#set-a-size-guideline>).

Claude Code also flags a run that grows unusually large. When a workflow schedules more than 25 agents, or its projected token total passes 1.5 million, its progress line in the task panel below the input box shows a `Large workflow` warning. The warning points you to [`/workflows`](<#watch-the-run>), where you can stop the run.

The warning is advisory: it doesn't pause or limit the run. Two settings change when you see it:

* If you choose a [size guideline](<#set-a-size-guideline>) yourself, its agent count replaces the 25-agent threshold. The built-in default guideline leaves the threshold at 25.
* Sessions with [ultracode](<#let-claude-decide-with-ultracode>) on don't show the warning, because turning ultracode on already opts you in to large runs.

Claude Code picks each workflow agent's model in the same [order it uses for subagents](<https://code.claude.com/docs/en/sub-agents#choose-a-model>). A model the script names for a stage counts as the per-invocation model in that order. When nothing else assigns one, the agent runs on your session's model.

To control the model cost:

* Check `/model` before a large run if you usually switch to a smaller model for routine work
* Ask Claude to use a smaller model for stages that don't need the strongest one when you describe the task

When your organization's [`availableModels` allowlist](<https://code.claude.com/docs/en/model-config#restrict-model-selection>) blocks a model the script requests for an agent, that agent runs on a substituted model instead, following the same [substitution rules as subagents](<https://code.claude.com/docs/en/sub-agents#choose-a-model>).

### Set a size guideline

A size guideline tells Claude how many agents to aim for when it writes a dynamic workflow. Claude Code sends the guideline to Claude as advice, not a cap, so a prompt that calls for a different scale still overrides it. Requires Claude Code v2.1.202 or later.

Each value maps to an agent count:

| Value | Agent count Claude aims for |
| :- | :- |
| `unrestricted` | No guideline: Claude sizes the workflow to the task |
| `small` | Fewer than 5 agents |
| `medium` | Fewer than 10 agents |
| `large` | Fewer than 50 agents |

The default is `medium`, or `small` when you're signed in on a Pro plan with Claude Code v2.1.271 or later. Until you choose a value, the `/config` row marks the value as the default, and the workflow's `Running in background` line names the size in force. Requires Claude Code v2.1.219 or later; earlier versions default to `unrestricted`.

To change the guideline, pick a value for the Dynamic workflow size setting in `/config`, or run `/config workflowSizeGuideline=small`. On v2.1.219 and later, you can also set the [`workflowSizeGuideline` key](<https://code.claude.com/docs/en/settings-reference#workflowsizeguideline>) in any settings file; that value takes precedence over `/config`, and Claude Code hides the `/config` row while a settings file provides one.

Changes take effect on the next prompt. The [runtime agent caps](<#behavior-and-limits>) still apply regardless of the setting.

### Turn workflows off

Workflows are available in the CLI, the Desktop app, the IDE extensions, [non-interactive mode](<https://code.claude.com/docs/en/headless>) with `claude -p`, and the [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>). The same disable settings apply on every surface.

To turn workflows off for yourself:

* Toggle Dynamic workflows off in `/config`. Persists across sessions.
* Set `"disableWorkflows": true` in `~/.claude/settings.json`. Persists across sessions.
* Set `CLAUDE_CODE_DISABLE_WORKFLOWS=1`. Read at startup, so it applies wherever you set it.

To turn workflows off for your whole organization, set `"disableWorkflows": true` in [managed settings](<https://code.claude.com/docs/en/server-managed-settings>), or use the toggle on the [Claude Code admin settings](<https://claude.ai/admin-settings/claude-code>) page.

When workflows are disabled:

* `/workflows`, the workflow commands, and the `/workflow-authoring` skill are unavailable
* The `ultracode` keyword no longer triggers a run, and the **Ultracode** toggle is removed from `/effort`

A run that was already in progress keeps going.

Turning workflows off also makes [ultracode](<#let-claude-decide-with-ultracode>) unavailable. No managed setting rules out ultracode alone: wherever it's [available](<https://code.claude.com/docs/en/model-config#when-ultracode-is-available>), users can turn it on with `/effort ultracode`. An [effort cap](<https://code.claude.com/docs/en/model-config#organization-effort-limits>) lowers the effort level a session with ultracode on runs at, but doesn't turn ultracode off.
