# 以编程方式运行 Claude Code

>  使用 Agent SDK 以编程方式从 CLI、Python 或 TypeScript 运行 Claude Code。

[Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) 为您提供与 Claude Code 相同的工具、agent 循环和上下文管理。它可以作为脚本的 CLI 和 CI/CD 提供，或者作为用于完全编程控制的 [Python](<https://code.claude.com/docs/en/agent-sdk/python>) 和 [TypeScript](<https://code.claude.com/docs/en/agent-sdk/typescript>) 包提供。

要以非交互模式运行 Claude Code，请在提示符下传递 `-p` 以及您需要的 [CLI 选项 ](<https://code.claude.com/docs/en/cli-reference>)：

```bash theme={null}
claude -p "Find and fix the bug in auth.py" --allowedTools "Read,Edit,Bash"
```

本页介绍通过 CLI (`claude -p`) 使用 Agent SDK。对于具有结构化输出、工具审批回调和本机消息对象的 Python 和 TypeScript SDK 包，请参阅 [ 完整的 Agent SDK 文档 ](<https://code.claude.com/docs/en/agent-sdk/overview>)。

## 基本用法

将 `-p`（或 `--print`）标志添加到任何 `claude` 命令中以非交互方式运行它。并非每个 [CLI 选项 ](<https://code.claude.com/docs/en/cli-reference>) 都与 `-p` 结合使用。 Claude Code 拒绝 `--bg`，并拒绝带有任务描述的 `--cloud`，并出现命名冲突的错误； `--cloud` 具有会话 ID 和 `-p`，而不是 [ 将消息排队到该云会话 ](<https://code.claude.com/docs/en/claude-code-on-the-web#send-follow-ups-from-the-cli>) 中并退出。您将与 `-p` 结合使用的选项通常包括：

* `--continue` 用于 [ 继续对话 ](<#continue-对话>)
* `--allowedTools` 用于 [ 自动批准工具 ](<#自动批准工具>)
* `--output-format` 用于 [ 结构化输出 ](<#获取结构化输出>)

此示例询问 Claude 有关您的代码库的问题并打印响应：

```bash theme={null}
claude -p "What does the auth module do?"
```

Claude Code 成功时以代码 0 退出，运行失败时以非零代码退出，因此您的脚本可以在退出状态下分支。如果传递无效标志，Claude Code 在运行开始之前向 stderr 报告错误。当运行内部发生故障时，例如缺少身份验证，Claude Code 会在 stdout 上打印故障结果。

### 使用裸模式启动更快

添加 `--bare` 通过跳过自动发现挂钩、技能、自定义命令、[子代理](<https://code.claude.com/docs/en/sub-agents>)、已安装的插件、MCP 服务器、自动内存和 CLAUDE.md 来减少启动时间。如果没有它，`claude -p` 会加载交互式会话相同的 [ 上下文 ](<https://code.claude.com/docs/en/how-claude-code-works#the-context-window>)，包括工作目录或 `~/.claude` 中配置的任何内容。

裸模式对于需要在每台计算机上获得相同结果的 CI 和脚本很有用。队友的 `~/.claude` 中的挂钩或项目的 `.mcp.json` 中的 MCP 服务器中的挂钩将不会运行，因为裸模式永远不会读取它们。以 `--add-dir` 命名的目录是部分例外：裸模式从其 `.claude/skills/` 文件夹加载技能，但仍跳过其 `.claude/commands/` 和 `.claude/agents/` 文件夹。 [来自其他目录的技能](<https://code.claude.com/docs/en/skills#skills-from-additional-directories>)涵盖了加载和不加载的内容。

如果没有 `--bare`，`-p` 会话将运行项目 `.claude/settings.json` 中的挂钩并连接其 `.mcp.json` 中的服务器，即使在您从未信任的文件夹中也是如此。 `-p` 会话不显示工作区信任对话框，也不显示每台服务器的批准提示。 [在信任文件夹之前运行的内容](<https://code.claude.com/docs/en/permissions#what-runs-before-you-trust-a-folder>)涵盖了`-p`下的每种存储库内容以及如何将其排除在外。

此示例在裸模式下运行一次性汇总任务并预先批准读取工具，以便调用在没有权限提示的情况下完成。在运行之前设置 `ANTHROPIC_API_KEY`，因为裸模式不使用您的订阅登录名：

```bash theme={null}
claude --bare -p "Summarize README.md" --allowedTools "Read"
```

在裸模式下，Claude Code 永远不会读取 OAuth 凭据或系统钥匙串。对于 Anthropic API，请使用在 [Claude 控制台 ](<https://platform.claude.com>) 中创建的密钥在环境中设置 `ANTHROPIC_API_KEY`，或在 `--settings` 中提供 `apiKeyHelper` JSON。 Amazon Bedrock、Google Cloud 的 Agent 平台和 Microsoft Foundry 继续照常读取自己的提供商凭证。

在裸模式下 Claude 可以访问 Bash、文件读取和文件编辑工具。使用标志传递您需要的任何上下文：

|加载|使用|
| - | - |
|系统提示添加| `--append-system-prompt`, `--append-system-prompt-file` |
|设置| `--settings <file-or-json>` |
|MCP 服务器| `--mcp-config <file-or-json>` |
|[定制 agents](<https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope>)| `--agents <file-or-json>` |
|一个插件| `--plugin-dir <path>`, `--plugin-url <url>` |

裸模式还限制会话运行时发生的情况：

* **MCP 服务器**：仅通过命令行提供的服务器进行连接，例如使用 `--mcp-config`。在交互式会话中，Claude Code 也会跳过自动 IDE 连接，除非您传递 `--ide`。
* **系统提醒**：Claude获取提示和工具结果，而没有[系统提醒](<https://code.claude.com/docs/en/glossary#system-reminder>)Claude Code会添加到它们旁边。例如，Claude 不会被告知其先前读取的文件在磁盘上发生更改，并且它不会获取可用技能的列表，包括 `--add-dir` 文件夹中的技能。
* **后台任务**：没有运行。达到 [ 超时 ](<https://code.claude.com/docs/en/tools-reference#timeout-and-output-limits>) 的命令会停止，而不是 [ 移动到后台 ](<https://code.claude.com/docs/en/tools-reference#background-commands>)。

在 v2.1.286 之前，这些限制仅部分有效：交互式 `--bare` 会话与普通会话一样连接 MCP 服务器，每个 `--bare` 会话发送系统提醒，并且后台任务保持可用。



**注释：**

`--bare` 是脚本调用和 SDK 调用的推荐模式，并将在未来版本中成为 `-p` 的默认模式。


### 退出时的后台任务

Claude 完成轮次并且标准输入关闭后，`claude -p` 运行可以保持打开状态以等待 Claude 启动的后台工作。

除非主对话启动的后台命令仍在运行，否则 Claude Code 默认情况下会在连续空闲等待 10 分钟后停止仍在运行的任何内容，并丢弃其部分结果。要更改 10 分钟上限，请设置 [`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`](<https://code.claude.com/docs/en/env-vars>)，或将其设置为 `0` 以在没有分钟的情况下等待。

运行等待后台工作，例如后台命令、子代理和工作流程、监视器监视和挂起的 `/loop` 唤醒：

* **[后台命令](<https://code.claude.com/docs/en/tools-reference#background-commands>)**：对于主对话启动的命令，例如开发服务器或监视构建，运行会等待，直到命令退出或达到其[时间限制](<https://code.claude.com/docs/en/tools-reference#time-limit-for-background-commands>)。 Claude 然后再进行一轮结果。当命令运行时，10 分钟上限不会结束等待。
* **后台[子代理](<https://code.claude.com/docs/en/sub-agents>)和工作流程**：运行保持打开状态，直到该工作完成，因为其结果是最终输出的一部分。
* **[监视器](<https://code.claude.com/docs/en/tools-reference#monitor-tool>)监视**：运行等待，直到监视超时或10分钟上限结束等待，以先到者为准。在等待期间，Claude 不断响应手表报告的内容。默认情况下，手表在 Claude 启动后五分钟超时。
* **等待唤醒**：在您以文本形式而不是使用`--input-format stream-json`传递提示的运行中，当Claude安排了[自进度`/loop`唤醒](<https://code.claude.com/docs/en/scheduled-tasks#let-claude-choose-the-interval>)时，运行将等待每次唤醒都会触发并运行其迭代，直到 [ 循环结束 ](<https://code.claude.com/docs/en/scheduled-tasks#stop-a-loop>)，甚至超过 10 分钟上限。

当 stderr 是终端并且运行已等待五秒时，Claude Code 会将一行以 `Waiting for background work to finish` 开头的行打印到 stderr 并命名工作。使用 [`json` 或 `stream-json` 输出 ](<#获取结构化输出>)，仅当 stdout 不是终端时才打印该行，因此脚本读取的 JSON 永远不会携带它。

如果运行达到其 [`--max-budget-usd`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 上限，Claude Code 将停止剩余的后台工作而不是等待。

当后台工作开始另一个回合时，运行将使用默认的 `text` 输出打印每个回合的结果，并使用 `json` 输出打印最后一个回合的结果。在v2.1.295之前，运行也仅打印最后一轮的结果，并输出`text`。

### 使用 SIGTERM 停止运行

如果使用 SIGTERM（例如使用 `kill` 或从进程管理程序）停止 `claude -p` 运行，则 Claude Code 将以代码 143 退出。 Claude Code 使正在进行的回合未完成，并且不记录任何结果。要结束回合，请在停止进程之前发送 SIGINT，或呼叫 Agent SDK 的 `interrupt()`。

在 SIGTERM 上，Claude Code 终止仍在运行的任何 Bash 命令的进程树。 Claude Code 然后运行 ​​[`SessionEnd` hooks](<https://code.claude.com/docs/en/hooks#sessionend>) 并退出。退出时，Claude Code 不会启动新的工具调用，不会发送新的模型请求，并且不会运行除 `SessionEnd` 之外的钩子。如果运行处于命令中间或在信号到达时等待权限提示，Claude Code 会按如下方式处理该步骤：

* **运行命令**：Claude Code将该命令记录为在会话中被杀死。
* **等待权限提示的答复**：如果您将SIGTERM发送到进程，Claude Code将使提示保持未答复。如果你的程序通过AgentSDK关闭会话，SDK会在发送任何信号之前结束Claude Code的输入，而Claude Code在输入结束后立即取消提示。

当您[恢复会话](<#continue-对话>)时，Claude Code保持中断的回合不变，并且您的下一个提示将推动对话。要让 Claude Code 继续中断的开启恢复，请设置 [`CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1`](<https://code.claude.com/docs/en/env-vars>)。

### 如果工作目录被删除

如果 `claude -p` 或 Agent SDK 会话的工作目录在会话中被删除，则会话将继续运行。当回合开始时目录丢失，Claude Code 会在 `stream-json` 输出中发出 [ 警告消息 ](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkinformationalmessage>)，并且 shell 命令会失败，直到目录再次存在。

## 示例

这些示例突出显示了常见的 CLI 模式。如果命令将文件命名为 `auth.py` 或 `build-error.txt`，请替换您自己的项目中的文件。在 CI 或其他脚本环境中，添加 [`--bare`](<#使用裸模式启动更快>)，以便 Claude Code 启动时不加载主机的钩子、插件、自动内存或 `CLAUDE.md`。

### 通过 Claude 传输数据

非交互模式读取标准输入，因此您可以像任何其他命令行工具一样通过管道输入数据并将响应重定向出去。

此示例将构建日志通过管道传输到 Claude 并将说明写入文件：

```bash theme={null}
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
```

使用 `--output-format json`，响应负载包括 `total_cost_usd` 和每个模型的成本细分，因此脚本调用者可以跟踪支出，而无需咨询 [ 使用仪表板 ](<https://code.claude.com/docs/en/costs>)。当您继续与 `--continue` 或 `--resume` 进行先前的对话时，运行会报告对话的全部总额，其中包括 [ 之前运行的支出 ](<https://code.claude.com/docs/en/agent-sdk/cost-tracking#accumulate-costs-across-multiple-calls>)。这两个数字都是[客户端估算](<https://code.claude.com/docs/en/agent-sdk/cost-tracking>)，可能与您的实际账单有所不同。



**注释：**

管道标准输入的上限为 10MB。如果超出上限，Claude Code 将退出并显示明显错误和非零状态。要使用更大的输入，请将内容写入文件并在提示中引用文件路径，而不是通过管道传输它。


如果 Claude Code 无法读取 stdin，例如因为启动它的进程断开了连接，Claude Code 会向 stderr 打印一条警告，并继续执行命令行的提示。在 v2.1.211 之前，Windows 上不可读的标准输入导致会话崩溃或使其静默退出且没有输出。

### 将 Claude 添加到构建脚本中

您可以将非交互式调用包装在脚本中，以使用 Claude 作为项目特定的 linter 或审阅者。

此 `package.json` 脚本将 `main` 的差异通过管道传输到 Claude 中，并要求其报告拼写错误。通过管道传输差异意味着 Claude 不需要 Bash 权限来读取它，并且转义的双引号使脚本可移植到 Windows：

```json theme={null}
{
  "scripts": {
    "lint:claude": "git diff main | claude -p \"you are a typo linter. for each typo in this diff, report filename:line on one line and the issue on the next. return nothing else.\""
  }
}
```

使用 `npm run lint:claude` 运行它。

### 获取结构化输出

使用 `--output-format` 控制如何返回响应：

* `text`（默认）：纯文本输出
* `json`：结构化 JSON，包含结果、会话 ID 和元数据
* `stream-json`：换行符分隔的 JSON 用于实时流式传输

此示例返回项目摘要为 JSON 以及会话元数据，文本结果位于 `result` 字段中：

```bash theme={null}
claude -p "Summarize this project" --output-format json
```

要获得符合特定模式的输出，请将 `--output-format json` 与 `--json-schema` 和 [JSON 模式 ](<https://json-schema.org/>) 定义结合使用。响应包括有关请求的元数据（会话 ID、使用情况等）以及 `structured_output` 字段中的结构化输出。

此示例提取函数名称并将它们作为字符串数组返回：

```bash theme={null}
claude -p "Extract the main function names from auth.py" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}'
```

如果该值不是有效的 JSON 架构，则 `claude` 退出并显示 `Error: --json-schema is not a valid JSON Schema`，后跟验证器的诊断。 Claude Code 接受使用 `format` 关键字的架构，例如 `"format": "email"`，但将 `format` 视为注释并且不强制执行。在 v2.1.205 之前，Claude Code 默默地忽略无效架构并返回非结构化文本，并将任何包含 `format` 的架构视为无效。



**提示：**

使用 [jq](<https://jqlang.org/>) 等工具来解析响应并提取特定字段：

  ```bash theme={null}
  # Extract the text result
  claude -p "Summarize this project" --output-format json | jq -r '.result'

  # Extract structured output
  claude -p "Extract function names from auth.py" \
    --output-format json \
    --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
    | jq '.structured_output'
  ```



### 流响应

将 `--output-format stream-json` 与 `--verbose` 和 `--include-partial-messages` 一起使用以接收生成的令牌。每行都是一个代表事件的 JSON 对象：

```bash theme={null}
claude -p "Explain recursion" --output-format stream-json --verbose --include-partial-messages
```

流的最后一行是 `result` 消息，其中包含最终响应文本、成本和会话元数据。

如果您的消费者读取流速度很慢，Claude Code 会在退出之前等待排队的输出耗尽，根据仍在排队的数量调整等待时间，上限为 30 秒。在 v2.1.214 之前，退出等待的上限约为两秒，这可能会中断大型响应的结束。

以下示例使用 [jq](<https://jqlang.org/>) 过滤文本增量并仅显示流文本。 `-r` 标志输出原始字符串（无引号），`-j` 连接不带换行符，因此令牌连续流动：

```bash theme={null}
claude -p "Write a poem" --output-format stream-json --verbose --include-partial-messages | \
  jq -rj 'select(.type == "stream_event" and .event.delta.type? == "text_delta") | .event.delta.text'
```

对于使用回调和消息对象的编程流式传输，请参阅 Agent SDK 文档中的 [实时流响应 ](<https://code.claude.com/docs/en/agent-sdk/streaming-output>)。

#### 关注子代理消息

来自 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>) 和来自 [ 在子代理 ](<https://code.claude.com/docs/en/skills#run-skills-in-a-subagent>) 中运行的技能的消息在流中显示为 `assistant` 和 `user` 消息。他们的 `parent_tool_use_id` 字段表示每个运行属于哪个运行。来自主对话的消息在该字段中带有 `null`。

来自分叉技能或来自在 [ 前台 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) 中运行的子代理的第一条消息是一条 `user` 消息，携带驱动它的提示或技能内容。在第一条消息之后，Claude Code 发出：

* **默认情况下**：运行的`tool_use`和`tool_result`块。
* **使用[`--forward-subagent-text`](<https://code.claude.com/docs/en/cli-reference#cli-flags>)或[`CLAUDE_CODE_FORWARD_SUBAGENT_TEXT`](<https://code.claude.com/docs/en/env-vars>)**：运行的文本和思维块，因此您可以重建每个运行的记录。

当您启用任一选项时， Claude Code 转发消息来自 [每个嵌套深度的子代理](<https://code.claude.com/docs/en/sub-agents#let-subagents-spawn-their-own-subagents>)，是否每个都由 Agent 工具或作为分叉技能开始。在 `parent_tool_use_id`，嵌套子代理的消息携带 ID 的 Agent 或启动它的技能工具调用，因此您可以按照这些 ID 重建完整的嵌套树。

Claude 以工具调用开始的运行携带该工具调用的 ID。分叉技能是通过传递 `/<skill-name>` 开始的，因为提示没有工具调用，因此它的消息会携带 `forked-command-` 值，并在完成后到达。在第一列中查找运行是如何开始的：

|跑步如何开始| `parent_tool_use_id` |当消息到达时|
| :- | :- | :- |
|Claude从主对话中调用Agent工具|Agent `tool_use` 块的 ID|当子代理工作时|
|Claude 从主对话中调用分叉技能的技能工具|该技能 `tool_use` 方块的 ID|当分叉技能发挥作用时|
|您传递 `/<skill-name>` 作为提示|以 `forked-command-` 开头的值|分叉技能完成后按顺序一起在一起|

对于从提示开始的分叉技能，请匹配 `forked-command-` 前缀上的 `parent_tool_use_id`，因为其后面的名称可能与您键入的名称不同。

如果您的流中缺少其中一些消息，请根据以下最低版本检查您的 Claude Code 版本：

* **`--forward-subagent-text` 和 `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT`**：v2.1.211 或更高版本
* **在每个嵌套深度转发**：v2.1.219或更高版本
* **分叉技能，Claude从主对话中的技能工具开始**：v2.1.86或更高版本的`tool_use`和`tool_result`块，以及v2.1.265或更高版本的第一个块`user`消息及其文本和思维块
* **分叉技能产生的子代理的消息，以及在子代理或另一个分叉技能内启动的分叉技能的消息**：v2.1.275或更高版本
* **通过传递`/<skill-name>`作为提示符**开始分叉技能的消息：v2.1.287或更高版本

#### 处理API重试

当 API 请求因可重试错误而失败时，Claude Code 在重试之前会发出 `system/api_retry` 事件。在 v2.1.246 或更高版本上，当 `401` 或 `403` 拒绝 [`apiKeyHelper`](<https://code.claude.com/docs/en/settings-reference#apikeyhelper>) 凭据时，Claude Code 会在没有事件的情况下安静地进行前两次重试，然后从第三次连续重试开始照常发出事件。安静重试仍计入 `attempt`。您可以使用该事件在您自己的界面中显示重试进度。

|领域|类型|描述|
| - | - | - |
| `type` | `"system"` |消息类型|
| `subtype` | `"api_retry"` |将其标识为重试事件|
| `attempt` |整数|当前尝试次数，从 1 开始|
| `max_retries` |整数|此失败原因允许的总重试次数|
| `retry_delay_ms` |整数|距离下一次尝试还有几毫秒|
| `error_status` |整数或空值|HTTP 失败尝试的状态代码，或 `null` 当尝试没有从 API 获得 HTTP 响应时|
| `no_response` |对象，可选|仅当失败的尝试[及时没有响应标头](<https://code.claude.com/docs/en/errors#no-response-from-api>)时才存在。 `waited_ms` 是该尝试等待的时间，`retry_wait_ms` 是重试将等待的时间。需要 Claude Code v2.1.261 或更高版本|
| `error` |字符串|错误类别：`authentication_failed`、`oauth_org_not_allowed`、`account_on_hold`、`billing_error`、`rate_limit`、`overloaded`、`invalid_request`、`model_not_found`、 `server_error`、`max_output_tokens`、`cloud_credential_error` 或 `unknown`|
| `uuid` |字符串|唯一的事件标识符|
| `session_id` |字符串|事件所属的会话|

#### 读取会话元数据

`system/init` 事件报告会话元数据，包括模型、工具、MCP 服务器和加载的插件。它是流中的第一个事件，除非启动事件在它之前：

* 设置 [`CLAUDE_CODE_SYNC_PLUGIN_INSTALL`](<https://code.claude.com/docs/en/env-vars>) 时，发生 `plugin_install` 事件。
* [`hook_started`、`hook_progress` 和 `hook_response` 事件 ](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkhookstartedmessage>)，同时配置的 [`SessionStart`](<https://code.claude.com/docs/en/hooks#sessionstart>) 或 [`Setup`](<https://code.claude.com/docs/en/hooks#setup>) 挂钩运行。当钩子产生它们时，它们就会流动。 Claude Codev2.1.169通过v2.1.203挂机后一批发货，仍领先于`system/init`； v2.1.204恢复直播。

该事件还携带一个可选的 `capabilities` 字符串数组，用于命名此 Claude Code 版本实现的协议行为，例如 `interrupt_receipt_v1` 或 `interrupt_cancel_queued_v1`。检查它以进行功能检测而不是比较版本字符串，并忽略您不认识的值。该字段需要 Claude Code v2.1.205 或更高版本，并且在早期版本中不存在。功能列表请参见[`SDKSystemMessage`](<https://code.claude.com/docs/en/agent-sdk/typescript#sdksystemmessage>)。

#### 当插件或 MCP 服务器未加载时失败 CI

使用 `system/init` 事件中的插件字段来捕获未加载的插件：

|领域|类型|描述|
| - | - | - |
| `plugins` |数组|已成功加载的插件，每个插件都有 `name` 和 `path`|
| `plugin_errors` |数组|插件加载时错误，每个错误都有 `plugin`、`type` 和 `message`。包括不满足的依赖版本和 `--plugin-dir` 加载失败，例如路径丢失或存档无效。 `plugins` 中缺少未加载的插件。没有错误时省略 key|

当 `--plugin-dir` 目录或存档本身无法加载时，其 `plugin_errors` 条目包含已解析的绝对路径为 `path`。使用它来判断几个 `--plugin-dir` 值中的哪一个失败。 `path` 字段需要 Claude Code v2.1.283 或更高版本。

以相同的方式使用 MCP 服务器字段。当您通过 `-p` 传递 [`--mcp-config`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 时，Claude Code 在运行第一回合之前会等待仍待处理的服务器，直至 [`MCP_TIMEOUT`](<https://code.claude.com/docs/en/env-vars>) 启动超时（默认为 30 秒）。具有 [ 缓存工具列表 ](<https://code.claude.com/docs/en/agent-sdk/mcp#connection-timing>) 的远程服务器会跳过等待，在 `system/init` 中显示 `pending`，并在第一次工具调用时进行连接。在 [ 自托管环境 ](<https://code.claude.com/docs/en/self-hosted-environments-configuration#connection-timing>) 中，等待时间较短。等待时间需要 Claude Code v2.1.221 或更高版本。

Claude Code 在启动时验证每个 `--mcp-config` 条目并跳过验证失败的条目，例如没有 `type` 的 `url` 条目。运行继续并干净地退出，因此检查这些字段以捕获从未加载的服务器：

|领域|类型|描述|
| - | - | - |
| `mcp_servers` |数组|会话中的 MCP 服务器，每个服务器都有 `name` 和 `status`|
| `mcp_server_errors` |数组|配置验证跳过的 `--mcp-config` 条目，每个条目都有 `name`、`type` 和 `message`。 `type` 是跳过类别，例如 `unknown_type`、`url_missing_type`、`invalid_config` 或 `reserved_name`；将您无法识别的值视为通用跳过。 `mcp_servers` 中不存在受影响的服务器。当没有错误时，密钥会被省略，因此 CI 门可能会在非空数组上失败。需要 Claude Code v2.1.219 或更高版本|

当您在终端中手动运行该命令时，Claude Code 还会向 stderr 打印启动警告，例如 `Warning: 1 MCP server skipped due to invalid config:`，后跟每个跳过条目的原因。当您重定向 stderr 时，或者当 CI 运行程序或 SDK 主机等程序捕获它时，Claude Code 不会打印任何警告，并且仅在 `mcp_server_errors` 字段中报告跳过的条目。该警告需要 Claude Code v2.1.219 或更高版本。

#### 跟踪插件安装

当设置 [`CLAUDE_CODE_SYNC_PLUGIN_INSTALL`](<https://code.claude.com/docs/en/env-vars>) 时，Claude Code 会在第一轮之前安装市场插件时发出 `system/plugin_install` 事件。使用它们在您自己的 UI 中显示安装进度。

|领域|类型|描述|
| - | - | - |
| `type` | `"system"` |消息类型|
| `subtype` | `"plugin_install"` |将其标识为插件安装事件|
| `status` |`"started"`、`"installed"`、`"failed"` 或 `"completed"`|`started`和`completed`支架整体安装； `installed` 和 `failed` 报告各个市场|
| `name` |字符串，可选|市场名称，出现在 `installed` 和 `failed` 上|
| `error` |字符串，可选|失败消息，出现在 `failed` 上|
| `uuid` |字符串|唯一的事件标识符|
| `session_id` |字符串|事件所属的会话|

### 自动批准工具

使用`--allowedTools`可以让Claude在没有提示的情况下使用某些工具。列出 `Read` 和 `Edit` 让 Claude 无需请求许可即可读取和编辑文件。列出 `Bash` 对 shell 命令执行相同的操作，但在以 [ 自动模式 ](<https://code.claude.com/docs/en/permission-modes#how-auto-mode-evaluates-actions>) 启动的运行中，其中 Claude Code 会删除一个裸露的 `Bash` 条目作为广泛的允许规则，而自动模式会评估每个命令。此示例运行一个测试套件并使用列出的三个工具修复故障：

```bash theme={null}
claude -p "Run the test suite and fix any failures" \
  --allowedTools "Bash,Read,Edit"
```

要为整个会话设置基线而不是列出各个工具，请传递 [ 权限模式 ](<https://code.claude.com/docs/en/permission-modes>)。没有设置权限模式的运行采用 [ 内置启动权限模式 ](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>)，可以是 `auto`，因此请传递您想要的模式：

* **`auto`**：通过`--permission-mode auto`让分类器代替你审查大多数操作
* **`dontAsk`**：Claude Code 拒绝否则会提示的每个呼叫，这对于锁定的 CI 运行很有用。在手动模式下无需批准的操作仍会运行，例如工作目录中的文件读取和 [ 只读命令集 ](<https://code.claude.com/docs/en/permissions#read-only-commands>)，以及 `--allowedTools` 条目或 `permissions.allow` 规则涵盖的操作。即使允许规则匹配，`AskUserQuestion`、连接器工具 [您的组织设置为 `ask`](<https://code.claude.com/docs/en/mcp#organization-controls-on-connector-tools>) 和标记为 [`requiresUserInteraction`](<https://code.claude.com/docs/en/mcp#require-approval-for-a-specific-tool>) 的 MCP 工具也会被拒绝
* **`acceptEdits`**：Claude在没有提示的情况下写入文件，Claude Code自动批准常见文件系统命令，例如`mkdir`、`touch`、`mv`和`cp`。 [无模式自动批准的操作](<https://code.claude.com/docs/en/permission-modes#actions-no-mode-auto-approves>)仍然适用。除了只读命令集之外，其他 shell 命令和网络请求仍然需要 `--allowedTools` 条目或 `permissions.allow` 规则。请参阅 [`acceptEdits` 自动批准的内容 ](<https://code.claude.com/docs/en/permission-modes#auto-approve-file-edits-with-acceptedits-mode>) 以获取完整列表

此示例应用以 `acceptEdits` 作为基线的 lint 修复：

```bash theme={null}
claude -p "Apply the lint fixes" --permission-mode acceptEdits
```

### 在无人值守运行中关闭权限提示

当没有人可以回答权限提示时（例如在计划的作业中），请传递 `--permission-prompts none`。当您的运行具有权限主机时，该标志最重要：具有 [`canUseTool` 回调 ](<https://code.claude.com/docs/en/agent-sdk/user-input>) 的 Agent SDK 应用程序，或使用 [`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 传递的 MCP 工具。如果没有该标志，您的运行将等待该主机回答每个权限请求。

有了该标志，您的运行就不会咨询主机或等待主机。除非 `PermissionRequest` 挂钩允许，否则任何提示都会被拒绝，Claude 被告知没有人可以批准该请求并且不能重试，然后运行继续。在没有主机的情况下运行的 `-p` 中，这些请求都会被拒绝，并且该标志还告诉 Claude 不要重试它们。权限规则，[`PermissionRequest` hooks](<https://code.claude.com/docs/en/hooks#permissionrequest>)，每次调用还是由你设置的权限模式决定； Claude Code 仅拒绝其他无法解决的请求。

此示例在 [ 自动模式 ](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) 下运行无人值守任务。分类器像往常一样审查每个操作，并且 Claude Code 拒绝任何会退回到提示的操作：

```bash theme={null}
claude -p "Update the dependency pins and run the tests" --permission-mode auto --permission-prompts none
```

与 `--permission-prompts none`, Claude Code 删除需要人回答的工具，例如 [`AskUserQuestion`](<https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior>)，所以 Claude 不能打电话给他们。任意 [MCP 启发请求](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>) 那不 [`Elicitation` 钩子](<https://code.claude.com/docs/en/hooks#elicitation>) 答案被取消。

对于`--output-format stream-json`，拒绝显示为`permission_denied`系统消息，最终结果消息将它们列在`permission_denials`中。



**注释：**

`--permission-prompts` 标志需要 Claude Code v2.1.259 或更高版本。早期版本拒绝它并出现未知选项错误。


### 创建提交

此示例审查分阶段的更改并使用适当的消息创建提交：

```bash theme={null}
claude -p "Look at my staged changes and create an appropriate commit" \
  --allowedTools "Bash(git diff *),Bash(git log *),Bash(git status *),Bash(git commit *)"
```

`--allowedTools` 标志使用 [ 权限规则语法 ](<https://code.claude.com/docs/en/settings-reference#permission-rule-syntax>)。尾随的 ` *` 启用前缀匹配，因此 `Bash(git diff *)` 允许任何以 `git diff` 开头的命令。 `*` 之前的空格很重要：没有它，`Bash(git diff*)` 也会匹配 `git diff-index`。



**注释：**

`-p` 模式下的命令支持有所不同：

  * 用户调用的 [ 技能 ](<https://code.claude.com/docs/en/skills>) 和自定义命令有效。在提示字符串中包含 `/skill-name`，Claude Code 在运行前将其展开。
  * 仅在终端界面中运行的内置命令（例如 `/login`）不可用。
  * `/model`、`/effort`、`/fast`、`/color` 和 `/rename` 接受值作为参数，例如 `/model sonnet` 和不带参数的 `/mcp` 打印服务器状态的文本摘要。这些表格需要 Claude Code v2.1.205 或更高版本，并遵循每个命令的 [ 可用性说明 ](<https://code.claude.com/docs/en/commands#all-commands>)。
  * 要更改设置，请将 `key=value` 传递到 `/config`，例如 `/config thinking=false`。
  * `/output-style <style>`开关[输出样式](<https://code.claude.com/docs/en/output-styles>)和`/output-style`单独列出它们。需要 Claude Code v2.1.269 或更高版本。



### 自定义系统提示

使用 `--append-system-prompt` 添加指令，同时保留 Claude Code 的默认行为。此示例将 PR diff 通过管道传输到 Claude 并指示其检查安全漏洞。将其保存为shell脚本，例如`review.sh`：

```bash theme={null}
gh pr diff "$1" | claude -p \
  --append-system-prompt "You are a security engineer. Review for vulnerabilities." \
  --output-format json
```

在脚本中，`"$1"` 代表您在命令行上传递的第一个参数。运行 `bash review.sh 123`，shell 将 `"$1"` 替换为 `123`，因此脚本会获取 PR 123 的差异。 Claude Code 将评论打印为 JSON，文本位于 `result` 字段中。

请参阅 [ 系统提示标志 ](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags>) 了解更多选项，包括 `--system-prompt` 来完全替换默认提示。

### Continue 对话

使用 `--continue` 继续最近的对话，或使用 `--resume` 与会话 ID 继续特定对话。在 Claude Code v2.1.257 或更高版本上，当您传递 `--continue` 时，Claude Code 将打开一个已完成但不是仍在运行的 [ 后台会话 ](<https://code.claude.com/docs/en/sessions#resume-a-session>)。此示例运行审核，然后发送后续提示：

```bash theme={null}
# First request
claude -p "Review this codebase for performance issues"

# Continue the most recent conversation
claude -p "Now focus on the database queries" --continue
claude -p "Generate a summary of all issues found" --continue
```

如果您正在运行多个对话，请捕获会话 ID 以恢复特定对话：

```bash theme={null}
session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"
```

您可以从不同的目录运行这两个命令： Claude Code [ 在本机上的任何项目中通过其 ID](<https://code.claude.com/docs/en/sessions#resume-a-session>) 查找会话。在 v2.1.223 之前，Claude Code 仅在当前项目目录及其 git 工作树中查找 ID，因此您必须从同一目录运行这两个命令。

您可以将 `--resume` 传递到会话 `.jsonl` [ 脚本文件 ](<https://code.claude.com/docs/en/sessions#where-transcripts-are-stored>) 的绝对路径来代替会话 ID，并且 Claude Code 继续存储在该文件中的对话。

# Run Claude Code programmatically

> Use the Agent SDK to run Claude Code programmatically from the CLI, Python, or TypeScript.

The [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) gives you the same tools, agent loop, and context management that power Claude Code. It's available as a CLI for scripts and CI/CD, or as [Python](<https://code.claude.com/docs/en/agent-sdk/python>) and [TypeScript](<https://code.claude.com/docs/en/agent-sdk/typescript>) packages for full programmatic control.

To run Claude Code in non-interactive mode, pass `-p` with your prompt and the [CLI options](<https://code.claude.com/docs/en/cli-reference>) you need:

```bash theme={null}
claude -p "Find and fix the bug in auth.py" --allowedTools "Read,Edit,Bash"
```

This page covers using the Agent SDK via the CLI (`claude -p`). For the Python and TypeScript SDK packages with structured outputs, tool approval callbacks, and native message objects, see the [full Agent SDK documentation](<https://code.claude.com/docs/en/agent-sdk/overview>).

## Basic usage

Add the `-p` (or `--print`) flag to any `claude` command to run it non-interactively. Not every [CLI option](<https://code.claude.com/docs/en/cli-reference>) combines with `-p`. Claude Code rejects `--bg`, and rejects `--cloud` with a task description, with an error naming the conflict; `--cloud` with a session ID and `-p` instead [queues a message into that cloud session](<https://code.claude.com/docs/en/claude-code-on-the-web#send-follow-ups-from-the-cli>) and exits. Options you'll combine with `-p` often include:

* `--continue` for [continuing conversations](<#continue-conversations>)
* `--allowedTools` for [auto-approving tools](<#auto-approve-tools>)
* `--output-format` for [structured output](<#get-structured-output>)

This example asks Claude a question about your codebase and prints the response:

```bash theme={null}
claude -p "What does the auth module do?"
```

Claude Code exits with code 0 on success and a non-zero code when the run fails, so your scripts can branch on the exit status. If you pass an invalid flag, Claude Code reports the error to stderr before the run starts. When a failure happens inside the run, such as missing authentication, Claude Code prints the failure as the result on stdout.

### Start faster with bare mode

Add `--bare` to reduce startup time by skipping auto-discovery of hooks, skills, custom commands, [subagents](<https://code.claude.com/docs/en/sub-agents>), installed plugins, MCP servers, auto memory, and CLAUDE.md. Without it, `claude -p` loads the same [context](<https://code.claude.com/docs/en/how-claude-code-works#the-context-window>) an interactive session would, including anything configured in the working directory or `~/.claude`.

Bare mode is useful for CI and scripts where you need the same result on every machine. A hook in a teammate's `~/.claude` or an MCP server in the project's `.mcp.json` won't run, because bare mode never reads them. A directory you name with `--add-dir` is a partial exception: bare mode loads skills from its `.claude/skills/` folder, but still skips its `.claude/commands/` and `.claude/agents/` folders. [Skills from additional directories](<https://code.claude.com/docs/en/skills#skills-from-additional-directories>) covers what does and doesn't load.

Without `--bare`, a `-p` session runs the hooks in a project's `.claude/settings.json` and connects the servers in its `.mcp.json`, even in a folder you've never trusted. A `-p` session shows no workspace trust dialog and no per-server approval prompt. [What runs before you trust a folder](<https://code.claude.com/docs/en/permissions#what-runs-before-you-trust-a-folder>) covers each kind of repository content under `-p` and how to keep it out.

This example runs a one-off summarize task in bare mode and pre-approves the Read tool so the call completes without a permission prompt. Set `ANTHROPIC_API_KEY` before running it, because bare mode doesn't use your subscription login:

```bash theme={null}
claude --bare -p "Summarize README.md" --allowedTools "Read"
```

In bare mode, Claude Code never reads OAuth credentials or the system keychain. For the Anthropic API, set `ANTHROPIC_API_KEY` in the environment, with a key created in the [Claude Console](<https://platform.claude.com>), or supply an `apiKeyHelper` in the `--settings` JSON. Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry continue to read their own provider credentials as usual.

In bare mode Claude has access to the Bash, file read, and file edit tools. Pass any context you need with a flag:

| To load | Use |
| - | - |
| System prompt additions | `--append-system-prompt`, `--append-system-prompt-file` |
| Settings | `--settings <file-or-json>` |
| MCP servers | `--mcp-config <file-or-json>` |
| [Custom agents](<https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope>) | `--agents <file-or-json>` |
| A plugin | `--plugin-dir <path>`, `--plugin-url <url>` |

Bare mode also limits what happens while the session runs:

* **MCP servers**: only servers supplied on the command line connect, for example with `--mcp-config`. In an interactive session, Claude Code also skips the automatic IDE connection unless you pass `--ide`.
* **System reminders**: Claude gets your prompts and the tool results without the [system reminders](<https://code.claude.com/docs/en/glossary#system-reminder>) Claude Code would add alongside them. For example, Claude isn't told when a file it read earlier changes on disk, and it doesn't get the list of available skills, including skills from an `--add-dir` folder.
* **Background tasks**: none run. A command that reaches its [timeout](<https://code.claude.com/docs/en/tools-reference#timeout-and-output-limits>) stops instead of [moving to the background](<https://code.claude.com/docs/en/tools-reference#background-commands>).

Before v2.1.286, these limits held only partly: an interactive `--bare` session connected the MCP servers that a normal session would, every `--bare` session sent system reminders, and background tasks stayed available.



**注释：**

  `--bare` is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release.


### Background tasks at exit

After Claude finishes its turn and stdin has closed, a `claude -p` run can stay open to wait for background work that Claude started.

Unless a background command that the main conversation started is still running, Claude Code stops whatever is still running after 10 minutes of continuous idle waiting by default and drops its partial result. To change the 10-minute cap, set [`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`](<https://code.claude.com/docs/en/env-vars>), or set it to `0` to wait without one.

The run waits for background work such as background commands, subagents and workflows, Monitor watches, and pending `/loop` wakeups:

* **[Background commands](<https://code.claude.com/docs/en/tools-reference#background-commands>)**: for a command that the main conversation started, for example a dev server or a watch build, the run waits until the command exits or reaches its [time limit](<https://code.claude.com/docs/en/tools-reference#time-limit-for-background-commands>). Claude then takes one more turn with the outcome. While the command runs, the 10-minute cap doesn't end the wait.
* **Background [subagents](<https://code.claude.com/docs/en/sub-agents>) and workflows**: the run stays open until that work completes, because its result is part of the final output.
* **[Monitor](<https://code.claude.com/docs/en/tools-reference#monitor-tool>) watches**: the run waits until the watch times out or the 10-minute cap ends the wait, whichever comes first. While it waits, Claude keeps responding to what the watch reports. By default, a watch times out five minutes after Claude starts it.
* **Pending wakeups**: in a run whose prompt you passed as text rather than with `--input-format stream-json`, when Claude has scheduled a [self-paced `/loop` wakeup](<https://code.claude.com/docs/en/scheduled-tasks#let-claude-choose-the-interval>), the run waits for each wakeup to fire and runs its iteration until the [loop ends](<https://code.claude.com/docs/en/scheduled-tasks#stop-a-loop>), even past the 10-minute cap.

When stderr is a terminal and the run has waited five seconds, Claude Code prints a line to stderr that starts with `Waiting for background work to finish` and names the work. With [`json` or `stream-json` output](<#get-structured-output>), the line prints only when stdout isn't a terminal, so the JSON your script reads never carries it.

If the run reaches its [`--max-budget-usd`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) cap, Claude Code stops the remaining background work instead of waiting.

When background work starts another turn, the run prints each turn's result with the default `text` output and the last turn's result with `json` output. Before v2.1.295, the run printed only the last turn's result with `text` output too.

### Stop a run with SIGTERM

If you stop a `claude -p` run with SIGTERM, for example with `kill` or from a process supervisor, Claude Code exits with code 143. Claude Code leaves the turn that was in progress unfinished and records no result for it. To end the turn instead, send SIGINT, or call the Agent SDK's `interrupt()`, before you stop the process.

On SIGTERM, Claude Code terminates the process tree of any Bash command that is still running. Claude Code then runs [`SessionEnd` hooks](<https://code.claude.com/docs/en/hooks#sessionend>) and exits. While exiting, Claude Code starts no new tool call, sends no new model request, and runs no hook other than `SessionEnd`. If the run was in the middle of a command or waiting on a permission prompt when the signal arrived, Claude Code handles that step as follows:

* **Running a command**: Claude Code records the command as killed in the session.
* **Waiting for an answer to a permission prompt**: if you send SIGTERM to the process, Claude Code leaves the prompt unanswered. If your program closes the session through the Agent SDK, the SDK ends Claude Code's input before sending any signal, and Claude Code cancels the prompt as soon as the input ends.

When you [resume the session](<#continue-conversations>), Claude Code leaves the interrupted turn as it is, and your next prompt drives the conversation. To have Claude Code continue the interrupted turn on resume instead, set [`CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1`](<https://code.claude.com/docs/en/env-vars>).

### If the working directory is deleted

If the working directory of a `claude -p` or Agent SDK session is deleted mid-session, the session keeps running. When a turn starts while the directory is missing, Claude Code emits a [warning message](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkinformationalmessage>) in `stream-json` output, and shell commands fail until the directory exists again.

## Examples

These examples highlight common CLI patterns. Where a command names a file such as `auth.py` or `build-error.txt`, substitute a file from your own project. In CI or other scripted environments, add [`--bare`](<#start-faster-with-bare-mode>) so Claude Code starts without loading the host's hooks, plugins, auto memory, or `CLAUDE.md`.

### Pipe data through Claude

Non-interactive mode reads stdin, so you can pipe data in and redirect the response out like any other command-line tool.

This example pipes a build log into Claude and writes the explanation to a file:

```bash theme={null}
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
```

With `--output-format json`, the response payload includes `total_cost_usd` and a per-model cost breakdown, so scripted callers can track spend without consulting the [usage dashboard](<https://code.claude.com/docs/en/costs>). When you continue an earlier conversation with `--continue` or `--resume`, the run reports the conversation's whole total, [earlier runs' spend included](<https://code.claude.com/docs/en/agent-sdk/cost-tracking#accumulate-costs-across-multiple-calls>). Both figures are [client-side estimates](<https://code.claude.com/docs/en/agent-sdk/cost-tracking>) and can differ from your actual bill.



**注释：**

  Piped stdin is capped at 10MB. If you exceed the cap, Claude Code exits with a clear error and a non-zero status. To work with larger inputs, write the content to a file and reference the file path in your prompt instead of piping it.


If Claude Code can't read stdin, for example because the process that started it disconnected its end, Claude Code prints a warning to stderr and continues with the prompt from the command line. Before v2.1.211, an unreadable stdin on Windows crashed the session or made it exit silently with no output.

### Add Claude to a build script

You can wrap a non-interactive call in a script to use Claude as a project-specific linter or reviewer.

This `package.json` script pipes the diff against `main` into Claude and asks it to report typos. Piping the diff means Claude doesn't need Bash permission to read it, and the escaped double quotes keep the script portable to Windows:

```json theme={null}
{
  "scripts": {
    "lint:claude": "git diff main | claude -p \"you are a typo linter. for each typo in this diff, report filename:line on one line and the issue on the next. return nothing else.\""
  }
}
```

Run it with `npm run lint:claude`.

### Get structured output

Use `--output-format` to control how responses are returned:

* `text` (default): plain text output
* `json`: structured JSON with result, session ID, and metadata
* `stream-json`: newline-delimited JSON for real-time streaming

This example returns a project summary as JSON with session metadata, with the text result in the `result` field:

```bash theme={null}
claude -p "Summarize this project" --output-format json
```

To get output conforming to a specific schema, use `--output-format json` with `--json-schema` and a [JSON Schema](<https://json-schema.org/>) definition. The response includes metadata about the request (session ID, usage, etc.) with the structured output in the `structured_output` field.

This example extracts function names and returns them as an array of strings:

```bash theme={null}
claude -p "Extract the main function names from auth.py" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}'
```

If the value isn't a valid JSON Schema, `claude` exits with `Error: --json-schema is not a valid JSON Schema` followed by the validator's diagnostic. Claude Code accepts schemas that use the `format` keyword, such as `"format": "email"`, but treats `format` as an annotation and doesn't enforce it. Before v2.1.205, Claude Code silently ignored an invalid schema and returned unstructured text, and treated any schema containing `format` as invalid.



**提示：**

  Use a tool like [jq](<https://jqlang.org/>) to parse the response and extract specific fields:

  ```bash theme={null}
  # Extract the text result
  claude -p "Summarize this project" --output-format json | jq -r '.result'

  # Extract structured output
  claude -p "Extract function names from auth.py" \
    --output-format json \
    --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
    | jq '.structured_output'
  ```



### Stream responses

Use `--output-format stream-json` with `--verbose` and `--include-partial-messages` to receive tokens as they're generated. Each line is a JSON object representing an event:

```bash theme={null}
claude -p "Explain recursion" --output-format stream-json --verbose --include-partial-messages
```

The last line of the stream is a `result` message with the final response text, cost, and session metadata.

If your consumer reads the stream slowly, Claude Code waits for the queued output to drain before exiting, scaling the wait with how much is still queued, capped at 30 seconds. Before v2.1.214 the exit wait was capped at about two seconds, which could cut off the end of a large response.

The following example uses [jq](<https://jqlang.org/>) to filter for text deltas and display only the streaming text. The `-r` flag outputs raw strings (no quotes) and `-j` joins without newlines so tokens stream continuously:

```bash theme={null}
claude -p "Write a poem" --output-format stream-json --verbose --include-partial-messages | \
  jq -rj 'select(.type == "stream_event" and .event.delta.type? == "text_delta") | .event.delta.text'
```

For programmatic streaming with callbacks and message objects, see [Stream responses in real-time](<https://code.claude.com/docs/en/agent-sdk/streaming-output>) in the Agent SDK documentation.

#### Follow subagent messages

Messages from [subagents](<https://code.claude.com/docs/en/sub-agents>) and from skills that [run in a subagent](<https://code.claude.com/docs/en/skills#run-skills-in-a-subagent>) appear in the stream as `assistant` and `user` messages. Their `parent_tool_use_id` field says which run each one belongs to. Messages from the main conversation carry `null` in that field.

The first message from a forked skill, or from a subagent running in the [foreground](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>), is a `user` message carrying the prompt or skill content that drives it. After that first message, Claude Code emits:

* **By default**: the run's `tool_use` and `tool_result` blocks.
* **With [`--forward-subagent-text`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) or [`CLAUDE_CODE_FORWARD_SUBAGENT_TEXT`](<https://code.claude.com/docs/en/env-vars>)**: the run's text and thinking blocks too, so you can reconstruct each run's transcript.

When you enable either option, Claude Code forwards messages from [subagents at every nesting depth](<https://code.claude.com/docs/en/sub-agents#let-subagents-spawn-their-own-subagents>), whether each one was spawned with the Agent tool or started as a forked skill. In `parent_tool_use_id`, the nested subagent's messages carry the ID of the Agent or Skill tool call that started it, so you can rebuild the full nesting tree by following those IDs.

A run that Claude starts with a tool call carries that tool call's ID. A forked skill that you start by passing `/<skill-name>` as the prompt has no tool call, so its messages carry a `forked-command-` value instead and arrive after it finishes. Find how the run started in the first column:

| How the run starts | `parent_tool_use_id` | When its messages arrive |
| :- | :- | :- |
| Claude calls the Agent tool from the main conversation | The ID of that Agent `tool_use` block | While the subagent works |
| Claude calls the Skill tool for a forked skill from the main conversation | The ID of that Skill `tool_use` block | While the forked skill works |
| You pass `/<skill-name>` as the prompt | A value that starts with `forked-command-` | Together and in order after the forked skill finishes |

For a forked skill started from the prompt, match `parent_tool_use_id` on the `forked-command-` prefix, because the name after it can differ from the one you typed.

If some of these messages are missing from your stream, check your Claude Code version against these minimums:

* **`--forward-subagent-text` and `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT`**: v2.1.211 or later
* **Forwarding at every nesting depth**: v2.1.219 or later
* **A forked skill that Claude starts with the Skill tool from the main conversation**: v2.1.86 or later for its `tool_use` and `tool_result` blocks, and v2.1.265 or later for its first `user` message and its text and thinking blocks
* **Messages of subagents that a forked skill spawns, and of forked skills started inside a subagent or another forked skill**: v2.1.275 or later
* **Messages of a forked skill you start by passing `/<skill-name>` as the prompt**: v2.1.287 or later

#### Handle API retries

When an API request fails with a retryable error, Claude Code emits a `system/api_retry` event before retrying. On v2.1.246 or later, when a `401` or `403` rejects an [`apiKeyHelper`](<https://code.claude.com/docs/en/settings-reference#apikeyhelper>) credential, Claude Code makes the first two retries quietly with no event, then emits the event as usual from the third consecutive retry onward. The quiet retries still count toward `attempt`. You can use the event to show retry progress in your own interface.

| Field | Type | Description |
| - | - | - |
| `type` | `"system"` | message type |
| `subtype` | `"api_retry"` | identifies this as a retry event |
| `attempt` | integer | current attempt number, starting at 1 |
| `max_retries` | integer | total retries permitted for this failure's cause |
| `retry_delay_ms` | integer | milliseconds until the next attempt |
| `error_status` | integer or null | HTTP status code of the failed attempt, or `null` when the attempt got no HTTP response from the API |
| `no_response` | object, optional | present only when the failed attempt got [no response headers in time](<https://code.claude.com/docs/en/errors#no-response-from-api>). `waited_ms` is how long that attempt waited and `retry_wait_ms` is how long the retry will wait. Requires Claude Code v2.1.261 or later |
| `error` | string | error category: `authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `billing_error`, `rate_limit`, `overloaded`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `cloud_credential_error`, or `unknown` |
| `uuid` | string | unique event identifier |
| `session_id` | string | session the event belongs to |

#### Read session metadata

The `system/init` event reports session metadata including the model, tools, MCP servers, and loaded plugins. It is the first event in the stream unless startup events precede it:

* `plugin_install` events, when [`CLAUDE_CODE_SYNC_PLUGIN_INSTALL`](<https://code.claude.com/docs/en/env-vars>) is set.
* [`hook_started`, `hook_progress`, and `hook_response` events](<https://code.claude.com/docs/en/agent-sdk/typescript#sdkhookstartedmessage>), while a configured [`SessionStart`](<https://code.claude.com/docs/en/hooks#sessionstart>) or [`Setup`](<https://code.claude.com/docs/en/hooks#setup>) hook runs. These stream as the hook produces them. Claude Code v2.1.169 through v2.1.203 delivered them in one batch after the hook completed, still ahead of `system/init`; v2.1.204 restored live delivery.

The event also carries an optional `capabilities` array of strings naming the protocol behaviors this Claude Code version implements, such as `interrupt_receipt_v1` or `interrupt_cancel_queued_v1`. Check it to feature-detect instead of comparing version strings, and ignore values you don't recognize. The field requires Claude Code v2.1.205 or later and is absent from earlier versions. See [`SDKSystemMessage`](<https://code.claude.com/docs/en/agent-sdk/typescript#sdksystemmessage>) for the capability list.

#### Fail CI when a plugin or MCP server doesn't load

Use the plugin fields in the `system/init` event to catch a plugin that didn't load:

| Field | Type | Description |
| - | - | - |
| `plugins` | array | plugins that loaded successfully, each with `name` and `path` |
| `plugin_errors` | array | plugin load-time errors, each with `plugin`, `type`, and `message`. Includes unsatisfied dependency versions and `--plugin-dir` load failures such as a missing path or invalid archive. A plugin that didn't load is absent from `plugins`. The key is omitted when there are no errors |

When a `--plugin-dir` directory or archive itself fails to load, its `plugin_errors` entry includes the resolved absolute path as `path`. Use it to tell which of several `--plugin-dir` values failed. The `path` field requires Claude Code v2.1.283 or later.

Use the MCP server fields the same way. When you pass [`--mcp-config`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) with `-p`, Claude Code waits for still-pending servers before running the first turn, up to the [`MCP_TIMEOUT`](<https://code.claude.com/docs/en/env-vars>) startup timeout, 30 seconds by default. A remote server with a [cached tool list](<https://code.claude.com/docs/en/agent-sdk/mcp#connection-timing>) skips the wait, shows `pending` in `system/init`, and connects on its first tool call. In a [self-hosted environment](<https://code.claude.com/docs/en/self-hosted-environments-configuration#connection-timing>), a shorter wait applies instead. The wait requires Claude Code v2.1.221 or later.

Claude Code validates each `--mcp-config` entry at startup and skips entries that fail validation, for example a `url` entry with no `type`. The run continues and exits cleanly, so check these fields to catch a server that never loaded:

| Field | Type | Description |
| - | - | - |
| `mcp_servers` | array | MCP servers in the session, each with `name` and `status` |
| `mcp_server_errors` | array | `--mcp-config` entries skipped by config validation, each with `name`, `type`, and `message`. `type` is a skip category such as `unknown_type`, `url_missing_type`, `invalid_config`, or `reserved_name`; treat values you don't recognize as a generic skip. Affected servers are absent from `mcp_servers`. The key is omitted when there are no errors, so a CI gate can fail on a non-empty array. Requires Claude Code v2.1.219 or later |

When you run the command by hand in a terminal, Claude Code also prints a startup warning to stderr, such as `Warning: 1 MCP server skipped due to invalid config:`, followed by the reason for each skipped entry. When you redirect stderr, or when a program such as a CI runner or an SDK host captures it, Claude Code prints no warning and reports the skipped entries only in the `mcp_server_errors` field. The warning requires Claude Code v2.1.219 or later.

#### Track plugin installs

When [`CLAUDE_CODE_SYNC_PLUGIN_INSTALL`](<https://code.claude.com/docs/en/env-vars>) is set, Claude Code emits `system/plugin_install` events while marketplace plugins install before the first turn. Use these to surface install progress in your own UI.

| Field | Type | Description |
| - | - | - |
| `type` | `"system"` | message type |
| `subtype` | `"plugin_install"` | identifies this as a plugin install event |
| `status` | `"started"`, `"installed"`, `"failed"`, or `"completed"` | `started` and `completed` bracket the overall install; `installed` and `failed` report individual marketplaces |
| `name` | string, optional | marketplace name, present on `installed` and `failed` |
| `error` | string, optional | failure message, present on `failed` |
| `uuid` | string | unique event identifier |
| `session_id` | string | session the event belongs to |

### Auto-approve tools

Use `--allowedTools` to let Claude use certain tools without prompting. Listing `Read` and `Edit` lets Claude read and edit files without asking for permission. Listing `Bash` does the same for shell commands, except in a run that starts in [auto mode](<https://code.claude.com/docs/en/permission-modes#how-auto-mode-evaluates-actions>), where Claude Code drops a bare `Bash` entry as a broad allow rule and auto mode evaluates each command instead. This example runs a test suite and fixes failures with those three tools listed:

```bash theme={null}
claude -p "Run the test suite and fix any failures" \
  --allowedTools "Bash,Read,Edit"
```

To set a baseline for the whole session instead of listing individual tools, pass a [permission mode](<https://code.claude.com/docs/en/permission-modes>). A run where nothing sets a permission mode takes the [built-in starting permission mode](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>), which can be `auto`, so pass the one you want:

* **`auto`**: pass `--permission-mode auto` to have a classifier review most actions instead of you
* **`dontAsk`**: Claude Code denies every call that would otherwise prompt, which is useful for locked-down CI runs. Actions that need no approval in Manual mode still run, such as file reads in your working directories and the [read-only command set](<https://code.claude.com/docs/en/permissions#read-only-commands>), and so do actions your `--allowedTools` entries or `permissions.allow` rules cover. `AskUserQuestion`, connector tools [your organization set to `ask`](<https://code.claude.com/docs/en/mcp#organization-controls-on-connector-tools>), and MCP tools marked [`requiresUserInteraction`](<https://code.claude.com/docs/en/mcp#require-approval-for-a-specific-tool>) are denied even when an allow rule matches
* **`acceptEdits`**: Claude writes files without prompting, and Claude Code auto-approves common filesystem commands such as `mkdir`, `touch`, `mv`, and `cp`. The [actions no mode auto-approves](<https://code.claude.com/docs/en/permission-modes#actions-no-mode-auto-approves>) still apply. Apart from the read-only command set, other shell commands and network requests still need an `--allowedTools` entry or a `permissions.allow` rule. See [what `acceptEdits` auto-approves](<https://code.claude.com/docs/en/permission-modes#auto-approve-file-edits-with-acceptedits-mode>) for the full list

This example applies lint fixes with `acceptEdits` as the baseline:

```bash theme={null}
claude -p "Apply the lint fixes" --permission-mode acceptEdits
```

### Turn off permission prompts in unattended runs

Pass `--permission-prompts none` when nobody is available to answer permission prompts, for example in a scheduled job. The flag matters most when your run has a permission host: an Agent SDK app with a [`canUseTool` callback](<https://code.claude.com/docs/en/agent-sdk/user-input>), or an MCP tool you pass with [`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>). Without the flag, your run waits for that host to answer each permission request.

With the flag, your run doesn't consult the host or wait on it. Anything that would prompt is denied unless a `PermissionRequest` hook allows it, Claude is told that nobody can approve the request and not to retry it, and the run continues. In a `-p` run with no host, these requests are denied either way, and the flag also tells Claude not to retry them. Permission rules, [`PermissionRequest` hooks](<https://code.claude.com/docs/en/hooks#permissionrequest>), and the permission mode you set still decide every call first; Claude Code denies only the requests that nothing else resolves.

This example runs an unattended task in [auto mode](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>). The classifier reviews each action as usual, and Claude Code denies anything that would have fallen back to a prompt:

```bash theme={null}
claude -p "Update the dependency pins and run the tests" --permission-mode auto --permission-prompts none
```

With `--permission-prompts none`, Claude Code removes the tools that need an answer from a person, such as [`AskUserQuestion`](<https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior>), so Claude can't call them. Any [MCP elicitation request](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>) that no [`Elicitation` hook](<https://code.claude.com/docs/en/hooks#elicitation>) answers is cancelled.

With `--output-format stream-json`, denials appear as `permission_denied` system messages, and the final result message lists them in `permission_denials`.



**注释：**

  The `--permission-prompts` flag requires Claude Code v2.1.259 or later. Earlier versions reject it with an unknown-option error.


### Create a commit

This example reviews staged changes and creates a commit with an appropriate message:

```bash theme={null}
claude -p "Look at my staged changes and create an appropriate commit" \
  --allowedTools "Bash(git diff *),Bash(git log *),Bash(git status *),Bash(git commit *)"
```

The `--allowedTools` flag uses [permission rule syntax](<https://code.claude.com/docs/en/settings-reference#permission-rule-syntax>). The trailing ` *` enables prefix matching, so `Bash(git diff *)` allows any command starting with `git diff`. The space before `*` is important: without it, `Bash(git diff*)` would also match `git diff-index`.



**注释：**

  Command support differs in `-p` mode:

  * User-invoked [skills](<https://code.claude.com/docs/en/skills>) and custom commands work. Include `/skill-name` in the prompt string and Claude Code expands it before running.
  * Built-in commands that only run in the terminal interface, such as `/login`, aren't available.
  * `/model`, `/effort`, `/fast`, `/color`, and `/rename` accept the value as an argument, for example `/model sonnet`, and `/mcp` with no argument prints a text summary of server status. These forms require Claude Code v2.1.205 or later and follow each command's [availability notes](<https://code.claude.com/docs/en/commands#all-commands>).
  * To change a setting, pass `key=value` to `/config`, for example `/config thinking=false`.
  * `/output-style <style>` switches [output styles](<https://code.claude.com/docs/en/output-styles>) and `/output-style` alone lists them. Requires Claude Code v2.1.269 or later.



### Customize the system prompt

Use `--append-system-prompt` to add instructions while keeping Claude Code's default behavior. This example pipes a PR diff to Claude and instructs it to review for security vulnerabilities. Save it as a shell script, for example `review.sh`:

```bash theme={null}
gh pr diff "$1" | claude -p \
  --append-system-prompt "You are a security engineer. Review for vulnerabilities." \
  --output-format json
```

In the script, `"$1"` stands for the first argument you pass on the command line. Run `bash review.sh 123` and the shell replaces `"$1"` with `123`, so the script fetches the diff for PR 123. Claude Code prints the review as JSON, with the text in the `result` field.

See [system prompt flags](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags>) for more options including `--system-prompt` to fully replace the default prompt.

### Continue conversations

Use `--continue` to continue the most recent conversation, or `--resume` with a session ID to continue a specific conversation. On Claude Code v2.1.257 or later, when you pass `--continue`, Claude Code opens a [background session](<https://code.claude.com/docs/en/sessions#resume-a-session>) that has finished, but not one that is still running. This example runs a review, then sends follow-up prompts:

```bash theme={null}
# First request
claude -p "Review this codebase for performance issues"

# Continue the most recent conversation
claude -p "Now focus on the database queries" --continue
claude -p "Generate a summary of all issues found" --continue
```

If you're running multiple conversations, capture the session ID to resume a specific one:

```bash theme={null}
session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"
```

You can run the two commands from different directories: Claude Code [finds the session by its ID](<https://code.claude.com/docs/en/sessions#resume-a-session>) in any project on this machine. Before v2.1.223, Claude Code looked for the ID only in the current project directory and its git worktrees, so you had to run both commands from the same directory.

In place of the session ID, you can pass `--resume` the absolute path to a session's `.jsonl` [transcript file](<https://code.claude.com/docs/en/sessions#where-transcripts-are-stored>), and Claude Code continues the conversation stored in that file.
