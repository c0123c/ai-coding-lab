# 管理会话

> 姓名、简历、分支以及在 Claude Code 对话之间切换。涵盖 `--continue`、`--resume`、`--from-pr`、`/resume` 选择器、会话命名、导出脚本以及存储脚本的位置。

会话是与项目目录关联的保存的对话。 Claude Code 在您工作时将其存储在本地，以便您可以从上次中断的位置继续、分支以尝试不同的方法或在任务之间切换。

[桌面应用程序](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>)、[claude.ai/code](<https://code.claude.com/docs/en/claude-code-on-the-web>)和[VS Code扩展](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>)各自保留自己的会话列表，并且桌面应用程序还可以[恢复CLI会话](<https://code.claude.com/docs/en/desktop#coming-from-the-cli>)。本页涵盖CLI。

## 恢复会话

当您工作时，会话会连续保存到[本地脚本文件](<#导出并定位会话数据>)，因此您可以在退出或运行`/clear`后返回到一个。使用这些入口点：

|命令|它的作用|
| :- | :- |
| `claude --continue` |重新打开当前目录中的最近对话|
| `claude --resume` |打开 [ 会话选择器 ](<#使用会话选择器>)|
| `claude --resume <name>` |直接恢复指定的会话|
| `claude --resume <transcript-path>` |恢复存储在 `.jsonl` [ 脚本文件 ](<#记录的存储位置>) 中该绝对路径的对话|
| `claude --from-pr <number>` |打开过滤到链接到该拉取请求的会话的会话选择器|
| `/resume` |从活动会话内切换到不同的对话|

Claude Code 离开创建的会话 [`claude -p`](<https://code.claude.com/docs/en/headless>) 或 [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) 退出会话选择器并退出 `claude --continue`。您仍然可以通过传递会话来恢复它 ID 到 `claude --resume <session-id>`。与 `claude --continue`, Claude Code 也跳过 [第一个提示是的会话 `/loop`](<#会话选择器的外观>)。当你跑步时 [`claude -p --continue`](<https://code.claude.com/docs/en/headless#continue-conversations>), Claude Code 包括 `-p`, SDK, 和 `/loop` 会议。

您可以从任何目录运行 `claude --resume <session-id>`，因此您可以恢复在其他位置启动或随 [`/cd`](<https://code.claude.com/docs/en/commands>) 移动的会话。 Claude Code 按以下顺序查找 ID：

1. 当前项目目录及其 git 工作树
2. 这台机器上的所有其他项目

仅当另一个项目恰好持有包含其消息的记录时，跨项目搜索才会解析 ID，因此手动复制的副本会使 Claude Code 报告找不到，而不是恢复任意副本。如果没有存储的会话与 ID 匹配，则 Claude Code 报告 `No conversation found with session ID: <session-id>`。

在 v2.1.223 之前，查找停止在当前项目目录及其 git 工作树，因此您必须从会话上次工作的目录恢复。

`claude --continue` 打开一个已完成的 [ 后台会话 ](<https://code.claude.com/docs/en/agent-view>)，但不是仍在运行的会话；打开已完成的后台会话需要 Claude Code v2.1.257 或更高版本。如果您最近的对话是您 [ 移至后台 ](<https://code.claude.com/docs/en/agent-view#send-the-session-to-the-background>) 并且仍在运行，则 Claude Code 将退出并显示 `Your most recent conversation is running in the background` 和该会话的 ID。从 [`claude agents`](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>) 附加到会话，或运行 `claude --resume` 选择另一个会话。

<h3 id="resume-a-running-background-session">
 恢复正在运行的后台会话
</h3>

当您与 `claude --resume` 或 `/resume` 恢复的对话属于仍在运行的 [ 后台会话 ](<https://code.claude.com/docs/en/agent-view>) 时，Claude Code 将打开正在运行的会话本身。在命令行上使用 `--bg`，简历将改为 [ 后台调度 ](<https://code.claude.com/docs/en/agent-view#from-your-shell>)。在v2.1.285之前，Claude Code拒绝并告诉你用`claude attach <id>`打开会话，或者先用`claude stop <id>`停止它。

* **从您的 shell**：`claude --resume <session>` 在同一终端的该会话上运行 [`claude attach`](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>)，而不是加载脚本本身。您在命令行上传递的提示（如 `claude --resume <session> "check the tests too"` 中所示）将首先进入下一轮会话，并且 Claude Code 在附加之前打印 `Sent your prompt to the background session (<id>); opening it…`。在终端上键入 `claude -p --resume <session> "prompt"` 会执行相同的操作，因此 `-p` 不会保持该运行非交互式。

当命令行有以下任一情况时，Claude Code 不会打开会话：

  * 管道或重定向的输入或输出
  * 配置会话的标志，例如 `--permission-mode`、`--model` 或 `--settings`
  * 读取输出的标志，例如 `--output-format json` 或 `--json-schema`
  * 限制或倒带运行的标志，例如 `--max-turns` 或 `--max-budget-usd`

对于其中任何一个，或者当[agent视图关闭](<https://code.claude.com/docs/en/agent-view#turn-off-agent-view>)时，Claude Code不发送任何内容并以状态1退出，打印会话正在后台运行以及打开它的`claude attach <id>`命令，或者告诉您在`claude agents`中找到它它无法确定ID。添加 `--fork-session` 以恢复对话的副本。要在您自己的会话中继续对话并应用您的标志，请运行 `claude stop <id>`，然后重复该命令。

不会发送以 `/` 或 `!` 开头的提示，并且在会话等待您回答问题时也不会发送任何提示。在这两种情况下，Claude Code 都不会打开会话，并且消息中包含带有原因的 `Your prompt was not sent to it`。
* **从会话内部**：`/resume`将当前对话移至后台并将此终端附加到正在运行的会话，打印`Opening "<title>", running in the background (<id>)`。在空提示中按 `←` 返回到 agent 视图，其中还列出了您留下的对话。当当前对话无法移动到后台时，例如因为您已附加到后台会话或会话持久性已关闭，`/resume` 会打印 `claude attach` 命令来运行。

### 恢复的会话恢复什么

当 Claude Code 从其记录中加载对话时，恢复的会话将恢复对话以及其中保存的状态：

* 对话历史记录：完整的历史记录，包括工具调用和结果。当上一个进程结束时（例如崩溃）仍在运行的工具在您恢复时不会完成或再次运行。 Claude 在记录其结果之前看到该调用被标记为已切断，并被告知在再次运行之前检查它是否生效，除非设置了 [`CLAUDE_CODE_RESUME_INTERRUPTED_TURN`](<https://code.claude.com/docs/en/env-vars#variables>)。在 v2.1.281 之前，Claude Code 将中断的通话从对话中挂断，或者将其显示给 Claude 作为您打断的通话。
* 模型：会话将在其正在使用的模型上继续，但[设置模型](<https://code.claude.com/docs/en/model-config#setting-your-model>)中的情况除外。
* Agent：会话开始于 [`--agent`](<https://code.claude.com/docs/en/sub-agents#invoke-subagents-explicitly>) 或 `agent` 设置继续如此 agent，保留其工具限制和模型。通行证 `--agent` 当继续选择另一件时；对于任一情况下的系统提示，请参阅 [恢复对话中的系统提示标志](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>). Claude Code 寻找 agent 在两个地方：会话的原始目录，前提是您有 [信任该工作空间](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>)，然后是您从中恢复的目录，因此是项目范围的 agent 当您从另一个目录恢复时仍然加载。如果 Claude Code 没有找到 agent 在任一位置，会话都会使用默认工具恢复并显示 [警告命名 agent](<https://code.claude.com/docs/en/errors#session-agent-no-longer-available>).
* 权限模式：如果您从带有 `claude --continue`、`claude --resume <session-id>` 或 `claude --resume <name>` 的终端恢复，且名称与一个会话匹配，而没有 `-p`，则 Claude Code 会恢复该会话所处的权限模式，但 [ 权限模式中的情况除外恢复](<#恢复时的权限模式>)，其中还涵盖会话选择器`/resume`，并使用`claude -p`恢复。通过`--permission-mode`或`--dangerously-skip-permissions`覆盖恢复模式。
* 活跃目标：会话结束时仍处于活跃状态的[目标](<https://code.claude.com/docs/en/goal#resume-with-an-active-goal>)结转；它的回合计数、计时器和代币支出基线重置。
* 计划任务：[未过期的任务](<https://code.claude.com/docs/en/scheduled-tasks#limitations>)恢复。后台 Bash 和监视任务则不然。
* 后台工作：以上一进程结束的 [ 后台子代理 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>)、后台 Bash 命令或 [ 工作流 ](<https://code.claude.com/docs/en/workflows>) 在恢复的记录中显示为尚未完成的注释。 Claude Code 不会从这些音符开始回合； Claude 在下一个提示时阅读它们。

并非原始启动时的每个配置标志都会被恢复。如果会话依赖于`--mcp-config`、`--settings`、`--plugin-dir`、`--fallback-model`或用`--add-dir`添加的目录，则在恢复时再次传递它们；在会话中添加 `/add-dir` 的目录也不会恢复，尽管会话选择器仍然使用它们来定位会话。标准设置文件（例如 `settings.json` 和 `settings.local.json`）会在启动时重新读取，因此不需要再次传递其中的配置。对于 `--system-prompt` 和 `--append-system-prompt`，请参阅 [恢复对话中的系统提示标志 ](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>)。

#### 恢复时的权限模式

哪种权限模式 Claude Code 启动恢复的会话取决于您恢复的方式。当 Claude Code 从其记录中加载对话时，以下情况适用；当您[打开仍在运行的后台会话](<#resume-a-running-background-session>)时，该会话将保留其所处的权限模式。

* 终端：当名称与一个会话匹配时，`claude --continue`、`claude --resume <session-id>` 或 `claude --resume <name>`，不带 `-p`。 Claude Code 恢复会话所处的权限模式，表中的情况除外。通过`--permission-mode`或`--dangerously-skip-permissions`覆盖恢复模式。
* 非交互式： `claude -p --resume` 或 `claude -p --continue`. Claude Code 以新的权限模式启动运行 `claude -p` 运行将开始，但以计划模式结束的会话将在计划模式下恢复 [以下条件](<#resume-in-plan-mode-with-p>).
* VS Code：分机的通话面板。该表仅涵盖以计划模式结束的对话；其余内容请参见[恢复过去的对话](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>)。
* 启动时的会话选择器：您从 [ 会话选择器 ](<#使用会话选择器>) 中选择的会话，无论您是单独使用 `claude --resume`、`claude --from-pr` 打开它，还是使用与多个会话匹配的名称打开它。 Claude Code 以权限模式启动会话，它将从同一命令行启动新会话，但以计划模式结束的会话将以计划模式恢复，除非您传递 `--permission-mode`、`--dangerously-skip-permissions` 或 `--fork-session`。不会恢复其他存储的权限模式。
* `/resume` 在会话内，带或不带参数：您切换到的对话将在当前会话所处的权限模式下继续，但在计划模式下结束的对话会在计划模式下恢复，即使您使用 `--permission-mode` 或 `--dangerously-skip-permissions` 启动 Claude Code。如果该对话在本次 Claude Code 运行的早期已经打开，例如您开始的对话或您使用 `/clear` 或 `/resume` 留下的对话，则它将继续以您当前的权限模式进行。

在非交互式和 VS Code 路径上恢复计划模式需要 Claude Code v2.1.246 或更高版本。每行都指定会话结束的权限模式、您恢复会话所用的终端、非交互式和 VS Code 路径，以及启动恢复的会话的权限模式 Claude Code。

|会议结束于|你如何恢复|恢复后的权限模式|
| :- | :- | :- |
| `bypassPermissions` |终端|新会话将启动的权限模式。要再次[绕过权限](<https://code.claude.com/docs/en/permission-modes#skip-all-checks-with-bypasspermissions-mode>)，请在启动时使用其启动标志之一或[用户中的`permissions.defaultMode: "bypassPermissions"`、`--settings`或托管设置](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>)启用它|
| `plan` |终端|计划模式。使用 `--fork-session`，新会话将启动的权限模式|
| `auto` |终端|`auto`，仅当您的账户仍满足[自动模式要求](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>)时|
|手册|终端|当新会话从 [ 内置默认值 ](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>) 以自动模式启动时，手动启动。当设置文件 [ 中的 `defaultMode` 生效 ](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>) 时，Claude Code 会以该模式启动恢复的会话|
| `plan` |非交互式，在以下[条件下](<#resume-in-plan-mode-with-p>)|计划模式|
|任意模式|在任何其他情况下都是非交互式的|新的 `claude -p` 运行将启动的权限模式|
| `plan` | VS Code |计划模式，[VS Code页面上的例外情况](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>)|

<a id="resume-in-plan-mode-with-p" />

##### 使用 `-p` 在计划模式下恢复

仅当满足所有这些条件时，`claude -p --resume` 或 `claude -p --continue` 运行才会在计划模式下恢复：

* 您通过了[`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>)但未通过[`--permission-prompts none`](<https://code.claude.com/docs/en/headless#turn-off-permission-prompts-in-unattended-runs>)，因此Claude Code可以提交计划以供审批
* 您未通过 `--permission-mode` 或 `--dangerously-skip-permissions`
* 你没有通过`--fork-session`
* 运行不是通过 [ 通道 ](<https://code.claude.com/docs/en/channels>) 启动

### 从摘要中恢复

在 Pro 或 Max 套餐中，当您恢复闲置时间超过一小时且超过 100,000 令牌的会话时，Claude Code 会恢复对话，然后在您发送第一条消息之前打开一个对话框。此时会话的 [ 提示缓存 ](<https://code.claude.com/docs/en/prompt-caching#cache-lifetime>) 已过期，因此无论您选择哪个对话框的选项，下一个请求都会处理完整历史记录一次。

该对话框提供了三种继续会话的方法。它们的不同之处在于每个会话将多少会话转移到以后的请求中，这是保留每个细节和每个请求发送更少令牌之间的权衡：

* **从摘要中恢复**：立即运行[`/compact`](<https://code.claude.com/docs/en/context-window#what-survives-compaction>)。 Claude Code 发送一个针对完整历史记录的摘要请求，然后将历史记录替换为摘要、您最近的交流以及最多五个最近读取的文件。稍后的请求携带摘要而不是完整的历史记录。
* **按原样恢复完整会话**：加载对话不变。发送第一条消息后，Claude Code 会重新处理并重新缓存完整历史记录，然后在缓存保持热状态时在以后的请求中从缓存中重新读取它。
* **不要再问我**：恢复完整会话并停止在所有未来的简历中显示对话框。

按原样恢复可保持对话的每个细节可用，每个请求的成本随对话的大小而变化。从摘要中恢复对于每个后续请求的成本较低，因为它携带的是摘要而不是完整的历史记录，但摘要遗漏的任何内容都不再在 Claude 的上下文中。请参阅 [为什么使用率会在长时间会话中攀升 ](<https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session>) 了解每个请求成本的来源。

### 会话选择器的外观

Claude Code 存储每个项目目录的会话。默认情况下，会话选择器显示：

* 当前工作树中的会话，包括 [ 后台会话 ](<https://code.claude.com/docs/en/agent-view>)，在列表中标记为 `bg`
* 会话在其他位置启动，添加了当前目录 `/add-dir`

使用 `Ctrl+W` 扩展到存储库的所有工作树，或使用 `Ctrl+A` 扩展到该计算机上的每个项目。

第一个提示是 [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop>) 命令的会话不会出现在选择器中，并且 `claude --continue` 也会跳过它们。稍后在对话中运行 `/loop` 不会隐藏会话。在 v2.1.211 之前，对话早期运行的 `/loop` 会对选择器永久隐藏会话。

使用 [`/cd`](<https://code.claude.com/docs/en/commands>) 移动会话会将其重新定位到新目录的项目存储，因此它随后会出现在该目录的选择器中。从 v2.1.196 开始，即使在崩溃或强制退出后，移动的会话也会保留在旧目录的选择器之外。在早期版本中，当旧路径包含下划线等特殊字符时，在不干净的退出后，它也可能重新出现在旧目录的列表中。

当您从同一存储库的另一个工作树中选择会话时，Claude Code 会在适当的位置恢复它；当会话自己的工作树不再存在时，Claude Code [会在当前目录](<https://code.claude.com/docs/en/worktrees#resume-a-worktree-session>)中恢复它。当您从不相关的项目中选择会话时，Claude Code 会将 `cd` 和恢复命令复制到剪贴板。如果该项目的目录不再存在，Claude Code 将在当前目录中恢复会话，而不是复制会失败的 `cd` 命令。

按名称恢复可解析当前存储库及其工作树。两种形式都会查找完全匹配并直接恢复它，即使它位于不同的工作树中：

|命令|精确匹配|名字不明确|
| :- | :- | :- |
| `claude --resume <name>` |直接恢复|打开会话选择器，其中名称预先填充为搜索词|
| `/resume <name>` |直接恢复|报告错误；不带参数运行 `/resume` 以打开会话选择器|

## 为您的会话命名

为会话提供描述性名称，以便可以在会话选择器中找到它们并可以按名称恢复它们。当您并行处理多个任务时，这一点最为重要。

|当|如何设置名称|
| :- | :- |
|启动时| `claude -n auth-refactor` |
|会议期间|`/rename auth-refactor`。该名称也会出现在提示栏上|
|从会话选择器|突出显示一个会话并按 `Ctrl+R`|
|按计划接受|在 [ 计划模式 ](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>) 中接受计划将为会话提供基于该计划生成的标题，除非您已经为其命名|
|来自 claude.ai 或 Claude 应用程序|重命名[远程控制会话](<https://code.claude.com/docs/en/remote-control#connect-from-another-device>)； Claude Code在CLI中应用相同的名称。需要 Claude Code v2.1.221 或更高版本|
|从桌面应用程序|重命名 [ 桌面应用程序 ](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>) 中的会话|

通过 CLI 路由或从 claude.ai 命名会话后，使用 `claude --resume <name>` 或 `/resume <name>` 返回该会话；桌面应用程序会话在 [ 桌面应用程序 ](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>) 中恢复。请参阅[恢复会话](<#恢复会话>)，了解跨工作树的名称解析行为。

当您使用该计算机上的另一个实时会话已使用的名称启动或恢复交互式会话时，或者将会话重命名为这样的名称时，Claude Code 会将该名称保留为已有的会话，将您的名称重命名为带有两个单词后缀的变体，例如 `auth-refactor-graceful-unicorn`，并告诉您。如果您想自己选择一个，请使用新名称运行 `/rename`。在v2.1.232之前，两个会话都保留了这个名字。

在三种情况下，Claude Code 不会重命名重复项，因此您仍然可以在列表中看到两个同名的会话：

* 它不检查AI-生成的标题或默认显示名称。
* 它在启动时不会检查 [ 后台 ](<https://code.claude.com/docs/en/agent-view#from-your-shell>) 或 `-p` 会话的 `--name`。
* 它无法重命名早期版本的 Claude Code 上的会话。

您未命名的会话仍会获得 Claude Code 分配的两个标签。只有生成的标题可以用作简历句柄：

* 默认显示名称：您从未命名的交互式会话在启动时仍会获得默认显示名称。需要 Claude Code v2.1.196 或更高版本。默认值将工作目录的名称与两个字符的后缀组合在一起，例如 `my-app-3f`，并在运行会话列表中标识会话，例如 [agent 视图 ](<https://code.claude.com/docs/en/agent-view>) 和 `claude agents --json` 输出。默认值不是恢复句柄。如果将其传递给 `claude --resume` 或 `/resume`，Claude Code 找不到会话。命名会话会替换这些列表中的默认值，接受计划也是如此。
* 生成的标题：如果您不命名会话，Claude Code 会为其生成会话标题。标题是第一个提示的简短摘要，由对 small/fast 模型（通常是 Haiku 级模型）的后台请求编写。直接从 shell 或脚本启动的 `claude -p` 运行不会得到一个。

接受计划会将生成的标题替换为基于计划的标题。命名会话也会替换它。

当未设置名称时，您会在 [ 会话选择器 ](<#使用会话选择器>) 和状态行 [`session_name`](<https://code.claude.com/docs/en/statusline>) 字段中看到第一个提示标题。计划标题显示在相同的两个位置，并且也在正在运行的会话列表中显示，它取代了默认显示名称。

您可以将标题传递给 `claude --resume` 或 `/resume`，Claude Code 将以与您设置的名称相同的方式解析它。

## 使用会话选择器

在会话内运行 `/resume`，或不带参数运行 `claude --resume`，以打开交互式会话选择器。使用这些键盘快捷键来导航、搜索和扩大列表：

|快捷方式|行动|
| :- | :- |
|`↑` / `↓` 或 `k` / `j`|在会话之间导航|
| `→` / `←` |展开或折叠分组会话|
| `Enter` |恢复突出显示的会话|
|`1` 至 `9`|在列表中的该位置恢复会话|
| `Space` |预览会话内容。 `Ctrl+V` 也适用于不将其捕获为粘贴的终端|
| `Ctrl+R` |重命名突出显示的会话|
|`/` 或除 `Space`、`j`、`k` 或数字之外的任何可打印字符|进入搜索模式并过滤会话。粘贴 GitHub、GitHub Enterprise、GitLab 或 Bitbucket 拉取或合并请求 URL 以查找创建它的会话|
| `Ctrl+A` |显示该计算机上所有项目的会话。再按一次返回当前存储库|
| `Ctrl+W` |显示当前存储库的所有工作树中的会话。再次按下可返回当前工作树。仅在多工作树存储库中显示|
| `Ctrl+B` |从当前 git 分支过滤到会话。再按一次显示所有分支|
| `Esc` |退出会话选择器或搜索模式|

如果您设置了会话名称，则每行显示会话名称，否则显示 AI- 生成的会话标题、对话摘要或第一个提示，以及自上次活动以来的时间、git 分支和文件大小。使用 `Ctrl+A` 扩大到所有项目，还可以查看每个会话的项目路径。

使用 `/branch` 或 `--fork-session` 创建的会话将获得自己的会话 ID 并显示为单独的行。当选择器找到同一会话的多个条目时，会将它们分组到一行下。按`→`展开组。

如果 Claude Code 无法加载您从 `claude --resume` 选择器中选择的会话，它将打印 [`Failed to resume the conversation`](<https://code.claude.com/docs/en/errors#failed-to-resume-the-conversation>) 以及重试命令，然后以代码 1 退出。从会话内的 `/resume` 选择器中，Claude Code 报告失败，并且您当前的对话继续运行。

## 分支会话

分支创建到目前为止对话的副本并将您切换到其中，而原始对话保持不变。使用它来尝试不同的方法，而不会迷失您所走的道路。

从会话内部，使用可选名称运行 `/branch`：

```text theme={null}
/branch try-streaming-approach
```

如果省略名称，Claude Code 将在对话中的第一个提示后命名新分支。从v2.1.198开始，这也适用于[压缩](<https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up>)之后；早期版本回退到字面名称 `Branched conversation`，而不是查看压缩摘要到原始的第一个提示。

在命令行中，将 `--continue` 或 `--resume` 与 `--fork-session` 组合：

```bash theme={null}
claude --continue --fork-session
```

`/branch` 确认打印两个会话 ID：您现在所在的新分支和原始分支。原始文件在磁盘上保持不变，并保留在会话选择器中；使用 `/resume <original-name>` 返回它，或者将其 ID 传递给 `/resume`。

`/branch` 复制转录本并切换正在运行的 Claude Code 进程以对其进行写入。这种区别决定了分支继承的内容：

|状态|`/branch`之后|
| :- | :- |
|对话历史记录|复制到分支中直到您运行的位置 `/branch`|
|“允许此会话”权限授予|结转；该分支机构在同一流程中运行，因此您现有的补助金仍然适用。如果您使用 `--fork-session` 分叉到一个单独的流程，则新流程将在没有它们的情况下启动，并且您在那里重新批准|
|运行中 [ 后台子代理 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) 和 [ 后台 Bash 命令 ](<https://code.claude.com/docs/en/interactive-mode#background-bash-commands>)|继续跑。它们的输出出现在您切换到的新分支中，而不是原始会话中|
|[远程控制](<https://code.claude.com/docs/en/remote-control>)连接|保持连接。连接到会话的电话或浏览器跟随您进入分支并不断接收新消息|

如果您在两个终端中恢复同一会话而不进行分叉，则来自两个终端的消息将交织成一个记录。对于单个会话中基于检查点的倒回，请参阅[检查点](<https://code.claude.com/docs/en/checkpointing>)。

## 管理会话中的上下文

这些命令无需离开会话即可控制上下文窗口中的内容：

* **`/clear`**：从空上下文开始。 Claude Code保存之前的对话；使用 `/resume` 恢复它，或者在同一 Claude Code 进程中，从 [ 快退菜单的上一个会话条目 ](<https://code.claude.com/docs/en/checkpointing#rewind-past-a-cleared-conversation>) 恢复它。如果没有参数，新对话将保留您使用 `--name` 或 `/rename` 设置的名称，但不保留 AI- 生成的会话标题。要命名您要离开的对话，请传递名称，如 `/clear release-prep` 中；然后新的对话开始未命名
* **`/compact [instructions]`**：用摘要替换历史记录，可选择重点关注您指定的内容
* **`/context`**：显示当前正在消耗的上下文

有关压缩如何与 CLAUDE.md、技能和规则交互的信息，请参阅 [ 上下文窗口指南 ](<https://code.claude.com/docs/en/context-window>)。有关何时清理与压缩的策略，请参阅[最佳实践](<https://code.claude.com/docs/en/best-practices#manage-your-session>)。

## 导出并定位会话数据

运行 `/export` 打开一个菜单，您可以将当前对话复制到剪贴板或将其保存为纯文本文件，并将消息和工具输出呈现为可读文本。传递文件名以跳过菜单并直接写入该文件。

### 从脚本访问对话

`/export` 生成供人阅读的渲染文本。下面的接口生成供脚本解析的结构化数据：运行的 JSON 结果、会话转录文件的路径或实时事件流。根据触发脚本的内容进行选择：

* **运行 Claude 一次并捕获结果 **：使用 [`--output-format json` 或 `stream-json`](<https://code.claude.com/docs/en/headless#get-structured-output>) 调用 `claude -p` 以捕获结构化的非交互式运行的结果、会话 ID、使用情况和成本JSON。
* **向现有会话询问问题**：将会话ID传递给[`claude -p --resume`](<https://code.claude.com/docs/en/headless#continue-conversations>)以发送后续提示（例如摘要请求）并捕获结构化响应。
* **React 到会话事件 **：读取 [ 挂钩 ](<https://code.claude.com/docs/en/hooks#common-input-fields>) 和 [ 状态行命令 ](<https://code.claude.com/docs/en/statusline#available-data>) 作为输入接收的 `transcript_path` 字段。 `SessionEnd` 挂钩可以在会话结束时存档记录。
* **将Claude嵌入TypeScript或Python应用程序**：使用[Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>)以编程方式接收每条消息。

下面的示例使用第二个接口。它向现有会话发送后续提示并使用 `jq` 读取答案：

```bash theme={null}
claude -p --resume <session-id> --output-format json "summarize what we changed" | jq -r '.result'
```

### 记录的存储位置

默认情况下，Claude Code 将转录本存储为 `~/.claude/projects/<project>/<session-id>.jsonl` 处的 JSONL，其中 `<project>` 是您的工作目录路径，其中非字母数字字符替换为 `-`。对于转换后的名称超过 200 个字符的工作目录，Claude Code 会将名称截断为 200 个字符并附加完整路径的哈希值，以便目录名称保持在文件系统限制内。

每行都是一个用于消息、工具使用或元数据条目的 JSON 对象。条目格式是 Claude Code 的内部格式，并且在版本之间发生变化，因此直接解析这些文件的脚本可能会在任何版本上中断。要基于会话数据进行构建，请改用 `/export` 或 [ 脚本接口 ](<#从脚本访问对话>)。

位置、保留和写入行为是可配置的：

|至|套装|哪里|
| - | - | - |
|关闭存储 `~/.claude`| [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>) |环境变量|
|[自己命名`<project>`目录](<#自己命名项目目录>)| [`CLAUDE_CODE_PROJECT_DIR_NAME`](<https://code.claude.com/docs/en/env-vars>) |环境变量|
|更改 30 天保留| [`cleanupPeriodDays`](<https://code.claude.com/docs/en/settings-reference#cleanupperioddays>) | `settings.json` |
|为 [Claude 桌面和 Cowork 成绩单设置年龄限制 ](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>)| [`desktopSessionCleanupPeriodDays`](<https://code.claude.com/docs/en/settings-reference#desktopsessioncleanupperioddays>) |用户设置、托管设置或 `--settings`|
|限制 `-p` 或 Agent SDK 会话转录文件的增长大小| [`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC`](<https://code.claude.com/docs/en/env-vars>) |环境变量|
|抑制所有模式下的转录写入| [`CLAUDE_CODE_SKIP_PROMPT_HISTORY`](<https://code.claude.com/docs/en/env-vars>) |环境变量|
|抑制一次非交互式运行的写入| [`--no-session-persistence`](<https://code.claude.com/docs/en/cli-reference>) |CLI 带有 `claude -p` 的标志|

### 删除会话数据

成绩单在以下情况下会老化 [保留清除规则](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>)。要更快地删除项目的成绩单和相关状态，请运行 [`claude purge`](<https://code.claude.com/docs/en/claude-directory#clear-local-data>)。如果删除一个 [后台会话](<https://code.claude.com/docs/en/agent-view>) 与 [`claude rm <id>`](<https://code.claude.com/docs/en/agent-view#what-deleting-a-session-removes>)，其转录本保留在磁盘上并通过以下方式保持可用 `claude --resume`.

### 自己命名项目目录

默认情况下，Claude Code 从整个工作目录路径派生出 `<project>` 名称。要自己选择名称，请将 `CLAUDE_CODE_PROJECT_DIR_NAME` 与 `CLAUDE_CONFIG_DIR` 一起设置。 Claude Code 然后将该会话的记录和 [ 自动记忆 ](<https://code.claude.com/docs/en/memory#auto-memory>) 存储在您的名字下。这适合嵌入 Claude Code 并为每个会话提供自己的配置目录的主机。需要 Claude Code v2.1.234 或更高版本。

例如，本次启动将租户 A 的数据保留在 `/srv/tenant-a` 下，并将其项目目录命名为 `work`：

```bash theme={null}
CLAUDE_CONFIG_DIR=/srv/tenant-a CLAUDE_CODE_PROJECT_DIR_NAME=work claude
```

Claude Code 将会话的记录写入 `/srv/tenant-a/projects/work/`，并将其自动内存写入 `/srv/tenant-a/projects/work/memory/`，无论工作目录是什么。

设置时适用三个规则：

* **也设置`CLAUDE_CONFIG_DIR`**：名称不随工作目录变化，因此在默认`~/.claude`下会将每个项目的脚本和自动内存合并到一个目录中。当`CLAUDE_CONFIG_DIR`未设置时，Claude Code忽略`CLAUDE_CODE_PROJECT_DIR_NAME`。
* **使用1-64字母、数字、连字符或下划线**：不要使用Windows设备名称，例如`con`。 Claude Code 忽略任何其他值并使用派生名称。
* **在启动`claude`**的shell环境中设置它：Claude Code在启动时从该环境中读取一次，因此设置文件中的`env`块无法设置它。

一旦您命名了配置目录的项目目录，请继续使用该名称启动。如果使用相同的 `CLAUDE_CONFIG_DIR` 但没有 `CLAUDE_CODE_PROJECT_DIR_NAME` 启动 Claude Code，它将再次读取和写入派生目录。以您的名称存储的会话保留在磁盘上：按 [ 会话选择器 ](<#使用会话选择器>) 中的 `Ctrl+A` 列出该配置目录下每个项目目录中的会话（包括固定的会话），无论您以哪种方式启动，[`claude --resume <session-id>`](<#恢复会话>) 都会找到以任一名称存储的会话。

# Manage sessions

> Name, resume, branch, and switch between Claude Code conversations. Covers `--continue`, `--resume`, `--from-pr`, the `/resume` picker, session naming, exporting transcripts, and where transcripts are stored.

A session is a saved conversation tied to a project directory. Claude Code stores it locally as you work, so you can resume where you left off, branch to try a different approach, or switch between tasks.

The [desktop app](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>), [claude.ai/code](<https://code.claude.com/docs/en/claude-code-on-the-web>), and the [VS Code extension](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>) each keep their own session list, and the desktop app can also [resume a CLI session](<https://code.claude.com/docs/en/desktop#coming-from-the-cli>). This page covers the CLI.

## Resume a session

Sessions are saved continuously to [local transcript files](<#export-and-locate-session-data>) as you work, so you can return to one after exiting or running `/clear`. Use these entry points:

| Command | What it does |
| :- | :- |
| `claude --continue` | Reopens the most recent conversation in the current directory |
| `claude --resume` | Opens the [session picker](<#use-the-session-picker>) |
| `claude --resume <name>` | Resumes the named session directly |
| `claude --resume <transcript-path>` | Resumes the conversation stored in the `.jsonl` [transcript file](<#where-transcripts-are-stored>) at that absolute path |
| `claude --from-pr <number>` | Opens the session picker filtered to sessions linked to that pull request |
| `/resume` | Switches to a different conversation from inside an active session |

Claude Code leaves sessions created with [`claude -p`](<https://code.claude.com/docs/en/headless>) or the [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) out of the session picker and out of `claude --continue`. You can still resume one by passing its session ID to `claude --resume <session-id>`. With `claude --continue`, Claude Code also skips [sessions whose first prompt was `/loop`](<#where-the-session-picker-looks>). When you run [`claude -p --continue`](<https://code.claude.com/docs/en/headless#continue-conversations>), Claude Code includes `-p`, SDK, and `/loop` sessions.

You can run `claude --resume <session-id>` from any directory, so you can resume a session that started elsewhere or moved with [`/cd`](<https://code.claude.com/docs/en/commands>). Claude Code looks for the ID in this order:

1. The current project directory and its git worktrees
2. Every other project on this machine

The cross-project search resolves the ID only when exactly one other project holds a transcript with messages for it, so a hand-copied duplicate makes Claude Code report not-found rather than resume an arbitrary copy. If no stored session matches the ID, Claude Code reports `No conversation found with session ID: <session-id>`.

Before v2.1.223, the lookup stopped at the current project directory and its git worktrees, so you had to resume from the directory the session last worked in.

`claude --continue` opens a [background session](<https://code.claude.com/docs/en/agent-view>) that has finished, but not one that is still running; opening finished background sessions requires Claude Code v2.1.257 or later. If your most recent conversation is one you [moved to the background](<https://code.claude.com/docs/en/agent-view#send-the-session-to-the-background>) and it is still running there, Claude Code exits with `Your most recent conversation is running in the background` and that session's ID. Attach to the session from [`claude agents`](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>), or run `claude --resume` to pick another one.

<h3 id="resume-a-running-background-session">
  Resume a running background session
</h3>

When the conversation you resume with `claude --resume` or `/resume` belongs to a [background session](<https://code.claude.com/docs/en/agent-view>) that is still running, Claude Code opens the running session itself. With `--bg` on the command line, the resume is a [background dispatch](<https://code.claude.com/docs/en/agent-view#from-your-shell>) instead. Before v2.1.285, Claude Code refused and told you to open the session with `claude attach <id>`, or to stop it with `claude stop <id>` first.

* **From your shell**: `claude --resume <session>` runs [`claude attach`](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>) on that session in the same terminal instead of loading the transcript itself. A prompt you pass on the command line, as in `claude --resume <session> "check the tests too"`, goes to the session as its next turn first, and Claude Code prints `Sent your prompt to the background session (<id>); opening it…` before attaching. `claude -p --resume <session> "prompt"` typed at a terminal does the same, so `-p` doesn't keep that run non-interactive.

  Claude Code doesn't open the session when the command line has any of these:

  * Piped or redirected input or output
  * Flags that configure the session, such as `--permission-mode`, `--model`, or `--settings`
  * Flags that read the output, such as `--output-format json` or `--json-schema`
  * Flags that limit or rewind the run, such as `--max-turns` or `--max-budget-usd`

  With any of these, or when [agent view is turned off](<https://code.claude.com/docs/en/agent-view#turn-off-agent-view>), Claude Code sends nothing and exits with status 1, printing that the session is running in the background along with the `claude attach <id>` command that opens it, or telling you to find it in `claude agents` when it can't determine the ID. Add `--fork-session` to resume a copy of the conversation instead. To continue the conversation itself in a session of your own, with your flags applied, run `claude stop <id>` and then repeat the command.

  A prompt that starts with `/` or `!` isn't sent, and neither is any prompt while the session waits on your answer to a question. In both cases Claude Code doesn't open the session, and the message includes `Your prompt was not sent to it` with the reason.
* **From inside a session**: `/resume` moves your current conversation to the background and attaches this terminal to the running session, printing `Opening "<title>", running in the background (<id>)`. Press `←` on an empty prompt to return to agent view, which also lists the conversation you left. When the current conversation can't move to the background, for example because you're already attached to a background session or session persistence is off, `/resume` prints the `claude attach` command to run instead.

### What a resumed session restores

When Claude Code loads a conversation from its transcript, the resumed session restores the conversation along with the state saved in it:

* Conversation history: the full history, including tool calls and results. A tool that was still running when the previous process ended, for example in a crash, doesn't finish or run again when you resume. Claude sees the call marked as cut off before its result was recorded and is told to check whether it took effect before running it again, unless [`CLAUDE_CODE_RESUME_INTERRUPTED_TURN`](<https://code.claude.com/docs/en/env-vars#variables>) is set. Before v2.1.281, Claude Code dropped the cut-off call from the conversation or showed it to Claude as one you interrupted.
* Model: the session continues on the model it was using, except in the cases in [Setting your model](<https://code.claude.com/docs/en/model-config#setting-your-model>).
* Agent: a session started with [`--agent`](<https://code.claude.com/docs/en/sub-agents#invoke-subagents-explicitly>) or the `agent` setting continues as that agent, keeping its tool restrictions and model. Pass `--agent` when resuming to pick a different one; for the system prompt in either case, see [System prompt flags in resumed conversations](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>). Claude Code looks for the agent in two places: the session's original directory, provided you have [trusted that workspace](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>), and then the directory you resume from, so a project-scoped agent still loads when you resume from another directory. If Claude Code doesn't find the agent in either place, the session resumes with the default tools and shows a [warning naming the agent](<https://code.claude.com/docs/en/errors#session-agent-no-longer-available>).
* Permission mode: if you resume from a terminal with `claude --continue`, `claude --resume <session-id>`, or `claude --resume <name>` when the name matches one session, without `-p`, Claude Code restores the permission mode the session was in, except in the cases in [permission mode on resume](<#permission-mode-on-resume>), which also covers the session picker, `/resume`, and resuming with `claude -p`. Pass `--permission-mode` or `--dangerously-skip-permissions` to override the restored mode.
* Active goal: a [goal](<https://code.claude.com/docs/en/goal#resume-with-an-active-goal>) that was still active when the session ended carries over; its turn count, timer, and token-spend baseline reset.
* Scheduled tasks: [tasks that haven't expired](<https://code.claude.com/docs/en/scheduled-tasks#limitations>) are restored. Background Bash and monitor tasks aren't.
* Background work: a [background subagent](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>), background Bash command, or [workflow](<https://code.claude.com/docs/en/workflows>) that ended with the previous process shows up in the resumed transcript as a note that it didn't finish. Claude Code doesn't start a turn from those notes; Claude reads them with your next prompt.

Not every configuration flag from the original launch is restored. If the session depended on `--mcp-config`, `--settings`, `--plugin-dir`, `--fallback-model`, or directories added with `--add-dir`, pass them again when you resume; directories added mid-session with `/add-dir` aren't restored either, though the session picker still uses them to locate the session. The standard settings files, such as `settings.json` and `settings.local.json`, are re-read at launch, so configuration that lives in them doesn't need to be passed again. For `--system-prompt` and `--append-system-prompt`, see [System prompt flags in resumed conversations](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>).

#### Permission mode on resume

Which permission mode Claude Code starts a resumed session in depends on how you resume. The cases below apply when Claude Code loads the conversation from its transcript; when you [open a background session that is still running](<#resume-a-running-background-session>) instead, that session keeps the permission mode it is in.

* Terminal: `claude --continue`, `claude --resume <session-id>`, or `claude --resume <name>` when the name matches one session, without `-p`. Claude Code restores the permission mode the session was in, except in the cases in the table. Pass `--permission-mode` or `--dangerously-skip-permissions` to override the restored mode.
* Non-interactive: `claude -p --resume` or `claude -p --continue`. Claude Code starts the run in the permission mode a new `claude -p` run would start in, except that a session that ended in plan mode resumes in plan mode under the [conditions below](<#resume-in-plan-mode-with-p>).
* VS Code: the extension's conversation panel. The table covers only a conversation that ended in plan mode; for the rest, see [resume past conversations](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>).
* Session picker at launch: a session you select from the [session picker](<#use-the-session-picker>), whether you opened it with `claude --resume` alone, `claude --from-pr`, or a name that matches more than one session. Claude Code starts the session in the permission mode it would start a new session in from the same command line, except that a session that ended in plan mode resumes in plan mode unless you pass `--permission-mode`, `--dangerously-skip-permissions`, or `--fork-session`. No other stored permission mode is restored.
* `/resume` inside a session, with or without an argument: the conversation you switch to continues in the permission mode your current session is in, except that a conversation that ended in plan mode resumes in plan mode, even if you launched Claude Code with `--permission-mode` or `--dangerously-skip-permissions`. If that conversation was already open earlier in this run of Claude Code, such as the conversation you started in or one you left with `/clear` or `/resume`, it continues in your current permission mode instead.

Restoring plan mode on the non-interactive and VS Code paths requires Claude Code v2.1.246 or later. Each row names the permission mode the session ended in, which of the terminal, non-interactive, and VS Code paths you resume it by, and the permission mode Claude Code starts the resumed session in.

| Session ended in | How you resume | Permission mode after you resume |
| :- | :- | :- |
| `bypassPermissions` | Terminal | The permission mode a new session would start in. To [bypass permissions](<https://code.claude.com/docs/en/permission-modes#skip-all-checks-with-bypasspermissions-mode>) again, enable it at launch with one of its launch flags or `permissions.defaultMode: "bypassPermissions"` in [user, `--settings`, or managed settings](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>) |
| `plan` | Terminal | Plan mode. With `--fork-session`, the permission mode a new session would start in |
| `auto` | Terminal | `auto`, only when your account still meets the [auto mode requirements](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) |
| Manual | Terminal | Manual when a new session would start in auto mode from the [built-in default](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>). When a `defaultMode` from a settings file [takes effect](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>), Claude Code starts the resumed session in that mode instead |
| `plan` | Non-interactive, under the [conditions below](<#resume-in-plan-mode-with-p>) | Plan mode |
| Any mode | Non-interactive, in any other case | The permission mode a new `claude -p` run would start in |
| `plan` | VS Code | Plan mode, with [the exceptions on the VS Code page](<https://code.claude.com/docs/en/vs-code#resume-past-conversations>) |

<a id="resume-in-plan-mode-with-p" />

##### Resume in plan mode with `-p`

A `claude -p --resume` or `claude -p --continue` run resumes in plan mode only when all of these conditions hold:

* You pass [`--permission-prompt-tool`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) and don't pass [`--permission-prompts none`](<https://code.claude.com/docs/en/headless#turn-off-permission-prompts-in-unattended-runs>), so that Claude Code can present the plan for approval
* You don't pass `--permission-mode` or `--dangerously-skip-permissions`
* You don't pass `--fork-session`
* The run isn't started through [channels](<https://code.claude.com/docs/en/channels>)

### Resume from a summary

On a Pro or Max plan, when you resume a session that has been inactive for more than about an hour and is over 100,000 tokens, Claude Code restores the conversation and then opens a dialog before you send your first message. The session's [prompt cache](<https://code.claude.com/docs/en/prompt-caching#cache-lifetime>) has expired by then, so the next request processes the full history once no matter which of the dialog's options you pick.

The dialog offers three ways to continue the session. They differ in how much of the conversation each one carries forward into later requests, which is a tradeoff between keeping every detail and sending fewer tokens per request:

* **Resume from summary**: runs [`/compact`](<https://code.claude.com/docs/en/context-window#what-survives-compaction>) immediately. Claude Code sends one summarization request over the full history, then replaces the history with the summary, your most recent exchanges, and up to five recently read files. Later requests carry the summary instead of the full history.
* **Resume full session as-is**: loads the conversation unchanged. After you send your first message, Claude Code reprocesses and re-caches the full history, then re-reads it from the cache on later requests while the cache stays warm.
* **Don't ask me again**: resumes the full session and stops showing the dialog on all future resumes.

Resuming as-is keeps every detail of the conversation available, at a per-request cost that scales with the conversation's size. Resuming from the summary costs less on each later request because it carries the summary instead of the full history, but whatever the summary leaves out is no longer in Claude's context. See [why usage climbs in a long session](<https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session>) for where that per-request cost comes from.

### Where the session picker looks

Claude Code stores sessions per project directory. By default the session picker shows:

* Sessions from the current worktree, including [background sessions](<https://code.claude.com/docs/en/agent-view>), which are marked `bg` in the list
* Sessions started elsewhere that added the current directory with `/add-dir`

Use `Ctrl+W` to widen to all worktrees of the repository or `Ctrl+A` to widen to every project on this machine.

Sessions whose first prompt was a [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop>) command don't appear in the picker, and `claude --continue` skips them too. Running `/loop` later in a conversation doesn't hide the session. Before v2.1.211, a `/loop` run early in a conversation hid the session from the picker permanently.

Moving a session with [`/cd`](<https://code.claude.com/docs/en/commands>) relocates it to the new directory's project storage, so it appears in that directory's picker afterward. As of v2.1.196, a moved session stays out of the old directory's picker even after a crash or forced exit. On earlier versions, it could also reappear in the old directory's list after an exit that wasn't clean when the old path contained special characters such as underscores.

When you select a session from another worktree of the same repository, Claude Code resumes it in place; when the session's own worktree no longer exists, Claude Code [resumes it in your current directory](<https://code.claude.com/docs/en/worktrees#resume-a-worktree-session>). When you select a session from an unrelated project, Claude Code copies a `cd` and resume command to your clipboard instead. If that project's directory no longer exists, Claude Code resumes the session in your current directory rather than copying a `cd` command that would fail.

Resuming by name resolves across the current repository and its worktrees. Both forms look for an exact match and resume it directly even if it lives in a different worktree:

| Command | Exact match | Ambiguous name |
| :- | :- | :- |
| `claude --resume <name>` | Resumes directly | Opens the session picker with the name pre-filled as a search term |
| `/resume <name>` | Resumes directly | Reports an error; run `/resume` with no argument to open the session picker |

## Name your sessions

Give sessions descriptive names so they're findable in the session picker and resumable by name. This matters most when you're working on several tasks in parallel.

| When | How to set the name |
| :- | :- |
| At startup | `claude -n auth-refactor` |
| During a session | `/rename auth-refactor`. The name also appears on the prompt bar |
| From the session picker | Highlight a session and press `Ctrl+R` |
| On plan accept | Accepting a plan in [plan mode](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>) gives the session a generated title based on the plan unless you've already named it |
| From claude.ai or the Claude app | Rename a [Remote Control session](<https://code.claude.com/docs/en/remote-control#connect-from-another-device>); Claude Code applies the same name in the CLI. Requires Claude Code v2.1.221 or later |
| From the desktop app | Rename a session in the [desktop app](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>) |

Once you name a session through a CLI route or from claude.ai, return to it with `claude --resume <name>` or `/resume <name>`; a desktop-app session resumes in the [desktop app](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>). See [Resume a session](<#resume-a-session>) for how name resolution behaves across worktrees.

When you start or resume an interactive session with a name that another live session on this machine already uses, or rename a session into such a name, Claude Code leaves the name with the session that already has it, renames yours to a variant with a two-word suffix, such as `auth-refactor-graceful-unicorn`, and tells you. Run `/rename` with a new name if you'd rather pick one yourself. Before v2.1.232, both sessions kept the name.

In three cases Claude Code doesn't rename the duplicate, so you can still see two sessions with the same name in listings:

* It doesn't check AI-generated titles or default display names.
* It doesn't check the `--name` of a [background](<https://code.claude.com/docs/en/agent-view#from-your-shell>) or `-p` session at startup.
* It can't rename a session on an earlier version of Claude Code.

Sessions you don't name still get two labels that Claude Code assigns. Only the generated title works as a resume handle:

* Default display name: interactive sessions you never name still get a default display name when they start. Requires Claude Code v2.1.196 or later. The default combines the working directory's name with a two-character suffix, for example `my-app-3f`, and identifies the session in listings of running sessions, such as [agent view](<https://code.claude.com/docs/en/agent-view>) and `claude agents --json` output. The default isn't a resume handle. If you pass it to `claude --resume` or `/resume`, Claude Code doesn't find the session. Naming the session replaces the default in those listings, and so does accepting a plan.
* Generated title: if you don't name a session, Claude Code generates a session title for it. The title is a short summary of your first prompt, written by a background request to the small/fast model, normally a Haiku-class model. A `claude -p` run you start directly from a shell or script doesn't get one.

  Accepting a plan replaces the generated title with a title based on the plan. Naming the session replaces it as well.

  You see the first-prompt title in the [session picker](<#use-the-session-picker>) and in the statusline [`session_name`](<https://code.claude.com/docs/en/statusline>) field when no name is set. The plan title shows in the same two places and also in the listings of running sessions, where it takes the place of the default display name.

  You can pass either title to `claude --resume` or `/resume`, and Claude Code resolves it the same way as a name you set.

## Use the session picker

Run `/resume` inside a session, or `claude --resume` with no arguments, to open the interactive session picker. Use these keyboard shortcuts to navigate, search, and widen the list:

| Shortcut | Action |
| :- | :- |
| `↑` / `↓` or `k` / `j` | Navigate between sessions |
| `→` / `←` | Expand or collapse grouped sessions |
| `Enter` | Resume the highlighted session |
| `1` to `9` | Resume the session at that position in the list |
| `Space` | Preview the session content. `Ctrl+V` also works on terminals that don't capture it as paste |
| `Ctrl+R` | Rename the highlighted session |
| `/` or any printable character other than `Space`, `j`, `k`, or a digit | Enter search mode and filter sessions. Paste a GitHub, GitHub Enterprise, GitLab, or Bitbucket pull or merge request URL to find the session that created it |
| `Ctrl+A` | Show sessions from all projects on this machine. Press again to return to the current repository |
| `Ctrl+W` | Show sessions from all worktrees of the current repository. Press again to return to the current worktree. Only shown in multi-worktree repositories |
| `Ctrl+B` | Filter to sessions from the current git branch. Press again to show all branches |
| `Esc` | Exit the session picker or search mode |

Each row shows the session name if you set one, otherwise the AI-generated session title, conversation summary, or first prompt, along with time since last activity, git branch, and file size. Widen to all projects with `Ctrl+A` to also see each session's project path.

Sessions created with `/branch` or `--fork-session` get their own session IDs and appear as separate rows. When the picker finds more than one entry for the same session, it groups them under a single row. Press `→` to expand a group.

If Claude Code can't load the session you select from the `claude --resume` picker, it prints [`Failed to resume the conversation`](<https://code.claude.com/docs/en/errors#failed-to-resume-the-conversation>) with a command to retry, then exits with code 1. From the `/resume` picker inside a session, Claude Code reports the failure and your current conversation keeps running.

## Branch a session

Branching creates a copy of the conversation so far and switches you into it, leaving the original intact. Use it to try a different approach without losing the path you were on.

From inside a session, run `/branch` with an optional name:

```text theme={null}
/branch try-streaming-approach
```

If you omit the name, Claude Code names the new branch after the first prompt in the conversation. As of v2.1.198 this also applies after [compaction](<https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up>); earlier versions fell back to the literal name `Branched conversation` instead of looking past the compaction summary to the original first prompt.

From the command line, combine `--continue` or `--resume` with `--fork-session`:

```bash theme={null}
claude --continue --fork-session
```

The `/branch` confirmation prints two session IDs: the new branch you are now in and the original. The original is unchanged on disk and remains in the session picker; return to it with `/resume <original-name>` or by passing its ID to `/resume`.

`/branch` copies the transcript and switches the running Claude Code process to write to it. That distinction determines what the branch inherits:

| State | After `/branch` |
| :- | :- |
| Conversation history | Copied into the branch up to the point you ran `/branch` |
| "Allow for this session" permission grants | Carried over; the branch runs in the same process, so your existing grants still apply. If you fork into a separate process with `--fork-session`, the new process starts without them and you re-approve there |
| In-flight [background subagents](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) and [background Bash commands](<https://code.claude.com/docs/en/interactive-mode#background-bash-commands>) | Keep running. Their output appears in the new branch you switched into, not in the original session |
| [Remote Control](<https://code.claude.com/docs/en/remote-control>) connection | Stays connected. A phone or browser connected to the session follows you into the branch and keeps receiving new messages there |

If you resume the same session in two terminals without forking, messages from both interleave into one transcript. For checkpoint-based rewind within a single session, see [Checkpointing](<https://code.claude.com/docs/en/checkpointing>).

## Manage context within a session

These commands control what's in the context window without leaving the session:

* **`/clear`**: start fresh with an empty context. Claude Code saves the previous conversation; resume it with `/resume`, or, in the same Claude Code process, from [the rewind menu's previous-session entry](<https://code.claude.com/docs/en/checkpointing#rewind-past-a-cleared-conversation>). With no argument, the new conversation keeps a name you set with `--name` or `/rename`, but not an AI-generated session title. To name the conversation you're leaving instead, pass the name, as in `/clear release-prep`; the new conversation then starts unnamed
* **`/compact [instructions]`**: replace history with a summary, optionally focused on what you specify
* **`/context`**: show what is currently consuming context

For how compaction interacts with CLAUDE.md, skills, and rules, see the [context window guide](<https://code.claude.com/docs/en/context-window>). For strategies on when to clear versus compact, see [Best practices](<https://code.claude.com/docs/en/best-practices#manage-your-session>).

## Export and locate session data

Run `/export` to open a menu that lets you copy the current conversation to your clipboard or save it as a plain-text file, with messages and tool outputs rendered as readable text. Pass a filename to skip the menu and write directly to that file.

### Access conversations from scripts

`/export` produces a rendered transcript for a person to read. The interfaces below produce structured data for a script to parse: a JSON result from a run, the path to a session's transcript file, or a live stream of events. Pick by what triggers the script:

* **Run Claude once and capture the result**: invoke `claude -p` with [`--output-format json` or `stream-json`](<https://code.claude.com/docs/en/headless#get-structured-output>) to capture the result, session ID, usage, and cost of a non-interactive run as structured JSON.
* **Ask an existing session a question**: pass a session ID to [`claude -p --resume`](<https://code.claude.com/docs/en/headless#continue-conversations>) to send a follow-up prompt, such as a summary request, and capture the structured response.
* **React to session events**: read the `transcript_path` field that [hooks](<https://code.claude.com/docs/en/hooks#common-input-fields>) and [status line commands](<https://code.claude.com/docs/en/statusline#available-data>) receive as input. A `SessionEnd` hook can archive the transcript when a session ends.
* **Embed Claude in a TypeScript or Python app**: use the [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>) to receive each message programmatically.

The example below uses the second interface. It sends a follow-up prompt to an existing session and reads the answer with `jq`:

```bash theme={null}
claude -p --resume <session-id> --output-format json "summarize what we changed" | jq -r '.result'
```

### Where transcripts are stored

By default, Claude Code stores transcripts as JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your working directory path with non-alphanumeric characters replaced by `-`. For a working directory whose converted name exceeds 200 characters, Claude Code truncates the name to 200 characters and appends a hash of the full path, so the directory name stays within filesystem limits.

Each line is a JSON object for a message, tool use, or metadata entry. The entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release. To build on session data, use `/export` or the [script interfaces](<#access-conversations-from-scripts>) instead.

The location, retention, and write behavior are configurable:

| To | Set | Where |
| - | - | - |
| Move storage off `~/.claude` | [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>) | Environment variable |
| [Name the `<project>` directory yourself](<#name-the-project-directory-yourself>) | [`CLAUDE_CODE_PROJECT_DIR_NAME`](<https://code.claude.com/docs/en/env-vars>) | Environment variable |
| Change the 30-day retention | [`cleanupPeriodDays`](<https://code.claude.com/docs/en/settings-reference#cleanupperioddays>) | `settings.json` |
| Set an age limit for [Claude Desktop and Cowork transcripts](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>) | [`desktopSessionCleanupPeriodDays`](<https://code.claude.com/docs/en/settings-reference#desktopsessioncleanupperioddays>) | User settings, managed settings, or `--settings` |
| Limit how large a `-p` or Agent SDK session's transcript file grows | [`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC`](<https://code.claude.com/docs/en/env-vars>) | Environment variable |
| Suppress transcript writes in all modes | [`CLAUDE_CODE_SKIP_PROMPT_HISTORY`](<https://code.claude.com/docs/en/env-vars>) | Environment variable |
| Suppress writes for one non-interactive run | [`--no-session-persistence`](<https://code.claude.com/docs/en/cli-reference>) | CLI flag with `claude -p` |

### Delete session data

Transcripts age out under the [retention sweep rules](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>). To delete a project's transcripts and related state sooner, run [`claude purge`](<https://code.claude.com/docs/en/claude-directory#clear-local-data>). If you delete a [background session](<https://code.claude.com/docs/en/agent-view>) with [`claude rm <id>`](<https://code.claude.com/docs/en/agent-view#what-deleting-a-session-removes>), its transcript stays on disk and remains available through `claude --resume`.

### Name the project directory yourself

By default, Claude Code derives the `<project>` name from the whole working directory path. To choose the name yourself, set `CLAUDE_CODE_PROJECT_DIR_NAME` alongside `CLAUDE_CONFIG_DIR`. Claude Code then stores that session's transcripts and [auto memory](<https://code.claude.com/docs/en/memory#auto-memory>) under your name. This suits a host that embeds Claude Code and gives each session its own config directory. Requires Claude Code v2.1.234 or later.

For example, this launch keeps tenant A's data under `/srv/tenant-a` and names its project directory `work`:

```bash theme={null}
CLAUDE_CONFIG_DIR=/srv/tenant-a CLAUDE_CODE_PROJECT_DIR_NAME=work claude
```

Claude Code writes the session's transcripts to `/srv/tenant-a/projects/work/` and its auto memory to `/srv/tenant-a/projects/work/memory/`, whatever the working directory is.

Three rules apply when you set it:

* **Set `CLAUDE_CONFIG_DIR` too**: the name doesn't vary with the working directory, so under the default `~/.claude` it would merge every project's transcripts and auto memory into one directory. Claude Code ignores `CLAUDE_CODE_PROJECT_DIR_NAME` when `CLAUDE_CONFIG_DIR` is unset.
* **Use 1-64 letters, digits, hyphens, or underscores**: don't use a Windows device name such as `con`. Claude Code ignores any other value and uses the derived name.
* **Set it in the shell environment that starts `claude`**: Claude Code reads it once at startup from that environment, so an `env` block in a settings file can't set it.

Once you've named a config directory's project directory, keep launching with that name. If you start Claude Code with the same `CLAUDE_CONFIG_DIR` but without `CLAUDE_CODE_PROJECT_DIR_NAME`, it reads and writes the derived directory again. The sessions stored under your name stay on disk: press `Ctrl+A` in the [session picker](<#use-the-session-picker>) to list sessions from every project directory under that config directory, the pinned one included, and whichever way you launch, [`claude --resume <session-id>`](<#resume-a-session>) finds a session stored under either name.
