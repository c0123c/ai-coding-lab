## 键盘快捷键



**注释：**

键盘快捷键可能因平台和终端而异。在 [ 全屏渲染 ](<https://code.claude.com/docs/en/fullscreen>) 中，在脚本查看器中按 `?` 可查看可用的快捷方式。

**macOS用户**：Option/Alt快捷键（`Alt+B`、`Alt+F`、`Alt+D`、`Alt+Y`、`Alt+P`）需要在终端中将选项配置为Meta。各终端的设置请参见[在macOS](<https://code.claude.com/docs/en/terminal-config#enable-option-key-shortcuts-on-macos>)上启用Option快捷键。

| :- | :- | :- |
| `Ctrl+C` |中断或清除输入|中断正在运行的操作。如果没有任何运行，第一次按将清除提示输入，第二次按将退出 Claude Code|
| `Ctrl+X Ctrl+K` |停止此会话中所有正在运行的 [ 后台子代理 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>)，并关闭其余会话的 [ 工件自动回复 ](<https://code.claude.com/docs/en/artifacts#let-claude-reply-to-comments-on-its-own>)。在 3 秒内按两次进行确认。您可以在后台子代理的权限提示打开时按下它|子代理控制|
| `Ctrl+D` |退出 Claude Code 会话|第一次按显示确认提示，第二次按 800 毫秒内退出。当提示有文本时，`Ctrl+D` 会删除 cursor 后面的字符|

| `Ctrl+B` |后台运行任务|背景 Bash 命令和 agents。 Tmux 用户按两次|
| `Ctrl+T` |切换Claude的任务清单|在状态区域显示或隐藏[Claude的待办事项清单](<#任务清单>)。这不是后台任务视图；使用 [`/tasks`](<https://code.claude.com/docs/en/commands>) 查看正在运行的 shell 和子代理|
| `Ctrl+S` |隐藏或恢复提示|输入文本后，将其隐藏并清除提示。在空提示符下再次按下，将恢复隐藏的文本、cursor 位置、粘贴的内容和输入模式，因此隐藏的 `!` [shell 命令 ](<#shell-mode-with-prefix>) 返回 shell 模式|
| `Ctrl+Z` |暂停Claude Code|仅限 Unix。挂起 shell 的进程；运行 `fg` 恢复|
| `Left/Right arrows` |循环浏览对话框选项卡|在权限对话框和菜单中的选项卡之间导航。在选项卡式对话框中，当选项卡行具有焦点时，按键会切换选项卡。请参阅[选项卡操作](<https://code.claude.com/docs/en/keybindings#tabs-actions>)了解焦点如何移动|
| `Tab` |接受自动完成建议，或向权限答案添加评论|当提示输入中显示自动完成建议时，接受所选建议。在大多数权限提示中，当聚焦于 **Yes** 或 **No** 时，会打开该选项的注释字段，再次按下该字段将关闭该字段。请参阅[在回答权限提示时添加评论](<https://code.claude.com/docs/en/permissions#add-a-comment-when-you-answer-a-permission-prompt>)|
|`Up/Down arrows` 或 `Ctrl+P`/`Ctrl+N`|移动 cursor 或导航命令历史记录|当输入跨越多个可视行时，无论是换行还是多行，首先在提示内移动 cursor。一旦 cursor 位于第一个或最后一个可视行，再次按下即可导航命令历史记录。当您有消息排队时，第一行中的 `Up` 相反 [ 将它们取回 ](<#收回你排队的东西>)|
| `Esc` |中断Claude，或关闭对话框|中途停止当前响应或工具调用，以便您可以重定向。 Claude 保持迄今为止已完成的工作。如果您有[消息排队](<#claude-工作时对消息进行排队>)，Claude Code接下来会发送它们。当对话框打开时，`Esc` 关闭该对话框。选择页脚项目时，例如提示下方的 [ 子代理面板 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) 中的一行，`Esc` [ 会取消选择它 ](<https://code.claude.com/docs/en/keybindings#footer-actions>)，而不是中断。在权限提示下，`Esc` 拒绝该操作，与 [**No** 没有评论](<https://code.claude.com/docs/en/permissions#add-a-comment-when-you-answer-a-permission-prompt>) 相同|
| `Esc` + `Esc` |清除输入草稿或倒回|当提示输入包含文本时，双击`Esc`将其清除并将草稿保存到历史记录中，以便`Up`调用它。当输入为空时，双击`Esc`打开[快退菜单](<https://code.claude.com/docs/en/checkpointing>)以恢复或总结上一点的代码和对话|
|`Ctrl+Enter` 或 `Ctrl+X Ctrl+S`|立即发送排队的消息|立即发送您的 [ 排队消息 ](<#claude-工作时对消息进行排队>) 以及您的草稿。 [当Claude Code发送您排队的内容时](<#当-claude-code-发送您排队的内容时>)涵盖了Claude正在处理的回合中发生的情况。在 [shell 模式 ](<#shell-mode-with-prefix>) 下，该键仅对您的命令进行排队。在不报告扩展密钥的终端中，`Ctrl+Enter` 以普通 `Enter` 形式到达； `Ctrl+X Ctrl+S`适用于任何终端。需要 Claude Code v2.1.275 或更高版本|
|当节点或 Bun 运行时未启用 VT 输入模式时，Windows 上的 `Shift+Tab` 或 `Alt+M`|循环权限模式|循环浏览 `default`（在模式指示器中标记为“手动”）、`acceptEdits`、`plan`，以及（如果可用）`bypassPermissions`，然后是 `auto`。从`auto`，第一次按切换到`default`。参见[权限模式](<https://code.claude.com/docs/en/permission-modes>)。在文件权限提示中，相同的键可关闭打开的 [ 注释字段 ](<https://code.claude.com/docs/en/permissions#add-a-comment-when-you-answer-a-permission-prompt>)。在没有打开字段的情况下，当提示提供该选项时，它会选择允许在会话的其余部分执行操作的选项|
|`Option+P` (macOS) 或 `Alt+P` (Windows/Linux)|开关型号|切换模型而不清除提示|
|`Option+T` (macOS) 或 `Alt+T` (Windows/Linux)|切换扩展思维|启用或禁用扩展思维模式。对作品 5.5、十四行诗 5.5、俳句 5.5 或始终使用扩展思维的寓言模型没有影响。适用于 macOS，无需将选项配置为元|
|`Option+O` (macOS) 或 `Alt+O` (Windows/Linux)|切换快速模式|启用或禁用[快速模式](<https://code.claude.com/docs/en/fast-mode>)|

|快捷方式|描述|背景|
| :- | :- | :- |
| `Ctrl+A` |将 cursor 移动到当前行的开头|在多行输入中，移动到当前逻辑行的开头|
| `Ctrl+E` |将 cursor 移至当前行末尾|在多行输入中，移动到当前逻辑行的末尾|

| `Ctrl+U` |删除从cursor到行首的位置|存储已删除的文本以供粘贴。重复此操作可清除多行输入中的跨行。在 macOS 上，包括 iTerm2 和 Terminal.app 在内的终端模拟器将 `Cmd+Backspace` 映射到此快捷方式|
| `Ctrl+W` |删除回之前的空白|存储已删除的文本以供粘贴。按一下即可删除整个路径或 `--flag=value`。要仅删除前一个单词，请按 macOS 上的 `Option+Delete` 或在 Windows 上按 `Ctrl+Backspace`|
| `Ctrl+Y` |粘贴删除的文本|使用单词或行删除快捷方式之一粘贴上次删除的文本，例如 `Ctrl+K`、`Ctrl+U` 或 `Ctrl+W`|

| `Alt+B` |cursor 后移一个字|词导航。需要 macOS 上的 [ 选项作为元 ](<#键盘快捷键>)|
| `Alt+F` |cursor 向前移动一个字|当 cursor 位于单词之间时，移至当前单词的末尾，或移至下一个单词的末尾。需要 [ 选项作为 macOS 上的元 ](<#键盘快捷键>)|
| `Alt+D` |删除到词尾|删除到当前单词的末尾，或者当单词之间有 cursor 时删除到下一个单词的末尾。存储已删除的文本以供粘贴。需要 [ 选项作为 macOS 上的元 ](<#键盘快捷键>)|
|`Ctrl+_` 或 `Ctrl+Shift+-`|撤消上次输入编辑|恢复之前输入的文本和cursor位置|

<h3 id="make-ctrl-w-delete-back-to-whitespace">
 编辑快捷方式中的字边界
</h3>

单词快捷方式 `Alt+B`、`Alt+F`、`Alt+D`、`Option+Delete` 和 `Ctrl+Backspace` 将单词视为一系列字母和数字，因此标点符号如 `_`、`.` 和`/` 分隔单词。在提示符中出现 `src/utils/foo.ts` 时，重复按 `Alt+B` 将在 `ts`、`foo`、`utils` 和 `src` 的开头处停止。

`Ctrl+W` 不同：它忽略标点符号并删除回到上一个空格，因此按一下即可删除所有 `src/utils/foo.ts`。

在没有空格的文本中，例如中文或日文，单词快捷方式仍然一次移动或删除一个单词。

这些 readline 约定适用于 Claude Code v2.1.261 及更高版本。在早期版本中打开它们的 [`keybindingFlavor`](<https://code.claude.com/docs/en/settings-reference#keybindingflavor>) 设置已被弃用并且没有任何效果。

您无法在 [ 键绑定配置文件 ](<https://code.claude.com/docs/en/keybindings>) 中重新映射这些快捷方式，该文件没有针对它们的操作。

## 命令

在 Claude Code 中键入 `/` 以查看可用的命令，或键入 `/` 后跟要过滤的任何字母。 `/` 菜单列出了内置命令、捆绑的和用户创作的 [ 技能 ](<https://code.claude.com/docs/en/skills>) 以及 [ 插件 ](<https://code.claude.com/docs/en/plugins/overview>) 和 [MCP 服务器 ](<https://code.claude.com/docs/en/mcp#use-mcp-prompts-as-commands>) 贡献的命令。并非所有内置命令都对每个用户可见，因为有些命令取决于您的平台或计划，并且 [ 一些可用命令通过设计从菜单中隐藏 ](<https://code.claude.com/docs/en/commands#how-the-command-menu-matches-what-you-type>) 并在您键入其全名时运行。

在[全屏渲染](<https://code.claude.com/docs/en/fullscreen#use-the-mouse>)中，`/`命令和`@`文件建议列表也会响应鼠标：悬停突出显示一行并单击接受它。

有关 Claude Code 中包含的命令的完整列表，请参阅 [ 命令参考 ](<https://code.claude.com/docs/en/commands>)。

### 在提示中完成命令

命令补全也可以在提示中进行：在空格后键入 `/`，然后键入名称的第一个字母，如 `run the tests, then /com` 所示。只有名称以这些字母开头的命令才会匹配，因此诸如 `/tmp/notes.md` 之类的文件路径不会使列表保持打开状态。仅当命令 [ 启动您的消息 ](<https://code.claude.com/docs/en/commands>) 时，Claude Code 才会运行命令本身。

* **在[全屏渲染](<https://code.claude.com/docs/en/fullscreen>)**中：在您键入时，匹配项会以列表形式打开，没有突出显示的行，因此`Enter`仍会按键入的方式发送提示。按 `Tab` 插入顶部匹配项，或使用箭头键和 `Enter` 选取一行。
* **全屏之外**：顶部匹配的其余部分在您的cursor上显示为幽灵文本，当有更多命令匹配时，计数如`+2`。按 `Tab` 插入唯一的匹配项，或者在有多个匹配项时打开列表，然后使用箭头键和 `Enter` 选取一行。

在两个渲染器中，在中间提示符 `/` 上按 `Tab` 可列出每个命令。

插件技能也与其裸名称匹配，因此 `/deploy` 找到名为 `myplugin:deploy-app` 的技能。当您插入匹配项时，Claude Code 会写入完整的 `/myplugin:deploy-app`。

## Vim 编辑器模式

通过 `/config` → 编辑器模式启用 vim 风格编辑。

当您使用 `Ctrl+O` 切换 [ 脚本查看器 ](<#成绩单查看器>) 或打开和关闭面板（例如 `/config`）时，Claude Code 会保留您的 vim 模式和 cursor 位置。如果您将提示保留为 NORMAL 模式，那么当您返回时，提示仍处于 NORMAL 模式，并且 cursor 位于您离开的位置。

### 重新映射 INSERT- 模式按键序列

[`vimInsertModeRemaps`](<https://code.claude.com/docs/en/settings-reference#viminsertmoderemaps>) 设置将两键 INSERT- 模式序列映射到 Escape，因此像 `jj` 这样的映射将返回到 NORMAL 模式。需要 Claude Code v2.1.208 或更高版本。

以下 `~/.claude/settings.json` 示例打开 vim 模式并将 `jj` 映射到 Escape：

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

每个键恰好是按顺序键入的两个可打印字符，并且 `"<Esc>"` 是唯一支持的目标。具有不同长度或目标的条目将被忽略。

键入序列的第一个字符会正常插入它。在一秒钟内按第二个字符将删除该待处理字符并切换到 NORMAL 模式，从而在输入中不保留任何字符。在一秒的窗口之后，或者如果后面跟着一个不同的键，两个字符都保持原义文本，因此您仍然可以通过在两个键之间暂停来键入包含该序列的单词。

Claude Code 仅从您的用户设置文件、`--settings` 标志和 [ 托管设置 ](<https://code.claude.com/docs/en/managed-settings>) 读取此设置。项目的 `.claude/settings.json` 或 `.claude/settings.local.json` 中的条目将被忽略，因此签出的存储库无法重新映射您的击键。

## 命令历史

Claude Code 保留您输入的提示的历史记录，并且向上箭头调用可以到达同一项目的过去会话中的提示：

* 输入历史记录按工作目录存储
* 运行 `/clear` 会启动一个新会话：然后调用，首先列出新会话的提示，后面列出早期会话的提示。先前会话的对话将被保留并且可以恢复。
* 连续两次提交相同的提示会记录一个历史记录条目，因此按向上键会转到上一个不同的提示
* 当您回忆起包含粘贴文本的提示时，Claude Code 会在您重新提交时再次发送完整的粘贴内容。如果内容已被[清理](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>)，则Claude Code不会发送文字`[Pasted text #N]`字符串；请参阅[粘贴大内容](<https://code.claude.com/docs/en/terminal-config#paste-large-content>)了解提示发生的情况
* 默认情况下禁用 `!` 的历史扩展

### 使用 Ctrl+R 反向搜索

按 `Ctrl+R` 以交互方式搜索命令历史记录。在 [ 全屏渲染 ](<https://code.claude.com/docs/en/fullscreen>) 中，`Ctrl+R` 将打开一个搜索对话框：键入进行筛选，按 `Up` 和 `Down` 在匹配项中移动，然后按 `Ctrl+S` 在该会话、该项目和所有项目中循环范围。按 `Enter` 或 `Tab` 在提示输入中放置匹配项，或按 `Esc` 取消。以下步骤描述了经典渲染器的内联搜索：

1. **开始搜索**：按`Ctrl+R`启动反向历史搜索
2. **键入查询**：输入要在之前命令中搜索的文本。搜索词在匹配结果中突出显示
3. **导航比赛**：再次按`Ctrl+R`循环浏览较旧的比赛
4. **搜索范围**：内联搜索始终搜索所有项目中的提示
5. **接受匹配**：
   * 按`Tab`或`Esc`接受当前匹配并继续编辑
   * 按`Enter`立即接受并执行命令
6. **取消搜索**：
   * 按`Ctrl+C`取消并恢复原始输入
   * 在空搜索上按`Backspace`取消

内联搜索会扫描完整的提示历史记录，最新的在前，重复项会折叠到最新出现的位置。全屏对话框会在所选范围内搜索整个提示历史记录，最新的在前，重复项会折叠到最新出现的位置：最新的提示会立即出现，并且在 Claude Code 加载其余内容时填充较旧的提示中的匹配项。显示匹配提示并突出显示搜索词，以便您可以查找并重复使用以前的输入。

即使 Claude Code 仍在加载历史记录，接受匹配或取消搜索也会立即生效。

## 后台 Bash 命令

Claude Code 支持在后台运行 Bash 命令，允许您在执行长时间运行的进程时继续工作。

### 背景如何工作

当Claude Code在后台运行命令时，它会异步运行该命令并立即返回后台任务ID。 Claude Code 可以在命令继续在后台执行的同时响应新的提示。

要在后台运行命令，您可以：

* 提示Claude Code在后台运行命令
* 按 `Ctrl+B` 将常规 Bash 工具调用移至后台。由于 tmux 的前缀键，Tmux 用户必须按 `Ctrl+B` 两次。

当命令在完成之前达到超时时，Claude Code 会自动 [ 将其移动到后台 ](<https://code.claude.com/docs/en/tools-reference#foreground-commands-that-move-to-the-background>)，而不是停止它，除非该命令以 `sleep` 开头。如果您已使用 [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](<https://code.claude.com/docs/en/env-vars#variables>) 或以 [ 裸模式 ](<https://code.claude.com/docs/en/headless#start-faster-with-bare-mode>) 启动来关闭后台任务，则该命令将在超时时停止。要更改超时，请设置 [Bash 超时环境变量 ](<https://code.claude.com/docs/en/tools-reference#timeout-and-output-limits>)。

**主要特点：**

* 输出被写入文件，Claude 可以使用读取工具检索它
* 后台任务具有用于跟踪和输出检索的唯一 ID
* 当Claude Code退出时，后台任务会自动清理。在 macOS 和 Linux 上，当您从 [`/tasks`](<https://code.claude.com/docs/en/commands>) 或 Claude Code 停止后台任务并在退出时将其停止时，与任务 shell 分离的进程（例如在 `setsid` 或 `timeout` 下启动的进程）也会停止
* 如果您将会话置于后台而不是退出它，则后台任务将在后台会话中继续运行。请参阅 [ 后台正在运行的会话 ](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>)
* 如果输出超过 5GB，后台任务将自动终止，并在 stderr 中注释解释原因
* 在 macOS 和 Linux 上，当操作系统报告严重内存压力时，Claude Code 会停止正在运行的后台任务，前提是会话已空闲至少 30 分钟且没有轮次或子代理运行
  * [调试日志](<https://code.claude.com/docs/en/debug-your-config>)说明为什么任务被停止，或者为什么压力事件让它们运行
  * 将 [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](<https://code.claude.com/docs/en/env-vars>) 设置为 `1` 以关闭内存压力停止
* 您通过终端、桌面应用程序或 VS Code 扩展进行操作的本地会话中的后台命令没有时间限制。在无人值守运行的会话中，例如 `-p` 运行或云会话，Claude Code 在其 [ 时间限制 ](<https://code.claude.com/docs/en/tools-reference#time-limit-for-background-commands>) 处停止后台命令
* 前台 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) 启动的后台命令在该子代理运行结束时结束，无论它完成、失败还是被中断；请参阅工具参考中的[当后台命令停止时](<https://code.claude.com/docs/en/tools-reference#when-a-background-command-stops>)

要禁用所有后台任务功能，请将 [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](<https://code.claude.com/docs/en/env-vars#variables>) 环境变量设置为 `1`。以 [ 裸模式 ](<https://code.claude.com/docs/en/headless#start-faster-with-bare-mode>) 启动也会将其关闭。

**常用后台命令：**

* 构建工具（webpack、vite、make）
* 包管理器（npm、纱线、pnpm）
* 测试运行程序（笑话、pytest）
* 开发服务器
* 长时间运行的进程（docker、terraform）

### 带有 `!` 前缀的 shell 模式

通过在输入前添加 `!` 前缀，直接运行 shell 命令，无需通过 Claude：

```bash theme={null}
! npm test
! git status
! ls -la
```

外壳模式：

* 将命令及其输出添加到对话上下文中
* 显示实时进度和输出
* 支持长时间运行命令的相同 `Ctrl+B` 后台
* 不需要 Claude 来解释或批准该命令
* 支持基于历史记录的自动完成：键入部分命令并按 `Tab` 来完成当前项目中先前的 `!` 命令
* 支持实时文件路径自动完成：键入包含正斜杠的标记，例如 `./src/` 或 `~/`，以查看匹配文件和目录的下拉列表，然后按 `Tab` 接受。在 Windows 上也使用正斜杠；下拉菜单由 `/` 触发，而不是 `\`
* 在空提示符下使用 `Escape`、`Backspace` 或 `Ctrl+U` 退出
* 将以 `!` 开头的文本粘贴到空提示符中会自动进入 shell 模式，匹配键入的 `!` 行为

除非您的会话是 [ 严格沙盒模式 ](<https://code.claude.com/docs/en/sandboxing#turn-off-the-retry-with-strict-sandbox-mode>) 下列出的会话之一，否则即使您启用了沙盒，您在 shell 模式下键入的命令也会在 [ 沙盒 ](<https://code.claude.com/docs/en/sandboxing>) 之外运行，因为沙盒适用于 Claude 运行的命令。

Claude 一旦命令输出进入记录，就会自动响应，因此您可以运行 `! npm test` 并获得失败的解释，而无需第二次提示。响应的费用与发送正常提示的费用相同。要将输出添加到上下文而不返回响应，请将 [`respondToBashCommands`](<https://code.claude.com/docs/en/settings-reference#respondtobashcommands>) 设置为 `settings.json` 中的 `false`。

## Claude 工作时对消息进行排队

输入消息并在 Claude 工作时按 `Enter`。 Claude Code 将消息排队而不是中断轮流，并列出会话中排队的条目，直到发送它们为止。您可以以相同的方式对 `!` [shell 命令 ](<#shell-mode-with-prefix>) 和大多数 [ 命令 ](<https://code.claude.com/docs/en/commands>) 进行排队，除了命令（例如 `/status`）之外，Claude Code 在发送后立即运行。

已发送和排队的消息显示为灰色，直到 Claude 开始响应它们，因此您可以知道哪些消息 Claude 尚未开始。

如果您将带有从 [ 连接的 IDE](<https://code.claude.com/docs/en/vs-code#the-built-in-ide-mcp-server>) 附加的选择的消息排队，它将保留您按 `Enter` 时的选择，无论您之后选择什么。

### 当 Claude Code 发送您排队的内容时

排队条目何时达到 Claude 取决于您排队的内容。

* 消息：如果您在 Claude 运行工具调用时对消息进行排队，Claude Code 一旦这些工具调用完成，就会在同一轮内将其传递给 Claude。当回合结束且消息仍在排队时，它们将按照您输入的顺序消失，无需再次按键
* 命令和 shell 命令：Claude Code 保留它们直到回合结束，然后一次运行一个，保持您排队的顺序

要立即发送您排队的内容，请按 `Ctrl+Enter`。您排队的消息会立即发出，如果您输入了草稿，那么您的草稿也会排队在它们后面。需要 Claude Code v2.1.275 或更高版本。

如果您在消息之前排队了 `!` shell 命令，则按键会中断轮流。否则，转弯会发生什么取决于按下该键时Claude正在做什么：

* 运行 shell 命令、子代理或其他可以移动到 [ 后台的工作 ](<#后台-bash-命令>)：该工作移动到后台并继续运行，并且 Claude 会同时读取您的消息
* 仅写入响应，或运行无法移动到后台的内容：Claude Code 中断回合并发送您的消息。在v2.1.281之前，钥匙在两种情况下都中断了转弯

在 [shell 模式 ](<#shell-mode-with-prefix>) 下，该键仅对您的命令进行排队。在不报告扩展密钥的终端中，`Ctrl+Enter` 以普通 `Enter` 形式到达，并对草稿进行排队； `Ctrl+X Ctrl+S` 适用于任何终端。两个键都是 [`chat:sendNow` 操作 ](<https://code.claude.com/docs/en/keybindings#chat-actions>) 的绑定。

按 `Esc` 中断回合而不提交草稿。 Claude Code 保留您排队的内容并立即发送。

Claude Code 在您发送命令后立即运行一些命令，而不是将它们排队，其中包括 `/model`、`/effort` 和 `/fast`。三者中的每一个都会更改一个设置：模型、工作量级别或快速模式。 Claude Code 是否将新设置应用于已在进行的回合 Claude，或者仅从下一个回合开始，因命令而异：

* [`/model`](<https://code.claude.com/docs/en/model-config#setting-your-model>)：一旦您确认[缓存警告](<https://code.claude.com/docs/en/prompt-caching#switching-models>)，如果Claude Code显示1，Claude Code将您的更改应用于该回合发出的下一个请求
* [`/effort`](<https://code.claude.com/docs/en/model-config#adjust-effort-level>)：一旦您确认[缓存警告](<https://code.claude.com/docs/en/prompt-caching#changing-effort-level>)，如果Claude Code显示1，Claude Code将您的更改应用于该回合发出的下一个请求
* [`/fast`](<https://code.claude.com/docs/en/fast-mode#toggle-fast-mode>)：Claude Code 保留回合开始时处于活动状态的快速模式设置，因此您的速度更改从下一个回合开始生效。如果您当前的模型不支持快速模式，打开它也会 [ 切换您的模型 ](<https://code.claude.com/docs/en/prompt-caching#turning-on-fast-mode>)，并且 Claude Code 使用该回合下一个请求中的新模型

### 收回你排队的东西

在输入框第一行按`Up`即可取回排队的消息和命令。 Claude Code 将它们从队列中删除，并将它们放入输入框中，每行一个，位于您键入的任何文本之前。编辑文本并按 `Enter` 将其作为一项再次排队，或清除输入框以将其删除。

Claude Code 仅当输入框为空且队列中没有其他内容时才取回排队的 shell 命令，并且在输入框为空时将输入框切换到 shell 模式。否则，它将它们留在队列中，并列出它们的 `!` 前缀，并在回合结束后运行它们。

## 及时建议

当您首次打开会话时，Claude Code 在提示输入中显示灰色示例命令以帮助您入门。它从您项目的 git 历史记录中选择此内容，因此该示例反映了您最近正在处理的文件。

Claude 响应后，Claude Code 可以根据您的对话历史记录建议您的下一个提示，例如多部分请求的后续步骤或工作流程的自然延续。

* 按`Tab`或`Right arrow`将建议放入提示输入中，然后按`Enter`提交
* 开始输入以将其关闭

Claude Code 生成每个下一个提示建议，并向您的会话正在使用的同一模型发出一个简短的后台请求。该请求计入您的计划的使用限制或您的 API 费用。因为它复用了会话的提示缓存，所以主要是缓存读取加上少量输出令牌，因此增加的成本很小。

### 当 Claude Code 跳过建议时

在交互模式下， Claude Code 默认情况下关闭提示建议并隐藏 **及时建议** 切换 `/config` 在一个 [不获取功能标志的会话](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>)，例如第三方提供商或通过 Claude 应用程序网关，并在 [安装或升级后的第一个会话](<https://code.claude.com/docs/en/env-vars#first-session-after-an-install-or-upgrade>) 谁的旗帜还没有到达。

Claude Code 还会在几种情况下跳过个别建议，包括：

* 提示缓存已冷，避免不必要的成本
* 在第一次对话之后，在某些会话中
* 上一个响应以错误结束
* 当您处于计划模式时
* 您的帐户已接近或达到其使用限制。要保留建议直至达到限制，请将 [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) 设置为 `true`。在v2.1.238之前，Claude Code在接近限制的情况下跳过它们，即使变量设置为`true`
* 在[agent团队](<https://code.claude.com/docs/en/agent-teams>)中，默认在队友的会话中。领导会议显示建议

通知 `Showing fewer prompt suggestions · use one to bring them back` 表示 Claude Code 显示建议的频率较低，因为您连续留下了许多未使用的建议。要返回到常用频率，请使用建议或将 [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) 设置为 `true`。

在打印模式下，Claude Code默认不生成建议。将 [`--prompt-suggestions`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 与 `-p "<prompt>" --output-format stream-json --verbose` 一起传递，让 Claude Code 在生成一条消息的每一回合后发出一条 `prompt_suggestion` 消息。生成器也会在这里跳过非常短的对话和冷提示缓存，因此单个短的 `-p` 查询不会发出任何内容。

### 关闭提示建议

要完全禁用提示建议，请使用以下任一方法：

* 关闭`/config`中的**提示建议**
* 在设置文件中将 [`promptSuggestionEnabled`](<https://code.claude.com/docs/en/settings-reference#promptsuggestionenabled>) 设置为 `false`
* 将 [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) 环境变量设置为 `false`，它优先于设置：
  ```bash theme={null}
  export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
  ```

要在整个组织中关闭提示建议，请在 [ 托管设置 ](<https://code.claude.com/docs/en/managed-settings>) 中将 `promptSuggestionEnabled` 设置为 `false`。还要将托管 [`env`](<https://code.claude.com/docs/en/settings-reference#env>) 密钥下的 `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` 设置为 `false`，以便用户无法使用自己的环境变量重新启用它们。

## 表情符号短代码

在提示输入中键入 `:`，后跟表情符号短代码以插入表情符号。需要 Claude Code v2.1.217 或更高版本。

* 输入完整的短代码，例如 `:heart:` 和 Claude Code 在输入结尾 `:` 后立即将其替换为 ❤️
* 输入 `:` 加上至少两个字符的名称，例如 `:hea`，打开建议弹出窗口，然后按 `Tab` 或 `Enter` 插入突出显示的表情符号

短代码必须开始输入或跟随一个空格，因此单词内的 `:` 或 URL 不会打开建议。

要关闭该功能，请将`settings.json`中的[`emojiCompletionEnabled`](<https://code.claude.com/docs/en/settings-reference#emojicompletionenabled>)设置为`false`。这会禁用建议弹出窗口和内联替换。

## 键入时检查拼写

Claude Code 可以在您键入时在提示输入中为拼写错误的单词添加下划线。它仅检查输入框中的文本，而不会检查 Claude 的回复或您的文件。当输入框处于 [ shell 模式 ](<#shell-mode-with-prefix>)、`Ctrl+R` 历史搜索或 [ 语音听写 ](<https://code.claude.com/docs/en/voice-dictation>) 时，它也不会检查任何内容。

默认情况下，拼写检查处于关闭状态，并且 Claude Code 在 [ 屏幕阅读器模式 ](<https://code.claude.com/docs/en/accessibility>) 中不进行任何检查。需要 Claude Code v2.1.235 或更高版本。

### 先决条件

* 安装 [aspell](<https://github.com/GNUAspell/aspell>)、[hunspell](<https://github.com/hunspell/hunspell>) 或 [ispell](<https://en.wikipedia.org/wiki/Ispell>) 并确保它位于您的 `PATH` 上。 Claude Code 在每个平台上按顺序运行它找到的三个中的第一个，包括包管理器在 Windows 上安装的 `.cmd` 填充程序。
* 要检查该程序是否在您的 `PATH` 上，请在终端中运行 `aspell --version`、`hunspell --version` 或 `ispell -v`。 “未找到命令”错误意味着它不在您的 `PATH` 上。

### 打开或关闭拼写检查

Claude Code从三个位置读取[`spellcheck`](<https://code.claude.com/docs/en/settings-reference#spellcheck>)设置，并在项目的`.claude/settings.json`和`.claude/settings.local.json`中忽略它。从您使用的任何一个打开它：



  

#### 用户设置

将 `spellcheck` 添加到 `~/.claude/settings.json`。它适用于您打开的每个项目，就像您的其余[用户设置](<https://code.claude.com/docs/en/settings#where-settings-live>)：

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  


  

#### 命令行

将`spellcheck`保存在JSON文件中，例如`spellcheck.json`：

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```

然后将文件传递给`--settings`。它仅适用于该会话：

    ```bash theme={null}
    claude --settings spellcheck.json
    ```
  


  

#### 托管设置

将 `spellcheck` 添加到您组织的 [ 托管设置源 ](<https://code.claude.com/docs/en/permissions#managed-settings>) 之一。它适用于收到这些设置的每个用户，并且他们无法将其关闭：

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  


要检查拼写检查是否已打开，请键入拼写错误的单词和空格。 Claude Code 在该词下划线。如果没有，请参见[当Claude Code什么都不下划线时](<#当-claude-code-没有下划线时>)。要再次关闭拼写检查，请在同一位置将 `enabled` 设置为 `false`，或删除 `spellcheck`。

要选择运行三个程序 Claude Code 中的哪一个、使用哪个字典或下划线颜色，请在 `enabled` 旁边的同一位置添加以下任意字段：

* `checker`：`aspell`、`hunspell` 或 `ispell`。 Claude Code 不会从您指定的检查器中回退，并将任何其他值视为 `auto`。
* `language`：检查器表单中的字典名称，例如`en_GB`。 Claude Code 忽略任何不是普通字典名称的值，例如路径或带有空格的名称，并且检查器使用其默认字典。
* `color`：颜色名称，例如 `yellow` 或 `#rrggbb`、`#rgb`、`rgb(r,g,b)`、`ansi256(n)` 或 `ansi:<name>` 值。 Claude Code 默认情况下使用主题的错误颜色以及它无法识别的任何值。

例如，此 `spellcheck` 设置使用其 `en_GB` 字典运行 hunspell 并用黄色下划线显示单词。它在 `~/.claude/settings.json`、传递给 `--settings` 的文件以及托管设置中的工作方式相同：

```json theme={null}
{
  "spellcheck": {
    "enabled": true,
    "checker": "hunspell",
    "language": "en_GB",
    "color": "yellow"
  }
}
```

如果三个位置中不止一个具有 `spellcheck` 设置，则 Claude Code 仅使用其中之一：首先是托管设置，然后是 `--settings`，最后是用户设置。它不会组合来自两个地方的字段。例如，当 `--settings` 设置 `spellcheck` 时，用户设置中的 `language` 无效。

### Claude Code 强调什么

暂停输入后不久，Claude Code 会在字典不认识的单词下划线。它会保留您仍在输入的单词，直到您越过它为止，并且它永远不会更改您的文本。它还会跳过看起来像代码的文本：

* `/help`、`@` 等命令提及、URL、文件路径和 `--verbose` 等标志
* 第一个后面带有数字、下划线或大写字母的单词以及反引号中的文本

Claude Code 还会跳过中文、日语、韩语、泰语、老挝语、高棉语和缅甸文本。

Claude Code 没有自己的单词列表：当检查员说某个单词拼写错误时。要阻止 Claude Code 在某个单词下划线，请按照检查者自己的文档将该单词添加到检查者的个人词典中。 Claude Code 重新启动后会拾取新单词。

### 当 Claude Code 没有下划线时

Claude Code 当它无法保持检查器运行时不会强调任何内容：

* 未安装检查器，或缺少您在 `checker` 中指定的检查器
* 检查器在启动时或会话后期连续失败两次。 Claude Code 在第一次失败后重新启动它，并在第二次失败后停止检查，直到您重新启动 Claude Code
* 检查员需要超过 15 秒才能回答，共 3 次。每次，Claude Code 都不会标记它正在等待的单词；第三次之后，它会停止检查，直到您重新启动 Claude Code

要查明发生了哪些情况，请启动 `claude --debug`，启用拼写检查并输入一个单词。然后在调试日志中查找 `~/.claude/debug/<session-id>.txt` 中的 `[spellcheck]` 行。其中一行将启动的程序命名为 Claude Code，或列出它查找但未找到的程序。后来的几行说明了它停止的原因。缺少字典错误意味着检查器没有适合您的 `language` 值的字典，或者在未设置 `language` 时没有默认字典。安装一个，或将 `language` 设置为您拥有的字典。

## 提示中的不可见字符

粘贴的文本可以携带终端绘制的 Unicode 字符，例如标签字符、双向控件和零宽度空格，因此提示可以包含您从未见过的文本。为了防止复制的文本携带终端不绘制的指令，Claude Code 会在您按 Enter 时删除这些字符，然后再发送任何内容。它会清除提示以及提示中包含的任何折叠的 [ 粘贴文本引用 ](<https://code.claude.com/docs/en/terminal-config#paste-large-content>) 的内容。 Claude Code 保留波斯语和印度语脚本编写的连接器以及表情符号序列内的选择器。

如果 Claude Code 删除了任何内容，则 Enter 不会发送任何内容。清理后的提示符会返回到输入框中，并带有诸如 `Removed 3 invisible characters · review and press Enter to send` 之类的通知，然后再次按 Enter 键会发送如图所示的文本。

当您在命令行上传递提示时，如 `claude "fix the login bug"` 中所示，Claude Code 不会等待第二次 Enter。它会删除字符，显示通知，并发送清理后的提示。如果清理后的提示以 `/` 开头，则 Claude Code 会将其放入输入框中供您查看并发送。

## 使用 /diff 查看更改

运行 `/diff` 以查看工作树中的更改，而无需离开 Claude Code。您会看到迄今为止 Claude 所做的编辑以及您尚未提交的任何其他内容。 `/diff` 打开的内容取决于哪个渲染器处于活动状态：

* **[全屏渲染](<https://code.claude.com/docs/en/fullscreen>)**：[差异面板](<#差速器面板>)在对话旁边打开。当您继续工作时，它会保持开放和更新。
* **经典渲染器**：[差异对话框](<#差异对话框>)在提示上方打开，读完后将其关闭。

面板和对话框均来自 `cc-plugin-diff`，其中之一 [内置模组 Claude Code](<https://code.claude.com/docs/en/plugins/mods/overview#mods-built-into-claude-code>)。如果你禁用该模组 `/plugin`, `/diff` 打开 Claude Code的早期面板和 [差异查看器](<https://code.claude.com/docs/en/keybindings#diff-actions>) 相反。

在从 git 读取的更改 `/diff` 中，子模块显示为单个条目，并且仅当提交它指向更改时才出现；对子模块内文件的编辑不会出现在那里。 Claude 编辑文件后，面板和对话框还提供每轮编辑的视图。这些转向视图来自 Claude 的文件编辑而不是来自 git，因此通过 shell 命令进行的更改 Claude 仅出现在工作树视图 `Current` 下。

### 差速器面板

差异面板列出了已更改的文件及其添加和删除的行数，并在列表下显示每个文件的差异。每次Claude编辑文件或运行shell命令时，Claude Code都会刷新它。要关闭面板，请再次运行`/diff`或单击其标题中的`✕`。

要使用该面板，您需要：

* [全屏渲染](<https://code.claude.com/docs/en/fullscreen>)
* 一个 git 存储库
* 至少 110 列宽的终端
* Claude Code v2.1.287 或更高版本

如果您的终端至少为 144 列宽，则一旦 Claude 开始编辑文件，该面板也会自行打开。当您自己使用 `/diff` 打开它后，只要 Claude 在任何宽度足以容纳该文件的终端中编辑文件，后续会话就会打开它。关闭面板并在本次会话和以后的会话中保持关闭状态，直到您再次运行 `/diff`。

当面板打开时，您可以：

* **跳转到文件**：在列表中单击其所在行。使用鼠标滚轮滚动面板。当文件列表本身太长而无法容纳时，请使用`Alt+Up`和`Alt+Down`或`Ctrl+Up`和`Ctrl+Down`滚动它。
* **询问Claude有关文件的更改**：单击文件名右侧其差异上方的`ask`。 Claude Code 将该文件的差异附加到您的下一个提示，按钮显示为 `asked ✓`，直到您发送该提示。询问第二个文件会替换第一个文件。
* **显示一回合的编辑**：单击面板标题中的`source`选择器，然后使用`Up`和`Down`选择回合并按`Enter`。匝数标记为 `T1`、`T2` 等。 Claude 编辑文件后，选择器就会出现，并且 `Current` 将返回到工作树。
* **显示面板遗漏的文件**：列表跳过测试文件和生成的文件，并将本次会话之前的更改折叠到底部的一行中。单击任一计数线将其展开。
* **更改面板与**进行比较的内容：按`Ctrl+X B`可从此会话的更改循环到作为一个列表的未提交更改，以及自您的分支从默认分支拆分以来的所有内容。 Claude Code 记住每个存储库的选择。

要重新绑定滚动文件列表或更改比较的按键，请参阅[差异面板操作](<https://code.claude.com/docs/en/keybindings#diff-panel-actions>)。

### 差异对话框

差异对话框作为提示上方的边框块打开，并列出已更改的文件及其添加和删除的行数。它将它们与 `HEAD` 进行比较，或者与您上次 [ 在此存储库的 diff 面板 ](<#差速器面板>) 中选择的内容进行比较。

Claude 编辑文件后，列表上方会出现 `source` 选择器。它为引导 Claude 编辑文件的每个提示提供一轮视图，标记为 `T1`、`T2` 等。回合视图仅显示该回合的编辑，`Current` 会将您返回到工作树。

在对话框中使用这些键：

* **上下**：选择文件。
* **输入**：打开所选文件的差异。向上和向下滚动，或 PageUp 和 PageDown。
* **Esc**：从文件的差异返回到列表，或从列表中关闭对话框。
* **选项卡**：移动到`source`选择器，然后选择`Current`或向上和向下的旋转视图，然后按Enter键。在文件的差异中，按 Tab 键移动到 `ask` 按钮。按 Enter 将该文件的差异附加到下一个提示中。

## /btw 的附带问题

使用 `/btw` 询问有关您当前工作的问题，而无需添加到对话历史记录。

```
/btw what was the name of that config file again?
```

Claude 回答了对话中已有内容的一个附带问题：您的消息、其回复以及它收集的工具结果。您可以询问 Claude 已阅读的代码、之前做出的决定或会话中的任何其他内容。稍后的附带问题也会看到您之前的附带问题：Claude Code 会重放每个询问的最新 20 交换，直到您清除它们。问题和答案永远不会进入对话历史记录。在终端中，它们出现在可关闭的叠加层中。终端将线程保留在内存中：按`x`清除之前的交换，当您退出Claude Code时它就消失了。

在 [VS Code 扩展 ](<https://code.claude.com/docs/en/vs-code#use-the-prompt-box>) 的聊天面板中，`/btw` 打开一个面板而不是本节描述的覆盖层，并且您可以直接在面板中提出后续问题。根据页面描述的保留计划，面板的线程在窗口重新加载后仍然存在。您需要 v2.1.227 或更高版本的扩展名。早期的扩展版本不提供 `/btw`。

* **在Claude工作时可用**：即使在Claude正在处理响应时，您也可以运行`/btw`。支线问题独立运行，不会打断主线。到目前为止，它可以看到对话中的所有内容，除了仍在写入的回复 Claude。
* **没有工具访问权限**：附带问题仅根据上下文中已有的内容进行回答。 Claude 在回答附带问题时无法读取文件、运行命令或搜索。如果 Claude 无论如何都以文本形式写出工具调用，则答案将以一条注释结束，表明未执行任何操作。
* **单一响应**：叠加层中没有后续回合。要继续线程，请询问另一个 `/btw` 问题。要继续在本地会话中进行完整的工具访问，请按 `f` 将此问题和答案分叉到 [ 后台子代理 ](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>) 中。
* **低成本**：虽然对话的[提示缓存](<https://code.claude.com/docs/en/prompt-caching>)很温暖，但除了答案本身之外，一个附带问题的成本很少。

您的五个最新的早期附带问题将显示为当前答案上方的灰色列表，并包含所有旧问题的计数。他们远离对话历史。

要在关闭覆盖层后返回到覆盖层，请毫无疑问地运行 `/btw`。叠加层会在您最近的交易中重新打开。在v2.1.212之前，没有问题的`/btw`打印了一条使用消息。

一旦出现答案，覆盖层就会接受这些键。

|钥匙|行动|
| :- | :- |
| `Space`, `Enter`, `Escape` |忽略答案并返回提示|
| `Up` / `Down` |滚动查看答案|
| `Shift+Left` / `Shift+Right` |介于此答案和您之前的 `/btw` 答案之间。 `Shift+Left` 移至较旧的答案，`Shift+Right` 返回当前答案。对于不使用箭头键报告 `Shift` 的终端，`[` 和 `]` 执行相同的操作。 `Tab` / `Shift+Tab` 循环浏览相同的答案。需要 Claude Code v2.1.257 或更高版本。在 v2.1.187 和 v2.1.256 之间，密钥是普通的 `Left` / `Right`|
| `c` |将答案作为原始 Markdown 复制到剪贴板。使用它代替鼠标选择，它捕获硬包装的终端渲染而不是源文本|
| `f` | 开始一个 [分叉子代理](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>) 它继承了父对话以及此问题和答案，因此它可以继续使用完整的工具访问权限。您留在当前会话中并在 [提示下方的面板](<https://code.claude.com/docs/en/sub-agents#observe-and-steer-running-forks>)。仅在本地会话中可用 |
| `x` |清除当前答案上方显示的早期 `/btw` 交换列表|

在附加的 [ 后台会话 ](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>) 中，`Left` 会分离并将您返回到 agent 视图，即使答案仍在到达。当你离开时，附带问题仍在继续。下次您附加到会话时，叠加层会重新打开，并显示附带问题或其答案。在v2.1.257之前，`Left`没有在那里分离。

`/btw` 可以看到您的完整对话，但没有工具。 [子代理](<https://code.claude.com/docs/en/sub-agents>)拥有工具，并从它收到的提示开始，或者，对于[分叉](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>)，从该对话的副本开始。使用`/btw`询问Claude从本次会话中已经知道了什么；使用子代理去寻找新的东西。

## 任务清单

任务列表是 Claude 的待办事项清单：为计划多步骤工作而创建的项目 Claude，并带有显示待处理、正在进行或已完成的任务的指示器。它与后台任务视图是分开的。要查看正在运行的 shell 和子代理，请改用 [`/tasks`](<https://code.claude.com/docs/en/commands>)。

该列表仅填充具有任务跟踪工具的会话，Claude Code 默认在 [Claude 3.x 型号、Opus 4 到 4.7、Sonnet 4 到 4.6 上提供，和俳句 4.5](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>)。在任何其他型号上，包括 ID Claude Code 无法识别的型号，列表将保持为空，除非您选择使用 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 或 [任务工具可用性 ](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>) 下的其他方式之一。当会话具有工具时，任务列表的工作方式如下：

* 按`Ctrl+T`切换任务列表视图。显示屏一次最多显示五个任务。当 Claude 尚未创建任何清单项目时，切换没有可见效果，因为没有任何内容可显示
* 如果您使列表保持展开状态，则下次启动仍包含任务的会话（例如 `--resume` 或 `--continue`）时，Claude Code 会恢复展开视图。当任务列表为空时，Claude Code开始折叠
* 要查看或清除所有任务，请直接询问 Claude：“显示所有任务”或“清除所有任务”
* 任务在上下文压缩中持续存在，帮助 Claude 在大型项目中保持井井有条
* 要跨会话共享任务列表，请将 `CLAUDE_CODE_TASK_LIST_ID` 设置为使用 `~/.claude/tasks/` 中的命名目录： `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

## 会议回顾

当您离开后返回终端时，Claude Code 会显示迄今为止会话中发生的情况的一行回顾。自上次完成转弯以来至少经过三分钟且终端未聚焦时，会在后台生成回顾，因此当您切换回来时它已准备就绪。回顾仅在会话至少进行三轮后才会出现，并且不会连续出现两次。

运行 `/recap` 以按需生成摘要。它仅在您自己要求时运行。当它到达从 Slack、Teams 或项目线程转发的消息中，或者到达例程发送的提示时，您会收到 [ 通知 ](<https://code.claude.com/docs/en/errors#recap-only-runs-when-you-ask-for-it-yourself>)，而不是回顾。

默认情况下，每个计划和提供商都会启用会话回顾。要关闭自动回顾，请打开 `/config` 并关闭 **会话回顾 **。自动重述永远不会出现在非交互模式下。 Claude Code 在 400 字符处限制自动重述和 `/recap` 输出。

## 等待使用限制重置

当 claude.ai [ 使用限制 ](<https://code.claude.com/docs/en/errors#youve-hit-your-session-limit>) 在任务中停止 Claude 时，Claude Code 在打开的会话中等待，并在限制重置后自行继续执行任务。默认情况下，在使用 claude.ai 订阅登录的交互式会话中，自动继续处于启用状态。需要 Claude Code v2.1.234 或更高版本。

当 Claude Code 等待时，会话底部的行会显示您的限制何时重置以及 Claude 何时继续：

```text theme={null}
Usage limit reached · limit resets 3:45pm
Continuing automatically at 3:45pm · esc to cancel
```

任何一行都可以在这些单词之后携带更多内容，例如第一行上的帮助链接或第二行上的 `/usage-credits to continue now`。当等待自行开始时，对话也会用一行 `Usage limit reached · continuing automatically at 3:45pm · esc to cancel` 记录它。

保持会话开放。接下来会发生什么取决于等待如何结束：

* **复位时**：第二行变为`Continuing shortly · esc to cancel`。然后`Usage limit reset · continuing automatically`出现在对话中，Claude Code提示Claude从停止的地方继续执行任务。它不会重新发送您的最后一条消息。
* **计算机睡眠后**：如果计算机睡眠时间超过30分钟，并且在睡眠期间重置限制，则第一行显示为`Your usage limit has reset`，第二行显示为`Press enter to continue`。按`Enter`继续。经过较短的睡眠时间或在重置之前结束的睡眠时间后，Claude Code 会自行继续。
* **早期**：当您使用`/usage-credits`添加[使用积分](<https://code.claude.com/docs/en/costs#add-usage-credits-to-your-subscription>)后，在`/upgrade`之后重新登录，或在等待期间使用`/model`切换模型， Claude Code 检查是否可以再次使用，如果可以则立即继续。在您自己在浏览器中进行升级或购买后，它不会进行检查。在 [`opusplan`](<https://code.claude.com/docs/en/model-config#opusplan-model-setting>) 和在不同模型上运行计划模式的其他模型设置下，Claude Code 会等待重置。

连续任务的运行方式与任何其他回合一样。 Claude Code 仍像往常一样请求 [ 权限 ](<https://code.claude.com/docs/en/permissions>)，因此任务可以在您离开时根据提示停止。如果再次达到限制，Claude Code 最多连续两次重新启动等待，然后停止并显示 `Automatic continue stopped after repeated usage-limit hits · /rate-limit-options to try again`。

### 取消等待

在出现空提示时按 `Esc`，或在显示行时按 `Ctrl+C`，或运行 [`/rate-limit-options`](<https://code.claude.com/docs/en/commands#all-commands>) 并选择 **不要自动继续 **。 Claude Code 使用以 `Automatic continue cancelled` 开头的行进行确认。

取消后，不会继续任何操作，直到您发送提示或选择以 ** 开头的行在此等待，然后再次从 `/rate-limit-options` 自动继续 **。 Claude Code 不会再次自行等待该重置窗口；下一个重置窗口将重新开始。

在这些情况下，等待也会结束而不继续执行任务：

* **您发送提示**：Claude Code发送提示而不是等待。如果您的提示也达到限制，它将保留在对话中，并且 Claude Code 再次开始等待。
* **您退出Claude Code**：当您恢复会话时，等待不会重新开始。
* **对话易手**：您使用`/login`切换帐户，清除或倒回对话，`/resume`另一个会话，使用`/teleport`拉动一个会话，使用`/tui`重新启动，或将会话移交给Claude 桌面、后台会话或云。
* **设置关闭，或者重置超过24小时**：这仅结束自行开始的等待Claude Code。您从`/rate-limit-options`中选择的等待不断倒计时。
* **继续被阻止**：阻止继续提示的[`UserPromptSubmit`挂钩](<https://code.claude.com/docs/en/hooks#userpromptsubmit>)，或者在到达模型之前失败，结束等待。 Claude Code 告诉您延续未运行。发送提示以继续。

### 自己开始等待

在这些情况下，Claude Code 不会自行启动等待：

* **远程控制和agent团队队友会话**：该终端上的人仍然可以启动会话。
* **距离24小时后重置**：每周限制可以重置天数。
* **当您运行该系列之外的模型时，Opus 或 Sonnet 限制**：您的下一个回合可能不会达到该限制。 [`opusplan`](<https://code.claude.com/docs/en/model-config#opusplan-model-setting>) 和在有限系列上运行计划模式的其他模型设置不会出现此异常。

在这些情况下，只要自动继续关闭，当您在自己的终端上达到限制时，Claude Code 在每个重置窗口中都会打开一次使用限制选项菜单。选择以**开始等待的行，然后自动继续**开始等待。在 [ 远程控制 ](<https://code.claude.com/docs/en/remote-control>) 或 [agent 团队 ](<https://code.claude.com/docs/en/agent-teams>) 队友会话中，自行运行 `/rate-limit-options` 以打开菜单。

Claude Code 在这些情况下根本不提供等待：

* **后台会话和`-p`运行**：菜单行不可用。
* **API 密钥、云提供商和基于使用情况的计费**：使用情况按请求计量，因此无需等待重置。
* ** 没有保存的 claude.ai 登录名的 [LLM 网关 ](<https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways>) **：Claude Code 仅在保存的 claude.ai 登录名是活动凭证时提供等待。

### 关闭自动继续

在`/config`中，在使用限制**时自动关闭**Continue，或在用户设置中将[`autoContinueAtUsageLimit`](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>)设置为`false`。 `/config autoContinueAtUsageLimit=false` 也适用，包括与 `-p` 一起使用，但 `key=value` 表单无法重新打开它，因为该设置授予无人值守执行。 Claude Code为此密钥读取哪些设置文件位于[设置参考](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>)中。

## PR审核状态

当处理具有开放拉取请求的分支时，Claude Code 在页脚中显示可单击的 PR 链接，例如“PR #446”。该链接有一条彩色下划线，指示审核状态：

* 绿色：已批准
* 黄色：待审核
* 红色：请求更改
* 灰色：草稿

一旦拉取请求合并或关闭，徽章就会消失。

`Cmd+click` (macOS) 或 `Ctrl+click` (Windows/Linux) 用于在浏览器中打开拉取请求的链接。

一旦 `git push` 或更改拉取请求的 `gh pr` 命令（例如 `gh pr create` 或 `gh pr merge`）在会话中成功，状态就会刷新。

Claude Code 会将徽章呈现为超链接，即使它无法检测到终端中的超链接支持，这通常发生在 SSH 或 tmux 中。设置 [`FORCE_HYPERLINK=0`](<https://code.claude.com/docs/en/env-vars>) 将徽章呈现为纯文本。

当您设置 [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](<https://code.claude.com/docs/en/env-vars>) 时，Claude Code 不会检查拉取请求或合并请求状态。



**注释：**

GitHub 存储库的 PR 状态需要 GitHub 令牌。 Claude Code 根据远程主机找到一个：

  * **github.com**: `GH_TOKEN` 或 `GITHUB_TOKEN`，或保存的令牌 `gh auth login`。如果没有，页脚会显示 `install gh for PR status` 当 `gh` CLI 未安装，或者 `gh auth login for PR status` 当它是
  * **A GitHub企业主机设置为`GH_HOST`**：`GH_ENTERPRISE_TOKEN`或`GITHUB_ENTERPRISE_TOKEN`，或`gh auth login --hostname <host>`保存的令牌。如果没有，页脚会显示相同的提示
  * **任何其他GitHub主机**：`gh auth login --hostname <host>`保存的令牌。如果没有，Claude Code 不会显示任何徽章和提示



### GitLab 合并请求

当您使用开放的 GitLab 合并请求处理分支时，Claude Code 在页脚插槽中显示可单击的 `MR !N` 徽章，否则该徽章包含 GitHub PR 链接。 `!N` 是 GitLab 自己的合并请求编号 N 的参考语法。彩色下划线显示合并请求的状态：

* 绿色：GitLab 将合并请求报告为可合并
* 黄色：任何其他打开状态
* 灰色：草稿

一旦合并请求合并或关闭，徽章就会消失。

一旦 `git push` 或更改合并请求的 `glab mr` 命令（例如 `glab mr create` 或 `glab mr merge`）在会话中成功，它就会刷新。

要获得徽章，您需要：

* Claude Code v2.1.234 或更高版本
* 指向您的 GitLab 主机的远程存储库，可以是 gitlab.com 或自我管理的实例
* 您的 `PATH` 上的 [`glab` CLI](<https://gitlab.com/gitlab-org/cli>)，已通过 `glab auth login` 进行身份验证

Claude Code 在检查状态时会忽略 `glab` 的令牌环境变量，例如 `GITLAB_TOKEN`，因此您无法仅从导出的令牌中获得徽章。 Claude Code 还会查找 `glab` 并在每个会话中登录一次，因此在安装 `glab` 或运行 `glab auth login` 后重新启动 Claude Code。

## 问题参考链接

当Claude提及问题为`owner/repo#123`时，只要您的终端支持超链接，您就可以点击参考打开它。如果 Claude Code 在您的终端中未检测到超链接支持，请将 [`FORCE_HYPERLINK`](<https://code.claude.com/docs/en/env-vars>) 设置为 `1` 以打开链接，或设置为 `0` 以将引用保留为纯文本。

您仅获得由两部分组成的 `owner/repo#123` 表单的链接。这些保持纯文本：

* 裸露`#123`
* 嵌套的 GitLab 路径，例如 `group/subgroup/project#123`
* 代码范围或代码块内的任何引用
* 回复中任何长度超过 1,000 行或 100,000 个字符的引用

Claude Code 为它从 git 远程识别的存储库主机构建链接，而不是为存储库引用名称构建链接：

|您的存储库的主机|`owner/repo#123` 链接在哪里|
| :- | :- |
|github.com、GitHub Enterprise 主机或下面未列出的任何主机| `https://<host>/owner/repo/issues/123` |
|gitlab.com| `https://gitlab.com/owner/repo/-/issues/123` |
|bitbucket.org、codeberg.org 或 gitea.com|没有链接；引用保持纯文本|

## Keyboard shortcuts

  Keyboard shortcuts may vary by platform and terminal. In [fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>), press `?` in the transcript viewer to see available shortcuts there.

### General controls

| Shortcut | Description | Context |
| :- | :- | :- |
| `Ctrl+C` | Interrupt, or clear input | Interrupts a running operation. If nothing is running, the first press clears the prompt input and a second press exits Claude Code |

Press twice within 3 seconds to confirm. You can press it while a background subagent's permission prompt is open | Subagent control |

Also expands lines that collapse by default, such as MCP calls, shown as a single `Called slack 3 times` line, and [messages from your other sessions](<https://code.claude.com/docs/en/cross-session-messaging#what-a-message-looks-like>), shown as a one-line `Message from @<sender>` preview |

<h3 id="make-ctrl-w-delete-back-to-whitespace">
  Word boundaries in editing shortcuts
</h3>

The word shortcuts `Alt+B`, `Alt+F`, `Alt+D`, `Option+Delete`, and `Ctrl+Backspace` treat a word as a run of letters and digits, so punctuation such as `_`, `.`, and `/` separates words. With `src/utils/foo.ts` in the prompt, repeated presses of `Alt+B` stop at the start of `ts`, `foo`, `utils`, and `src`.

`Ctrl+W` is different: it ignores punctuation and deletes back to the previous whitespace, so one press removes all of `src/utils/foo.ts`.

In text written without spaces, such as Chinese or Japanese, the word shortcuts still move or delete one word at a time.

These readline conventions apply in Claude Code v2.1.261 and later. The [`keybindingFlavor`](<https://code.claude.com/docs/en/settings-reference#keybindingflavor>) setting that turned them on in earlier versions is deprecated and has no effect.

You can't remap these shortcuts in the [keybindings configuration file](<https://code.claude.com/docs/en/keybindings>), which has no actions for them.

## Commands

Type `/` in Claude Code to see the commands available to you, or type `/` followed by any letters to filter. The `/` menu lists built-in commands, bundled and user-authored [skills](<https://code.claude.com/docs/en/skills>), and commands contributed by [plugins](<https://code.claude.com/docs/en/plugins/overview>) and [MCP servers](<https://code.claude.com/docs/en/mcp#use-mcp-prompts-as-commands>). Not all built-in commands are visible to every user since some depend on your platform or plan, and [a few available commands are hidden from the menu by design](<https://code.claude.com/docs/en/commands#how-the-command-menu-matches-what-you-type>) and run when you type their full name.

In [fullscreen rendering](<https://code.claude.com/docs/en/fullscreen#use-the-mouse>), the `/` command and `@` file suggestion lists also respond to the mouse: hovering highlights a row and clicking accepts it.

See the [commands reference](<https://code.claude.com/docs/en/commands>) for the full list of commands included in Claude Code.

### Complete a command mid-prompt

Command completion also works partway through a prompt: type `/` after a space, then the first letters of a name, as in `run the tests, then /com`. Only commands whose names start with those letters match, so a file path such as `/tmp/notes.md` doesn't keep a list open. Claude Code runs a command itself only when the command [starts your message](<https://code.claude.com/docs/en/commands>).

* **In [fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>)**: the matches open as a list while you type, with no row highlighted, so `Enter` still sends your prompt as typed. Press `Tab` to insert the top match, or pick a row with the arrow keys and `Enter`.
* **Outside fullscreen**: the rest of the top match appears as ghost text at your cursor, with a count such as `+2` when more commands match. Press `Tab` to insert the only match, or to open the list when several match, then pick a row with the arrow keys and `Enter`.

In both renderers, press `Tab` on a bare mid-prompt `/` to list every command.

A plugin skill matches on its bare name too, so `/deploy` finds a skill named `myplugin:deploy-app`. When you insert the match, Claude Code writes the full `/myplugin:deploy-app`.

### Remap INSERT-mode key sequences

The [`vimInsertModeRemaps`](<https://code.claude.com/docs/en/settings-reference#viminsertmoderemaps>) setting maps a two-key INSERT-mode sequence to Escape, so a mapping like `jj` returns you to NORMAL mode. Requires Claude Code v2.1.208 or later.

The following `~/.claude/settings.json` example turns on vim mode and maps `jj` to Escape:

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

Each key is exactly two printable characters typed in sequence, and `"<Esc>"` is the only supported target. Entries with a different length or target are ignored.

Typing the first character of a sequence inserts it normally. Pressing the second character within one second removes that pending character and switches to NORMAL mode, leaving neither character in your input. After the one-second window, or if a different key follows, both characters stay as literal text, so you can still type a word containing the sequence by pausing between the two keys.

Claude Code reads this setting from your user settings file, the `--settings` flag, and [managed settings](<https://code.claude.com/docs/en/managed-settings>) only. Entries in a project's `.claude/settings.json` or `.claude/settings.local.json` are ignored, so a checked-out repository can't remap your keystrokes.

## Command history

Claude Code keeps a history of the prompts you type, and Up-arrow recall reaches prompts from past sessions of the same project:

* Input history is stored per working directory
* Running `/clear` starts a new session: recall then lists the new session's prompts first, with earlier sessions' prompts after them. The previous session's conversation is preserved and can be resumed.
* Submitting the same prompt twice in a row records one history entry, so pressing Up steps to the previous distinct prompt
* When you recall a prompt that included pasted text, Claude Code sends the full pasted content again when you resubmit. If the content has since been [cleaned up](<https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically>), Claude Code doesn't send the literal `[Pasted text #N]` string; see [Paste large content](<https://code.claude.com/docs/en/terminal-config#paste-large-content>) for what happens to the prompt
* History expansion with `!` is disabled by default

### Reverse search with Ctrl+R

Press `Ctrl+R` to interactively search through your command history. In [fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>), `Ctrl+R` opens a search dialog instead: type to filter, press `Up` and `Down` to move through matches, and press `Ctrl+S` to cycle the scope through this session, this project, and all projects. Press `Enter` or `Tab` to place a match in the prompt input, or `Esc` to cancel. The steps below describe the classic renderer's inline search:

1. **Start search**: press `Ctrl+R` to activate reverse history search
2. **Type query**: enter text to search for in previous commands. The search term is highlighted in matching results
3. **Navigate matches**: press `Ctrl+R` again to cycle through older matches
4. **Search scope**: the inline search always searches prompts from all projects
5. **Accept match**:
   * Press `Tab` or `Esc` to accept the current match and continue editing
   * Press `Enter` to accept and execute the command immediately
6. **Cancel search**:
   * Press `Ctrl+C` to cancel and restore your original input
   * Press `Backspace` on empty search to cancel

The inline search scans your full prompt history, newest first, with duplicates collapsed to the newest occurrence. The fullscreen dialog searches your whole prompt history in the selected scope, newest first, with duplicates collapsed to the newest occurrence: the most recent prompts appear immediately, and matches from older prompts fill in as Claude Code loads the rest. Matching prompts display with the search term highlighted, so you can find and reuse previous inputs.

Accepting a match or canceling the search takes effect immediately, even while Claude Code is still loading the history.

## Background Bash commands

Claude Code supports running Bash commands in the background, allowing you to continue working while long-running processes execute.

### How backgrounding works

When Claude Code runs a command in the background, it runs the command asynchronously and immediately returns a background task ID. Claude Code can respond to new prompts while the command continues executing in the background.

To run commands in the background, you can either:

* Prompt Claude Code to run a command in the background
* Press `Ctrl+B` to move a regular Bash tool invocation to the background. Tmux users must press `Ctrl+B` twice due to tmux's prefix key.

When a command reaches its timeout before it finishes, Claude Code automatically [moves it to the background](<https://code.claude.com/docs/en/tools-reference#foreground-commands-that-move-to-the-background>) instead of stopping it, unless the command starts with `sleep`. If you've turned background tasks off with [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](<https://code.claude.com/docs/en/env-vars#variables>) or by starting in [bare mode](<https://code.claude.com/docs/en/headless#start-faster-with-bare-mode>), the command stops at its timeout. To change the timeout, set the [Bash timeout environment variables](<https://code.claude.com/docs/en/tools-reference#timeout-and-output-limits>).

**Key features:**

* Output is written to a file and Claude can retrieve it using the Read tool
* Background tasks have unique IDs for tracking and output retrieval
* Background tasks are automatically cleaned up when Claude Code exits. On macOS and Linux, when you stop a background task from [`/tasks`](<https://code.claude.com/docs/en/commands>) or Claude Code stops it at exit, processes that detached from the task's shell, such as ones started under `setsid` or `timeout`, stop too
* If you background the session instead of exiting it, your background tasks keep running in the background session. See [background a running session](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>)
* Background tasks are automatically terminated if output exceeds 5GB, with a note in stderr explaining why
* On macOS and Linux, Claude Code stops your running background tasks when the operating system reports critical memory pressure, provided the session has been idle for at least 30 minutes and no turn or subagent is running
  * The [debug log](<https://code.claude.com/docs/en/debug-your-config>) says why tasks were stopped, or why a pressure event left them running
  * Set [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](<https://code.claude.com/docs/en/env-vars>) to `1` to turn off memory-pressure stops
* Background commands in a local session you work in from a terminal, the desktop app, or the VS Code extension have no time limit. In a session that runs unattended, such as a `-p` run or a cloud session, Claude Code stops a background command at its [time limit](<https://code.claude.com/docs/en/tools-reference#time-limit-for-background-commands>)
* A background command that a foreground [subagent](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) started ends when that subagent's run ends, whether it finished, failed, or was interrupted; see [When a background command stops](<https://code.claude.com/docs/en/tools-reference#when-a-background-command-stops>) in the tools reference

To disable all background task functionality, set the [`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`](<https://code.claude.com/docs/en/env-vars#variables>) environment variable to `1`. Starting in [bare mode](<https://code.claude.com/docs/en/headless#start-faster-with-bare-mode>) turns it off as well.

**Common backgrounded commands:**

* Build tools (webpack, vite, make)
* Package managers (npm, yarn, pnpm)
* Test runners (jest, pytest)
* Development servers
* Long-running processes (docker, terraform)

### Shell mode with `!` prefix

Run shell commands directly without going through Claude by prefixing your input with `!`:

```bash theme={null}
! npm test
! git status
! ls -la
```

Shell mode:

* Adds the command and its output to the conversation context
* Shows real-time progress and output
* Supports the same `Ctrl+B` backgrounding for long-running commands
* Doesn't require Claude to interpret or approve the command
* Supports history-based autocomplete: type a partial command and press `Tab` to complete from previous `!` commands in the current project
* Supports live file path autocomplete: type a token containing a forward slash, such as `./src/` or `~/`, to see a dropdown of matching files and directories, then press `Tab` to accept. Use forward slashes on Windows too; the dropdown is triggered by `/`, not `\`
* Exit with `Escape`, `Backspace`, or `Ctrl+U` on an empty prompt
* Pasting text that starts with `!` into an empty prompt enters shell mode automatically, matching typed `!` behavior

Unless your session is one of those listed under [strict sandbox mode](<https://code.claude.com/docs/en/sandboxing#turn-off-the-retry-with-strict-sandbox-mode>), commands you type in shell mode run outside the [sandbox](<https://code.claude.com/docs/en/sandboxing>) even when you've enabled sandboxing, because the sandbox applies to the commands Claude runs.

Claude responds to the command output automatically once it lands in the transcript, so you can run `! npm test` and get an explanation of the failures without a second prompt. The response costs the same as sending a normal prompt. To add the output to context without a response instead, set [`respondToBashCommands`](<https://code.claude.com/docs/en/settings-reference#respondtobashcommands>) to `false` in `settings.json`.

## Queue messages while Claude works

Type a message and press `Enter` while Claude is working. Claude Code queues the message instead of interrupting the turn, and lists the queued entries in the conversation until it sends them. You can queue `!` [shell commands](<#shell-mode-with-prefix>) and most [commands](<https://code.claude.com/docs/en/commands>) the same way, apart from the commands, such as `/status`, that Claude Code runs as soon as you send them.

Sent and queued messages show in gray until Claude starts responding to them, so you can tell which messages Claude hasn't started on yet.

If you queue a message with a selection attached from a [connected IDE](<https://code.claude.com/docs/en/vs-code#the-built-in-ide-mcp-server>), it keeps the selection you had when you pressed `Enter`, whatever you select afterward.

### When Claude Code sends what you queued

When a queued entry reaches Claude depends on what you queued.

* Messages: if you queue a message while Claude is running tool calls, Claude Code passes it to Claude as soon as those tool calls finish, within the same turn. When the turn ends with messages still queued, they go out without another key press, in the order you typed them
* Commands and shell commands: Claude Code holds them until the turn ends, then runs them one at a time, keeping the order you queued them in

To send what you queued without waiting, press `Ctrl+Enter`. Your queued messages go out right away, with your draft queued behind them if you had typed one. Requires Claude Code v2.1.275 or later.

If you queued a `!` shell command ahead of your messages, the key interrupts the turn. Otherwise, what happens to the turn depends on what Claude is doing when you press the key:

* Running shell commands, subagents, or other work that can move to the [background](<#background-bash-commands>): that work moves to the background and keeps running, and Claude reads your messages in the same turn
* Only writing a response, or running something that can't move to the background: Claude Code interrupts the turn and sends your messages next. Before v2.1.281, the key interrupted the turn in both cases

In [shell mode](<#shell-mode-with-prefix>), the key only queues your command. In terminals that don't report extended keys, `Ctrl+Enter` arrives as plain `Enter` and queues the draft instead; `Ctrl+X Ctrl+S` works in any terminal. Both keys are bindings of the [`chat:sendNow` action](<https://code.claude.com/docs/en/keybindings#chat-actions>).

Press `Esc` to interrupt the turn without submitting your draft. Claude Code keeps what you queued and sends it right away.

Claude Code runs some commands as soon as you send them instead of queueing them, among them `/model`, `/effort`, and `/fast`. Each of the three changes a setting: the model, the effort level, or fast mode. Whether Claude Code applies the new setting to the turn Claude is already working on, or only from your next turn, differs by command:

* [`/model`](<https://code.claude.com/docs/en/model-config#setting-your-model>): once you confirm the [cache warning](<https://code.claude.com/docs/en/prompt-caching#switching-models>), if Claude Code shows one, Claude Code applies your change to the next request it makes in that turn
* [`/effort`](<https://code.claude.com/docs/en/model-config#adjust-effort-level>): once you confirm the [cache warning](<https://code.claude.com/docs/en/prompt-caching#changing-effort-level>), if Claude Code shows one, Claude Code applies your change to the next request it makes in that turn
* [`/fast`](<https://code.claude.com/docs/en/fast-mode#toggle-fast-mode>): Claude Code keeps the fast mode setting that was active when the turn started, so your speed change applies from your next turn. If your current model doesn't support fast mode, turning it on also [switches your model](<https://code.claude.com/docs/en/prompt-caching#turning-on-fast-mode>), and Claude Code uses the new model from its next request in that turn

### Take back what you queued

Press `Up` from the first line of the input box to take back the queued messages and commands. Claude Code removes them from the queue and puts them in the input box, one per line, ahead of any text you had typed. Edit the text and press `Enter` to queue it again as one entry, or clear the input box to drop it.

Claude Code takes back queued shell commands only when the input box is empty and you have nothing else queued, and it switches the input box to shell mode when it does. Otherwise it leaves them in the queue, listed with their `!` prefix, and runs them after the turn ends.

## Prompt suggestions

When you first open a session, Claude Code shows a grayed-out example command in the prompt input to help you get started. It picks this from your project's git history, so the example reflects files you've been working on recently.

After Claude responds, Claude Code can suggest your next prompt based on your conversation history, such as a follow-up step from a multi-part request or a natural continuation of your workflow.

* Press `Tab` or `Right arrow` to place the suggestion in the prompt input, then `Enter` to submit
* Start typing to dismiss it

Claude Code generates each of these next-prompt suggestions with a short background request to the same model your session is using. The request counts toward your plan's usage limits or your API costs. Because it reuses the conversation's prompt cache, it is mostly cache reads plus a few output tokens, so the added cost is small.

### When Claude Code skips suggestions

In interactive mode, Claude Code leaves prompt suggestions off by default and hides the **Prompt suggestions** toggle in `/config` in a [session that doesn't fetch feature flags](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>), such as one on a third-party provider or through a Claude apps gateway, and in a [first session after an install or upgrade](<https://code.claude.com/docs/en/env-vars#first-session-after-an-install-or-upgrade>) whose flags haven't arrived yet.

Claude Code also skips individual suggestions in several situations, including:

* The prompt cache is cold, to avoid unnecessary cost
* After the first turn of a conversation, in some sessions
* The previous response ended in an error
* While you're in plan mode
* Your account is close to or at its usage limit. To keep suggestions on until you reach the limit, set [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) to `true`. Before v2.1.238, Claude Code skipped them near the limit even with the variable set to `true`
* In an [agent team](<https://code.claude.com/docs/en/agent-teams>), in teammates' sessions by default. The lead's session shows suggestions

The notice `Showing fewer prompt suggestions · use one to bring them back` means Claude Code is showing suggestions less often because you left many in a row unused. To return to the usual frequency, use a suggestion or set [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) to `true`.

In print mode, Claude Code doesn't generate suggestions by default. Pass [`--prompt-suggestions`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) with `-p "<prompt>" --output-format stream-json --verbose` to have Claude Code emit a `prompt_suggestion` message after each turn that generates one. The generator skips very short conversations and cold prompt caches here too, so a single short `-p` query can emit none.

### Turn prompt suggestions off

To disable prompt suggestions entirely, use any of the following:

* Turn off **Prompt suggestions** in `/config`
* Set [`promptSuggestionEnabled`](<https://code.claude.com/docs/en/settings-reference#promptsuggestionenabled>) to `false` in your settings file
* Set the [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](<https://code.claude.com/docs/en/env-vars>) environment variable to `false`, which takes precedence over the setting:
  ```bash theme={null}
  export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
  ```

To turn prompt suggestions off across an organization, set `promptSuggestionEnabled` to `false` in [managed settings](<https://code.claude.com/docs/en/managed-settings>). Also set `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` to `false` under the managed [`env`](<https://code.claude.com/docs/en/settings-reference#env>) key so that users can't re-enable them with their own environment variable.

## Emoji shortcodes

Type a `:` followed by an emoji shortcode in the prompt input to insert the emoji. Requires Claude Code v2.1.217 or later.

* Type a complete shortcode such as `:heart:` and Claude Code replaces it with ❤️ as soon as you type the closing `:`
* Type `:` plus at least two characters of a name, such as `:hea`, to open a suggestion popup, then press `Tab` or `Enter` to insert the highlighted emoji

The shortcode must start the input or follow a space, so a `:` inside a word or URL doesn't open suggestions.

To turn the feature off, set [`emojiCompletionEnabled`](<https://code.claude.com/docs/en/settings-reference#emojicompletionenabled>) to `false` in `settings.json`. This disables both the suggestion popup and the inline replacement.

## Check spelling as you type

Claude Code can underline misspelled words in the prompt input while you type. It checks only the text in the input box, never Claude's replies or your files. It also checks nothing while the input box is in [shell mode](<#shell-mode-with-prefix>), `Ctrl+R` history search, or [voice dictation](<https://code.claude.com/docs/en/voice-dictation>).

Spell checking is off by default, and Claude Code checks nothing in [screen reader mode](<https://code.claude.com/docs/en/accessibility>). Requires Claude Code v2.1.235 or later.

### Prerequisites

* Install [aspell](<https://github.com/GNUAspell/aspell>), [hunspell](<https://github.com/hunspell/hunspell>), or [ispell](<https://en.wikipedia.org/wiki/Ispell>) and make sure it's on your `PATH`. Claude Code runs the first of the three it finds, in that order, on every platform, including a `.cmd` shim a package manager installs on Windows.
* To check that the program is on your `PATH`, run `aspell --version`, `hunspell --version`, or `ispell -v` in your terminal. A "command not found" error means it isn't on your `PATH` yet.

### Turn spell checking on or off

Claude Code reads the [`spellcheck`](<https://code.claude.com/docs/en/settings-reference#spellcheck>) setting from three places, and ignores it in a project's `.claude/settings.json` and `.claude/settings.local.json`. Turn it on from whichever one you use:



  

#### User settings

    Add `spellcheck` to `~/.claude/settings.json`. It applies in every project you open, like the rest of your [user settings](<https://code.claude.com/docs/en/settings#where-settings-live>):

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  


  

#### Command line

    Save `spellcheck` in a JSON file, such as `spellcheck.json`:

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```

    Then pass the file to `--settings`. It applies to that session only:

    ```bash theme={null}
    claude --settings spellcheck.json
    ```
  


  

#### Managed settings

    Add `spellcheck` to one of your organization's [managed settings sources](<https://code.claude.com/docs/en/permissions#managed-settings>). It applies to every user who receives those settings, and they can't turn it off:

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  


To check that spell checking is on, type a misspelled word and a space. Claude Code underlines the word. If it doesn't, see [When Claude Code underlines nothing](<#when-claude-code-underlines-nothing>). To turn spell checking off again, set `enabled` to `false` in the same place, or remove `spellcheck`.

To choose which of the three programs Claude Code runs, which dictionary it uses, or the underline color, add any of these fields next to `enabled`, in the same place:

* `checker`: `aspell`, `hunspell`, or `ispell`. Claude Code doesn't fall back from a checker you name, and treats any other value as `auto`.
* `language`: a dictionary name in your checker's form, such as `en_GB`. Claude Code ignores any value that isn't a plain dictionary name, such as a path or a name with spaces, and the checker uses its default dictionary.
* `color`: a color name such as `yellow`, or a `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)`, or `ansi:<name>` value. Claude Code uses your theme's error color by default and for any value it doesn't recognize.

For example, this `spellcheck` setting runs hunspell with its `en_GB` dictionary and underlines words in yellow. It works the same in `~/.claude/settings.json`, in the file you pass to `--settings`, and in managed settings:

```json theme={null}
{
  "spellcheck": {
    "enabled": true,
    "checker": "hunspell",
    "language": "en_GB",
    "color": "yellow"
  }
}
```

If more than one of the three places has a `spellcheck` setting, Claude Code uses only one of them: managed settings first, then `--settings`, then user settings. It doesn't combine fields from two places. For example, when `--settings` sets `spellcheck`, a `language` in your user settings has no effect.

### What Claude Code underlines

Shortly after you pause typing, Claude Code underlines the words the dictionary doesn't know. It leaves the word you're still typing alone until you move past it, and it never changes your text. It also skips text that looks like code:

* Commands such as `/help`, `@` mentions, URLs, file paths, and flags such as `--verbose`
* Words with digits, underscores, or a capital letter after the first, and text in backticks

Claude Code also skips Chinese, Japanese, Korean, Thai, Lao, Khmer, and Myanmar text.

Claude Code has no word list of its own: a word is misspelled when your checker says so. To stop Claude Code from underlining a word, add the word to your checker's personal dictionary, following the checker's own documentation. Claude Code picks up the new word after you restart it.

### When Claude Code underlines nothing

Claude Code underlines nothing when it can't keep a checker running:

* No checker is installed, or the one you named in `checker` is missing
* The checker fails twice in a row, at startup or later in the session. Claude Code restarts it after the first failure and stops checking after the second, until you restart Claude Code
* The checker takes more than 15 seconds to answer, three times. Each time, Claude Code leaves the words it was waiting on unmarked; after the third, it stops checking until you restart Claude Code

To find out which of these happened, start `claude --debug` with spell checking on and type a word. Then look for the `[spellcheck]` lines in the debug log at `~/.claude/debug/<session-id>.txt`. One line names the program Claude Code started, or lists the ones it looked for and didn't find. Later lines say why it stopped. A missing-dictionary error there means the checker has no dictionary for your `language` value, or no default one when `language` is unset. Install one, or set `language` to a dictionary you have.

## Invisible characters in prompts

Pasted text can carry Unicode characters that a terminal draws as nothing at all, such as tag characters, bidirectional controls, and zero-width spaces, so a prompt can contain text you never see. To keep copied text from carrying instructions your terminal doesn't draw, Claude Code removes those characters when you press Enter, before sending anything. It cleans both the prompt and the contents of any collapsed [pasted-text reference](<https://code.claude.com/docs/en/terminal-config#paste-large-content>) the prompt includes. Claude Code keeps the joiners that Persian and Indic scripts write and the selectors inside emoji sequences.

If Claude Code removed anything, that Enter sends nothing. The cleaned prompt goes back into the input box with a notice such as `Removed 3 invisible characters · review and press Enter to send`, and pressing Enter again sends the text as shown.

When you pass a prompt on the command line, as in `claude "fix the login bug"`, Claude Code doesn't wait for a second Enter. It removes the characters, shows a notice, and sends the cleaned prompt. If the cleaned prompt would begin with `/`, Claude Code puts it in the input box for you to review and send instead.

## Review changes with /diff

Run `/diff` to look over the changes in your working tree without leaving Claude Code. You see the edits Claude has made so far alongside anything else you haven't committed. What `/diff` opens depends on which renderer is active:

* **[Fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>)**: the [diff panel](<#diff-panel>) opens beside the conversation. It stays open and updates while you keep working.
* **Classic renderer**: the [diff dialog](<#diff-dialog>) opens above the prompt, and you close it when you're done reading.

The panel and the dialog both come from `cc-plugin-diff`, one of the [mods built into Claude Code](<https://code.claude.com/docs/en/plugins/mods/overview#mods-built-into-claude-code>). If you disable that mod in `/plugin`, `/diff` opens Claude Code's earlier panel and [diff viewer](<https://code.claude.com/docs/en/keybindings#diff-actions>) instead.

In the changes `/diff` reads from git, a submodule appears as a single entry, and only when the commit it points to changes; edits to files inside the submodule don't appear there. The panel and the dialog also offer a view of each turn's edits once Claude has edited files. These turn views come from Claude's file edits rather than from git, so a change Claude makes through a shell command appears only under `Current`, the working-tree view.

### Diff panel

The diff panel lists the changed files with their added and removed line counts, and shows each file's diff under the list. Claude Code refreshes it each time Claude edits a file or runs a shell command. To close the panel, run `/diff` again or click the `✕` in its header.

To use the panel you need:

* [Fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>)
* A git repository
* A terminal at least 110 columns wide
* Claude Code v2.1.287 or later

The panel also opens on its own once Claude starts editing files, if your terminal is at least 144 columns wide. After you've opened it yourself with `/diff`, later sessions open it as soon as Claude edits a file in any terminal wide enough to fit it. Close the panel and it stays closed, in this session and later ones, until you run `/diff` again.

While the panel is open, you can:

* **Jump to a file**: click its row in the list. Scroll the panel with the mouse wheel. When the file list itself is too long to fit, scroll it with `Alt+Up` and `Alt+Down`, or `Ctrl+Up` and `Ctrl+Down`.
* **Ask Claude about a file's changes**: click `ask`, at the right of the file's name above its diff. Claude Code attaches that file's diff to your next prompt, and the button reads `asked ✓` until you send that prompt. Asking on a second file replaces the first.
* **Show one turn's edits**: click the `source` picker in the panel's header, then choose a turn with `Up` and `Down` and press `Enter`. Turns are labeled `T1`, `T2`, and so on. The picker appears once Claude has edited files, and `Current` returns you to the working tree.
* **Show the files the panel leaves out**: the list skips test files and generated files, and collapses changes from before this session into one line at the bottom. Click either count line to expand it.
* **Change what the panel compares against**: press `Ctrl+X B` to cycle from this session's changes, to your uncommitted changes as one list, to everything since your branch split from the default branch. Claude Code remembers the choice for each repository.

To rebind the keys that scroll the file list or change the comparison, see [Diff panel actions](<https://code.claude.com/docs/en/keybindings#diff-panel-actions>).

### Diff dialog

The diff dialog opens as a bordered block above the prompt and lists your changed files with their added and removed line counts. It compares them against `HEAD`, or against whatever you last [chose in the diff panel](<#diff-panel>) for this repository.

Once Claude has edited files, a `source` picker appears above the list. It offers one turn view, labeled `T1`, `T2`, and so on, for each of your prompts that led Claude to edit files. A turn view shows only that turn's edits, and `Current` returns you to the working tree.

Use these keys in the dialog:

* **Up and Down**: select a file.
* **Enter**: open the selected file's diff. Scroll it with Up and Down, or PageUp and PageDown.
* **Esc**: return from a file's diff to the list, or close the dialog from the list.
* **Tab**: move to the `source` picker, then choose `Current` or a turn view with Up and Down and press Enter. In a file's diff, Tab moves to the `ask` button. Press Enter to attach that file's diff to your next prompt.

## Side questions with /btw

Use `/btw` to ask a question about your current work without adding to the conversation history.

```
/btw what was the name of that config file again?
```

Claude answers a side question from what's already in the conversation: your messages, its replies, and the tool results it has gathered. You can ask about code Claude has already read, decisions it made earlier, or anything else from the session. A later side question also sees your earlier side questions: Claude Code replays the newest 20 exchanges with each ask, until you clear them. The question and answer never enter the conversation history. In the terminal, they appear in a dismissible overlay. The terminal keeps the thread in memory: press `x` to clear the earlier exchanges, and it's gone when you exit Claude Code.

In the [VS Code extension](<https://code.claude.com/docs/en/vs-code#use-the-prompt-box>)'s chat panel, `/btw` opens a panel rather than the overlay this section describes, and you ask follow-up questions right in the panel. The panel's thread survives window reloads, on the retention schedule that page describes. You need the extension at v2.1.227 or later. Earlier extension versions don't offer `/btw`.

* **Available while Claude is working**: you can run `/btw` even while Claude is processing a response. The side question runs independently and doesn't interrupt the main turn. It sees everything in the conversation so far, except the reply Claude is still writing.
* **No tool access**: side questions answer only from what is already in context. Claude can't read files, run commands, or search when answering a side question. If Claude writes out tool calls as text anyway, the answer ends with a note that nothing was executed.
* **Single response**: there are no follow-up turns in the overlay. To continue the thread, ask another `/btw` question. To continue with full tool access in a local session, press `f` to fork this question and answer into a [background subagent](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>).
* **Low cost**: while the conversation's [prompt cache](<https://code.claude.com/docs/en/prompt-caching>) is warm, a side question costs little beyond the answer itself.

Your five newest earlier side questions appear as a dimmed list above the current answer, with a count of any older ones. They stay out of the conversation history.

To return to the overlay after dismissing it, run `/btw` with no question. The overlay reopens on your most recent exchange. Before v2.1.212, `/btw` without a question printed a usage message instead.

Once the answer appears, the overlay accepts these keys.

| Key | Action |
| :- | :- |
| `Space`, `Enter`, `Escape` | Dismiss the answer and return to the prompt |
| `Up` / `Down` | Scroll the answer |
| `Shift+Left` / `Shift+Right` | Step between this answer and your earlier `/btw` answers. `Shift+Left` moves to older answers and `Shift+Right` returns toward the current one. `[` and `]` do the same, for terminals that don't report `Shift` with arrow keys. `Tab` / `Shift+Tab` cycle through the same answers. Requires Claude Code v2.1.257 or later. Between v2.1.187 and v2.1.256, the keys were plain `Left` / `Right` |
| `c` | Copy the answer to your clipboard as raw Markdown. Use this instead of mouse selection, which captures the hard-wrapped terminal rendering rather than the source text |
| `f` | Start a [forked subagent](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>) that inherits the parent conversation plus this question and answer, so it can continue with full tool access. You stay in the current session and find the fork in the [panel below your prompt](<https://code.claude.com/docs/en/sub-agents#observe-and-steer-running-forks>). Available in local sessions only |
| `x` | Clear the list of earlier `/btw` exchanges shown above the current answer |

In an attached [background session](<https://code.claude.com/docs/en/agent-view#attach-to-a-session>), `Left` detaches and returns you to agent view, even while the answer is still arriving. The side question keeps running while you're away. The next time you attach to the session, the overlay reopens with the side question, or with its answer. Before v2.1.257, `Left` didn't detach there.

`/btw` sees your full conversation but has no tools. A [subagent](<https://code.claude.com/docs/en/sub-agents>) has tools and starts from the prompt it receives, or, for a [fork](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>), from a copy of this conversation. Use `/btw` to ask about what Claude already knows from this session; use a subagent to go find out something new.

## Task list

The task list is Claude's to-do checklist: items Claude created to plan multi-step work, with indicators showing what's pending, in progress, or complete. It's separate from the background-task view. To see running shells and subagents, use [`/tasks`](<https://code.claude.com/docs/en/commands>) instead.

The list fills only in sessions that have the task-tracking tools, which Claude Code provides by default on [Claude 3.x models, Opus 4 through 4.7, Sonnet 4 through 4.6, and Haiku 4.5](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>). On any other model, including a model ID Claude Code doesn't recognize, the list stays empty unless you opt in with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` or one of the other ways under [Task tool availability](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>). When the session has the tools, the task list works as follows:

* Press `Ctrl+T` to toggle the task list view. The display shows up to five tasks at a time. When Claude hasn't created any checklist items yet, the toggle has no visible effect because there's nothing to display
* If you leave the list expanded, Claude Code restores the expanded view the next time you launch into a session that still has tasks, such as with `--resume` or `--continue`. When the task list is empty, Claude Code starts it collapsed
* To see all tasks or clear them, ask Claude directly: "show me all tasks" or "clear all tasks"
* Tasks persist across context compactions, helping Claude stay organized on larger projects
* To share a task list across sessions, set `CLAUDE_CODE_TASK_LIST_ID` to use a named directory in `~/.claude/tasks/`: `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

## Session recap

When you return to the terminal after stepping away, Claude Code shows a one-line recap of what happened in the session so far. The recap generates in the background once at least three minutes have passed since the last completed turn and the terminal is unfocused, so it's ready when you switch back. Recaps only appear once the session has at least three turns, and never twice in a row.

Run `/recap` to generate a summary on demand. It runs only when you ask for it yourself. When it arrives in a message relayed from a Slack, Teams, or project thread, or in a prompt a routine sent, you get a [notice](<https://code.claude.com/docs/en/errors#recap-only-runs-when-you-ask-for-it-yourself>) instead of a recap.

Session recap is on by default for every plan and provider. To turn automatic recaps off, open `/config` and turn off **Session recap**. The automatic recap never appears in non-interactive mode. Claude Code caps both automatic recaps and `/recap` output at 400 characters.

## Wait for a usage limit to reset

When a claude.ai [usage limit](<https://code.claude.com/docs/en/errors#youve-hit-your-session-limit>) stops Claude mid-task, Claude Code waits in the open session and continues the task on its own after the limit resets. Automatic continue is on by default in interactive sessions signed in with a claude.ai subscription. Requires Claude Code v2.1.234 or later.

While Claude Code waits, the lines at the bottom of the session show when your limit resets and when Claude will continue:

```text theme={null}
Usage limit reached · limit resets 3:45pm
Continuing automatically at 3:45pm · esc to cancel
```

Either line can carry more after these words, such as a help link on the first or `/usage-credits to continue now` on the second. When the wait starts on its own, the conversation also records it with a line that reads `Usage limit reached · continuing automatically at 3:45pm · esc to cancel`.

Keep the session open. What happens next depends on how the wait ends:

* **At the reset**: the second line changes to `Continuing shortly · esc to cancel`. Then `Usage limit reset · continuing automatically` appears in the conversation, and Claude Code prompts Claude to pick the task up where it stopped. It doesn't resend your last message.
* **After your computer slept**: if it slept for more than about 30 minutes and the limit reset while it slept, the first line reads `Your usage limit has reset` and the second reads `Press enter to continue`. Press `Enter` to continue. After a shorter sleep, or one that ended before the reset, Claude Code continues on its own.
* **Early**: when you finish adding [usage credits](<https://code.claude.com/docs/en/costs#add-usage-credits-to-your-subscription>) with `/usage-credits`, sign back in after `/upgrade`, or switch models with `/model` during the wait, Claude Code checks whether usage is available again and continues right away if it is. It doesn't check after an upgrade or purchase you make in a browser on your own. Under [`opusplan`](<https://code.claude.com/docs/en/model-config#opusplan-model-setting>) and other model settings that run plan mode on a different model, Claude Code waits for the reset instead.

The continued task runs like any other turn. Claude Code still asks for [permissions](<https://code.claude.com/docs/en/permissions>) as usual, so the task can stop on a prompt while you're away. If it hits the limit again, Claude Code re-arms the wait on its own at most twice in a row, then stops and shows `Automatic continue stopped after repeated usage-limit hits · /rate-limit-options to try again`.

### Cancel the wait

Press `Esc` at an empty prompt, or `Ctrl+C`, while the lines show, or run [`/rate-limit-options`](<https://code.claude.com/docs/en/commands#all-commands>) and pick **Don't continue automatically**. Claude Code confirms with a line that starts `Automatic continue cancelled`.

After a cancel, nothing continues until you send a prompt or pick the row that starts **Wait here, then continue automatically** from `/rate-limit-options` again. Claude Code doesn't start a wait on its own again for that reset window; the next reset window starts fresh.

The wait also ends without continuing the task in these cases:

* **You send a prompt**: Claude Code sends your prompt instead of waiting. If your prompt hits the limit too, it stays in the conversation and Claude Code starts the wait again.
* **You exit Claude Code**: the wait doesn't restart when you resume the session.
* **The conversation changes hands**: you switch accounts with `/login`, clear or rewind the conversation, `/resume` another session, pull one with `/teleport`, relaunch with `/tui`, or hand the session to Claude Desktop, a background session, or the cloud.
* **The setting turns off, or the reset moves past 24 hours**: this ends only a wait Claude Code started on its own. A wait you picked from `/rate-limit-options` keeps counting down.
* **The continuation is blocked**: a [`UserPromptSubmit` hook](<https://code.claude.com/docs/en/hooks#userpromptsubmit>) that blocks the continuation prompt, or a failure before it reaches the model, ends the wait. Claude Code tells you the continuation didn't run. Send a prompt to continue.

### Start a wait yourself

Claude Code doesn't start the wait on its own in these cases:

* **Remote Control and agent team teammate sessions**: a person at that terminal can still start one.
* **A reset more than 24 hours away**: a weekly limit can reset days out.
* **An Opus or Sonnet limit while you run a model outside that family**: your next turn may not hit that limit. [`opusplan`](<https://code.claude.com/docs/en/model-config#opusplan-model-setting>) and other model settings that run plan mode on the limited family don't get this exception.

In those cases, and whenever automatic continue is off, Claude Code opens the usage-limit options menu once per reset window when you hit a limit at your own terminal. Pick the row that starts **Wait here, then continue automatically** to start the wait. In a [Remote Control](<https://code.claude.com/docs/en/remote-control>) or [agent team](<https://code.claude.com/docs/en/agent-teams>) teammate session, run `/rate-limit-options` yourself to open the menu.

Claude Code doesn't offer the wait at all in these cases:

* **Background sessions and `-p` runs**: the menu row isn't available.
* **API keys, cloud providers, and usage-based billing**: usage there is metered per request, so there is no reset to wait for.
* **An [LLM gateway](<https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways>) without a saved claude.ai login**: Claude Code offers the wait only while a saved claude.ai login is the active credential.

### Turn automatic continue off

In `/config`, turn off **Continue automatically at usage limit**, or set [`autoContinueAtUsageLimit`](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>) to `false` in your user settings. `/config autoContinueAtUsageLimit=false` also works, including with `-p`, but the `key=value` form can't turn it back on, because the setting grants unattended execution. Which settings files Claude Code reads for this key is in the [settings reference](<https://code.claude.com/docs/en/settings-reference#autocontinueatusagelimit>).

## PR review status

When working on a branch with an open pull request, Claude Code displays a clickable PR link in the footer, such as "PR #446". The link has a colored underline indicating the review state:

* Green: approved
* Yellow: pending review
* Red: changes requested
* Gray: draft

The badge disappears once the pull request merges or closes.

`Cmd+click` (macOS) or `Ctrl+click` (Windows/Linux) the link to open the pull request in your browser.

The status refreshes as soon as a `git push`, or a `gh pr` command that changes the pull request, such as `gh pr create` or `gh pr merge`, succeeds in the session.

Claude Code renders the badge as a hyperlink even when it can't detect hyperlink support in your terminal, which commonly happens over SSH or in tmux. Set [`FORCE_HYPERLINK=0`](<https://code.claude.com/docs/en/env-vars>) to render the badge as plain text.

When you set [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](<https://code.claude.com/docs/en/env-vars>), Claude Code doesn't check pull request or merge request status.



**注释：**

  PR status for GitHub repositories needs a GitHub token. Claude Code finds one based on the remote's host:

  * **github.com**: `GH_TOKEN` or `GITHUB_TOKEN`, or the token saved by `gh auth login`. Without one, the footer shows `install gh for PR status` when the `gh` CLI isn't installed, or `gh auth login for PR status` when it is
  * **A GitHub Enterprise host set as `GH_HOST`**: `GH_ENTERPRISE_TOKEN` or `GITHUB_ENTERPRISE_TOKEN`, or the token saved by `gh auth login --hostname <host>`. Without one, the footer shows the same hints
  * **Any other GitHub host**: the token saved by `gh auth login --hostname <host>`. Without one, Claude Code shows no badge and no hint



### GitLab merge requests

When you work on a branch with an open GitLab merge request, Claude Code shows a clickable `MR !N` badge in the footer slot that otherwise holds the GitHub PR link. `!N` is GitLab's own reference syntax for merge request number N. The colored underline shows the merge request's state:

* Green: GitLab reports the merge request as mergeable
* Yellow: any other open state
* Gray: draft

The badge disappears once the merge request merges or closes.

It refreshes as soon as a `git push`, or a `glab mr` command that changes the merge request, such as `glab mr create` or `glab mr merge`, succeeds in the session.

To get the badge, you need:

* Claude Code v2.1.234 or later
* A repository remote that points at your GitLab host, either gitlab.com or a self-managed instance
* The [`glab` CLI](<https://gitlab.com/gitlab-org/cli>) on your `PATH`, authenticated with `glab auth login`

Claude Code ignores `glab`'s token environment variables, such as `GITLAB_TOKEN`, when it checks status, so you get no badge from an exported token alone. Claude Code also looks for `glab` and for its login once per session, so restart Claude Code after you install `glab` or run `glab auth login`.

## Issue reference links

When Claude mentions an issue as `owner/repo#123`, you can click the reference to open it, as long as your terminal supports hyperlinks. If Claude Code doesn't detect hyperlink support in your terminal, set [`FORCE_HYPERLINK`](<https://code.claude.com/docs/en/env-vars>) to `1` to turn the links on, or to `0` to keep references as plain text.

You get a link only for the two-part `owner/repo#123` form. These stay plain text:

* A bare `#123`
* A nested GitLab path such as `group/subgroup/project#123`
* Any reference inside a code span or code block
* Any reference in a reply longer than about 1,000 lines or 100,000 characters

Claude Code builds the link for the host of the repository it identifies from your git remote, not for the repository the reference names:

| Your repository's host | Where `owner/repo#123` links |
| :- | :- |
| github.com, a GitHub Enterprise host, or any host not listed below | `https://<host>/owner/repo/issues/123` |
| gitlab.com | `https://gitlab.com/owner/repo/-/issues/123` |
| bitbucket.org, codeberg.org, or gitea.com | No link; the reference stays plain text |
