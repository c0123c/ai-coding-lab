# 通过 ultrareview 查找 bug

> 使用 /code-review ultra 在云中运行深度、多 agent 代码审查，以在合并之前查找并验证错误。



**注释：**

Ultrareview 是一项研究预览功能。功能、定价和可用性可能会根据反馈而变化。命令是`/code-review ultra`。当您的帐户可以使用 ultrareview 时，`/ultrareview` 是一个别名。


Ultrareview 是一种深度代码审查，在 Anthropic 的基础设施上作为 [ 云会话 ](<https://code.claude.com/docs/en/claude-code-on-the-web>) 运行。当您运行 `/code-review ultra` 时，Claude Code 在云沙箱中启动一组审阅者 agents，以查找分支或拉取请求中的错误。

与本地 `/code-review` 相比，ultrareview 提供：

* **更高的信号**：每个报告的发现都是独立重现和验证的，因此结果侧重于真正的错误而不是风格建议
* **更广泛的覆盖范围**：更大的审核者队伍agents并行探索变化，这暴露了本地审核可能错过的问题
* **不使用本地资源**：审核完全在云沙箱中运行，因此您的终端在运行时可以自由地进行其他工作

Ultrareview 需要使用 claude.ai 帐户进行身份验证，因为它作为云会话在 Anthropic 的基础设施上运行。如果您仅使用 API 密钥登录，请运行 `/login` 并首先使用 claude.ai 进行身份验证。当将 Claude Code 与 Amazon Bedrock、Google Cloud 的 Agent 平台或 Microsoft Foundry 结合使用时，Ultrareview 不可用，并且不适用于已启用零数据保留或应用了 [HIPAA 配置 ](<https://code.claude.com/docs/en/hipaa-setup>) 的组织。当 ultrareview 不可用时，`/code-review ultra` 会在您的会话中运行本地审核。

## 从 CLI 运行 ultrareview

从任何 git 存储库开始审查：

```text theme={null}
/code-review ultra
```

如果没有参数，ultrareview 会检查当前分支和默认分支之间的差异，包括未提交和暂存的更改。

对于分支审核，Claude Code 捆绑存储库状态，并根据 [ 将本地存储库上传到云会话 ](<https://code.claude.com/docs/en/claude-code-on-the-web#send-local-repositories-without-github>) 的规则将其上传到云沙箱，这些规则涵盖大小限制、签出要求以及名为凭证或密钥的文件中未提交的更改会发生什么情况，例如 `.env` 和`*.tfvars` 文件。当您[查看拉取请求](<#审查拉取请求>)时，Claude Code不会从您的计算机上传任何内容。

在启动之前，Claude Code 会显示一个确认对话框，其中包含审核范围、剩余免费运行以及预计成本；对于分支审查，范围包括文件和行数。确认后，审核将在后台继续进行，同时您继续使用会话。

仅当您使用 `/code-review ultra` 调用该命令时，该命令才会运行； Claude 本身不会启动超级审查。

### 根据不同的基础进行审查

要与默认分支以外的基础进行比较，请传递分支名称。此示例将根据 `develop` 检查您当前的分支：

```text theme={null}
/code-review ultra develop
```

基本分支不需要存在于您的本地克隆中； Claude Code 从 `origin` 获取它。如果名称有拼写错误，Claude Code 会建议错误中最接近的分支名称。

提交 ID 或标签也可以作为基础，然后审核将涵盖自该提交以来分支上的更改。

### 审查拉取请求

要在 `github.com` 而不是本地分支上查看拉取请求，请传递 PR 编号：

```text theme={null}
/code-review ultra 1234
```

该命令还接受 `#1234`、`PR 1234` 和粘贴的 PR URL；粘贴的 URL 必须指向当前目录中的存储库。

PR 模式需要 `github.com` 上的存储库。对于 [GitHub Enterprise Server](<https://code.claude.com/docs/en/github-enterprise-server>) 实例上的存储库，请运行不带 PR 编号的 `/code-review ultra` 以查看您的本地分支。

在 PR 模式下，云沙箱克隆来自 `github.com` 的拉取请求，而不是上传您的工作树。它使用连接到您的 Claude 帐户的 GitHub 帐户，因此该帐户需要对存储库的读取权限。

运行[`/web-setup`](<https://code.claude.com/docs/en/web-quickstart#connect-from-your-terminal>)将您的GitHubCLI登录名连接到您的Claude帐户。

### 将调查结果发布到拉取请求

在 Claude Code v2.1.227 或更高版本上，当您审核 `github.com` 上的拉取请求时，您可以让 Claude 将完成的调查结果作为来自您自己的 GitHub 帐户的单个普通评论发布到 PR。该评论不是审核或批准，并且以“由 Claude Code 生成”注释结尾。当您检查分支时，Claude Code 仅显示您会话中的结果。

Claude Code 永远不会发布，除非您选择在该运行中发布，并且 `--no-post` 是默认值。发布是您为每次运行所做的选择：

* **交互式**：在启动对话框中，选择**运行并将结果发布到PR，以我的身份**。如果将 `--post` 添加到命令中，如 `/code-review ultra 1234 --post` 中所示，Claude Code 会预先选择该选项，并且在启动之前仍然会询问。
* **非交互式**：使用`--post`运行[`claude ultrareview`子命令](<#以非交互方式运行-ultrareview>)。您通过运行带有该标志的子命令来同意该帖子，因此 Claude Code 无需询问即可发布。在 `claude -p '/code-review ultra'` 运行中，Claude Code 在结果到达之前退出，因此它不会发布任何内容；请改用子命令。

Claude Code 无法从您的计算机上发布。它将评论的会话 ID 发送到 Anthropic API，后者通过您连接到 Claude 的 GitHub 帐户将评论的存储结果作为评论发布。发布需要与评论本身相同的 claude.ai 登录，并且在第三方提供商或设置 [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](<https://code.claude.com/docs/en/env-vars>) 时不可用。

在交互式会话中，Claude Code 在调查结果到达时开始发布帖子，因此请保持会话开放，直到审核完成。 Claude Code 仅在该会话中保留发帖选择。如果会话在审核完成之前结束，Claude Code 不会发布任何内容，即使您稍后恢复对话也是如此。

帖子结束后，Claude 会告诉您结果：

* **发布**：Claude为您提供评论的链接。
* **已经发布**：同一评论的早期帖子已经将评论放在PR上，因此Claude将您链接到拉取请求而不是再次发布。
* **失败**：Claude告诉您原因，并且结果保留在您的终端中，以便您可以手动发布它们。

### 用简单的语言传递请求

在 Claude Code v2.1.218 或更高版本上，您还可以用简单的语言描述您正在做什么：

```text theme={null}
/code-review ultra check my auth changes
```

审查仍然涵盖您当前的分支，与不带参数运行的范围相同。 Claude 将您的文本保留为注释，显示在启动对话框中，并在发现结果到达时将其与其关联。

仅当您的文本包含多个单词且不是分支名称或 PR 引用时，Claude Code 才会将其视为注释。它将单个单词读取为分支名称或 PR 引用，因此输入错误的分支名称会从 [ 针对不同的基础 ](<#根据不同的基础进行审查>) 进行审查获取最近的分支错误，而不是使用注释启动。如果您的文本将 PR 引用与其他单词结合在一起，例如 `check PR 123 again`，则 Claude Code 也不会启动；它要求您仅使用 PR 编号重新运行以查看 PR，或者不使用参考来查看您当前的分支。



**提示：**

如果您的存储库太大而无法捆绑，Claude Code 会提示您使用 PR 模式。对于 `github.com` 上的存储库，推送您的分支并打开草稿 PR，然后运行 ​​`/code-review ultra <PR-number>`。


### 差异限制和回退

Ultrareview 会在运行任何审核工作之前检查差异，并在无法按原样审核时告诉您：

* **差异太大**：默认情况下，分支审阅最多可包含 500 个更改的文件和 8,000 个更改的行。确切的值可能会改变，[拒绝](<https://code.claude.com/docs/en/errors#diff-is-too-large-for-ultrareview>)会命名有效的值、差异的大小以及更改最多的行的文件。 Claude Code 以同样的方式拒绝太大的拉取请求，命名其文件和行数，但不命名每个文件的细分
* **没有什么需要审查**：当与基础的差异为空时，ultrareview 会拒绝并命名分支或将其提交，与您所处的情况进行比较，例如位于基础分支本身上，没有任何未提交的内容，或者提交的所有分支都已经是基础的一部分。它还建议了这种情况的出路，例如切换到您的工作分支，暂存或提交本地编辑，或传递不同的基础
* **首次提交**：存储库的首次提交没有任何早期可比较的内容，因此在启动对话框中确认后，ultrareview 会检查其中的每个文件。如果您有未跟踪的文件，它会拒绝并告诉您 `git add` 您想要查看的文件。同样的尺寸限制也适用。

仅在确认后才会对第一次提交进行整体审查，因此 `claude ultrareview` 子命令和 `claude -p` 会拒绝它并转而将您指向交互式会话。需要 Claude Code v2.1.277 或更高版本
* **无合并基础**：当您的分支与基础分支没有共享历史记录，或者存储库没有可比较的基础分支时，ultrareview 会检查存储库中的每个跟踪文件。后备需要完整克隆并应用相同的大小限制。仅当您在启动对话框中确认或自行运行 `claude ultrareview` 子命令时，它才会启动。在 `claude -p` 和其他任何地方都没有发生，ultrareview 拒绝，说审核将覆盖每个文件，并引导您进入交互式会话。

在没有分支或其他引用的结账时，例如在获取 URL 后通过签出 `FETCH_HEAD` 创建的分离 HEAD，Claude Code [ 拒绝审核 ](<https://code.claude.com/docs/en/errors#your-checkout-has-no-branches>) 并建议首先创建分支

## 定价和免费运行

Ultrareview 是一项高级功能，根据使用积分而不是您的计划包含的使用量进行计费。

|计划|包含免费运行|自由跑后|
| - | - | - |
|专业版|3 免费运行|计费为[使用积分](<https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans>)|
|最大|3 免费运行|计费为[使用积分](<https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans>)|

* **免费运行**：三个Pro和Max运行是每个帐户一次性分配的，不会刷新。
* **每次审核成本**：使用免费运行后，通常会根据更改的大小在使用积分中 \$5 到 \$25，与每次运行之前启动对话框显示的估计值相匹配。
* **运行计数时**：云会话启动后。您提前停止或未能完成的审核仍使用免费运行；仅支付已运行部分的审核费用。

由于 ultrareview 始终按照免费运行之外的使用积分进行计费，因此您的帐户或组织必须先启用使用积分，然后才能启动付费评论。如果未打开使用积分，Claude Code 会阻止启动。如果您可以管理帐户的账单，Claude Code 会将您链接到账单设置，您可以在其中打开使用积分。

您还可以运行`/usage-credits`来检查或更改您的使用积分设置。

Claude Code 要求您在每个对话中确认一次使用积分计费：当您开始新对话时，例如与 `/clear`，Claude Code 会再次显示下一次付费评论的确认。

## 跟踪正在进行的审核

审核通常需要 5 到 10 分钟。审核作为后台任务运行，因此您可以继续在会话中工作或启动其他命令。如果您选择 [ 将调查结果发布到拉取请求 ](<#将调查结果发布到拉取请求>)，请保持会话开放，直到审核完成；如果会话先结束，Claude Code 不会发布任何内容。

使用 `/tasks` 查看正在运行和已完成的审核、打开审核的详细信息视图或停止正在进行的审核。如果您停止审核，Claude Code 会将云会话存档，并且不会返回部分结果。

Claude 还可以告诉您评论已停止或未找到其会话：

* 如果在审核完成之前审核的云会话已停止或 [ 在 claude.ai 上存档 ](<https://code.claude.com/docs/en/claude-code-on-the-web#archive-sessions>)，Claude 会告诉您审核已停止。
* 如果评论的云会话已删除，或者您在启动后登录到不同的 Claude 帐户或组织，Claude 会告诉您未找到该会话。
* 如果您切换了帐户，审核可能仍会在启动审核的帐户下完成。如果审核仍在进行，请以该帐户重新登录并恢复与 `claude --resume` 的对话以重新附加它。

审核完成后，Claude Code 将在您的会话中将已验证的结果显示为通知。每个发现都包含文件位置和问题说明，因此您可以要求 Claude 直接修复它。

## 以非交互方式运行 ultrareview

使用 `claude ultrareview` 子命令从 CI 或没有交互式会话的脚本启动 ultrareview。该子命令启动与 `/code-review ultra` 相同的审查，阻塞直到远程审查完成，并将结果打印到标准输出。

```bash theme={null}
claude ultrareview
claude ultrareview 1234
claude ultrareview origin/main
```

如果不带参数，子命令会检查当前分支和默认分支之间的差异，当不存在合并基础时，具有与 `/code-review ultra` 相同的 [ 整个存储库回退 ](<#差异限制和回退>)。将 PR 编号传递给 [ 审核 `github.com`](<#审查拉取请求>) 上的拉取请求，或传递一个基础分支以对其进行审核； [基本分支处理](<#根据不同的基础进行审查>)与交互式命令匹配。

您同意整个存储库后备以及运行子命令时的计费和条款提示，因此运行无需等待输入即可开始。自己运行才算同意。当 Claude 为您运行子命令时，例如通过 Bash 工具，Claude Code 拒绝整个存储库审查。

`claude -p '/code-review ultra'` 无法为您提供结果，因此请在脚本中使用 `claude ultrareview`。 `-p` 运行启动云审核并立即退出，无需等待。当审核对使用积分进行计费时，`-p` 运行会停止而不启动。在 v2.1.218 之前，`/code-review ultra` 在非交互式会话中进行了本地审核。

`claude ultrareview` 将其进度消息写入 stderr，以便 stdout 保持可解析。使用这些标志来控制其输出、超时以及是否发布结果：

|旗帜|描述|
| - | - |
| `--json` |打印原始 `bugs.json` 有效负载而不是格式化的结果|
| `--timeout <minutes>` |等待审核完成的最长分钟数。默认为 45|
| `--post` |[将完成的发现](<#将调查结果发布到拉取请求>)作为来自您的GitHub帐户的一条简单评论发布到拉取请求中。适用于 `github.com` 拉取请求目标；在其他目标上，Claude Code 忽略该标志并这样说。需要 Claude Code v2.1.227 或更高版本|
| `--no-post` |不要发布调查结果。这是默认设置，如果您传递两个标志，则 Claude Code 不会发布。需要 Claude Code v2.1.227 或更高版本|

运行 `claude ultrareview` 需要与 `/code-review ultra` 相同的身份验证和使用积分配置。

该子命令以以下三个代码之一退出：

* **0**：审核已完成，有或没有发现结果
* **1**：审核无法启动或在完成之前停止、云会话出错或超时
* **130**：您使用 Ctrl-C 中断了子命令

如果子命令在结果到达之前退出，它们永远不会到达您的终端。审核可能仍在云端运行。再次运行该子命令将开始一项新的审阅，而不是恢复该审阅，并且新审阅 [ 使用免费运行或账单作为使用积分 ](<#定价和免费运行>)。

使用 `--post`，子命令在打印结果后立即启动帖子，并打印到 stderr 的链接。

* 如果运行失败、停止或超时，则子命令不会发布任何内容。
* 如果审核完成但评论未发布，Claude Code 会将原因打印到 stderr，并且结果保留在 stdout 上，以便您可以手动发布它们。

对于 GitHub 拉取请求的自动审查，[代码审查 ](<https://code.claude.com/docs/en/code-review>) 直接与您的存储库集成，并将结果发布为内联 PR 评论，无需 CLI 步骤。

## ultrareview 与 /code-review 相比如何

两种审查都会检查代码，但您在工作流程的不同阶段使用它们。

| | `/code-review` | `/code-review ultra` |
| - | - | - |
|目标|你的工作差异、拉取请求、分支或路径|你的工作差异或拉取请求|
|跑步|在您的本地会话中|在云沙箱中|
|深度|与努力论证成比例|具有独立验证的多agent车队|
|持续时间|几秒到几分钟|大约 5 到 10 分钟|
|成本|计入正常使用|免费运行，然后每次评论大约 \$5 到 \$25 作为使用积分|
|最适合|迭代时快速反馈|合并前对重大变化的信心|

在工作时使用 `/code-review` 获得快速反馈，或传递 PR 编号以在批准之前审查团队成员的拉取请求。当您想要更深入地通过以捕获本地审核可能错过的问题时，请在合并重大更改之前使用 `/code-review ultra`。

# Find bugs with ultrareview

> Run a deep, multi-agent code review in the cloud with /code-review ultra to find and verify bugs before you merge.



**注释：**

  Ultrareview is a research preview feature. The feature, pricing, and availability may change based on feedback. The command is `/code-review ultra`. When ultrareview is available to your account, `/ultrareview` is an alias.


Ultrareview is a deep code review that runs as a [cloud session](<https://code.claude.com/docs/en/claude-code-on-the-web>) on Anthropic's infrastructure. When you run `/code-review ultra`, Claude Code launches a fleet of reviewer agents in a cloud sandbox to find bugs in your branch or pull request.

Compared to a local `/code-review`, ultrareview offers:

* **Higher signal**: every reported finding is independently reproduced and verified, so the results focus on real bugs rather than style suggestions
* **Broader coverage**: a larger fleet of reviewer agents explores the change in parallel, which surfaces issues that a local review can miss
* **No local resource use**: the review runs entirely in a cloud sandbox, so your terminal stays free for other work while it runs

Ultrareview requires authentication with a claude.ai account because it runs as a cloud session on Anthropic's infrastructure. If you are signed in with an API key only, run `/login` and authenticate with claude.ai first. Ultrareview is not available when using Claude Code with Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry, and it is not available to organizations that have enabled Zero Data Retention or have the [HIPAA configuration](<https://code.claude.com/docs/en/hipaa-setup>) applied. When ultrareview is not available, `/code-review ultra` runs a local review in your session instead.

## Run ultrareview from the CLI

Start a review from any git repository:

```text theme={null}
/code-review ultra
```

Without arguments, ultrareview reviews the diff between your current branch and the default branch, including uncommitted and staged changes.

For a branch review, Claude Code bundles the repository state and uploads it to a cloud sandbox under the rules for [uploading a local repository to a cloud session](<https://code.claude.com/docs/en/claude-code-on-the-web#send-local-repositories-without-github>), which cover the size limits, the checkout requirements, and what happens to uncommitted changes in files named like credentials or keys, such as `.env` and `*.tfvars` files. When you [review a pull request](<#review-a-pull-request>), Claude Code uploads nothing from your machine.

Before launching, Claude Code shows a confirmation dialog with the review scope, your remaining free runs, and the estimated cost; for a branch review, the scope includes the file and line count. After you confirm, the review continues in the background while you keep using your session.

The command runs only when you invoke it with `/code-review ultra`; Claude doesn't start an ultrareview on its own.

### Review against a different base

To compare against a base other than the default branch, pass the branch name. This example reviews your current branch against `develop` instead:

```text theme={null}
/code-review ultra develop
```

The base branch doesn't need to exist in your local clone; Claude Code fetches it from `origin`. If the name has a typo, Claude Code suggests the closest branch name in the error.

A commit id or tag also works as the base, and the review then covers the changes on your branch since that commit.

### Review a pull request

To review a pull request on `github.com` instead of a local branch, pass the PR number:

```text theme={null}
/code-review ultra 1234
```

The command also accepts `#1234`, `PR 1234`, and pasted PR URLs; a pasted URL must point to the repository in your current directory.

PR mode needs a repository on `github.com`. For a repository on a [GitHub Enterprise Server](<https://code.claude.com/docs/en/github-enterprise-server>) instance, run `/code-review ultra` without a PR number to review your local branch instead.

In PR mode, the cloud sandbox clones the pull request from `github.com` instead of uploading your working tree. It uses the GitHub account connected to your Claude account, so that account needs read access to the repository.

Run [`/web-setup`](<https://code.claude.com/docs/en/web-quickstart#connect-from-your-terminal>) to connect your GitHub CLI login to your Claude account.

### Post findings to the pull request

On Claude Code v2.1.227 or later, when you review a pull request on `github.com`, you can have Claude post the finished findings to the PR as a single plain comment from your own GitHub account. The comment isn't a review or an approval, and it ends with a "Generated by Claude Code" note. When you review a branch, Claude Code shows the findings in your session only.

Claude Code never posts unless you choose to on that run, and `--no-post` is the default. Posting is a choice you make for each run:

* **Interactive**: in the launch dialog, select **Run and post the findings to the PR as me**. If you add `--post` to the command, as in `/code-review ultra 1234 --post`, Claude Code preselects that choice and still asks before launching.
* **Non-interactive**: run the [`claude ultrareview` subcommand](<#run-ultrareview-non-interactively>) with `--post`. You consent to the post by running the subcommand with the flag, so Claude Code posts without asking. In a `claude -p '/code-review ultra'` run, Claude Code exits before the findings arrive, so it posts nothing; use the subcommand instead.

Claude Code doesn't post from your machine. It sends the review's session ID to the Anthropic API, which posts the review's stored findings as the comment through the GitHub account you've connected to Claude. Posting requires the same claude.ai sign-in as the review itself, and it isn't available on third-party providers or when you set [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](<https://code.claude.com/docs/en/env-vars>).

In an interactive session, Claude Code starts the post when the findings arrive, so keep the session open until the review finishes. Claude Code keeps the posting choice only in that session. If the session ends before the review finishes, Claude Code posts nothing, even if you resume the conversation later.

When the post finishes, Claude tells you the outcome:

* **Posted**: Claude gives you a link to the comment.
* **Already posted**: an earlier post of the same review already put the comment on the PR, so Claude links you to the pull request instead of posting again.
* **Failed**: Claude tells you why, and the findings stay in your terminal so you can post them by hand.

### Pass a request in plain words

On Claude Code v2.1.218 or later, you can also describe what you're working on in plain words:

```text theme={null}
/code-review ultra check my auth changes
```

The review still covers your current branch, the same scope as running with no argument. Claude keeps your text as a note, shown in the launch dialog, and relates the findings to it when they arrive.

Claude Code treats your text as a note only when it has more than one word and isn't a branch name or PR reference. It reads a single word as a branch name or PR reference, so a mistyped branch name gets the closest-branch error from [Review against a different base](<#review-against-a-different-base>) instead of launching with a note. If your text combines a PR reference with other words, such as `check PR 123 again`, Claude Code doesn't launch either; it asks you to rerun with the PR number alone to review that PR, or without the reference to review your current branch.



**提示：**

  If your repository is too large to bundle, Claude Code prompts you to use PR mode instead. For a repository on `github.com`, push your branch and open a draft PR, then run `/code-review ultra <PR-number>`.


### Diff limits and fallbacks

Ultrareview checks the diff before any review work runs and tells you when it can't review it as-is:

* **Diff too large**: a branch review can include up to 500 changed files and 8,000 changed lines by default. The exact values can change, and the [refusal](<https://code.claude.com/docs/en/errors#diff-is-too-large-for-ultrareview>) names the ones in effect, the size of your diff, and the files with the most changed lines. Claude Code refuses a too-large pull request the same way, naming its file and line counts but not the per-file breakdown
* **Nothing to review**: when the diff against the base is empty, ultrareview refuses and names the branch or commit it compared against and the case you're in, such as being on the base branch itself with nothing uncommitted, or a branch whose commits are all part of the base already. It also suggests the way out for that case, such as switching to the branch with your work, staging or committing local edits, or passing a different base
* **First commit**: a repository's first commit has nothing earlier to compare with, so ultrareview reviews every file in it after you confirm in the launch dialog. If you have untracked files, it refuses instead and tells you to `git add` the ones you want reviewed. The same size limits apply.

  A first commit is reviewed whole only after that confirmation, so the `claude ultrareview` subcommand and `claude -p` refuse it and point you to an interactive session instead. Requires Claude Code v2.1.277 or later
* **No merge base**: when your branch shares no history with the base branch, or the repository has no base branch to compare with, ultrareview reviews every tracked file in the repository instead. The fallback requires a full clone and applies the same size limits. It launches only when you confirm in the launch dialog or run the `claude ultrareview` subcommand yourself. In `claude -p` and anywhere else neither happens, ultrareview refuses, says the review would cover every file, and points you to an interactive session.

  On a checkout with no branches or other refs, such as a detached HEAD created by checking out `FETCH_HEAD` after fetching a URL, Claude Code [refuses the review](<https://code.claude.com/docs/en/errors#your-checkout-has-no-branches>) and suggests creating a branch first

## Pricing and free runs

Ultrareview is a premium feature that bills against usage credits rather than your plan's included usage.

| Plan | Included free runs | After free runs |
| - | - | - |
| Pro | 3 free runs | billed as [usage credits](<https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans>) |
| Max | 3 free runs | billed as [usage credits](<https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans>) |

* **Free runs**: the three Pro and Max runs are a one-time allotment per account and don't refresh.
* **Cost per review**: after you use the free runs, typically \$5 to \$25 in usage credits depending on the size of the change, matching the estimate the launch dialog shows before each run.
* **When a run counts**: once the cloud session starts. A review you stop early or that fails to complete still uses a free run; a paid review bills only for the portion that ran.

Because ultrareview always bills as usage credits outside the free runs, your account or organization must have usage credits turned on before you can launch a paid review. If usage credits aren't turned on, Claude Code blocks the launch. If you can manage billing for your account, Claude Code links you to the billing settings where you can turn on usage credits.

You can also run `/usage-credits` to check or change your usage-credits setting.

Claude Code asks you to confirm usage-credits billing once per conversation: when you start a new conversation, for example with `/clear`, Claude Code shows the confirmation again for the next paid review.

## Track a running review

A review typically takes 5 to 10 minutes. The review runs as a background task, so you can keep working in your session or start other commands. If you chose to [post the findings to the pull request](<#post-findings-to-the-pull-request>), keep the session open until the review finishes; if the session ends first, Claude Code posts nothing.

Use `/tasks` to see running and completed reviews, open the detail view for a review, or stop a review that is in progress. If you stop a review, Claude Code archives the cloud session and doesn't return partial findings.

Claude can also tell you that a review was stopped or that its session wasn't found:

* If the review's cloud session is stopped or [archived](<https://code.claude.com/docs/en/claude-code-on-the-web#archive-sessions>) on claude.ai before the review finishes, Claude tells you it was stopped.
* If the review's cloud session was deleted, or you've signed in to a different Claude account or organization since launching it, Claude tells you the session wasn't found.
* If you switched accounts, the review may still finish under the account that started it. If the review is still running, sign back in as that account and resume the conversation with `claude --resume` to re-attach it.

When the review finishes, Claude Code shows the verified findings as a notification in your session. Each finding includes the file location and an explanation of the issue so you can ask Claude to fix it directly.

## Run ultrareview non-interactively

Use the `claude ultrareview` subcommand to start an ultrareview from CI or a script without an interactive session. The subcommand launches the same review as `/code-review ultra`, blocks until the remote review finishes, and prints the findings to stdout.

```bash theme={null}
claude ultrareview
claude ultrareview 1234
claude ultrareview origin/main
```

Without arguments, the subcommand reviews the diff between your current branch and the default branch, with the same [whole-repository fallback](<#diff-limits-and-fallbacks>) as `/code-review ultra` when no merge base exists. Pass a PR number to [review a pull request on `github.com`](<#review-a-pull-request>), or a base branch to review against it; [base-branch handling](<#review-against-a-different-base>) matches the interactive command.

You consent to the whole-repository fallback and to the billing and terms prompt when you run the subcommand, so the run starts without waiting for input. Running it yourself is what counts as consent. When Claude runs the subcommand for you instead, for example through the Bash tool, Claude Code refuses the whole-repository review.

`claude -p '/code-review ultra'` doesn't get you the findings, so use `claude ultrareview` in scripts. The `-p` run launches the cloud review and exits without waiting for it. When the review would bill usage credits, the `-p` run stops without launching it. Before v2.1.218, `/code-review ultra` in a non-interactive session ran a local review.

`claude ultrareview` writes its progress messages to stderr so stdout stays parseable. Use these flags to control its output, the timeout, and whether to post the findings:

| Flag | Description |
| - | - |
| `--json` | Print the raw `bugs.json` payload instead of the formatted findings |
| `--timeout <minutes>` | Maximum minutes to wait for the review to finish. Defaults to 45 |
| `--post` | [Post the finished findings](<#post-findings-to-the-pull-request>) to the pull request as one plain comment from your GitHub account. Works on `github.com` pull request targets; on other targets, Claude Code ignores the flag and says so. Requires Claude Code v2.1.227 or later |
| `--no-post` | Don't post the findings. This is the default, and if you pass both flags, Claude Code doesn't post. Requires Claude Code v2.1.227 or later |

Running `claude ultrareview` requires the same authentication and usage-credits configuration as `/code-review ultra`.

The subcommand exits with one of three codes:

* **0**: the review completed, with or without findings
* **1**: the review failed to launch or was stopped before it finished, the cloud session errored, or the timeout elapsed
* **130**: you interrupted the subcommand with Ctrl-C

If the subcommand exits before the findings arrive, they never reach your terminal. The review may still be running in the cloud. Running the subcommand again starts a new review rather than resuming that one, and the new review [uses a free run or bills as usage credits](<#pricing-and-free-runs>).

With `--post`, the subcommand starts the post right after printing the findings, and prints the link to stderr.

* If the run fails, is stopped, or times out, the subcommand posts nothing.
* If the review completes but the comment isn't posted, Claude Code prints the reason to stderr, and the findings stay on stdout so you can post them by hand.

For automatic reviews on GitHub pull requests, [Code Review](<https://code.claude.com/docs/en/code-review>) integrates with your repository directly and posts findings as inline PR comments without a CLI step.

## How ultrareview compares to /code-review

Both reviews examine code, but you use them at different stages of your workflow.

| | `/code-review` | `/code-review ultra` |
| - | - | - |
| Target | your working diff, a pull request, a branch, or a path | your working diff or a pull request |
| Runs | locally in your session | in a cloud sandbox |
| Depth | scales with the effort argument | multi-agent fleet with independent verification |
| Duration | seconds to a few minutes | roughly 5 to 10 minutes |
| Cost | counts toward normal usage | free runs, then roughly \$5 to \$25 per review as usage credits |
| Best for | quick feedback while iterating | pre-merge confidence on substantial changes |

Use `/code-review` for fast feedback as you work, or pass a PR number to review a teammate's pull request before approving it. Use `/code-review ultra` before merging a substantial change when you want a deeper pass that catches issues a local review might miss.
