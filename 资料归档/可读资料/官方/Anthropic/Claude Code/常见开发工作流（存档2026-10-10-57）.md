# 常见工作流程

> 使用 Claude Code 探索代码库、修复错误、重构、测试和其他日常任务的分步指南。

此页面收集了日常开发的简短秘诀。有关提示和上下文管理的更高级别指南，请参阅[最佳实践](<https://code.claude.com/docs/en/best-practices>)。

此页面涵盖：

* [提示秘诀](<#提示食谱>)用于探索代码、修复错误、重构、测试、PR 和文档
* [恢复之前的对话](<#恢复之前的对话>)，以便任务可以跨越多个会话
* [使用工作树运行并行会话](<#使用工作树运行并行会话>)，以便并发编辑不会发生冲突
* [编辑前计划](<#编辑前计划>)在接触磁盘之前检查更改

## 提示食谱

这些是日常任务的提示模式，例如探索不熟悉的代码、调试、重构、编写测试和创建 PR。每个都可以在任何 Claude Code 表面上工作；根据您的项目调整措辞。

### 了解新的代码库

要在 monorepo 或大型代码库中配置 Claude Code，请参阅 [Monorepos 和大型仓库 ](<https://code.claude.com/docs/en/large-codebases>)。

#### 快速了解代码库概述

假设您刚刚加入一个新项目，需要快速了解其结构。



  

#### 导航到项目根目录

    ```bash theme={null}
    cd /path/to/project 
    ```

将 `/path/to/project` 替换为您的项目路径。
  


  

#### 开始Claude Code

    ```bash theme={null}
    claude 
    ```
  


  

#### 请求高级概述

    ```text wrap theme={null}
    give me an overview of this codebase
    ```
  


  

#### 深入研究特定组件

    ```text wrap theme={null}
    explain the main architecture patterns used here
    ```

    ```text wrap theme={null}
    what are the key data models?
    ```

    ```text wrap theme={null}
    how is authentication handled?
    ```
  




**提示：**

温馨提示：

  * 从广泛的问题开始，然后缩小到特定领域
  * 询问项目中使用的编码约定和模式
  * 索取项目特定术语表



#### 查找相关代码

假设您需要查找与特定特性或功能相关的代码。



  

#### 请Claude查找相关文件

    ```text wrap theme={null}
    find the files that handle user authentication
    ```
  


  

#### 获取有关组件如何交互的上下文

    ```text wrap theme={null}
    how do these authentication files work together?
    ```
  


  

#### 了解执行流程

    ```text wrap theme={null}
    trace the login process from front-end to database
    ```
  




**提示：**

温馨提示：

  * 具体说明您要寻找的内容
  * 使用项目中的领域语言
  * 为您的语言安装 [ 代码智能插件 ](<https://code.claude.com/docs/en/plugins/code-intelligence>)，以提供 Claude 精确的“转到定义”和“查找引用”导航

### 高效修复错误

假设您遇到错误消息并需要查找并修复其来源。



  

#### 与 Claude 分享错误

    ```text wrap theme={null}
    I'm seeing an error when I run npm test
    ```
  


  

#### 寻求修复建议

    ```text wrap theme={null}
    suggest a few ways to fix the @ts-ignore in user.ts
    ```
  


  

#### 应用修复

    ```text wrap theme={null}
    update user.ts to add the null check you suggested
    ```
  




**提示：**

温馨提示：

  * 告诉 Claude 命令来重现问题并获取堆栈跟踪
  * 提及重现错误的任何步骤
  * 让 Claude 知道错误是间歇性的还是持续的

### 重构代码

假设您需要更新旧代码以使用现代模式和实践。

要将整个代码库移植到新语言，请参阅博客上的 [Anthropic 如何使用 Claude Code](<https://claude.com/blog/ai-code-migration>) 运行大规模代码迁移。



  

#### 识别遗留代码以进行重构

    ```text wrap theme={null}
    find deprecated API usage in our codebase
    ```
  


  

#### 获取重构建议

    ```text wrap theme={null}
    suggest how to refactor utils.js to use modern JavaScript features
    ```
  


  

#### 安全地应用更改

    ```text wrap theme={null}
    refactor utils.js to use ES2024 features while maintaining the same behavior
    ```
  


  

#### 验证重构

    ```text wrap theme={null}
    run tests for the refactored code
    ```
  




**提示：**

温馨提示：

  * 请 Claude 解释现代方法的好处
  * 要求更改在需要时保持向后兼容性
  * 以小的、可测试的增量进行重构

### 处理测试

假设您需要为未覆盖的代码添加测试。



  

#### 识别未经测试的代码

    ```text wrap theme={null}
    find functions in NotificationsService.swift that are not covered by tests
    ```
  


  

#### 生成测试脚手架

    ```text wrap theme={null}
    add tests for the notification service
    ```
  


  

#### 添加有意义的测试用例

    ```text wrap theme={null}
    add test cases for edge conditions in the notification service
    ```
  


  

#### 运行并验证测试

    ```text wrap theme={null}
    run the new tests and fix any failures
    ```
  


Claude 可以生成遵循项目现有模式和约定的测试。当要求进行测试时，请具体说明您想要验证的行为。 Claude 检查现有的测试文件以匹配已在使用的样式、框架和断言模式。

为了提高覆盖率，请询问 Claude 以确定您可能错过的边缘情况。 Claude 可以分析您的代码路径，并建议对错误条件、边界值和经常被忽视的意外输入进行测试。

### 创建拉取请求

您可以通过直接询问 Claude（“为我的更改创建 pr”）来创建拉取请求，或指导 Claude 逐步完成：



  

#### 总结一下你的改变

    ```text wrap theme={null}
    summarize the changes I've made to the authentication module
    ```
  


  

#### 生成拉取请求

    ```text wrap theme={null}
    create a pr
    ```
  


  

#### 审查和完善

    ```text wrap theme={null}
    enhance the PR description with more context about the security improvements
    ```
  


要稍后查找会话，请使用您自己的 PR 编号运行 `claude --from-pr 1234`，这将打开筛选到链接到该 PR 的会话的会话选择器，或将 PR URL 粘贴到 [`/resume` 选择器 ](<https://code.claude.com/docs/en/sessions#use-the-session-picker>)搜索。当 Claude 使用 `gh pr create` 或 `glab mr create` 创建会话时，以及当 Claude [ 在现有 PR](<https://code.claude.com/docs/en/agent-view#pull-request-status>) 上工作时，Claude Code 将会话链接到 PR。



**提示：**

在提交之前查看 Claude 生成的 PR，并要求 Claude 强调潜在的风险或注意事项。

### 在笔记和非代码文件夹中工作

Claude Code 适用于任何目录。在笔记库、文档文件夹或任何 Markdown 文件集合中运行它，以与编码相同的方式搜索、编辑和重新组织内容。

`.claude/` 目录和 `CLAUDE.md` 与其他工具的配置目录并存，不会发生冲突。 Claude 在每次工具调用时读取新的文件，因此下次读取该文件时它会看到您在另一个应用程序中所做的编辑。

### 参考文件和目录

使用@可以快速包含文件或目录，而无需等待Claude读取它们。



  

#### 引用单个文件

    ```text wrap theme={null}
    Explain the logic in @src/utils/auth.js
    ```

当符合 [ 读取工具 ](<https://code.claude.com/docs/en/tools-reference#read-tool-behavior>) 的令牌限制时，这包括对话中的文件内容，默认为 25,000 令牌。不包括大于 256KB 的文本文件。
  


  

#### 引用目录

    ```text wrap theme={null}
    What's the structure of @src/components?
    ```
  


  

#### 参考【MCP】资源

    ```text wrap theme={null}
    Show me the data from @github:repos/owner/repo/issues
    ```

这使用 @server:resource 格式从连接的 MCP 服务器获取数据。详情请参阅[MCP资源](<https://code.claude.com/docs/en/mcp#use-mcp-resources>)。
  




**提示：**

温馨提示：

  * 文件路径可以是相对路径或绝对路径
  * 输入 `@` 打开路径建议菜单，然后按 Enter 或 Tab 接受突出显示的路径，然后再次按 Enter 发送消息
  * @文件引用将文件目录和父目录中的`CLAUDE.md`添加到上下文中
  * 目录引用显示文件列表，而不是内容
  * 您可以在一条消息中引用多个文件（例如，“@file1.js 和 @file2.js”）

### 按计划运行 Claude

假设您希望 Claude 定期自动处理任务，例如每天早上查看开放的 PR，每周审核依赖项，或夜间检查 CI 故障。

根据您希望任务运行的位置选择计划选项：

|选项|它运行在哪里|最适合|
| :- | :- | :- |
|[例程](<https://code.claude.com/docs/en/routines>)|云，Anthropic-默认管理|即使计算机关闭时也应运行的任务。除了计划之外，还可以触发 API 呼叫或 GitHub 事件。在[claude.ai/code/routines](<https://claude.ai/code/routines>)处配置。|
|[桌面计划任务](<https://code.claude.com/docs/en/desktop-scheduled-tasks>)|您的机器，通过桌面应用程序|需要直接访问本地文件、工具或未提交更改的任务。|
|[GitHub 行动](<https://code.claude.com/docs/en/github-actions>)|您的 CI 管道|与存储库事件相关的任务，例如打开的 PR，或应与工作流程配置一起存在的 cron 计划。|
| [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) |当前 CLI 会话|会话打开时快速轮询。 `--resume` 和 `--continue` 恢复未过期的固定间隔循环。|



**提示：**

在为计划任务编写提示时，请明确说明成功是什么样子以及如何处理结果。该任务是自主运行的，因此它无法提出澄清问题。例如：“查看标记为 `needs-review` 的公开 PR，对任何问题留下内联评论，并在 `#eng-reviews` Slack 频道中发布摘要。”

## 恢复之前的对话

当一项任务需要多次进行时，请从上次停下的地方继续，而不是重新解释上下文。 Claude Code 将每个对话保存在本地。

```bash theme={null}
claude --continue
```

这将恢复当前目录中的最新会话；如果还没有，则打印 `No conversation found to continue` 并退出。使用 `claude --resume` 从列表中进行选择，或使用 `/resume` 从正在运行的会话中进行选择。有关命名、分支和完整选择器参考，请参阅[管理会话](<https://code.claude.com/docs/en/sessions>)。

## 使用工作树运行并行会话

在一个终端中处理一项功能，同时 Claude 修复另一个终端中的错误，而不会发生编辑冲突。每个 [git worktree](<https://git-scm.com/docs/git-worktree>) 都是其自己分支上的单独签出，从现有提交创建，因此存储库首先需要至少一次提交。

```bash theme={null}
claude --worktree feature-auth
```

在第二个终端中使用不同的名称运行相同的命令以启动隔离的并行会话。在没有提交的存储库中，命令失败并显示 `Failed to resolve base branch "HEAD": git rev-parse failed`。请参阅 [Worktrees](<https://code.claude.com/docs/en/worktrees>) 了解清理、`.worktreeinclude` 和非 git VCS 支持。要从一个屏幕而不是单独的终端监控并行会话，请参阅[背景agents](<https://code.claude.com/docs/en/agent-view>)。

## 编辑前计划

对于您想要在触及磁盘之前查看的更改，请切换到计划模式。 Claude 读取文件并提出计划，但在您批准之前不会进行任何编辑。当计划模式处于活动状态时，状态栏显示 `⏸ plan mode on`。

```bash theme={null}
claude --permission-mode plan
```

您也可以在会话中按 `Shift+Tab`，直到状态栏显示 `⏸ plan mode on`。请参阅[计划模式](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>)了解批准流程并在文本编辑器中编辑计划。

## 将研究委托给子代理

探索大型代码库会通过文件读取来填充您的上下文。委托探索，以便只返回结果。

```text wrap theme={null}
use a subagent to investigate how our auth system handles token refresh
```

子代理在其自己的上下文窗口中读取文件并报告摘要。请参阅 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>) 以使用其自己的工具和提示定义自定义 agents。

## 通过管道 Claude 到脚本中

以非交互方式运行 Claude 以执行 CI、预提交挂钩或批处理。 Stdin 和 stdout 的工作方式与任何 Unix 工具一样。

```bash theme={null}
git log --oneline -20 | claude -p "summarize these recent commits"
```

有关输出格式、权限标志和扇出模式，请参阅[非交互模式](<https://code.claude.com/docs/en/headless>)。

# Common workflows

> Step-by-step guides for exploring codebases, fixing bugs, refactoring, testing, and other everyday tasks with Claude Code.

This page collects short recipes for everyday development. For higher-level guidance on prompting and context management, see [Best practices](<https://code.claude.com/docs/en/best-practices>).

## Prompt recipes

These are prompt patterns for everyday tasks like exploring unfamiliar code, debugging, refactoring, writing tests, and creating PRs. Each works in any Claude Code surface; adapt the wording to your project.

### Understand new codebases

For configuring Claude Code in a monorepo or large codebase, see [Monorepos and large repos](<https://code.claude.com/docs/en/large-codebases>).

#### Get a quick codebase overview

Suppose you've just joined a new project and need to understand its structure quickly.



  

#### Navigate to the project root directory

    ```bash theme={null}
    cd /path/to/project 
    ```

    Replace `/path/to/project` with the path to your project.
  


  

#### Start Claude Code

    ```bash theme={null}
    claude 
    ```
  


  

#### Ask for a high-level overview

    ```text wrap theme={null}
    give me an overview of this codebase
    ```
  


  

#### Dive deeper into specific components

    ```text wrap theme={null}
    explain the main architecture patterns used here
    ```

    ```text wrap theme={null}
    what are the key data models?
    ```

    ```text wrap theme={null}
    how is authentication handled?
    ```
  




**提示：**

  Tips:

  * Start with broad questions, then narrow down to specific areas
  * Ask about coding conventions and patterns used in the project
  * Request a glossary of project-specific terms



#### Find relevant code

Suppose you need to locate code related to a specific feature or functionality.

### Run Claude on a schedule

Suppose you want Claude to handle a task automatically on a recurring basis, like reviewing open PRs every morning, auditing dependencies weekly, or checking for CI failures overnight.

Pick a scheduling option based on where you want the task to run:

| Option | Where it runs | Best for |
| :- | :- | :- |
| [Routines](<https://code.claude.com/docs/en/routines>) | Cloud, Anthropic-managed by default | Tasks that should run even when your computer is off. Can also trigger on API calls or GitHub events in addition to a schedule. Configure at [claude.ai/code/routines](<https://claude.ai/code/routines>). |
| [Desktop scheduled tasks](<https://code.claude.com/docs/en/desktop-scheduled-tasks>) | Your machine, via the desktop app | Tasks that need direct access to local files, tools, or uncommitted changes. |
| [GitHub Actions](<https://code.claude.com/docs/en/github-actions>) | Your CI pipeline | Tasks tied to repo events like opened PRs, or cron schedules that should live alongside your workflow config. |
| [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) | The current CLI session | Quick polling while a session is open. `--resume` and `--continue` restore unexpired fixed-interval loops. |



**提示：**

  When writing prompts for scheduled tasks, be explicit about what success looks like and what to do with results. The task runs autonomously, so it can't ask clarifying questions. For example: "Review open PRs labeled `needs-review`, leave inline comments on any issues, and post a summary in the `#eng-reviews` Slack channel."

## Resume previous conversations

When a task spans multiple sittings, pick up where you left off instead of re-explaining context. Claude Code saves every conversation locally.

```bash theme={null}
claude --continue
```

This resumes the most recent session in the current directory; if there isn't one yet, it prints `No conversation found to continue` and exits. Use `claude --resume` to choose from a list, or `/resume` from inside a running session. See [Manage sessions](<https://code.claude.com/docs/en/sessions>) for naming, branching, and the full picker reference.

## Run parallel sessions with worktrees

Work on a feature in one terminal while Claude fixes a bug in another, without the edits colliding. Each [git worktree](<https://git-scm.com/docs/git-worktree>) is a separate checkout on its own branch, created from an existing commit, so the repository needs at least one commit first.

```bash theme={null}
claude --worktree feature-auth
```

Run the same command with a different name in a second terminal to start an isolated parallel session. In a repository with no commits, the command fails with `Failed to resolve base branch "HEAD": git rev-parse failed`. See [Worktrees](<https://code.claude.com/docs/en/worktrees>) for cleanup, `.worktreeinclude`, and non-git VCS support. To monitor parallel sessions from one screen instead of separate terminals, see [background agents](<https://code.claude.com/docs/en/agent-view>).

## Plan before editing

For changes you want to review before they touch disk, switch to plan mode. Claude reads files and proposes a plan but makes no edits until you approve. The status bar shows `⏸ plan mode on` while plan mode is active.

```bash theme={null}
claude --permission-mode plan
```

You can also press `Shift+Tab` mid-session until the status bar shows `⏸ plan mode on`. See [Plan mode](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>) for the approval flow and editing the plan in your text editor.

## Delegate research to subagents

Exploring a large codebase fills your context with file reads. Delegate the exploration so only the findings come back.

```text wrap theme={null}
use a subagent to investigate how our auth system handles token refresh
```

The subagent reads files in its own context window and reports a summary. See [Subagents](<https://code.claude.com/docs/en/sub-agents>) for defining custom agents with their own tools and prompts.

## Pipe Claude into scripts

Run Claude non-interactively for CI, pre-commit hooks, or batch processing. Stdin and stdout work like any Unix tool.

```bash theme={null}
git log --oneline -20 | claude -p "summarize these recent commits"
```

See [Non-interactive mode](<https://code.claude.com/docs/en/headless>) for output formats, permission flags, and fan-out patterns.
