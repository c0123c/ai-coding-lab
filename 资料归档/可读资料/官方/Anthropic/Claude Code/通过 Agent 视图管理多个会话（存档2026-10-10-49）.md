# 使用 agent 视图管理多个 agents

> 从一个屏幕调度和管理多个Claude Code会话。 Agent 视图显示每个会话正在执行的操作以及哪些会话需要您的输入。

使用 `claude agents` 打开的 Agent 视图是所有后台会话的一个屏幕：正在运行的内容、需要输入的内容以及已完成的操作。调度新的会话，一目了然地查看他们的状态，而不是滚动查看记录，并且仅在有人需要时介入。每个后台会话都是一个完整的 Claude Code 对话，无需连接终端即可继续运行，因此您可以随时打开它、回复并离开。

当您有多个独立任务 Claude 可以处理而无需您观看每个步骤时，请使用 agent 视图。将错误修复、拉取请求审查和片状测试调查分派为三行，继续在另一个窗口中工作，并在一行显示需要您或有结果时回来检查。

当您想在任何 agent 的会话中更直接地工作时，请附加到该行以输入完整的对话。

要将 agent 视图与子代理、agent 团队和工作树进行比较，请参阅[并行运行 agents](<https://code.claude.com/docs/en/agents>)。 Agent 视图在您的计算机上运行会话并分派每个会话；要让 Claude 从一个对话开始并跟踪云中的并行会话，请参阅 [ 项目 ](<https://code.claude.com/docs/en/claude-projects>)。



**注释：**

Agent 视图处于研究预览中。随着功能的发展，界面和键盘快捷键可能会发生变化。


## 快速启动

本演练涵盖了核心 agent 视图循环：分派任务，在 Claude 工作时观察其行更新，查看并回复，并附加完整对话。关闭 agent 视图后，您分派的会话将继续运行，因此您可以离开并返回。



  

#### 打开agent视图

从您的 shell 中运行：

    ```bash theme={null}
    claude agents
    ```

如果您尚未接受目录的 [ 工作空间信任对话框 ](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>)，Claude Code 会在 agent 视图打开之前显示它，并显示相同的对话框 `claude`。接受以保存对工作区的信任并继续。如果您拒绝，Claude Code 将退出而不打开 agent 视图。

Agent 视图打开，底部有一个输入，并在会话开始时填充一个表格。按 `Esc` 返回 shell；如果您通过使用 `←` 将会话置于后台来打开 agent 视图，则 `Esc` 将返回到该对话。当您离开时，您的会话将继续运行，并在您下次打开 agent 视图时重新出现。
  


  

#### 调度会话

输入描述任务的提示并按 `Enter`。一个新的后台会话将在该任务上启动，并显示为一行，显示该任务是否正在工作、正在等待您或已完成。新会话使用 agent 视图标题中显示的模型。 [它在](<#许可模式模型和努力>)中启动哪种权限模式取决于您打开agent视图的方式。

您在此处输入的每个提示都会启动自己的新会话。输入另一个提示并按 `Enter` 会在第一个会话旁边启动第二个会话，而不是发送后续会话。您可以通过这种方式并行运行多个。

每个会话独立使用您的订阅配额，因此在一次调度多个会话之前请参阅[限制](<#局限性>)。
  


  

#### 查看并回复

使用箭头键选择一行，然后按`Space`打开查看面板。它显示会话的最新输出或正在等待的问题，而不是完整的记录。输入回复并按 `Enter` 即可发送，而无需离开 agent 视图。
  


  

#### 连接和分离

当您想要完整对话时，按行上的 `Enter` 或 `→` 进行附加。该会话接管终端作为完整的交互式 Claude Code 会话。在空提示中按 `←` 分离并返回表。
  


  

#### 将现有会话引入

此步骤需要运行会话。如果您按照前面的步骤操作，则在此终端中没有打开一个会话，因此请在另一个终端中打开一个常规 `claude` 会话，然后先向其发送一条消息。

要将已打开的会话移动到 agent 视图中，请在其中运行 `/bg`，或者在空提示上按 `←` 将其置于后台并一步打开 agent 视图。在还没有消息的新会话中，`/bg` 会要求您先发送消息，而 `←` 会立即工作。该会话将继续运行，并与您调度的会话一起显示为一行。
  


在常规的`claude`会话中，提示页脚的`←`提示会计算正在等待您的后台agents，例如`← 2 agents`，并在不需要输入时返回`← for agents`。 99 以上的计数显示为 `99+`。当终端聚焦时，计数大约每十秒刷新一次，并在焦点返回时立即刷新。当它移动和 agent 完成时，它会短暂改变颜色；当后台会话完成但不需要您输入时，它会短暂显示已完成的数字，例如 `← 2 done`。当 [`prefersReducedMotion` 设置 ](<https://code.claude.com/docs/en/settings-reference#prefersreducedmotion>) 开启时，两个闪光灯均关闭，并且在 [ 屏幕阅读器模式 ](<https://code.claude.com/docs/en/accessibility>) 下隐藏提示。

### 默认打开agent视图

要让不带参数的 `claude` 打开 agent 视图而不是新对话，请打开 `/config` 设置。



  

#### 开启设置

在常规 `claude` 会话中，运行 `/config` 并打开 **默认打开 agents 视图 **。要跳过菜单，直接设置[`defaultToAgentsView`](<https://code.claude.com/docs/en/settings-reference#defaulttoagentsview>)键：

    ```text theme={null}
    /config defaultToAgentsView=true
    ```
  


  

#### 开始Claude Code

退出会话，然后不带参数运行 `claude`：

    ```bash theme={null}
    claude
    ```

Agent 视图将打开以代替新对话。
  


要在设置打开时启动常规会话，请传递提示：`claude "fix the login test"`。要关闭该设置，请在常规会话中或在从 agent 视图附加到的会话中运行 `/config defaultToAgentsView=false`。

## 使用 agent 视图监视会话

运行`claude agents`打开agent视图。它接管整个终端并列出按状态分组的每个会话，其中固定会话和需要您的会话位于顶部。每行显示会话的名称、当前活动及其期限（从会话创建时开始计算）；完成的训练的年龄会冻结在跑步所用的时间上。

该名称会使用 [`/color`](<https://code.claude.com/docs/en/commands>) 在该会话中设置的颜色进行着色，包括当您 [ 使用 `←` 或 `/background` 将会话 ](<#from-inside-a-session>) 置于后台时。

默认情况下，该列表显示您在所有项目中启动的每个后台会话。无论您从哪个目录打开 agent 视图，在一个存储库中工作的会话和在不同工作树中工作的另一个会话都会显示在此处。要将列表范围缩小到一个项目，请传递 `--cwd`：

```bash theme={null}
claude agents --cwd ~/projects/my-app
```

这仅显示在该目录下启动的会话。它仍然列出了已将 [ 移至 `~/projects/my-app/.claude/worktrees/` 下的工作树 ](<#如何隔离文件编辑>) 中的会话。

您在其他终端中打开的交互式会话只有在您[将其设置为后台](<#from-inside-a-session>)后才会出现。会话生成的 [子代理 ](<https://code.claude.com/docs/en/sub-agents>) 和 [ 队友 ](<https://code.claude.com/docs/en/agent-teams>) 未列为单独的行。

```text theme={null}

Ready for review

Completed
  ✻ title screen              menu, options, and credits done               9m
  ∙ sound effects             14 SFX exported to assets/audio               4h
  … 6 more
```

### 读取会话状态

每行都以一个图标开头，其颜色和动画显示会话的状态：

|状态|图标显示为|这意味着什么|
| :- | :- | :- |
|工作|动画|Claude 正在主动运行工具或生成响应|
|需要输入|黄色|Claude 正在等待只有您可以提供的内容：问题的答案、权限决定或只有您可以回答的其他提示，例如 [ 沙箱 ](<https://code.claude.com/docs/en/sandboxing>) 提示，以允许网络主机或 MCP 服务器的 [ 请求输入](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>)。需要附加终端的命令，例如 `/install-github-app` 或 `/mcp` 设置列表，[ 也在这里保持无人值守会话 ](<#附加到会话>)|
|空闲|变暗|该会话没有任何事情可做，已准备好等待您的下一个提示|
|已完成|绿色|任务顺利完成|
|失败|红色|任务因错误而结束|
|已停止|灰色|您使用 `Ctrl+X` 或 `claude stop` 停止了会话，[其进程从外部结束 Claude Code](<#主管流程>)，或 [在后台服务关闭时结束](<#sessions-show-as-failed-after-shutdown>)|

另外，图标的形状有其自己的含义：

|形状|这意味着什么|
| :- | :- |
|`✻` 或动画 `✽`|会话进程正在运行，或者会话需要您的输入|
| `∙` |该进程已退出。您仍然可以查看该行，当您回复或附加时，Claude 从上次中断的位置重新开始|
| `✢` |[`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) 会话在迭代之间休眠。该行显示其运行计数和倒计时|

可以出现在行右边缘的 `#N` 或 `!N` 标签是指向会话的 [ 拉取请求或合并请求 ](<#拉取请求状态>) 的链接，而不是状态图标的一部分。

终端选项卡标题显示 agent 视图打开时的等待输入计数：当会话需要输入时为 `2 awaiting input · claude agents`，或当会话不需要输入时为 `claude agents`。

要从脚本或其他程序读取会话状态，请使用 [`claude agents --json`](<#从脚本读取会话状态>) 而不是 `~/.claude/jobs/` 下的文件。

当 agent 视图打开时，当本地后台会话开始需要您的输入、完成或失败时，Claude Code 还会通过您配置的 [ 终端通知通道 ](<https://code.claude.com/docs/en/terminal-config#get-a-terminal-bell-or-notification>) 发送通知。按计划运行的会话（例如 [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) 会话）仅在需要您的输入时发出通知。通知使用与 Claude Code 其余部分相同的 [`preferredNotifChannel` 设置 ](<https://code.claude.com/docs/en/settings-reference#preferrednotifchannel>)，并使用 `agent_needs_input` 或 `agent_completed` 类型触发 [`Notification` 挂钩 ](<https://code.claude.com/docs/en/hooks#notification>)。

后台会话不需要打开任何终端即可继续工作。一个单独的 [ 管理进程 ](<#主管流程>) 运行它们，因此您可以关闭 agent 视图、关闭 shell 或启动新的交互式会话，并且您分派的工作将继续进行。

会话状态通过自动更新和主管重新启动保留在磁盘上。当您的计算机休眠时，会话也会被保留。它们的进程在唤醒时恢复，并且主管重新连接到它们，而不是将时间间隔视为空闲。关闭仍然会停止正在运行的会话；请参阅 [ 会话在关闭后显示为失败或停止 ](<#sessions-show-as-failed-after-shutdown>) 了解如何恢复它们。

当机器休眠时处于响应中期的会话可能会变得无响应。当您打开已停止响应的会话时，主管会重新启动其进程，并且会话会从中断处继续中断的响应。

### 行摘要

每行中的一行摘要由 [Haiku 级模型 ](<https://code.claude.com/docs/en/model-config>) 生成，因此该行可以告诉您会话正在做什么、需要什么或产生了什么，而无需打开记录。当会话正在积极工作时，行文本最多每 15 秒从会话自己的最近输出更新一次，而不发送模型请求，并且模型在每轮结束时写入新的摘要。

工作行显示会话正在执行的操作，阻塞行显示它提出的问题。在长时间的转动过程中，模型还会每隔几分钟重写一次摘要，这样繁忙的行就不会一直显示过时的行。摘要文本填充行的剩余宽度；打开[查看面板](<#查看并回复>)读取终端边缘剪辑的句子。

当列表为 [按目录分组](<#整理清单>)，摘要打开时会话状态以彩色单词显示，例如 `Needs input · double jump or wall climb?`。在默认状态分组中，组标题已命名状态，因此该行仅显示摘要。

回合结束摘要和每个回合中重写是通过您的正常提供商发出的一个简短的俳句类请求，按照与会话本身相同的 [ 数据使用条款 ](<https://code.claude.com/docs/en/data-usage>) 进行计费和处理。模型重写之间的 15 秒更新重用会话自己的输出并且不发送请求。在没有配置俳句类模型的第三方提供商或网关上，请求改为使用会话的主模型；设置[`ANTHROPIC_DEFAULT_HAIKU_MODEL`](<https://code.claude.com/docs/en/model-config#environment-variables>)选择其中之一。

### 拉取请求状态

当会话 [ 打开拉取请求 ](<#如何隔离文件编辑>) 时，Claude Code 在行的右边缘添加一个标签，链接到拉取请求：

* Claude Code 将拉取请求的标签写入为 `#1234`，将 GitLab 合并请求的标签写入为 `!1234`。
* 即使 Claude Code 无法检测到超链接支持（例如通过 SSH 或 tmux），它也会发出链接。设置 [`FORCE_HYPERLINK=0`](<https://code.claude.com/docs/en/env-vars>) 将标签呈现为纯文本。
* 在您向会话发送后续信息后，Claude Code 会保留标签，同时该行返回实时进度。

处理现有拉取请求的会话以相同的方式链接到它。 Claude Code 根据运行的命令 Claude 查找不同的拉取请求：

* 当 Claude 使用 `gh` 编辑、评论、关闭或标记拉取请求时，Claude Code 链接该命令自己的输出命名的拉取请求。捕获的输出名称为 no pull request 的 `gh` 命令不会创建链接； `gh pr merge` 是常见情况，因为它仅将结果打印到交互式终端。
* 当 Claude 使用 `gh pr checkout` 检查拉取请求或推送到分支时，Claude Code 使用 `gh pr view` 查找分支并链接其打开的拉取请求。
* 当 Claude 推送时，拉取请求不需要存在：Claude Code 在最多五个 `git`、`gh`、`glab` 或 `curl` 命令在同一目录中运行后重试分支查找，因此在推送，包括通过 GitHub REST API 创建的一个 Claude，在重试找到它时链接。

当一个会话链接到多个拉取请求时，标签会显示计数，例如 `3 PRs`，并由最需要注意的开放拉取请求着色。打开[查看面板](<#查看并回复>)即可查看全部内容。

拉取请求编号按其状态着色：

|颜色|拉取请求状态|
| :- | :- |
|黄色|等待检查或审核，或检查失败|
|绿色|检查已通过并且没有审查被阻止|
|紫色|合并|
|灰色|草案或封闭|

对于以拉取请求结束的任务，请检查此标签以获取结果：当拉取请求的编号变为绿色时，查看并合并拉取请求。

### 查看并回复

在选定的行上按 `Space` 打开查看面板。它以行在终端边缘截断的句子开头，哪个句子取决于会话的状态：

* 正在等待您的会话：它所提出的确切问题，位于回复输入上方
* 结束的会话：其结果
* 工作会议：完整的状态语句

接下来列出了链接到会话的所有拉取请求。对于正在等待您的会话​​，其下方的诸如 `waiting 3m` 之类的行显示了它已经等待了多长时间，并且这是面板中显示的唯一时间。该行右边缘的年龄是不同的数字：它从会话开始时开始计算。

大多数时候，查看面板就足够了，您不需要打开完整的成绩单。

在查看面板中键入回复，然后按 `Enter` 将其发送到该会话。在回复中添加 `!` 前缀以发送 Bash 命令。回复的情况取决于会话和您发送的内容：

* 正在运行的会话： `/model`, `/effort`, `/rename`, 和 `/usage` 马上跑。其他回复加入会话 [消息队列](<https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works>) 而不是中断响应，并生效 [当排队输入时](<https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued>)。其他 [命令](<https://code.claude.com/docs/en/commands>) 等待回合结束，即使是在会话自己的提示符下键入后立即运行的程序
* 完全是 `/stop` 的回复：立即停止会话而不是传递给它，无论会话正在工作还是正在等待您
* [shell 作业 ](<#运行外壳命令>)：包含 `/stop` 的回复将作为键入的输入转到命令的终端

当会话等待您时，您如何从查看面板中回答取决于它正在等待的内容：

* 带有预定义选项的问题：面板按数字列出选项。在回复输入为空的情况下，按选项的数字进行填写，然后 `Enter` 发送，或者输入您自己的答案
* 没有预定义选项的问题：输入您的答案。当空输入显示建议回复时，按`Tab`填写并编辑后再发送
* 权限提示或其他对话框，例如 [ 沙箱 ](<https://code.claude.com/docs/en/sandboxing>) 提示或 MCP 服务器的 [ 输入请求 ](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>)：回复未应答。您的消息在队列中等待。要回答对话框，请附加 `→`

当 [`PermissionRequest`](<https://code.claude.com/docs/en/hooks#permissionrequest>) 或 [`PreToolUse`](<https://code.claude.com/docs/en/hooks#pretooluse>) 挂钩返回输出 Claude Code 无法验证会话所询问的调用时，该行会在待处理请求的文本之前显示挂钩事件和带有验证错误的 `hook output invalid:`。对于以其他方式失败的挂钩，该行表示该挂钩失败。会话仍然等待相同的请求。

当无法发送回复时，错误消息会显示回复是否已保存。前缀为 `!` 或 `/` 的回复永远不会被保存。 Claude Code 下次重新启动会话时发送保存的回复作为会话的下一个提示；再次发送任何其他回复。

与 [语音听写](<https://code.claude.com/docs/en/voice-dictation>) 启用于 [保持模式](<https://code.claude.com/docs/en/voice-dictation#hold-to-record>)，在集中回复输入时按住一键通键可口述回复而不是键入回复。底部的调度输入也有同样的作用 agent 视图。

使用 `↑` 和 `↓` 在不关闭面板的情况下查看相邻会话，或使用 `→` 进行附加。

### 附加到会话

在所选行上按 `Enter` 或 `→` 进行附加。 Agent 视图被完整的交互式会话取代。当您附加时，Claude 会发布您离开时发生的事情的简短回顾。

连接后，会话的行为与任何其他 Claude Code 会话类似：[ 命令 ](<https://code.claude.com/docs/en/commands>)、键盘快捷键和功能均可用，但以下情况除外。

连接后，`/install-github-app` 和 [`/mcp`](<https://code.claude.com/docs/en/mcp>) 设置列表正常工作，因为终端上的人员可以完成他们的对话。当没有人附加时，这些命令无法打开其对话框，因此会话会显示在 agent 视图中的 `Needs input` 下，并带有诸如 `open this session to manage MCP servers` 之类的行，并且副本回复也显示相同内容。再次附加并运行命令以继续；当您附加时，需求输入行将被清除。 `/mcp reconnect <server>`、`/mcp enable` 和 `/mcp disable` 无需连接任何一种方式即可工作。

无论您的 `tui` 设置如何，附加会话始终以 [ 全屏模式 ](<https://code.claude.com/docs/en/fullscreen>) 呈现，因为后台会话没有要附加的终端回滚。使用 `PgUp`、`PgDn` 或鼠标滚轮滚动，然后按 `Ctrl+O` 进入转录模式。您的终端的本机滚动和 tmux 复制模式仅显示当前视口，与运行任何全屏应用程序时相同。

在空提示符下按 `←`，或运行 `/exit`，以分离并返回到 agent 视图，无论您是从 agent 视图还是从 shell 中使用 `claude attach <id>` 打开会话。

当 [`/btw` 覆盖层 ](<https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw>) 打开时，`←` 也会分离。需要 Claude Code v2.1.257 或更高版本。当您离开时，仍在回答的附带问题仍在运行。下次附加时，叠加层会重新打开它或它的答案。

在 Windows 上，如果您在连接后约半秒内按 `←`，Claude Code 将显示 `Ambiguous ←, press again to detach`，因为在该窗口中，终端可以重新发送连接之前的按操作。再次按 `←` 即可分离。

`Ctrl+Z` 也会分离，但会返回到您开始的位置：如果您从那里连接，则为 agent 视图；如果您运行了 `claude attach`，则为您的 shell。当对话框具有焦点并且不响应 `←` 时，使用 `Ctrl+Z`。

`Ctrl+C` 在连接时保持其标准中断行为：它取消正在运行的响应或 `!` shell 命令而不是分离。在空提示中按 `Ctrl+C` 两次会分离，与任何会话中的情况相同。

分离永远不会停止后台会话：`←`、`Ctrl+Z`、`/exit` 和双 `Ctrl+C` 或双 `Ctrl+D` 都使其保持运行。要从内部结束会话，请运行 `/stop`。

#### 无需离开终端即可切换会话

在前台运行的会话中，您在终端中启动会话，而不是从 agent 视图附加会话，在空提示符上按 `←` 会将其置于背景中，并打开选择该行的 agent 视图，因此您可以在不离开终端的情况下切换会话。同样的一次按下会分离附加的会话。

如果您在删除最后一个提示文本或浏览提示历史记录后立即按 `←`，Claude Code 会要求您确认：第一次按会在附加会话中显示 `Press ← again to open agents` 或 `Press ← again to go back to agents`，第二次按会切换。

当 `←` 将前台会话置于后台时，agent 视图会在列表上方显示 `Your conversation moved to the background`，并且已选择该会话的行。从那里：

* 按 `Enter` 重新开始对话。
* 按`Esc`撤消切换并返回通话。如果`Esc`显示`Still starting — try again in a moment`，则后台会话尚未准备好，请稍后再按`Esc`。
* 按 `Ctrl+C` 两次退出 shell。

当 Claude Code 无法重新打开对话时，它会退出并打印 `claude --resume` 命令来恢复对话。

[Claude 的任务列表 ](<https://code.claude.com/docs/en/interactive-mode#task-list>) 会随对话移至后台会话，因此当您返回到该行时，清单完好无损。

在您使用箭头键或鼠标移动选择后，您按下 `←` 的行也会保留粗体、未变暗的名称，以便您可以知道您来自哪个会话。

如果按 `←` 时工具正在运行，Claude Code 会在后台等待其完成，而 Claude 会在后台会话中继续响应。再次按`←`立即进入后台，无需等待。当正在进行的工作无法转移到后台会话时，Claude Code 首先显示 `Background this session?` 对话框，与 [`/background`](<#from-inside-a-session>) 相同。

大约十秒后，Claude Code 将会话置于后台，不再等待，但以下情况除外：

* **前台子代理仍在运行**：Claude Code继续等待，因此[前台子代理](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>)Claude的工作开始延续，并显示`Still backgrounding after the current tool`。再次按 `←` 进入后台，无需等待，这将从头开始重新启动这些子代理。
* **权限提示或问题正在等待您的回答**：当权限提示或问题Claude等待时，Claude Code继续等待并显示`Still backgrounding after the current tool — a question is waiting for your answer.`
* **您在提示符中输入**：Claude Code会取消切换，因为未发送的文本保留在终端的输入框中，不会移动到后台会话。它显示`Backgrounding cancelled — you have unsent text in the input. Send it or clear it, then press ← again.`
* **排队的消息无法移动**：[在Claude工作时排队的消息](<https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works>)移动到对话的后台会话。当其中之一不能时，会话将停留在前台，并且 Claude Code 显示一条通知，例如 `Cannot open agents — 1 queued message can't move to the background. Press ← again once Claude has read it.`

即使对话还没有消息，按 `←` 也会创建会话行，因此 `→` 仍会返回到该行。

您可以使用 `/config` 中的 [`leftArrowOpensAgents`](<https://code.claude.com/docs/en/settings-reference#leftarrowopensagents>) 设置为前台会话关闭此快捷方式。

### 整理清单

Agent 视图对会话进行分组，因此需要输入的会话位于顶部，`Ready for review` 和 `Needs input` 位于 `Working` 和 `Completed` 之上。这些组名称不会一对一映射到上面的 [ 状态 ](<#读取会话状态>)：当会话有需要审核的开放拉取请求或检查失败时，会话会移动到 `Ready for review`，并且 `Completed` 将已完成、失败和停止的会话收集在一起。

按 `Ctrl+S` 按目录分组。您的选择在运行过程中持续存在。

在一个组内：

* 按 `Ctrl+T` 将会话固定到顶部并 [ 在空闲时保持其进程运行 ](<#主管流程>)
* 按 `Shift+↑` 或 `Shift+↓` 重新排序会话
* 按 `Ctrl+R` 重命名会话
* 在组标题上按 `Enter` 将其折叠，除非 [ 筛选器 ](<#过滤会话>) 处于活动状态，且每个组都保持展开状态

要从列表中删除会话，请按 `Ctrl+X` 将其停止，然后在两秒内再次按 `Ctrl+X` 将其删除。在组标题上按 `Ctrl+X` 会在确认后删除该组中的每个会话。

即使停止尝试失败，第二次按下也会删除会话，例如因为 [ 后台服务没有响应 ](<#agent查看说后台服务没有响应>)：确认会再保持活动状态两秒钟，并且删除会结束会话进程本身。按 `Esc` 取消确认而不删除。

除了[删除会话会删除什么](<#删除会话会删除什么>)中介绍的保留情况外，删除会从列表中删除会话，并且为其创建的工作树Claude将被删除、保留或留在原处，具体取决于您删除的方式以及工作树所包含的内容。对话记录始终保留在您的本地计算机上，可通过 `claude --resume` 获取。

要在 Claude Code v2.1.212 或更高版本上恢复会话，请在调度输入中键入 `/resume`。将打开一个选择器，其中包含您打开 agent 视图的存储库的过去会话，最新的在前，包括您从列表中删除的会话；已经有一行的会话不会列出。 `↑`/`↓` 移动选择，`Enter` 将所选会话恢复为后台会话，以便它作为一行重新加入列表，`Esc` 关闭选取器。

选择器仅针对裸露的 `/resume` 打开。选择器无法提供有针对性、范围或受限的简历，因此 agent 视图会在以下情况下显示 `attach to a session to run it` 提示：

* `/resume` 命名 ID 或搜索词
* 该视图的范围为 `--cwd`
* 该视图以 [`--safe-mode`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 开始
* 视图是使用 `--permission-mode` 或 `--settings` 等标志打开的

屏幕无法容纳的已完成会话将折叠到 `… N more` 行中。 `Completed` 组填充实时组之后留下的垂直空间，并且在短终端上，标题压缩为单个摘要行，以便正在工作或需要输入的会话保持可见。

### 过滤会话

使用以下过滤器之一启动调度输入，以在您键入时缩小列表范围：

|过滤器|演出|
| :- | :- |
| `a:<name>` |运行名为 agent 的会话|
| `s:<state>` |给定状态下的会话，例如 `s:working`，或给定组标头下的会话，例如 `Ready for review` 的 `s:ready`。 `s:blocked` 列出一切等待着你|
| `n:<text>` |名称或第一个提示包含文本的会话，例如 `n:login`。需要 Claude Code v2.1.287 或更高版本|
| `o:<text>` |结果包含文本的会话，例如 `o:merged`。裸露的 `o:` 列出了已报告结果的每个会话|
|拉取或合并请求编号，例如 `#1234` 或其 URL|处理该拉取请求或合并请求的会话|
|任何其他 URL|第一个提示包含 URL 的会话|

要组合过滤器，请以 `a:`、`s:`、`n:` 或 `o:` 开头，然后添加更多过滤器，并用空格分隔。该列表显示与所有这些匹配的会话。例如，`s:blocked a:reviewer` 列出了正在等待您的 `reviewer` 会话。

当过滤器处于活动状态时，您折叠的组会展开以显示其匹配项，并且会选择一个匹配项，因此按 `Enter` 将其打开。清除输入以删除过滤器，这些组会再次崩溃。

## 发货新品 agents

您可以从 agent 视图调度新的后台会话，将现有的交互式会话发送或复制到后台，或者直接从 shell 启动一个会话。

<span id="from-agent-view" />

### 从 agent 视图发送 agent

在 agent 视图底部的输入中键入提示，然后按 `Enter` 启动新的后台会话。会话根据提示自动命名；稍后将其重命名为 `Ctrl+R`。

自动名称是一个短标签，由 [俳句级模型](<https://code.claude.com/docs/en/model-config>)。会话稍后获得的名称也会出现在其行中，包括 [生成的标题](<https://code.claude.com/docs/en/sessions#name-your-sessions>) 当您进行会话时 [接受计划](<https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan>) 在那次会议上。

将图像粘贴到提示中，以在任务中包含屏幕截图或图表。

粘贴的文本长度超过 800 个字符或超过三行会折叠为 `[Pasted text #N]` 占位符，以便输入保留在一行上；全文会在您发送时发送。要在分派之前查看或编辑折叠的文本，请再次粘贴相同的文本，占位符将展开回输入中。

前缀或提及提示的部分内容以控制会话的启动方式：

|输入|效果|
| :- | :- |
| `<agent-name> <prompt>` |如果第一个单词与自定义 [subagent](<https://code.claude.com/docs/en/sub-agents>) 名称匹配，则该子代理将作为会话的主 agent 运行，并使用其 frontmatter 中的配置|
| `@<agent-name>` |在提示中的任意位置提及自定义子代理以将其作为主代理运行 agent|
| `@<repo>` |提及一个存储库以在那里运行会话。请参阅[分派到列出存储库的特定目录](<#调度到特定目录>)|
| `/<command>` |建议派遣[技能](<https://code.claude.com/docs/en/skills>)和[命令](<https://code.claude.com/docs/en/commands>)作为提示|
| `! <command>` |将 shell 命令作为后台作业运行，而不是启动 Claude 会话。该作业显示为一行，您可以附加、监视和分离|
|`#<number>` 或拉取或合并请求 URL|如果会话已在处理该拉取请求或合并请求，Claude Code 将选择其行而不是分派新会话|

一小组命令在 agent 视图本身中运行而不是调度：

* `/exit` 和 `/quit` 关闭 agent 视图
* `/logout` 将您注销
* `/model`设置[调度模型](<#设置模型>)
* `/login` 打开登录对话框，以便您可以在不附加到会话的情况下再次登录
* 裸露的 `/resume` 或其 `/continue` 别名会打开存储库过去会话的选择器，以 [ 将一个返回 ](<#整理清单>) 作为后台会话。需要 Claude Code v2.1.212 或更高版本

技能、您自己的命令和提示扩展内置程序（例如 `/init`）将作为其第一个提示发送到新的后台会话。其他内置命令会显示 `attach to a session to run it` 提示。您输入的所有内容都会保留在提示旁边的输入中，以便您可以对其进行编辑。

将重复任务打包为 [ 技能 ](<https://code.claude.com/docs/en/skills>) 使您可以从 agent 视图重复启动相同的工作流程，而无需重新键入提示。

当相同的 `@name` 同时匹配子代理和同级存储库时，子代理优先。裸第一个单词匹配也适用，因此恰好以某个子代理名称开头的提示会调度该子代理，而不是将该单词视为纯文本。当您想要明确时，请使用 `@` 形式，或者使用不同的单词开始提示以避免匹配。

#### 调度到特定目录

新会话在您打开 agent 视图的目录中运行。要定位不同的目录，请使用以下任一方法：

* 打开该目录中的`claude agents`。
* 在父目录中打开 `claude agents` 并在提示中使用 `@<repo>` 提及子存储库。输入 `@` 列出这些目标：

  * Git 存储库位于启动目录下一级
  * 您从其目录树中实时启动的存储库的注册 [git worktrees](<https://code.claude.com/docs/en/worktrees>)，例如 Claude 在 `.claude/worktrees/` 下创建的存储库，标有其签出分支。未列出在存储库外部添加的工作树，例如使用 `git worktree add ../feature`
  * 列表中已有会话的任何目录

名称中包含空格的目录不会列出。
* 从 shell 中，`cd` 进入目录并运行 `claude --bg "<prompt>"`。

当 agent 视图按目录分组时，分派会将提示发送到所选行的目录，因此您可以选择一个组并分派到其中，而无需重新输入路径。

### 将会话发送或复制到后台

两个命令将工作从您所在的会话移至后台：`/background` 将当前对话发送到那里并释放您的终端，`/fork` 在您继续在当前位置工作时发送副本。

#### 将会话发送到后台

运行 `/background` 或其别名 `/bg` 将当前对话移至后台会话。通过`/bg run the test suite and fix any failures`等提示先再给出一条指令。如果在您运行 `/bg` 时 Claude 正在响应，则响应将在后台会话中继续。

退出仍在运行后台工作（例如子代理、后台 shell 命令、工作流或 [ 监视器 ](<https://code.claude.com/docs/en/tools-reference#monitor-tool>)）的会话时，会显示 `Background work is running` 对话框，而不是立即退出。选择 `Move to background and exit` 以与 `/background` 相同的方式将会话置于后台，然后返回到 shell。当 agent 视图 [ 关闭 ](<#关闭-agent-视图>) 时，不会显示该选项。

如果列表中的后台会话已具有对话的名称，则 Claude Code 会对新行的名称进行编号，例如 `my-session (2)`，并保留现有行的名称。要重命名新行，请在 agent 视图中选择它，然后按 `Ctrl+R`。

#### 使用 /fork 复制会话

运行 `/fork` 将当前对话复制到新的后台会话中，同时原始对话继续运行。副本从对话中到此为止的所有内容开始；请参阅下面的项目符号以了解副本运行的位置。它还会继承您在会话期间添加的模型、权限模式、工作级别以及任何目录或“不再询问”权限授予。该副本在 agent 视图中显示为单独的行。

分叉后，两个对话是独立的：副本不会自行进入原始对话，但在启用 [ 跨会话消息传递 ](<https://code.claude.com/docs/en/cross-session-messaging>) 的会话中，任一会话的 Claude 可以显式向另一个会话发送消息。

复制会话需要 Claude Code v2.1.212 或更高版本；在 v2.1.161 到 v2.1.211 上，`/fork` 启动一个 [ 分叉子代理 ](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>)，现在是 `/subtask`。当 [agent 视图关闭 ](<#关闭-agent-视图>) 时，`/fork` 保留分叉子代理行为，并且 `/subtask` 不可用。

通过诸如 `/fork open a draft pull request with the work so far` 之类的提示，副本会立即开始处理。如果没有提示，副本将等待其第一条指令：在 `claude agents` 中选择其行，然后按 `Space` 发送一条指令，或运行 `claude attach <id>`。等待时所选行显示 `space to send it a prompt`。

`/fork` 确认是显示副本状态的一行，例如 `session running`、其 agent 视图行的名称以及 `claude attach` 的会话 ID。单击名称切换到副本：此会话移至后台，与按`←`相同，agent视图打开副本的会话。

除非副本 [ 就地编辑 ](<#如何隔离文件编辑>)，Claude Code 指示它在进行代码更改之前创建自己的工作树。在 git 存储库之外，只有从钩子创建的工作树移出的副本才能获取指令；如果没有 [`WorktreeCreate` 挂钩 ](<https://code.claude.com/docs/en/hooks#worktreecreate>)，则副本就地编辑。移出工作树的副本还被告知永远不要编辑、运行命令或进入该工作树，无论隔离设置如何。

复制的开始位置取决于当前会话的运行位置：

* 与任何分派会话一样，副本 [ 在编辑文件 ](<#如何隔离文件编辑>) 之前移动到其自己的工作树中。在这种情况下，确认不会提及副本在哪里运行。
* 当您的会话在启动后移动到其链接的 [ 工作树 ](<https://code.claude.com/docs/en/worktrees>) 时，副本将从移动前会话所在的位置开始，并且除非它 [ 就地编辑 ](<#如何隔离文件编辑>)，否则会在其自己的工作树中进行代码更改。当您的工作树在分支上签出时，该指令还会告诉其任务基于您的工作的副本将其新分支基于您的工作，因为您的分支在工作树中保持签出状态。确认以 `runs in the origin tree` 结束。
* 当您在具有主工作树的存储库的链接工作树内启动会话时，副本将从该主工作树开始，具有相同的自身工作树规则，但没有分支指令。此处的确认也以 `runs in the origin tree` 结尾。
* 在裸存储库布局的工作树内启动的会话没有可返回的主工作树，因此副本保留在原来的位置，并且确认以 `edits this checkout` 结束。当工作树隔离在不在链接工作树内的会话中关闭[](<#如何隔离文件编辑>)时，会出现相同的注释，因为副本会编辑您已打开的文件。

使用副本不会继承的启动标志启动的会话（例如替换的系统提示符或 `--tools` 白名单）无法分叉； Claude Code 是这么说的，而不是制作部分副本。从 agent 视图分派的会话通常分叉：使用相同的 [agent 定义 ](<https://code.claude.com/docs/en/sub-agents>) 启动副本，并附加与其来自的会话相同的指令。

#### 当你成为背景时会发生什么

后台启动一个新的进程，从保存的对话中恢复，正在进行的工作转移到它：运行后台 shell 命令、后台子代理、动态工作流程、您使用 [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) 创建的计划任务，以及 Claude 对工件注释的 [ 自动回复 ](<https://code.claude.com/docs/en/artifacts#let-claude-reply-to-comments-on-its-own>) 全部保留并继续在那里运行。子代理与其启动的所有工作一起移动，因此只有当所有工作也可以移动时，它才会继续下去。要停止正在进行的工作而不是继续进行，请设置 [`CLAUDE_DISABLE_ADOPT=1`](<https://code.claude.com/docs/en/env-vars#variables>) 环境变量； Claude Code 然后要求您在后台之前确认。

当 [ 动态工作流程 ](<https://code.claude.com/docs/en/workflows>) 仍有子代理运行时，Claude Code 在后台使用 `Background this session?` 对话框之前进行询问，该对话框显示将重新启动多少个子代理。选择`Stay`让他们先完成。如果您确认，Claude Code 将在后台会话中重播运行：仍在运行的子代理从头开始，因此它们迄今为止使用的令牌将再次被花费。请参阅[暂停后恢复](<https://code.claude.com/docs/en/workflows#resume-after-a-pause>)，了解已完成的子代理返回其保存的结果并再次运行的情况。

Claude Code 停止无法延续的工作，例如正在运行的 [ 监视器 ](<https://code.claude.com/docs/en/tools-reference#monitor-tool>)，并停止拥有监视器的后台子代理。当任何此类工作正在运行时，Claude Code 会显示 `Background this session?` 对话框，以便您可以在停止工作之前进行确认。

一旦进入后台，会话就可以启动新的子代理、监视器和后台命令，并且这些命令在以后分离和重新附加时继续运行。

最初启动时的配置标志会延续到后台会话，因此其 MCP 服务器、设置和后备模型仍然有效：

* `--mcp-config` 和 `--strict-mcp-config`
* `--settings`
* `--setting-sources`
* `--add-dir`
* `--plugin-dir`
* `--fallback-model`
* `--allow-dangerously-skip-permissions`

您在会话期间使用 [`/add-dir`](<https://code.claude.com/docs/en/permissions#additional-directories-grant-file-access-not-configuration>) 添加的目录也会保留。携带 `--allow-dangerously-skip-permissions` 使 `bypassPermissions` 在后台会话中可访问，但它不会授予任何新内容：该模式仍然需要 [ 权限模式、模型和工作 ](<#许可模式模型和努力>) 中描述的一次性交互式接受。

### 从您的 shell 发送 agent

传递 `--bg` 或其长格式 `--background` 启动直接进入后台的会话：

```bash theme={null}
claude --bg "investigate the flaky SettingsChangeDetector test"
```

提示是位置参数，而不是 `-p` 值。 Claude Code 在创建任何会话之前拒绝将 `--bg` 与 `-p` 或 `--print` 组合，因为 `--print` 永远不会启动 `claude agents` 附加到的交互式会话。

如果您从 [ 不信任 ](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>) 的目录中的终端运行 `claude --bg`，则首先出现工作区信任对话框，一旦您接受，会话就会启动。如果您拒绝，Claude Code 将退出而不启动会话。如果没有对话框出现，例如在脚本中，该命令将退出并显示 [`Workspace not trusted`](<https://code.claude.com/docs/en/errors#workspace-not-trusted-when-dispatching-a-background-session>) 错误。

要运行您定义的特定 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>)（例如 `code-reviewer`）作为会话的主 agent，请将 `--bg` 与 `--agent` 组合：

```bash theme={null}
claude --agent code-reviewer --bg "address review comments on PR 1234"
```

如果名称与您的任何子代理都不匹配，则启动失败：Claude Code 打印 `no agent named` 警告，并且仍将会话报告为后台运行，但会话会立即退出并出现 `--agent '<name>' not found` 错误。

当后台会话稍后恢复或重新启动时， Claude Code 恢复 agent 及其工具限制；其系统提示符请参见 [恢复对话中的系统提示标志](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>)。它在会话自己的目录中搜索 agent 首先，假设你已经 [信任该工作空间](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>)，所以项目范围 agent 当会话从另一个目录恢复时仍然加载。如果 agent 不再存在，会话将使用默认工具继续，并且其记录会以 [警告命名 agent](<https://code.claude.com/docs/en/errors#session-agent-no-longer-available>).

要在后台继续现有对话，请使用 `--resume` 传递其完整会话 ID：

```bash theme={null}
claude --resume 1f0e2c9a-6d0b-4c11-9f39-2a77c1d4e8b5 --bg "pick up where you left off and finish the migration"
```

在 Claude Code v2.1.257 或更高版本上，Claude Code 要么在同一 ID 下继续该会话，要么在新的 ID 下启动副本并打印 `note:` 行，解释为什么它无法就地继续。当会话继续就位时，`claude agents` 显示一行。

当您将 `--bg` 与 `--continue`、裸露的 `--resume` 或 `--resume` 与名称或文件路径组合时，Claude Code 始终会启动这样的副本。故意添加`--fork-session`开始复制，不带注释。

传递 `--name` 以在 agent 视图中设置会话的显示名称，而不是自动生成的显示名称：

```bash theme={null}
claude --bg --name "flaky-test-fix" "investigate the flaky SettingsChangeDetector test"
```

后台运行后，Claude 打印会话的简短内容 ID 以及管理它的命令。当托管后台会话的服务尚未运行时，`--bg` 可能首先在此输出上方打印 `Starting background service…`。当您通过`--name`时，名称会出现在短ID之后：

```text theme={null}
backgrounded · 7c5dcf5d · flaky-test-fix
  claude agents             list sessions
  claude attach 7c5dcf5d    open in this terminal
  claude logs 7c5dcf5d      show recent output
  claude stop 7c5dcf5d      stop this session
```

#### 运行外壳命令

要将 shell 命令作为后台作业而不是 Claude 会话运行，请传递 `--exec`。以下示例将 `pytest -x` 作为后台作业运行：

```bash theme={null}
claude --bg --exec 'pytest -x'
```

从 agent 视图中，通过键入 `!` 作为调度输入的第一个字符来调度相同类型的作业：`!` 显示为前缀，其后的所有内容都是命令，并且 `Enter` 启动作业。

该命令作为 PTY- 支持的作业运行，并在 agent 视图中显示为一行，最新的输出行作为其状态。 shell 作业代替 Claude 运行该命令，因此不会调用任何模型，并且输出不会发送到任何会话。

要查看输出，请附加到该行，按 `Space` 进行查看而不附加，或从 shell 运行 `claude logs <id>`。捕获的输出保留在内存中，不会写入磁盘。该行及其输出会在命令退出后大约五分钟自动清理，因此如果您需要结果，请在此之前阅读它。

### 如何隔离文件编辑

当您从 agent 视图分派后台会话或使用 `claude --bg` 启动后台会话时，会话将在您的工作目录中启动。在编辑文件之前，Claude 将会话移动到 `.claude/worktrees/` 下的独立的 [git 工作树 ](<https://code.claude.com/docs/en/worktrees>) 中，因此并行会话可以读取相同的结帐，但每个会话都写入自己的内容。一旦会话位于其工作树中，Claude Code [ 就会对会话及其生成的任何子代理强制执行工作树隔离 ](<https://code.claude.com/docs/en/worktrees#how-claude-code-enforces-isolation>)。

Claude 在以下情况下跳过工作树：

* 您[使用`←`或`/background`将已打开的会话移至后台](<#from-inside-a-session>)。该会话继续在已经工作的地方编辑文件
* 该会话已经位于链接的 git 工作树内，无论 Claude 在 `.claude/worktrees/` 下创建它还是您在其他地方使用 `git worktree add` 创建它
* Claude 正在编辑的文件位于链接的 git 工作树内，例如会话或其子代理使用 `git worktree add` 创建的文件
* 工作目录不是 git 存储库，并且没有配置 [`WorktreeCreate` 挂钩 ](<https://code.claude.com/docs/en/hooks#worktreecreate>)
* 写入位于工作目录之外

要关闭 git 工作树不实用的存储库的工作树隔离，请将 [`worktree.bgIsolation`](<https://code.claude.com/docs/en/settings-reference#worktree-bgisolation>) 设置为 `"none"`。然后，后台会话直接编辑您的工作副本，而无需先进入工作树。将设置添加到项目的`.claude/settings.json`：

```json theme={null}
{
  "worktree": {
    "bgIsolation": "none"
  }
}
```

在 git 存储库之外，会话直接写入工作目录并且彼此不隔离，因此请避免分派编辑相同文件的并行会话。如果您使用不同的版本控制系统，请配置 [`WorktreeCreate` 挂钩 ](<https://code.claude.com/docs/en/worktrees#non-git-version-control>) 和 Claude 隔离编辑的方式与 git 相同。

当挂钩在不是 git 存储库的目录中失败时，Claude 会跳过该目录的隔离并就地编辑工作目录。在 git 存储库中，Claude 在编辑之前移动到工作树中的会话无法在共享结账上使用 `Edit`、`Write` 或 `NotebookEdit` 工具，直到发生移动。

要查找会话的工作树路径，请附加并检查其工作目录。

后台会话生成的 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>) 继承会话的工作目录。一旦会话位于工作树中，子代理的文件编辑就会落在该工作树中，而不是您的工作副本中。要为子代理提供自己单独的工作树，请在其 frontmatter 中设置 [`isolation: worktree`](<https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields>) 或在生成它时传递 `isolation: "worktree"`。

当后台会话在输入的工作树 Claude 中进行代码更改时，Claude Code 指示 Claude 在完成之前保留工作，因此如果您删除会话及其工作树，它仍然存在：

* **提交并推送**：Claude无需询问即可提交，并在存储库具有远程时推送分支。
* **草稿拉取请求**：Claude在任务调用时打开一个拉取请求，并且[`#N`标签](<#拉取请求状态>)出现在该行上。
* **从不**：推送到`main`或`master`，强制推送并合并。
* **你的git指令优先**：如果任务`CLAUDE.md`或[内存](<https://code.claude.com/docs/en/memory>)说你自己处理提交或推送，Claude将git留给你。

编辑未隔离自身的结帐的会话在提交或切换分支之前仍然会询问。这适用于隔离设置为 `"none"` 时、工作树移动失败时或会话在已存在的工作树内启动时。

无论什么任务，Claude 都会以一份报告结束工作，说明它做了什么以及工作在哪里：路径、分支、拉取请求或答案本身。

#### 删除会话会删除什么

在 [agent 视图 ](<#整理清单>) 中或使用 [`claude rm`](<#从-shell-管理会话>) 两次删除使用 `Ctrl+X` 的会话。除以下保留的情况外，会话将离开列表。它的转录本通过 `claude --resume` 保留在您的计算机上，并且在主管重新启动后删除仍然存在。

为会话创建的工作树 Claude 会发生什么情况：

* Agent 视图将其删除，包括未提交的更改，因此请先提交您想要保留的内容。
* 当有未提交的更改时，`claude rm` 将其与会话行一起保留。
* agent 视图和 `claude rm` 都不会删除另一个正在运行的会话正在使用或已锁定的工作树，并且再次删除不会改变这一点。 Claude Code保留工作树和会话，并给出保留目录名称及原因；在 agent 视图中，会话的行显示 `not deleted`。关闭其他会话，然后再次删除。
* 当您删除其工作树具有 Claude Code 无法确认保存在其他地方的提交的会话时，Claude Code 会保留工作树和会话，并且消息会命名工作树的分支以及未推送的提交数量。该消息还提供了两种前进方式：推送提交，或再次删除以丢弃它们。

远程提交不会阻止删除。只要在主签出中签出该分支，即存储库目录本身而不是工作树，就不会在 `origin` 远程默认分支的本地副本上提交。

拒绝后，您选择：

  * 要保留提交，请推送它们，或将它们合并到默认分支中，然后再次删除会话。
  * 要丢弃它们，请再次删除会话而不推送：在 agent 视图中的行上按 `Ctrl+X` 两次，或运行显示拒绝的 `claude rm <id> --discard-unpushed` 命令。这将删除会话和工作树及其分支，丢弃未推送的提交和任何未提交的更改。

当您再次删除时，Claude Code 仅丢弃拒绝显示的内容：如果工作树此后获得了提交，Claude Code 会再次保留它并显示更新的状态。

当另一个完成的会话的记录也命名该工作树时，当您再次删除时它会保留；推送提交，然后再次删除。
* 工作树 git 不再识别，例如在 `git worktree prune` 之后，不会阻止删除。 Claude Code 删除会话并将目录保留在磁盘上。
* 当 git 或 [`WorktreeRemove` 挂钩 ](<https://code.claude.com/docs/en/hooks#worktreeremove>) 无法删除工作树时，Claude Code 会保留工作树和会话，并且消息会指出原因。对于钩子，该消息说明它是如何结束的，例如 `exited 1`，并引用其 stderr 的开头。该消息还告诉您下一步要执行以下哪一项操作：

  * 再次删除会话以删除目录，方法是在 agent 视图中按两次 `Ctrl+X` 或运行 `claude rm` 拒绝打印的 `claude rm <id> --force-remove-worktree <worktree-id>` 命令。工作树的分支保留在存储库中。

Claude Code仅在可以确认以下所有内容时提供此信息：

    * 该目录是 `.claude/worktrees/` 下存储库的链接工作树之一
    * 工作树和签出的子模块都没有对跟踪文件进行未提交的更改
    * 没有其他会话的记录命名它

当 Claude Code 无法验证子模块签出的状态时，例如被单独的 git 存储库替换的子模块，它也不提供此功能。
  * 修复阻碍的因素，例如提交或隐藏未提交的更改、将单独的 git 存储库移出工作树、关闭正在使用该目录的任何内容或修复挂钩，然后再次删除会话。
  * 自行删除该目录，然后再次删除会话。

无论哪种方式，您自己创建并在其中启动会话的工作树都会保留在原处。

工作树目录不属于任何 git 存储库的会话，因为存储库已被删除或 [`WorktreeCreate` 挂钩 ](<https://code.claude.com/docs/en/hooks#worktreecreate>) 在其他地方创建了该目录，仍然可以被删除。当文件保留在目录中时：

* Agent 视图要求在丢弃它们之前双击相同的 `Ctrl+X`。对于钩子创建的目录，它会运行您的 [`WorktreeRemove` 钩子 ](<https://code.claude.com/docs/en/hooks#worktreeremove>)，如果没有钩子，它会拒绝删除并保留会话。
* `claude rm`保留会话和工作树，并指出原因。

任一路径都保留另一个已完成会话的记录名称的目录。

### 设置模型

agent 视图标题中显示的模型名称是调度默认值。您从输入开始的新会话使用此模型，该模型来自用户设置中的 [`model` 设置 ](<https://code.claude.com/docs/en/settings-reference#model>)。通过在[`/model`选择器](<https://code.claude.com/docs/en/model-config>)中选择型号进行设置，或直接编辑设置。

要覆盖整个 agent 视图会话的调度默认值，请在打开 agent 视图时传递 `--model`。参见[权限模式、模型和工作量](<#许可模式模型和努力>)。

要从 agent 视图内部更改调度默认值，请在调度输入中键入 `/model`，后跟型号名称，然后按 `Enter`。标题会更新以显示带有 `(session)` 标记的模型，并且您随后分派的会话将使用它。输入 `/model default` 以清除覆盖并返回到调度默认值。此覆盖持续当前 `claude agents` 运行的其余部分，并且不会写入您的设置文件。以下示例在 Opus 上分派一个会话，在 Sonnet 上分派下一个会话：

```text theme={null}
/model opus
refactor auth
/model sonnet
run the test suite
```

每个后台会话可以在不同的模型上运行。要在一个会话中覆盖它：

* 从 shell 中，通过 `--model` 和 `claude --bg`。
* 附加到正在运行的会话并运行 `/model` 进行切换：从选择器中进行的选择或键入的 `/model <name>` 将保存为新会话的默认值，除非您在选择器中按 `s` 进行仅会话切换。如果会话重新生成，仅会话切换仍然存在。
* 调度一个 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>)，其 frontmatter 设置 `model` 字段。

### 许可模式、模型和努力

后台会话从您调度它的位置和方式获取其设置、提供程序、权限模式、模型和工作量。下面的小节介绍了每个源，以及主管重新启动会话时仍然存在的内容。

#### 设置和提供商

后台会话读取其 [设置](<https://code.claude.com/docs/en/settings>) 从它运行的目录开始，就像你开始一样 `claude` 那里与 [它继承的配置标志](<#当你成为背景时会发生什么>)。这包括 [`env` 价值观](<https://code.claude.com/docs/en/settings-reference#env>) 在项目设置中，所以 `ANTHROPIC_MODEL` 或提供程序变量设置适用于该目录中的每个后台会话。

后台会话还使用您从中调度它的 shell 的 `PATH` 运行，因此它运行的命令会找到与您的终端相同的工具。它还保留该 shell 的云提供商选择，例如 `CLAUDE_CODE_USE_BEDROCK` 或 `CLAUDE_CODE_USE_VERTEX`，及其 `ANTHROPIC_DEFAULT_*_MODEL` 别名以及您导出到此处的任何 [`CLAUDE_CODE_EXTRA_BODY`](<https://code.claude.com/docs/en/env-vars>) 覆盖。

#### LLM网关

如果您通过 [LLM 网关 ](<https://code.claude.com/docs/en/llm-gateway>) 路由 Claude Code，请将网关变量放入设置文件的 `env` 块中，而不是在 shell 中导出它们，并且后台会话会读取它们及其其余设置。 [在设置文件中设置](<https://code.claude.com/docs/en/llm-gateway-connect#set-in-a-settings-file>)显示块以及用于凭证的设置文件。

如果您仅在 shell 中导出网关 `ANTHROPIC_BASE_URL`，则仅当 [supervisor](<#主管流程>) 本身从导出相同网关的 shell 启动时，它才会与您导出的 `ANTHROPIC_CUSTOM_HEADERS` 和凭证一起到达后台会话，并且仅在以下情况下：

* 您使用 `←` 或 `/background` 为自己的会话设置背景
* 您将会话分派到您所在的目录中
* 您可以通过附加或回复来唤醒所在目录中已停止的会话

Claude Code 在云提供商面前转发网关。如果您从中分派的 shell 选择提供程序并使用其 auth-bypass 标志导出其网关端点，则 Claude Code 在适用于 `ANTHROPIC_BASE_URL` 的条件下将端点和标志对与 `ANTHROPIC_CUSTOM_HEADERS` 一起转发到会话。例如，使用 `ANTHROPIC_VERTEX_BASE_URL` 和 `CLAUDE_CODE_SKIP_VERTEX_AUTH=1` 导出 `CLAUDE_CODE_USE_VERTEX=1`，并且 Claude Code 转发该端点和标志。

Claude Code 仅将转发网关应用于该会话的运行进程，并且从不将其写入磁盘。

#### 权限模式

[权限模式](<https://code.claude.com/docs/en/permissions>)取决于您启动会话的方式：

* **以 `/bg` 或 `←`** 为背景：Claude Code 保留会话所处的权限模式，因此您切换到 `acceptEdits` 或 `auto` 的会话在分离后仍保留在那里
* **从您使用`←`**打开的agent视图调度：首先是目标自己的配置，并且当没有其他设置时，应用您来自的会话的权限模式
* **从 shell 中启动的 `claude agents` 调度，或使用 `claude --bg`** 调度：新会话以该目录中新的 `claude` 会话的方式启动，除非您从使用 [dispatch 打开的 agent 视图调度它默认值](<#调度默认值>)。 [会话以哪种权限模式启动](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>)列出了顺序

对于从使用 `←` 打开的 agent 视图分派的会话，Claude Code 采用第一个适用的权限模式：

1. 目标目录的[`permissions.defaultMode`](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>)。适用两条来源规则：
   * `auto` 和 `bypassPermissions` [ 仅在托管设置、`--settings` 文件或 `~/.claude/settings.json`](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>) 中生效。
   * Claude Code 拒绝来自项目 `.claude/settings.json` 或 `.claude/settings.local.json` 的 `defaultMode`，该项目选择比您所在会话更宽松的模式。
2. 您来自的会话的权限模式

当 Claude Code 因过于宽松而拒绝某个源的模式时，由列表中的下一个源决定。例如，如果您从计划模式会话分派到其签入设置要求 `acceptEdits` 的目录，则新会话将以计划模式启动。如果您将 `defaultMode` 移至 `~/.claude/settings.json`，则无论您来自的会话的权限模式如何，它都适用。

宽容性运行计划，然后是手动和 `dontAsk`，然后是 `acceptEdits` 和自动，每个都比另一个更宽容，然后是 `bypassPermissions`。

#### 调度默认值

要为从 agent 视图分派的每个会话设置默认值，请在打开它时传递 `--permission-mode`、`--model`、`--effort` 或 `--agent` 中的任意一个：

```bash theme={null}
claude agents --permission-mode plan --model opus --effort high
```

这里的`--effort`接受与[顶级`--effort`标志](<https://code.claude.com/docs/en/cli-reference#cli-flags>)相同的值，包括`ultracode`。

`--agent` 设置当调度提示未命名时使用的 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>)，可以使用 `@name` 或作为第一个单词。如果设置了，则默认为 [`agent` 设置 ](<https://code.claude.com/docs/en/settings-reference#agent>)，否则为内置包罗万象 `claude` agent。在调度输入中命名子代理会覆盖两者。

`claude agents` 还接受 `--dangerously-skip-permissions` 作为 `--permission-mode bypassPermissions` 和 `--allow-dangerously-skip-permissions` 的简写，以使 `bypassPermissions` 在每个调度会话的 `Shift+Tab` 周期中可用，而无需在该模式下启动。两者都匹配 [ 顶级 CLI 标志 ](<https://code.claude.com/docs/en/cli-reference>)。

传递 `--restricted` 以启动您在 [ 限制模式 ](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 下从视图分派的每个会话，就好像每个会话都是使用顶级 `--restricted` 标志启动的。需要 Claude Code v2.1.248 或更高版本。

活动默认值显示在调度输入下方的页脚中。

Claude Code 拒绝 `claude --bg --permission-mode bypassPermissions`，直到您通过交互运行一次 `claude --dangerously-skip-permissions` 接受绕过免责声明，因为该模式允许您未观看的会话在未经批准的情况下进行操作。如果您之前未接受，则将 `--dangerously-skip-permissions` 或 `--permission-mode bypassPermissions` 传递给 `claude agents` 会显示相同的免责声明，并且接受会将 `bypassPermissions` 应用于您从视图启动的会话。传递 `--allow-dangerously-skip-permissions` 也会显示相同的免责声明，接受会使 `bypassPermissions` 在这些会话的 `Shift+Tab` 周期中可用，而无需在其中启动它们。

#### 重启后仍然存在的问题

您为后台会话选择的权限模式、模型和工作量，以及它携带的 [ 配置标志 ](<#当你成为背景时会发生什么>)，当主管稍后 [ 停止并重新启动 ](<#主管流程>) 其进程时，所有这些都会保留。重新启动后，您使用 `claude --bg --dangerously-skip-permissions` 或 `claude --bg --permission-mode bypassPermissions` 启动的会话将保留在 `bypassPermissions` 中。您在会话中使用 `/model` 或 `/effort` 更改的模型或工作也会保留。

如果会话从您的设置而不是从 `--effort` 或 `/effort` 获取工作，则 Claude Code 每次启动会话进程时都会再次读取您的设置。在 `settings.json` 中编辑保存的工作后，更改会到达您使用 `←` 或 `/bg` 的后台会话，并且它们稍后会重新启动。节省的精力是 [`effortLevel`](<https://code.claude.com/docs/en/settings-reference#effortlevel>) 键或 [`modelSettings`](<https://code.claude.com/docs/en/settings-reference#modelsettings>) 条目。

Claude Code 还会在重新启动后保留您使用 [`/rename`](<https://code.claude.com/docs/en/commands>) 或 `Ctrl+R` 设置的名称，因此您仍然可以运行 [`claude --resume <name>`](<https://code.claude.com/docs/en/sessions#name-your-sessions>) 来访问会话。

您在附加时使用 [`Ctrl+S`](<https://code.claude.com/docs/en/interactive-mode#general-controls>) 隐藏的提示也会与会话一起保留。在进程停止或重新启动后重新打开会话，然后按 `Ctrl+S` 恢复隐藏的文本。存储中粘贴的内容在重新启动后将无法保留。

### 设置、插件和 MCP 服务器

Agent 视图接受与 `claude` 相同的配置标志，用于加载设置、插件、MCP 服务器和其他目录。 Agent 视图将 `--settings`、`--setting-sources` 和 `--plugin-dir` 应用于自身，并将每个配置标志传递到您从中分派的会话，因此您以这种方式加载的插件或 MCP 服务器在这些会话中可用。

|旗帜|效果|
| :- | :- |
| [`--settings <file-or-json>`](<https://code.claude.com/docs/en/settings>) |覆盖 agent 视图和分派会话的设置|
| [`--setting-sources <sources>`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) |仅加载 agent 视图和分派会话中指定的设置源|
| [`--add-dir <path>`](<https://code.claude.com/docs/en/permissions#additional-directories-grant-file-access-not-configuration>) |授予文件访问附加目录的权限|
| [`--plugin-dir <path>`](<https://code.claude.com/docs/en/plugins/create#load-a-directory-or-archive-for-one-session>) |从本地目录加载插件|
| [`--mcp-config <file-or-json>`](<https://code.claude.com/docs/en/mcp>) |从配置文件或 JSON 字符串加载 MCP 服务器|
| `--strict-mcp-config` |仅使用 `--mcp-config` 中的 MCP 服务器，忽略其他 MCP 配置。请参阅 [ 使用 managed-mcp.json](<https://code.claude.com/docs/en/managed-mcp#exclusive-control-with-managed-mcp-json>) 进行独占控制，了解该标志在托管 MCP 文件下的作用|

每个值重复一次 `--add-dir`、`--plugin-dir` 或 `--mcp-config`。 `claude agents`不支持空格分隔形式，例如`--add-dir a b c`。

您可以将 `--settings`、`--setting-sources` 和 `--plugin-dir` 放置在 `agents` 之前或之后。将 `--add-dir` 和 `--mcp-config` 保留在 `agents` 之后：如果将其中之一放在 `agents` 之前，则 [`claude agents --json`](<#从-shell-管理会话>) 将失败并出现 `unknown option` 错误。

以下示例打开 agent 视图，其中包含设置覆盖和一个额外目录：

```bash theme={null}
claude agents --settings ./ci-settings.json --add-dir ../shared-lib
```

`--settings` 接受文件路径或内联 JSON 字符串。文件路径必须指向现有文件；如果不存在，Claude Code 会退出并出现 `Settings file not found` 错误。

## 从 shell 管理会话

每个后台会话都有一个简短的 ID，您可以从 shell 中使用。当您使用`claude --bg`启动会话时，会打印ID，每个会话的ID是其在`~/.claude/jobs/`下的目录名称。这些命令对于编写脚本或当您不想打开 agent 视图时非常有用。

|命令|目的|
| :- | :- |
| `claude agents` |打开agent视图|
| `claude agents --cwd <path>` |打开范围为 `<path>` 下启动的会话的 agent 视图|
| `claude agents --json` |将会话打印为 JSON 数组并退出。请参阅 [将会话列为 JSON](<#将会话列为-json>)|
| `claude attach <id\|name>` |附加到此终端中的会话|
| `claude logs <id\|name>` |打印会话的最近输出|
| `claude stop <id>` |停止会话。还接受 `claude kill`|
| `claude respawn <id>` |重新启动会话，运行或停止，例如获取更新的 Claude Code 二进制文件。重新启动的会话将恢复其保存的对话；当磁盘上没有任何内容时，它会再次运行原始提示作为新对话|
| `claude respawn --all` |重新启动每个正在运行的会话，例如立即将所有会话移至更新的 Claude Code 二进制文件|
| `claude rm <id>` |从列表中删除会话，以及在可以安全删除时为其创建的工作树 Claude；请参阅[删除会话会删除什么](<#删除会话会删除什么>)。对话记录保留在您的本地计算机上，并可通过 `claude --resume` 获取|
| `claude rm <id> --discard-unpushed <commit>@<worktree-id>` |删除因未推送的提交而删除被拒绝的会话，丢弃工作树及其分支和提交。传递拒绝打印的确切值；请参阅[删除会话会删除什么](<#删除会话会删除什么>)。需要 v2.1.260 或更高版本|
| `claude rm <id> --force-remove-worktree <worktree-id>` |删除由于 git 或 `WorktreeRemove` 挂钩无法删除其工作树而被拒绝删除的会话，无论如何都会删除工作树目录并将其分支保留在存储库中。传递拒绝打印的确切值；请参阅[删除会话会删除什么](<#删除会话会删除什么>)。需要 v2.1.268 或更高版本|
| `claude daemon status` |打印 [supervisor 的 ](<#主管流程>) 状态、版本、套接字目录和工作线程数|
| `claude daemon logs` |遵循主管的日志文件 [`~/.claude/daemon.log`](<#状态存储位置>)，在新行到达时打印新行，直到按 `Ctrl+C`|
| `claude daemon stop --any` |停止主管进程及其托管的后台会话。传递 `--keep-workers` 以使后台会话保持运行，以便下一个主管重新连接到它们。下一个 `claude agents` 或 `claude --bg` 开始一个新的主管|

`claude attach` 和 `claude logs` 可以作为会话名称的一部分来代替 ID，如 `claude logs "auth refactor"` 中所示。传递名称需要 Claude Code v2.1.290 或更高版本。

### 将会话列为 JSON

`claude agents --json` 将活动会话打印为 JSON 数组并退出：每个实时会话，以及仍在工作或被阻止的后台会话，即使其进程已退出。添加 `--all` 以还包括已完成的后台会话，并添加 `--cwd <path>` 以将列表限制为在该目录下启动的会话。

每个条目描述一个会话：

|领域|现在|描述|
| :- | :- | :- |
| `cwd`, `kind`, `startedAt` |总是|工作目录，`interactive` 或 `background`，以及以 Unix 毫秒为单位的开始时间|
| `id` |背景会议|短ID，可与`claude attach`、`claude logs`和`claude stop`一起使用|
| `state` |背景会议|`working`、`blocked`、`done`、`failed` 或 `stopped` 之一。请参阅 [从脚本读取会话状态 ](<#从脚本读取会话状态>) 了解每个值的含义|
| `pid`, `status` |当进程还活着时|处理 ID 以及 `busy`、`waiting` 或 `idle` 之一|
| `waitingFor` |当`status`为`waiting`时|会话被阻止的原因：`permission prompt` 用于批准、`input needed` 用于来自 Claude 的问题或 MCP 服务器的输入请求、`sandbox request`、`worker request` 或 `dialog open`|
| `sessionId`, `name` |设置时|`sessionId` 是完整会话 UUID，可与 [`claude --resume`](<https://code.claude.com/docs/en/sessions>) 一起使用。交互式会话的 `name` 是其 [ 默认显示名称 ](<https://code.claude.com/docs/en/sessions#name-your-sessions>)，直到您为会话命名或接受其中的计划|

### 从脚本读取会话状态

`claude agents --json` 是从外部 Claude Code 读取会话状态的受支持方法，例如从状态栏、调度程序或监督后台工作的另一个 Claude 会话。轮询`claude agents --json --all`，不断列出进程已退出的会话，并读取每个条目的`state`、`status`和`waitingFor`。

| `state` |这意味着什么|
| :- | :- |
| `working` |轮次正在运行，或者会话处于其自行驱动的工作步骤之间，例如 [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) 迭代或等待 CI。 `status`告诉你现在它的进程是否是`busy`|
| `blocked` |会话正在等待您：它提出的问题、权限或沙箱决定、只有您可以清除的错误（例如登录过期），或者如果您在没有提示的情况下启动它，则它的第一个提示。当等待是实时进程中的打开提示时，`waitingFor` 将其命名为|
| `done` |最后一轮完成了您所要求的内容，并且会话已准备好等待您的下一个提示，无论其进程是否仍然存在|
| `failed`, `stopped` |任务因错误而结束，或者会话已停止|

已完成轮次并等待下一条指令的会话将读取 `done`，而不是 `blocked`。 `blocked` 始终意味着会话需要您提供一些信息才能继续。

`~/.claude/jobs/<id>/`下的文件不是稳定的接口。会话或其他程序写入 `state`、`detail`、`tempo` 或 `needs` 的值将在下次更新时替换。

如果您希望会话用自己的语言报告进度，请让它编写自己的文件，例如在 `$CLAUDE_JOB_DIR/tmp` 下，而不是编辑 `state.json`。

## 后台会话如何托管

Claude Code 将 agent 视图中列出的每个会话视为后台会话，无论您当前是否附加到该会话。相比之下，通过直接运行 `claude` 启动的会话会与该终端绑定，并在终端关闭时结束，除非您 [ 将其发送到后台 ](<#from-inside-a-session>)。

要检查您所处的会话类型，请运行 [`/status`](<https://code.claude.com/docs/en/commands>)。 `Session kind` 行在后台会话中读取 `background job · attached` 或 `background job · unattended`，具体取决于是否连接终端，以及在任何其他会话中读取 `interactive`。

### 主管流程

Supervisor 是一项后台服务，运行您的后台会话，以便在您关闭 agent 视图或终端后它们仍能继续工作。 Claude Code 会在您第一次后台会话或打开 agent 视图时启动它，并且您不需要自己管理它。

每个会话都是其自己的 Claude Code 进程，位于主管之下，该进程发生的情况取决于会话的状态：

* **正在工作，在权限提示或其他对话框中暂停，或附加**：进程继续运行。正在运行的子代理、工作流或监视器算作工作，待处理的 [ 会话范围计划任务 ](<https://code.claude.com/docs/en/scheduled-tasks>)（例如 `/loop` 唤醒）也算作工作。
* **已完成或正在等待您的下一条消息，并且未连接大约一个小时**：主管停止进程以释放资源。通过询问您问题而结束的会话算作等待您的下一条消息。对话保留在磁盘上，下次您附加或回复时，会话将从中断处恢复。使用 `Ctrl+T` 固定会话以保持其进程运行。
* **主管运行时意外退出**：主管重新启动进程。使用 `←` 或 `/background`（例如 `kill`）结束您自己的后台会话，将其标记为停止而不是重新启动。对于以关闭结束的会话，请参阅[会话在关闭后显示为失败或停止](<#sessions-show-as-failed-after-shutdown>)。
* **自动更新后**：Supervisor 自行重新启动到新版本，并将空闲会话转移到后台。正在运行、等待您或附加的会话不会被中断。

当会话的进程停止或重新启动时，其中启动的后台 shell 命令、动态工作流程和后台子代理 Claude 会转移到下一个进程；运行监视器和 shell 命令，子代理启动并停止该进程。删除会话会停止它所延续的所有内容。要停止所有进程，请将 [`CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF`](<https://code.claude.com/docs/en/env-vars#variables>) 设置为 `1`。

主管及其会话使用与交互式会话相同的存储凭据进行身份验证。对于哪些设置和 shell 变量到达会话，包括 `PATH`，请参阅 [设置和提供程序 ](<#设置和提供商>)。对于网关端点，请参阅 [LLM 网关 ](<#llm网关>)。

### 状态存储位置

会话状态存储在您的 Claude Code 配置目录下。如果您设置 [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>)，主管将使用该目录而不是 `~/.claude`，并作为具有自己会话的单独实例运行。

|路径|内容|
| :- | :- |
| `~/.claude/daemon.log` |主管日志|
| `~/.claude/daemon/roster.json` |正在运行的后台会话列表，用于重启后重新连接|
| `~/.claude/jobs/<id>/state.json` |每个会话的状态显示在 agent 视图中。通过[`claude agents --json`](<#从脚本读取会话状态>)读取而不是解析文件|
| `~/.claude/jobs/<id>/tmp/` |每个会话的临时目录。 Claude 的 `Write` 和 `Edit` 调用此处不会提示权限。删除会话时删除|

每个后台会话都将 `CLAUDE_JOB_DIR` 环境变量设置为其 `~/.claude/jobs/<id>` 目录，因此会话运行的 shell 命令可以将临时文件写入 `$CLAUDE_JOB_DIR/tmp`，而不会与并行会话发生冲突。

要检查此状态而不直接读取文件，请运行 `claude daemon status`。它报告主管是否可以访问、其进程 ID 和版本、套接字目录以及有多少后台会话处于活动状态。

当正在运行的 Supervisor 的版本与您调用的 `claude` 不同时，该命令还会发出警告，这种情况会在 Supervisor 尚未重新启动到更新后发生。该警告显示两个版本，并告诉您运行 `claude daemon stop --any` 以获取新版本。当 Claude Code 作为 OS 服务安装时，建议的命令是不带标志的 `claude daemon stop`。

会话在版本不匹配的情况下完好无损：更新会话的 `state.json` 的旧 Claude Code 版本会保留它无法识别的字段并保持会话列出。 `roster.json` 中的会话列表遵循相同的规则，因此新版本启动的会话在 Supervisor 重新启动后仍可访问并继续接受输入。

### 关闭 agent 视图

要完全关闭背景 agents 和 agent 视图，请将 `disableAgentView` [ 设置 ](<https://code.claude.com/docs/en/settings>) 设置为 `true` 或设置 `CLAUDE_CODE_DISABLE_AGENT_VIEW` 环境变量。管理员可以通过[托管设置](<https://code.claude.com/docs/en/managed-settings>)强制执行此操作。

## 故障排除

### `claude agents` 列出子代理而不是打开 agent 视图

如果 `claude agents` 打印计数，后跟您配置的子代理，然后退出，则 agent 视图在您的环境中不可用。运行`claude update`安装最新版本。

如果更新后agent视图仍然打不开，请检查是否已通过设置或环境变量[关闭](<#关闭-agent-视图>)。

### Agent 视图打开但没有会话

在分派第一个会话之前，agent 视图显示空的部分标题，每个部分标题下都有说明，并在输入上方添加一行说明（代替会话列表）。在底部的输入中键入提示，然后按 `Enter` 调度您的第一个会话。

### 背景显示 `Background this session?` 对话框

如果您按 `←` 将当前会话置于后台，并且 Claude Code 显示 `Background this session?` 对话框，则会话正在进行中的工作，后台将停止、重新启动或在无人值守的情况下运行，并且 Claude Code 在执行以下任何操作之前会询问：

* **无法移动的工作**：会话有无法移动到后台会话的工作，例如正在运行的[监视器](<https://code.claude.com/docs/en/tools-reference#monitor-tool>)。该对话框命名要停止的工作 Claude Code，并单独计算继续执行的任务。
* **正在运行子代理的工作流**：[动态工作流](<https://code.claude.com/docs/en/workflows>)仍然有子代理运行。工作流本身会继续运行，但其正在运行的子代理会从头开始重新启动，并且对话框会显示有多少个。
* **自动工件回复**：Claude是[回复工件本身的评论](<https://code.claude.com/docs/en/artifacts#let-claude-reply-to-comments-on-its-own>)。这些回复将在后台会话中继续进行，对话框中也是如此。

运行 `/tasks` 查看正在运行的所有内容，然后确认到后台或选择 `Stay` 让工作先完成。请参阅 [后台运行时会延续哪些内容 ](<#当你成为背景时会发生什么>) 了解哪些类型的工作会延续以及哪些工作会停止 Claude Code。

### 提示因太短而被拒绝

调度输入需要任务描述，而不是对话式开场白。少于四个字符的提示将被拒绝并显示 `Too short` 提示，因此杂散的击键不会启动会话。描述您希望会话执行的操作，例如 `investigate the flaky checkout test`。

<h3 id="sessions-show-as-failed-after-shutdown">
 会话在关闭后显示为失败或停止
</h3>

关闭或重新启动计算机会停止运行后台会话。当您回来时，正在等待您输入的会话将保留在 `Needs input` 下。对于任何其他正在运行的会话，agent 视图显示的内容取决于它上次取得进展的时间：

* 在 48 小时内，会话显示为失败。附加或回复它，它就会从上次中断的地方重新开始。
* 过去 48 小时，例如机器关闭几天后，会话显示为已停止并显示 `ended while the background service was off`。按该行的`Enter`，页脚显示`Press enter again to resume this session (it ended while the background service was off), or ctrl+x to delete it.` 再次按同一行的`Enter`可恢复已保存的对话。回复或 `claude attach <id>` 会在没有页脚提示的情况下恢复它。

当 [ 转录清理 ](<https://code.claude.com/docs/en/settings-reference#cleanupperioddays>) 删除了已停止会话的已保存对话时，Claude Code 拒绝打开该行：该消息表明没有任何内容可以恢复。 `claude rm <id>` 删除该行，但上述 [ 保留的情况 ](<#删除会话会删除什么>) 除外，并且 `claude respawn <id>` 再次运行其原始提示。请参阅[此会话保存的对话不再位于磁盘上](<https://code.claude.com/docs/en/errors#this-sessions-saved-conversation-is-no-longer-on-disk>)。

仅仅睡觉并不能停止治疗。会话在睡眠期间保留，主管在唤醒时重新连接到它们。

### 打开会话表示对话已经打开

两个进程无法写入相同的记录。当已停止会话的已保存对话已在另一个实时 Claude Code 进程中打开时，Claude Code 拒绝启动会话自己的进程。您看到的内容取决于对话的内容：

* 您恢复对话的终端，例如使用 `claude --resume` 或 `/resume`：该行显示 `Open in a terminal`，并提示在那里继续对话，打开该行会显示 `Can't open — this session is running in another terminal`。 Continue 在该终端中，或退出它并再次打开该行。
* 另一个非交互式 Claude Code 进程，例如尚未退出的同一对话的后台会话进程：打开行显示 `This conversation is already open in another running Claude session`。使用该进程，或等待它退出并再次打开该行。

Claude Code 保存您输入的拒绝尝试的回复（前缀为 `!` 或 `/` 的回复除外），并在下次会话启动时发送。

### 打开会话显示没有保存的记录

当您打开一个 [ 从另一个对话 ](<#from-inside-a-session>) 后台运行的会话并且该会话在它自己运行之前停止时，Claude Code 将恢复该对话。如果 Claude Code 找不到对话，则拒绝打开会话：

* `claude attach` 打印 `This session has no saved transcript`。
* Agent 视图在列表下方显示 `Press enter again to restart this session fresh`。

再次按同一行上的 `Enter` 以使用空对话重新启动会话，或从 shell 运行 `claude respawn <id>`。

有关详细信息，请参阅[错误参考](<https://code.claude.com/docs/en/errors#this-session-has-no-saved-transcript>)。

### 终端主机死亡或会话停止响应

[supervisor](<#主管流程>) 在其自己的主机进程中运行每个后台会话的终端。当该进程终止或停止响应时，Claude Code 会显示原因并提供重新启动；在这两种情况下，对话都会被保存并重新启动即可恢复。 [错误参考](<https://code.claude.com/docs/en/errors#terminal-host-process-died>)引用了完整消息。

Claude Code 永远不会从 `Enter` 或 `claude attach` 重新启动运行 [shell 命令 ](<#运行外壳命令>) 的行，因为那样会再次运行该命令；该行的消息和 `claude attach` 都表示该命令不再运行。

### 会话在开始之前失败并显示 `possibly low memory` 注释

当后台会话的进程在完成启动之前退出并且主机内存不足时，该行的状态会命名该退出并添加 `possibly low memory — free some up and retry`。

该注释是一种假设，而非已证实的原因。 Claude Code仅在进程静默退出时添加它，没有写入错误，也没有被信号停止，并且主机当时报告内存不足。当进程在退出之前确实写入了错误时，该行会显示该错误。

释放计算机上的内存，然后附加或回复该行，主管将启动会话的新进程。当内存保持较低水平时，主管还会[停止空闲会话](<#主管流程>)以自行释放资源，并且如果停止其他会话没有释放任何资源，也会停止空闲固定会话。

### Agent查看说后台服务没有响应

如果附加、查看或 `claude logs` 报告后台服务没有响应，则主管进程可能已停止。停下来，让下一个`claude agents`重新开始。要在重新启动期间保持后台会话运行，请传递 `--keep-workers`：

```bash theme={null}
claude daemon stop --any --keep-workers
```

新主管重新连接到正在运行的会话。如果没有 `--keep-workers`，该命令也会结束后台会话。 `--any` 标志确认您想要停止按需启动的 Supervisor，而不是作为默认安装的服务启动的 Supervisor。

启动但无法接受连接的主管会退出并自行释放其锁定，因此下一个 `claude agents` 会启动一个新的主管，而无需手动停止。当正在运行的 Supervisor 停止时，上述步骤适用。

如果命令退出，表示记录的进程无法验证为主管，请检查报告的进程 ID：如果它是您拥有的主管，请自行停止它，然后删除 `~/.claude/daemon.lock`，以便下一个 `claude agents` 重新开始。

在 Windows 上，如果主管不响应停止请求，该命令将打印其进程 ID。使用 `taskkill /PID <pid>` 结束该过程以完成恢复。当您通过 `--keep-workers` 时，后台会话仍会保留。

### 调度失败并显示 `Could not resolve authentication method`

如果后台调度失败并显示 `Could not resolve authentication method`，而交互式会话正常进行身份验证，则接收调度的工作人员不会获取凭据。后台会话从 [supervisor](<#主管流程>) 获取凭据，因此此错误意味着主管进程本身没有可用的存储凭据。确认您已运行 `/login` 或配置了 API 键，然后停止 Supervisor：

```bash theme={null}
claude daemon stop --any --keep-workers
```

下一个 `claude agents` 或 `claude --bg` 启动一个新的主管来读取您存储的凭据。如果您使用环境变量（例如 `ANTHROPIC_API_KEY` 而不是 `/login`）进行身份验证，请从设置了该变量的 shell 运行下一个命令。

有关原因和修复的完整列表，请参阅 [ 错误参考 ](<https://code.claude.com/docs/en/errors#could-not-resolve-authentication-method>)。

### 后台会话无法读取 macOS 上的桌面、文档或下载

在 macOS 上，后台会话主机作为其自己的进程运行，并请求与您的终端分开访问受保护的文件夹。如果后台会话在读取 `~/Desktop`、`~/Documents`、`~/Downloads` 或其他受保护位置时报告 `Operation not permitted`，请在隐私和安全 > 文件和文件夹下的系统设置中授予访问权限，或为该条目启用完全磁盘访问。

对于本机安装程序，该条目显示为 Claude Code，并且授权在更新过程中持续存在。对于其他安装方法（例如 Homebrew 或 npm），该条目显示二进制路径，并且可能需要在更新后再次授予。

### 后台会话无法到达 macOS 上的本地网络主机

在 macOS 15 及更高版本上，系统会阻止进程访问本地网络上的设备，直到您授予本地网络权限，因此，针对 LAN 地址的命令可能会在后台会话中失败并显示 `connect: no route to host`，即使它在前台终端中运行也是如此。连接到本地网络地址的后台会话中的第一个命令会触发 Claude Code 的 macOS 本地网络权限提示。授予一次权限，这些命令就会像在前台终端中一样到达 LAN 主机。

### 会话在附加后响应缓慢

当已完成或正在等待下一条消息的会话保持未附加状态大约一个小时时，主管将停止其进程以释放资源。附加会从中断处启动一个新进程，并在进程重新启动时立即切换到会话。正在运行的会话、在权限提示或其他对话框中暂停的会话，或者 [ 固定的 ](<#整理清单>) 不会以这种方式停止，因此请使用 `Ctrl+T` 固定会话以保持其响应。

当流程开始时，Claude Code 显示会话记录的尾部，其格式与实时会话呈现的方式相同，其中包含降价、突出显示的代码块和工具调用作为灰色行，在带有 `Session is starting` 注释的灰色提示区域上方。一旦准备好，实时会话就会取代它。

### `.claude/worktrees/` 已满

在 agent 视图中删除会话会删除为其创建的工作树 Claude，但 [ 某些删除会保留工作树或将其目录保留在磁盘上 ](<#删除会话会删除什么>)，因此剩余目录可能会累积。 git 不再识别的目录不会出现在 `git worktree list` 中，因此请手动删除它们。

列出项目目录中带有 `git worktree list` 的剩余条目，并删除带有 `git worktree remove <path>` 的每个条目。请参阅[清理工作树](<https://code.claude.com/docs/en/worktrees#clean-up-worktrees>)。

## 局限性

Agent 视图处于研究预览阶段，具有以下限制：

* **适用速率限制**：后台会话与交互式会话一样消耗您的订阅使用量，因此并行运行十个 agents 使用配额的速度大约是运行一个的十倍。
* **会话是本地的**：后台会话在您的计算机上运行。它们在睡眠期间保留，但如果机器关闭则停止。
* **Claude 创建的工作树与 agent 视图中的会话一起删除**：在删除在其自己的工作树中编辑文件的会话之前提交更改。 [某些删除会保留工作树](<#删除会话会删除什么>)。

# Manage multiple agents with agent view

> Dispatch and manage many Claude Code sessions from one screen. Agent view shows what every session is doing and which ones need your input.

Agent view, opened with `claude agents`, is one screen for all your background sessions: what's running, what needs your input, and what's done. Dispatch new sessions, watch their state at a glance instead of scrolling through transcripts, and step in only when one needs you. Each background session is a full Claude Code conversation that keeps running without a terminal attached, so you can open it, reply, and leave whenever you want.

Use agent view when you have several independent tasks Claude can work on without you watching every step. Dispatch a bug fix, a pull request review, and a flaky-test investigation as three rows, keep working in another window, and check back when a row shows it needs you or has a result.

When you want to work more directly in any agent's session, attach to the row to enter the full conversation.

To compare agent view with subagents, agent teams, and worktrees, see [Run agents in parallel](<https://code.claude.com/docs/en/agents>). Agent view runs sessions on your machine and you dispatch each one; to have Claude start and track parallel sessions in the cloud from one conversation instead, see [Projects](<https://code.claude.com/docs/en/claude-projects>).



**注释：**

  Agent view is in research preview. The interface and keyboard shortcuts may change as the feature evolves.


## Quick start

This walkthrough covers the core agent view loop: dispatch a task, watch its row update as Claude works, peek to check on it and reply, and attach for the full conversation. The session you dispatch keeps running after you close agent view, so you can leave and come back to it.



  

#### Open agent view

    From your shell, run:

    ```bash theme={null}
    claude agents
    ```

    If you haven't yet accepted the [workspace trust dialog](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>) for the directory, Claude Code shows it before agent view opens, the same dialog `claude` shows. Accept to save trust for the workspace and continue. If you decline, Claude Code exits without opening agent view.

    Agent view opens with an input at the bottom and a table that fills in as sessions start. Press `Esc` to return to your shell; if you opened agent view by backgrounding a session with `←`, `Esc` returns to that conversation instead. Your sessions keep running while you're away and reappear the next time you open agent view.
  


  

#### Dispatch a session

    Type a prompt describing a task and press `Enter`. A new background session starts on that task and appears as a row showing whether it's working, waiting on you, or done. The new session uses the model shown in the agent view header. [Which permission mode it starts in](<#permission-mode-model-and-effort>) depends on how you opened agent view.

    Every prompt you enter here starts its own new session. Typing another prompt and pressing `Enter` launches a second session alongside the first rather than sending a follow-up to it. You can run several in parallel this way.

    Each session uses your subscription quota independently, so see [Limitations](<#limitations>) before dispatching many at once.
  


  

#### Peek and reply

    Select a row with the arrow keys and press `Space` to open the peek panel. It shows the session's most recent output, or the question it's waiting on, rather than the full transcript. Type a reply and press `Enter` to send it without leaving agent view.
  


  

#### Attach and detach

    Press `Enter` or `→` on a row to attach when you want the full conversation. The session takes over the terminal as a full interactive Claude Code session. Press `←` on an empty prompt to detach and return to the table.
  


  

#### Bring an existing session in

    This step needs a running session. If you followed the earlier steps you don't have one open in this terminal, so open a regular `claude` session in another terminal and send it a message first.

    To move a session you already have open into agent view, run `/bg` inside it, or press `←` on an empty prompt to background it and open agent view in one step. In a fresh session with no messages yet, `/bg` asks you to send a message first, while `←` works right away. The session keeps running and appears as a row alongside the ones you dispatched.
  


Inside a regular `claude` session, the prompt footer's `←` hint counts the background agents that are waiting on you, such as `← 2 agents`, and returns to `← for agents` when none need input. Counts above 99 show as `99+`. The count refreshes about every ten seconds while the terminal is focused and immediately when focus returns. It briefly changes color when it moves and when an agent completes, and when a background session finishes while none need your input it briefly shows the number completed, such as `← 2 done`. Both flashes are off when the [`prefersReducedMotion` setting](<https://code.claude.com/docs/en/settings-reference#prefersreducedmotion>) is on, and the hint is hidden in [screen reader mode](<https://code.claude.com/docs/en/accessibility>).

### Open agent view by default

To have `claude` with no arguments open agent view instead of a new conversation, turn on a `/config` setting.



  

#### Turn on the setting

    In a regular `claude` session, run `/config` and turn on **Open agents view by default**. To skip the menu, set the [`defaultToAgentsView`](<https://code.claude.com/docs/en/settings-reference#defaulttoagentsview>) key directly:

    ```text theme={null}
    /config defaultToAgentsView=true
    ```
  


  

#### Start Claude Code

    Exit the session, then run `claude` with no arguments:

    ```bash theme={null}
    claude
    ```

    Agent view opens in place of a new conversation.
  


To start a regular session while the setting is on, pass a prompt: `claude "fix the login test"`. To turn the setting off, run `/config defaultToAgentsView=false` in a regular session or in one you attach to from agent view.

## Monitor sessions with agent view

Run `claude agents` to open agent view. It takes over the full terminal and lists every session grouped by state, with pinned sessions and the ones that need you at the top. Each row shows the session's name, current activity, and its age, counted from when the session was created; a finished session's age freezes at how long the run took.

The name is tinted with the color set by [`/color`](<https://code.claude.com/docs/en/commands>) in that session, including when you [background a session](<#from-inside-a-session>) with `←` or `/background`.

By default the list shows every background session you've started, across all your projects. A session working in one repository and another in a different worktree both appear here, regardless of which directory you opened agent view from. To narrow the list to one project, pass `--cwd`:

```bash theme={null}
claude agents --cwd ~/projects/my-app
```

This shows only sessions started under that directory. It still lists a session that has [moved into a worktree](<#how-file-edits-are-isolated>) under `~/projects/my-app/.claude/worktrees/`.

Interactive sessions you have open in other terminals don't appear until you [background them](<#from-inside-a-session>). [Subagents](<https://code.claude.com/docs/en/sub-agents>) and [teammates](<https://code.claude.com/docs/en/agent-teams>) a session spawns aren't listed as separate rows.

```text theme={null}
Pinned
  ✽ clawd walk cycle          Drawing the walk-cycle sprite frames          3m

Ready for review
  ∙ jump physics              Opened PR with collision fix                 #2048  2h

Needs input
  ✻ power-up design           double jump or wall climb?                    1m

Working
  ✽ collision detection       Adding swept-AABB checks to CollisionSystem   2m
  ✢ playtest level 3          all checkpoints cleared ×12                in 4m

Completed
  ✻ title screen              menu, options, and credits done               9m
  ∙ sound effects             14 SFX exported to assets/audio               4h
  … 6 more
```

### Read session state

Each row starts with an icon whose color and animation show the session's state:

| State | Icon shows as | What it means |
| :- | :- | :- |
| Working | Animated | Claude is actively running tools or generating a response |
| Needs input | Yellow | Claude is waiting on something only you can provide: an answer to a question, a permission decision, or another prompt only you can answer, such as a [sandbox](<https://code.claude.com/docs/en/sandboxing>) prompt to allow a network host or an MCP server's [request for input](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>). A command that needs an attached terminal, such as `/install-github-app` or the `/mcp` settings list, [holds an unattended session here too](<#attach-to-a-session>) |
| Idle | Dimmed | The session has nothing to do and is ready for your next prompt |
| Completed | Green | The task finished successfully |
| Failed | Red | The task ended with an error |
| Stopped | Grey | You stopped the session with `Ctrl+X` or `claude stop`, [its process was ended from outside Claude Code](<#the-supervisor-process>), or [it ended while the background service was off](<#sessions-show-as-failed-after-shutdown>) |

Separately, the icon's shape has its own meaning:

| Shape | What it means |
| :- | :- |
| `✻` or animated `✽` | The session process is running, or the session needs your input |
| `∙` | The process has exited. You can still peek at the row, and when you reply or attach, Claude restarts from where it left off |
| `✢` | A [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) session sleeping between iterations. The row shows its run count and a countdown |

The `#N` or `!N` label that can appear at the right edge of a row is a link to the session's [pull request or merge request](<#pull-request-status>), not part of the state icon.

The terminal tab title shows the awaiting-input count while agent view is open: `2 awaiting input · claude agents` when sessions need input, or `claude agents` when none do.

To read session state from a script or another program, use [`claude agents --json`](<#read-session-state-from-a-script>) rather than the files under `~/.claude/jobs/`.

While agent view is open, Claude Code also sends a notification through your configured [terminal notification channel](<https://code.claude.com/docs/en/terminal-config#get-a-terminal-bell-or-notification>) when a local background session starts needing your input, finishes, or fails. Sessions that run on a schedule, such as [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) sessions, notify only when they need your input. Notifications use the same [`preferredNotifChannel` setting](<https://code.claude.com/docs/en/settings-reference#preferrednotifchannel>) as the rest of Claude Code and fire the [`Notification` hook](<https://code.claude.com/docs/en/hooks#notification>) with the `agent_needs_input` or `agent_completed` type.

Background sessions don't need any terminal open to keep working. A separate [supervisor process](<#the-supervisor-process>) runs them, so you can close agent view, close your shell, or start a new interactive session and your dispatched work keeps going.

Session state persists on disk through auto-updates and supervisor restarts. Sessions are also preserved when your machine sleeps. Their processes resume on wake and the supervisor reconnects to them instead of treating the time gap as idle. Shutting down still stops running sessions; see [Sessions show as failed or stopped after shutdown](<#sessions-show-as-failed-after-shutdown>) for how to recover them.

A session that was mid-response when the machine slept can come back unresponsive. When you open a session that has stopped responding, the supervisor restarts its process and the session continues the interrupted response from where it left off.

### Row summaries

The one-line summary in each row is generated by a [Haiku-class model](<https://code.claude.com/docs/en/model-config>) so the row can tell you what the session is doing, what it needs, or what it produced without opening the transcript. While a session is actively working, the row text updates at most once every 15 seconds from the session's own recent output without sending a model request, and the model writes a fresh summary when each turn ends.

A working row shows what the session says it's doing, and a blocked row shows the question it's asking. During a long turn, the model also rewrites the summary every few minutes so a busy row doesn't keep showing an outdated one. The summary text fills the row's remaining width; open the [peek panel](<#peek-and-reply>) to read a sentence the terminal edge clips.

When the list is [grouped by directory](<#organize-the-list>), the summary opens with the session's state as a colored word, such as `Needs input · double jump or wall climb?`. In the default state grouping, the group header already names the state, so the row shows only the summary.

The end-of-turn summary and each mid-turn rewrite are one short Haiku-class request through your normal provider, billed and handled under the same [data usage terms](<https://code.claude.com/docs/en/data-usage>) as the session itself. The 15-second updates between model rewrites reuse the session's own output and don't send a request. On a third-party provider or gateway with no Haiku-class model configured, the request uses the session's main model instead; set [`ANTHROPIC_DEFAULT_HAIKU_MODEL`](<https://code.claude.com/docs/en/model-config#environment-variables>) to choose one.

### Pull request status

When a session [opens a pull request](<#how-file-edits-are-isolated>), Claude Code adds a label at the right edge of the row, linked to the pull request:

* Claude Code writes the label as `#1234` for a pull request and as `!1234` for a GitLab merge request.
* Claude Code emits the link even when it can't detect hyperlink support, for example over SSH or tmux. Set [`FORCE_HYPERLINK=0`](<https://code.claude.com/docs/en/env-vars>) to render the label as plain text.
* After you send a follow-up to the session, Claude Code keeps the label while the row returns to live progress.

A session that works on an existing pull request is linked to it the same way. Claude Code finds the pull request differently depending on the command Claude runs:

* When Claude edits, comments on, closes, or marks a pull request ready with `gh`, Claude Code links the pull request that the command's own output names. A `gh` command whose captured output names no pull request doesn't create a link; `gh pr merge` is the common case, because it prints its result only to an interactive terminal.
* When Claude checks a pull request out with `gh pr checkout` or pushes to a branch, Claude Code looks the branch up with `gh pr view` and links its open pull request.
* The pull request doesn't need to exist yet when Claude pushes: Claude Code retries the branch lookup after up to five later `git`, `gh`, `glab`, or `curl` commands run in the same directory, so a pull request created after the push, including one Claude creates through the GitHub REST API, links when a retry finds it.

When a session is linked to more than one pull request, the label shows a count instead, such as `3 PRs`, colored by the open pull request that most needs attention. Open the [peek panel](<#peek-and-reply>) to see them all.

The pull request number is colored by its status:

| Color | Pull request status |
| :- | :- |
| Yellow | Waiting on checks or review, or checks failed |
| Green | Checks passed and no review is blocking |
| Purple | Merged |
| Grey | Draft or closed |

For a task that ends in a pull request, check this label for the result: review and merge the pull request when its number turns green.

### Peek and reply

Press `Space` on a selected row to open the peek panel. It opens with the sentence the row truncates at the terminal edge, and which sentence that is depends on the session's state:

* A session that's waiting on you: the exact question it's asking, above the reply input
* A finished session: its result
* A working session: its full status sentence

Any pull requests linked to the session are listed next. For a session that's waiting on you, a line such as `waiting 3m` below them shows how long it has been waiting, and it's the only time shown in the panel. The age at the right edge of the row is a different number: it counts from when the session started.

Most of the time the peek panel is enough and you don't need to open the full transcript.

Type a reply in the peek panel and press `Enter` to send it to that session. Prefix a reply with `!` to send a Bash command instead. What happens to the reply depends on the session and on what you send:

* A session that's working: `/model`, `/effort`, `/rename`, and `/usage` run right away. Other replies join the session's [message queue](<https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works>) instead of interrupting the response, and take effect [when queued input does](<https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued>). Other [commands](<https://code.claude.com/docs/en/commands>) wait for the turn to end, even ones that run as soon as you type them at a session's own prompt
* A reply that is exactly `/stop`: stops the session at once instead of being delivered to it, whether the session is working or waiting on you
* A [shell job](<#run-a-shell-command>): the reply, `/stop` included, goes to the command's terminal as typed input

When the session is waiting on you, how you answer from the peek panel depends on what it's waiting for:

* A question with predefined choices: the panel lists the choices by number. With the reply input empty, press a choice's number to fill it in, then `Enter` to send it, or type your own answer instead
* A question without predefined choices: type your answer. When the empty input shows a suggested reply, press `Tab` to fill it in and edit it before sending
* A permission prompt or another dialog, such as a [sandbox](<https://code.claude.com/docs/en/sandboxing>) prompt or an MCP server's [request for input](<https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests>): replying doesn't answer it. Your message waits in the queue. To answer the dialog, attach with `→`

When a [`PermissionRequest`](<https://code.claude.com/docs/en/hooks#permissionrequest>) or [`PreToolUse`](<https://code.claude.com/docs/en/hooks#pretooluse>) hook returns output Claude Code can't validate for the call the session is asking about, the row shows the hook event and `hook output invalid:` with the validation error before the pending request's text. For a hook that fails another way, the row says the hook failed. The session still waits on the same request.

When a reply can't be delivered, the error message says whether it was saved. A reply prefixed with `!` or `/` is never saved. Claude Code sends a saved reply as the session's next prompt the next time you restart the session; send any other reply again.

With [voice dictation](<https://code.claude.com/docs/en/voice-dictation>) enabled in [hold mode](<https://code.claude.com/docs/en/voice-dictation#hold-to-record>), hold your push-to-talk key while the reply input is focused to dictate a reply instead of typing it. The same works in the dispatch input at the bottom of agent view.

Use `↑` and `↓` to peek at adjacent sessions without closing the panel, or `→` to attach.

### Attach to a session

Press `Enter` or `→` on a selected row to attach. Agent view is replaced by the full interactive session. When you attach, Claude posts a short recap of what happened while you were away.

While attached, the session behaves like any other Claude Code session: [commands](<https://code.claude.com/docs/en/commands>), keyboard shortcuts, and features all work, with the exceptions below.

While you're attached, `/install-github-app` and the [`/mcp`](<https://code.claude.com/docs/en/mcp>) settings list work normally, since a human at the terminal can complete their dialogs. When nobody is attached, these commands can't open their dialogs, so the session appears under `Needs input` in agent view with a row such as `open this session to manage MCP servers`, and the transcript reply says the same. Attach and run the command again to continue; the needs-input row clears when you attach. `/mcp reconnect <server>`, `/mcp enable`, and `/mcp disable` work without attaching either way.

Attached sessions always render in [fullscreen mode](<https://code.claude.com/docs/en/fullscreen>), regardless of your `tui` setting, because a background session has no terminal scrollback to append to. Scroll with `PgUp`, `PgDn`, or the mouse wheel, and press `Ctrl+O` for transcript mode. Your terminal's native scroll and tmux copy mode show only the current viewport, the same as when you run any fullscreen application.

Press `←` on an empty prompt, or run `/exit`, to detach and return to agent view, whether you opened the session from agent view or with `claude attach <id>` from your shell.

`←` also detaches while the [`/btw` overlay](<https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw>) is open. Requires Claude Code v2.1.257 or later. A side question that's still answering keeps running while you're away. The next time you attach, the overlay reopens with it, or with its answer.

On Windows, if you press `←` within about half a second of attaching, Claude Code shows `Ambiguous ←, press again to detach`, because in that window the terminal can redeliver a press from before you attached. Press `←` again to detach.

`Ctrl+Z` also detaches but goes back to where you started instead: agent view if you attached from there, or your shell if you ran `claude attach`. Use `Ctrl+Z` when a dialog has focus and isn't responding to `←`.

`Ctrl+C` keeps its standard interrupt behavior while attached: it cancels a running response or `!` shell command rather than detaching. Pressing `Ctrl+C` twice on an empty prompt detaches, the same as in any session.

Detaching never stops a background session: `←`, `Ctrl+Z`, `/exit`, and double `Ctrl+C` or double `Ctrl+D` all leave it running. To end a session from inside it, run `/stop`.

#### Switch sessions without leaving the terminal

In a session running in the foreground, one you started in the terminal rather than attached to from agent view, pressing `←` on an empty prompt backgrounds it and opens agent view with that row selected, so you can switch sessions without leaving the terminal. The same single press detaches an attached session.

If you press `←` right after you delete the last of the prompt's text or move through prompt history, Claude Code asks you to confirm: the first press shows `Press ← again to open agents`, or `Press ← again to go back to agents` in an attached session, and the second press switches.

When `←` backgrounds a foreground session, agent view shows `Your conversation moved to the background` above the list, with that session's row already selected. From there:

* Press `Enter` to reopen the conversation.
* Press `Esc` to undo the switch and return to the conversation. If `Esc` shows `Still starting — try again in a moment`, the background session isn't ready yet, so press `Esc` again in a moment.
* Press `Ctrl+C` twice to exit to your shell.

When Claude Code can't reopen the conversation, it exits and prints a `claude --resume` command that resumes it.

[Claude's task list](<https://code.claude.com/docs/en/interactive-mode#task-list>) moves to the background session with the conversation, so the checklist is intact when you return to that row.

The row you pressed `←` from also keeps a bold, undimmed name after you move the selection with the arrow keys or the mouse, so you can tell which session you came from.

If a tool is running when you press `←`, Claude Code waits for it to finish before backgrounding, and Claude continues the response in the background session. Press `←` again to background immediately instead of waiting. When in-flight work can't carry over to the background session, Claude Code shows the `Background this session?` dialog first, the same as with [`/background`](<#from-inside-a-session>).

After about ten seconds, Claude Code backgrounds the session without waiting any longer, except in cases such as these:

* **Foreground subagents are still running**: Claude Code keeps waiting so the work of the [foreground subagents](<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>) Claude started carries over, and shows `Still backgrounding after the current tool`. Press `←` again to background without waiting, which restarts those subagents from the beginning.
* **A permission prompt or question is waiting for your answer**: while a permission prompt or a question Claude asked waits, Claude Code keeps waiting and shows `Still backgrounding after the current tool — a question is waiting for your answer.`
* **You type into the prompt input**: Claude Code cancels the switch, because unsent text stays in your terminal's input box and wouldn't move to the background session. It shows `Backgrounding cancelled — you have unsent text in the input. Send it or clear it, then press ← again.`
* **A queued message can't move**: messages you [queued while Claude was working](<https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works>) move to the background session with the conversation. When one of them can't, the session stays in the foreground and Claude Code shows a notice such as `Cannot open agents — 1 queued message can't move to the background. Press ← again once Claude has read it.`

Pressing `←` creates the session's row even when the conversation has no messages yet, so `→` still returns to it.

You can turn this shortcut off for foreground sessions with the [`leftArrowOpensAgents`](<https://code.claude.com/docs/en/settings-reference#leftarrowopensagents>) setting in `/config`.

### Organize the list

Agent view groups sessions so the ones that need input are at the top, with `Ready for review` and `Needs input` above `Working` and `Completed`. These group names don't map one-to-one to the [states](<#read-session-state>) above: a session moves to `Ready for review` when it has an open pull request that needs review or has failing checks, and `Completed` collects finished, failed, and stopped sessions together.

Press `Ctrl+S` to group by directory instead. Your choice persists across runs.

Within a group:

* Press `Ctrl+T` to pin a session to the top and [keep its process running](<#the-supervisor-process>) while idle
* Press `Shift+↑` or `Shift+↓` to reorder sessions
* Press `Ctrl+R` to rename a session
* Press `Enter` on a group header to collapse it, except while a [filter](<#filter-sessions>) is active, when every group stays expanded

To remove a session from the list, press `Ctrl+X` to stop it and `Ctrl+X` again within two seconds to delete it. Pressing `Ctrl+X` on a group header deletes every session in that group after confirmation.

The second press deletes the session even when the stop attempt fails, for example because the [background service isn't responding](<#agent-view-says-the-background-service-did-not-respond>): the confirmation stays active for another two seconds, and the delete ends the session's process itself. Press `Esc` to dismiss the confirmation without deleting.

Except in the kept cases covered in [What deleting a session removes](<#what-deleting-a-session-removes>), deleting removes the session from the list, and a worktree Claude created for it is removed, kept, or left in place depending on how you delete and what the worktree holds. The conversation transcript always stays on your local machine, available through `claude --resume`.

To bring a session back on Claude Code v2.1.212 or later, type `/resume` in the dispatch input. A picker opens with past sessions of the repository you opened agent view from, newest first, including sessions you deleted from the list; sessions that already have a row aren't listed. `↑`/`↓` move the selection, `Enter` resumes the selected session as a background session so it rejoins the list as a row, and `Esc` closes the picker.

The picker opens only for a bare `/resume`. A targeted, scoped, or restricted resume can't be served by the picker, so agent view shows the `attach to a session to run it` hint instead when:

* `/resume` names an id or a search term
* the view is scoped with `--cwd`
* the view was started with [`--safe-mode`](<https://code.claude.com/docs/en/cli-reference#cli-flags>)
* the view was opened with a flag such as `--permission-mode` or `--settings`

Completed sessions that don't fit on screen fold into a `… N more` row. The `Completed` group fills the vertical space left after the live groups, and on a short terminal the header compacts to a single summary line so sessions that are working or need input stay visible.

### Filter sessions

Start the dispatch input with one of these filters to narrow the list as you type:

| Filter | Shows |
| :- | :- |
| `a:<name>` | Sessions running the named agent |
| `s:<state>` | Sessions in the given state, such as `s:working`, or under the given group header, such as `s:ready` for `Ready for review`. `s:blocked` lists everything waiting on you |
| `n:<text>` | Sessions whose name or first prompt contains the text, such as `n:login`. Requires Claude Code v2.1.287 or later |
| `o:<text>` | Sessions whose result contains the text, such as `o:merged`. A bare `o:` lists every session that has reported a result |
| A pull or merge request number, such as `#1234`, or its URL | The session working on that pull request or merge request |
| Any other URL | The session whose first prompt contained that URL |

To combine filters, start with `a:`, `s:`, `n:`, or `o:` and add more, separated by spaces. The list shows the sessions that match all of them. For example, `s:blocked a:reviewer` lists the `reviewer` sessions that are waiting on you.

While a filter is active, groups you collapsed expand to show their matches and a match is selected, so pressing `Enter` opens it. Clear the input to remove the filter, and those groups collapse again.

## Dispatch new agents

You can dispatch new background sessions from agent view, send or copy an existing interactive session to the background, or start one directly from the shell.

<span id="from-agent-view" />

### Dispatch an agent from agent view

Type a prompt in the input at the bottom of agent view and press `Enter` to start a new background session. The session is named automatically from the prompt; rename it later with `Ctrl+R`.

The automatic name is a short label written by a [Haiku-class model](<https://code.claude.com/docs/en/model-config>). A name the session gets later also appears on its row, including the [generated title](<https://code.claude.com/docs/en/sessions#name-your-sessions>) the session gets when you [accept a plan](<https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan>) in that session.

Paste an image into the prompt to include a screenshot or diagram with the task.

Pasted text longer than 800 characters or more than three lines collapses to a `[Pasted text #N]` placeholder so the input stays on one line; the full text is sent when you dispatch. To review or edit the collapsed text before dispatching, paste the same text again and the placeholder expands back into the input.

Prefix or mention parts of the prompt to control how the session starts:

| Input | Effect |
| :- | :- |
| `<agent-name> <prompt>` | If the first word matches a custom [subagent](<https://code.claude.com/docs/en/sub-agents>) name, that subagent runs as the session's main agent with the configuration from its frontmatter |
| `@<agent-name>` | Mention a custom subagent anywhere in the prompt to run it as the main agent |
| `@<repo>` | Mention a repository to run the session there. See [Dispatch to a specific directory](<#dispatch-to-a-specific-directory>) for which repositories are listed |
| `/<command>` | Suggest [skills](<https://code.claude.com/docs/en/skills>) and [commands](<https://code.claude.com/docs/en/commands>) to dispatch as the prompt |
| `! <command>` | Run a shell command as a background job instead of starting a Claude session. The job appears as a row you can attach to, watch, and detach from |
| `#<number>` or a pull or merge request URL | If a session is already working on that pull request or merge request, Claude Code selects its row instead of dispatching a new session |

A small set of commands run in agent view itself instead of dispatching:

* `/exit` and `/quit` close agent view
* `/logout` signs you out
* `/model` sets the [dispatch model](<#set-the-model>)
* `/login` opens the sign-in dialog so you can sign in again without attaching to a session
* A bare `/resume`, or its `/continue` alias, opens a picker of the repository's past sessions to [bring one back](<#organize-the-list>) as a background session. Requires Claude Code v2.1.212 or later

Skills, your own commands, and prompt-expanding built-ins such as `/init` are sent to a new background session as their first prompt. Other built-in commands show an `attach to a session to run it` hint instead. Everything you typed stays in the input next to the hint so you can edit it.

Packaging a recurring task as a [skill](<https://code.claude.com/docs/en/skills>) lets you start the same workflow from agent view repeatedly without retyping the prompt.

When the same `@name` matches both a subagent and a sibling repository, the subagent takes precedence. The bare first-word match also applies, so a prompt that happens to begin with one of your subagent names dispatches that subagent rather than treating the word as plain text. Use the `@` form when you want to be explicit, or start the prompt with a different word to avoid the match.

#### Dispatch to a specific directory

A new session runs in the directory you opened agent view from. To target a different directory, use any of these:

* Open `claude agents` in that directory.
* Open `claude agents` in a parent directory and mention a child repository with `@<repo>` in the prompt. Typing `@` lists these targets:

  * Git repositories one level below the launch directory
  * The registered [git worktrees](<https://code.claude.com/docs/en/worktrees>) of the repository you launched from that live inside its directory tree, such as the ones Claude creates under `.claude/worktrees/`, labeled with their checked-out branch. Worktrees added outside the repository, such as with `git worktree add ../feature`, aren't listed
  * Any directory that already has a session in the list

  A directory whose name contains a space isn't listed.
* From the shell, `cd` into the directory and run `claude --bg "<prompt>"`.

When agent view is grouped by directory, dispatching sends the prompt to the selected row's directory, so you can select a group and dispatch into it without retyping the path.

<span id="from-inside-a-session" />

### Send or copy a session to the background

Two commands move work from the session you're in to the background: `/background` sends the current conversation there and frees your terminal, and `/fork` sends a copy while you keep working where you are.

#### Send the session to the background

Run `/background` or its alias `/bg` to move the current conversation into a background session. Pass a prompt such as `/bg run the test suite and fix any failures` to give one more instruction first. If Claude is responding when you run `/bg`, the response continues in the background session.

Exiting a session that still has background work running, such as subagents, background shell commands, workflows, or [monitors](<https://code.claude.com/docs/en/tools-reference#monitor-tool>), shows a `Background work is running` dialog instead of quitting immediately. Choose `Move to background and exit` to background the session the same way `/background` does and return to your shell. The option isn't shown when agent view is [turned off](<#turn-off-agent-view>).

If a background session on the list already has the conversation's name, Claude Code numbers the new row's name, such as `my-session (2)`, and leaves the existing row's name alone. To rename the new row, select it in agent view and press `Ctrl+R`.

#### Copy the session with /fork

Run `/fork` to copy the current conversation into a new background session while the original keeps running. The copy starts with everything in the conversation up to that point; see the bullets below for where the copy runs. It also carries over the model, permission mode, effort level, and any directories or "don't ask again" permission grants you added during the session. The copy appears as its own row in agent view.

After the fork, the two conversations are independent: nothing the copy does enters the original conversation on its own, though in sessions where [cross-session messaging](<https://code.claude.com/docs/en/cross-session-messaging>) is enabled, either session's Claude can explicitly message the other.

Copying the session requires Claude Code v2.1.212 or later; on v2.1.161 through v2.1.211, `/fork` starts a [forked subagent](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>) instead, which is now `/subtask`. When [agent view is turned off](<#turn-off-agent-view>), `/fork` keeps the forked-subagent behavior and `/subtask` isn't available.

Pass a prompt such as `/fork open a draft pull request with the work so far` and the copy starts working on it immediately. Without a prompt the copy waits for its first instruction: select its row in `claude agents` and press `Space` to send one, or run `claude attach <id>`. The selected row shows `space to send it a prompt` while it waits.

The `/fork` confirmation is one line showing the copy's state, such as `session running`, the name of its agent-view row, and its session ID for `claude attach`. Click the name to switch into the copy: this session moves to the background, the same as pressing `←`, and agent view opens the copy's session.

Except when the copy [edits in place](<#how-file-edits-are-isolated>), Claude Code instructs it to create a worktree of its own before making code changes. Outside a git repository, only a copy moved out of a hook-created worktree gets the instruction; with no [`WorktreeCreate` hook](<https://code.claude.com/docs/en/hooks#worktreecreate>), the copy edits in place. A copy moved out of your worktree is also told never to edit, run commands in, or enter that worktree, whatever the isolation setting.

Where the copy starts depends on where the current session is running:

* Like any dispatched session, the copy [moves into its own worktree before editing files](<#how-file-edits-are-isolated>). In that case the confirmation doesn't mention where the copy runs.
* When your session moved into its linked [worktree](<https://code.claude.com/docs/en/worktrees>) after it started, the copy starts back where the session was before the move and, unless it [edits in place](<#how-file-edits-are-isolated>), makes its code changes in a worktree of its own there. When your worktree is checked out on a branch, that instruction also tells a copy whose task builds on your work to base its new branch on yours, since your branch stays checked out in your worktree. The confirmation ends with `runs in the origin tree`.
* When you launched the session inside a linked worktree of a repository that has a main working tree, the copy starts in that main working tree, with the same worktree-of-its-own rule but no branch instruction. The confirmation ends with `runs in the origin tree` here too.
* A session launched inside a worktree of a bare-repository layout has no main working tree to return to, so the copy stays where it is, and the confirmation ends with `edits this checkout`. The same note appears when worktree isolation is [turned off](<#how-file-edits-are-isolated>) in a session that isn't inside a linked worktree, because the copy then edits the files you have open.

Sessions started with launch flags the copy wouldn't inherit, such as a replaced system prompt or a `--tools` allowlist, can't be forked; Claude Code says so instead of making a partial copy. A session dispatched from agent view forks normally: the copy is launched with the same [agent definition](<https://code.claude.com/docs/en/sub-agents>) and appended instructions as the session it came from.

#### What carries over when you background

Backgrounding starts a fresh process that resumes from the saved conversation, and in-flight work moves to it: running background shell commands, backgrounded subagents, dynamic workflows, scheduled tasks you created with [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>), and Claude's [automatic replies to artifact comments](<https://code.claude.com/docs/en/artifacts#let-claude-reply-to-comments-on-its-own>) all carry over and keep running there. A subagent moves together with everything it started, so it carries over only when all of that work can move too. To stop in-flight work instead of carrying it over, set the [`CLAUDE_DISABLE_ADOPT=1`](<https://code.claude.com/docs/en/env-vars#variables>) environment variable; Claude Code then asks you to confirm before backgrounding.

When a [dynamic workflow](<https://code.claude.com/docs/en/workflows>) still has subagents running, Claude Code asks before backgrounding with the `Background this session?` dialog, which says how many subagents would restart. Choose `Stay` to let them finish first. If you confirm, Claude Code replays the run in the background session: subagents that were still running start over from the beginning, so the tokens they used so far are spent again. See [Resume after a pause](<https://code.claude.com/docs/en/workflows#resume-after-a-pause>) for which completed subagents return their saved results and which run again.

Claude Code stops work that can't carry over, such as a running [monitor](<https://code.claude.com/docs/en/tools-reference#monitor-tool>), and stops a backgrounded subagent that owns a monitor along with it. When any such work is running, Claude Code shows the `Background this session?` dialog so you can confirm before it stops the work.

Once in the background, the session can start new subagents, monitors, and background commands, and those keep running across later detach and reattach.

Configuration flags from the original launch carry through to the backgrounded session, so its MCP servers, settings, and fallback model remain in effect:

* `--mcp-config` and `--strict-mcp-config`
* `--settings`
* `--setting-sources`
* `--add-dir`
* `--plugin-dir`
* `--fallback-model`
* `--allow-dangerously-skip-permissions`

Directories you added during the session with [`/add-dir`](<https://code.claude.com/docs/en/permissions#additional-directories-grant-file-access-not-configuration>) also carry through. Carrying `--allow-dangerously-skip-permissions` keeps `bypassPermissions` reachable in the backgrounded session, but it doesn't grant anything new: the mode still requires the one-time interactive acceptance described in [Permission mode, model, and effort](<#permission-mode-model-and-effort>).

<span id="from-your-shell" />

### Dispatch an agent from your shell

Pass `--bg` or its long form `--background` to start a session that goes straight to the background:

```bash theme={null}
claude --bg "investigate the flaky SettingsChangeDetector test"
```

The prompt is the positional argument, not a `-p` value. Claude Code rejects `--bg` combined with `-p` or `--print` before any session is created, because `--print` never starts the interactive session that `claude agents` attaches to.

If you run `claude --bg` from a terminal in a directory you haven't [trusted](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>), the workspace trust dialog appears first and the session starts once you accept. If you decline, Claude Code exits without starting a session. Where no dialog can appear, such as in a script, the command exits with a [`Workspace not trusted`](<https://code.claude.com/docs/en/errors#workspace-not-trusted-when-dispatching-a-background-session>) error instead.

To run a specific [subagent](<https://code.claude.com/docs/en/sub-agents>) you have defined, such as a `code-reviewer`, as the session's main agent, combine `--bg` with `--agent`:

```bash theme={null}
claude --agent code-reviewer --bg "address review comments on PR 1234"
```

If the name doesn't match any of your subagents, the launch fails: Claude Code prints a `no agent named` warning and still reports the session as backgrounded, but the session exits immediately with an `--agent '<name>' not found` error.

When the backgrounded session later resumes or restarts, Claude Code restores the agent and its tool restrictions; for its system prompt, see [System prompt flags in resumed conversations](<https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations>). It searches the session's own directory for the agent first, provided you've [trusted that workspace](<https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust>), so a project-scoped agent still loads when the session is resumed from another directory. If the agent no longer exists, the session continues with the default tools and its transcript opens with a [warning naming the agent](<https://code.claude.com/docs/en/errors#session-agent-no-longer-available>).

To continue an existing conversation in the background, pass its full session ID with `--resume`:

```bash theme={null}
claude --resume 1f0e2c9a-6d0b-4c11-9f39-2a77c1d4e8b5 --bg "pick up where you left off and finish the migration"
```

On Claude Code v2.1.257 or later, Claude Code either continues that session under the same ID, or starts a copy under a new ID and prints a `note:` line explaining why it couldn't continue in place. When the session continues in place, `claude agents` shows one row for it.

When you combine `--bg` with `--continue`, a bare `--resume`, or `--resume` with a name or file path, Claude Code always starts such a copy. Add `--fork-session` to start a copy on purpose, without the note.

Pass `--name` to set the session's display name in agent view instead of the auto-generated one:

```bash theme={null}
claude --bg --name "flaky-test-fix" "investigate the flaky SettingsChangeDetector test"
```

After backgrounding, Claude prints the session's short ID and the commands for managing it. When the service that hosts background sessions isn't already running, `--bg` may first print `Starting background service…` above this output. When you pass `--name`, the name appears after the short ID:

```text theme={null}
backgrounded · 7c5dcf5d · flaky-test-fix
  claude agents             list sessions
  claude attach 7c5dcf5d    open in this terminal
  claude logs 7c5dcf5d      show recent output
  claude stop 7c5dcf5d      stop this session
```

#### Run a shell command

To run a shell command as a background job instead of a Claude session, pass `--exec`. The following example runs `pytest -x` as a background job:

```bash theme={null}
claude --bg --exec 'pytest -x'
```

From agent view, dispatch the same kind of job by typing `!` as the first character of the dispatch input: the `!` shows as a prefix, everything after it is the command, and `Enter` starts the job.

The command runs as a PTY-backed job and appears as a row in agent view, with the most recent line of output as its status. A shell job runs the command in place of Claude, so no model is invoked and the output isn't sent to any session.

To see the output, attach to the row, press `Space` to peek without attaching, or run `claude logs <id>` from your shell. The captured output stays in memory and isn't written to disk. The row and its output clean up automatically about five minutes after the command exits, so read it before then if you need the result.

### How file edits are isolated

When you dispatch a background session from agent view or start one with `claude --bg`, the session starts in your working directory. Before editing files, Claude moves the session into an isolated [git worktree](<https://code.claude.com/docs/en/worktrees>) under `.claude/worktrees/`, so parallel sessions can read the same checkout but each writes to its own. Once the session is in its worktree, Claude Code [enforces worktree isolation](<https://code.claude.com/docs/en/worktrees#how-claude-code-enforces-isolation>) for the session and for any subagents it spawns.

Claude skips the worktree when:

* You [moved a session you already had open to the background](<#from-inside-a-session>) with `←` or `/background`. That session keeps editing files where it was already working
* The session is already inside a linked git worktree, whether Claude created it under `.claude/worktrees/` or you created it with `git worktree add` somewhere else
* The file that Claude is editing is inside a linked git worktree, such as one that the session or its subagent created with `git worktree add`
* The working directory isn't a git repository and no [`WorktreeCreate` hook](<https://code.claude.com/docs/en/hooks#worktreecreate>) is configured
* The write is outside the working directory

To turn off worktree isolation for a repository where git worktrees are impractical, set [`worktree.bgIsolation`](<https://code.claude.com/docs/en/settings-reference#worktree-bgisolation>) to `"none"`. Background sessions then edit your working copy directly without moving into a worktree first. Add the setting to the project's `.claude/settings.json`:

```json theme={null}
{
  "worktree": {
    "bgIsolation": "none"
  }
}
```

Outside a git repository, sessions write to the working directory directly and aren't isolated from each other, so avoid dispatching parallel sessions that edit the same files. If you use a different version control system, configure a [`WorktreeCreate` hook](<https://code.claude.com/docs/en/worktrees#non-git-version-control>) and Claude isolates edits the same way it does for git.

When the hook fails in a directory that isn't a git repository, Claude skips isolation for that directory and edits the working directory in place. Inside a git repository, a session that Claude moves into a worktree before editing can't use the `Edit`, `Write`, or `NotebookEdit` tools on the shared checkout until that move happens.

To find a session's worktree path, attach and check its working directory.

A [subagent](<https://code.claude.com/docs/en/sub-agents>) the background session spawns inherits the session's working directory. Once the session is in a worktree, the subagent's file edits land in that worktree rather than in your working copy. To give a subagent its own separate worktree instead, set [`isolation: worktree`](<https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields>) in its frontmatter or pass `isolation: "worktree"` when spawning it.

When a background session has made code changes in a worktree Claude entered, Claude Code instructs Claude to preserve the work before finishing, so it survives if you delete the session and its worktree:

* **Commit and push**: Claude commits without asking, and pushes the branch when the repository has a remote.
* **Draft pull request**: Claude opens one when the task calls for it, and the [`#N` label](<#pull-request-status>) appears on the row.
* **Never**: pushing to `main` or `master`, force-pushing, and merging.
* **Your git instructions take precedence**: if the task, `CLAUDE.md`, or [memory](<https://code.claude.com/docs/en/memory>) says you handle committing or pushing yourself, Claude leaves git to you.

A session editing a checkout it didn't isolate itself still asks before committing or switching branches. This applies when isolation is set to `"none"`, when the worktree move failed, or when the session started inside a worktree that already existed.

Whatever the task, Claude ends the job with a report saying what it did and where the work is: a path, a branch, a pull request, or the answer itself.

#### What deleting a session removes

Delete a session with `Ctrl+X` twice in [agent view](<#organize-the-list>) or with [`claude rm`](<#manage-sessions-from-the-shell>). Except in the kept cases below, the session leaves the list. Its transcript stays on your machine through `claude --resume`, and the removal survives supervisor restarts.

What happens to a worktree Claude created for the session:

* Agent view removes it, including uncommitted changes, so commit what you want to keep first.
* `claude rm` keeps it, along with the session row, when it has uncommitted changes.
* Neither agent view nor `claude rm` removes a worktree that another running session is using or has locked, and deleting again doesn't change that. Claude Code keeps the worktree and the session, and names the kept directory and the reason; in agent view, the session's row shows `not deleted`. Close the other session, then delete again.
* When you delete a session whose worktree has commits that Claude Code can't confirm are saved elsewhere, Claude Code keeps the worktree and the session, and the message names the worktree's branch and how many commits are unpushed. The message also offers the two ways forward: push the commits, or delete again to discard them.

  Commits on a remote don't block the delete. Neither do commits on the local copy of your `origin` remote's default branch, as long as that branch is checked out in your main checkout, the repository directory itself rather than a worktree.

  After that refusal, you choose:

  * To keep the commits, push them, or merge them into that default branch, then delete the session again.
  * To discard them, delete the session again without pushing: press `Ctrl+X` twice on its row in agent view, or run the `claude rm <id> --discard-unpushed` command the refusal printed. This removes the session and the worktree along with its branch, discarding the unpushed commits and any uncommitted changes.

  When you delete again, Claude Code discards only what the refusal showed: if the worktree has gained a commit since, Claude Code keeps it again and shows the updated state.

  When another finished session's records also name the worktree, it stays when you delete again; push the commits, then delete again.
* A worktree git no longer recognizes, for example after `git worktree prune`, doesn't block the delete. Claude Code deletes the session and leaves the directory on disk.
* When git or your [`WorktreeRemove` hook](<https://code.claude.com/docs/en/hooks#worktreeremove>) fails to remove the worktree, Claude Code keeps the worktree and the session, and the message names the cause. For a hook, the message says how it ended, such as `exited 1`, and quotes the start of its stderr. The message also tells you which of these to do next:

  * Delete the session again to remove the directory anyway, by pressing `Ctrl+X` twice on its row in agent view or running the `claude rm <id> --force-remove-worktree <worktree-id>` command that the `claude rm` refusal printed. The worktree's branch stays in the repository.

    Claude Code offers this only when it can confirm all of the following:

    * The directory is one of the repository's linked worktrees under `.claude/worktrees/`
    * Neither the worktree nor a checked-out submodule has uncommitted changes to tracked files
    * No other session's record names it

    When Claude Code can't verify a submodule checkout's state, such as one replaced by a separate git repository, it doesn't offer this either.
  * Fix what stands in the way, such as committing or stashing the uncommitted changes, moving a separate git repository out of the worktree, closing whatever is using the directory, or fixing the hook, then delete the session again.
  * Remove the directory yourself, then delete the session again.

A worktree you created yourself and started the session inside is left in place either way.

A session whose worktree directory belongs to no git repository, because the repository was deleted or a [`WorktreeCreate` hook](<https://code.claude.com/docs/en/hooks#worktreecreate>) created the directory elsewhere, can still be deleted. While files remain in the directory:

* Agent view asks for the same `Ctrl+X` double-press before discarding them. For a hook-created directory it runs your [`WorktreeRemove` hook](<https://code.claude.com/docs/en/hooks#worktreeremove>) instead, and without one it refuses the delete and keeps the session.
* `claude rm` keeps the session and worktree, and names the reason.

Either path keeps a directory that another finished session's records name.

### Set the model

The model name shown in the agent view header is the dispatch default. New sessions you start from the input use this model, which comes from the [`model` setting](<https://code.claude.com/docs/en/settings-reference#model>) in your user settings. Set it by selecting a model in the [`/model` picker](<https://code.claude.com/docs/en/model-config>), or edit the setting directly.

To override the dispatch default for the whole agent view session, pass `--model` when opening agent view. See [Permission mode, model, and effort](<#permission-mode-model-and-effort>).

To change the dispatch default from inside agent view, type `/model` followed by a model name in the dispatch input and press `Enter`. The header updates to show that model with a `(session)` marker, and sessions you dispatch afterward use it. Type `/model default` to clear the override and return to the dispatch default. This override lasts for the rest of the current `claude agents` run and doesn't write to your settings file. The following example dispatches one session on Opus and the next on Sonnet:

```text theme={null}
/model opus
refactor auth
/model sonnet
run the test suite
```

Each background session can run on a different model. To override it for one session:

* From the shell, pass `--model` with `claude --bg`.
* Attach to a running session and run `/model` to switch: a pick from the picker, or a typed `/model <name>`, saves as your default for new sessions unless you press `s` in the picker for a session-only switch. A session-only switch persists if the session is respawned.
* Dispatch a [subagent](<https://code.claude.com/docs/en/sub-agents>) whose frontmatter sets a `model` field.

### Permission mode, model, and effort

A background session takes its settings, provider, permission mode, model, and effort from where and how you dispatched it. The subsections below cover each source, and what persists when the supervisor restarts the session.

#### Settings and provider

A background session reads its [settings](<https://code.claude.com/docs/en/settings>) from the directory it runs in, the same as if you had started `claude` there with the [configuration flags it carried over](<#what-carries-over-when-you-background>). This includes [`env` values](<https://code.claude.com/docs/en/settings-reference#env>) in project settings, so an `ANTHROPIC_MODEL` or provider variable set there applies to every background session in that directory.

A background session also runs with the `PATH` of the shell you dispatched it from, so the commands it runs find the same tools your terminal does. It keeps that shell's cloud provider selection too, such as `CLAUDE_CODE_USE_BEDROCK` or `CLAUDE_CODE_USE_VERTEX`, along with its `ANTHROPIC_DEFAULT_*_MODEL` aliases and any [`CLAUDE_CODE_EXTRA_BODY`](<https://code.claude.com/docs/en/env-vars>) override you exported there.

#### LLM gateway

If you route Claude Code through an [LLM gateway](<https://code.claude.com/docs/en/llm-gateway>), put the gateway variables in a settings file's `env` block rather than exporting them in your shell, and background sessions read them with the rest of their settings. [Set in a settings file](<https://code.claude.com/docs/en/llm-gateway-connect#set-in-a-settings-file>) shows the block and which settings file to use for the credential.

If you export a gateway `ANTHROPIC_BASE_URL` only in your shell instead, it reaches a background session, together with the `ANTHROPIC_CUSTOM_HEADERS` and credential you exported with it, only when the [supervisor](<#the-supervisor-process>) was itself started from a shell that exported the same gateway, and only in these cases:

* You background your own session with `←` or `/background`
* You dispatch a session into the directory you're in
* You wake a stopped session in the directory you're in by attaching or replying to it

Claude Code forwards a gateway in front of a cloud provider. If the shell you dispatch from selects the provider and exports its gateway endpoint with its auth-bypass flag, Claude Code forwards the endpoint-and-flag pair to the session under the conditions that apply to `ANTHROPIC_BASE_URL`, together with `ANTHROPIC_CUSTOM_HEADERS`. For example, export `CLAUDE_CODE_USE_VERTEX=1` with `ANTHROPIC_VERTEX_BASE_URL` and `CLAUDE_CODE_SKIP_VERTEX_AUTH=1`, and Claude Code forwards that endpoint and flag.

Claude Code applies a forwarded gateway to that session's running process only and never writes it to disk.

#### Permission mode

The [permission mode](<https://code.claude.com/docs/en/permissions>) depends on how you started the session:

* **Backgrounded with `/bg` or `←`**: Claude Code keeps the permission mode the session was in, so one you switched to `acceptEdits` or `auto` stays there after detaching
* **Dispatched from an agent view you opened with `←`**: the target's own configuration comes first, and the permission mode of the session you came from applies when nothing else sets one
* **Dispatched from `claude agents` started in a shell, or with `claude --bg`**: the new session starts the way a new `claude` session in that directory would, unless you dispatched it from an agent view you opened with [dispatch defaults](<#dispatch-defaults>). [Which permission mode a session starts in](<https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in>) lists the order

For a session you dispatch from an agent view opened with `←`, Claude Code takes the permission mode from the first of these that applies:

1. The target directory's [`permissions.defaultMode`](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>). Two source rules apply:
   * `auto` and `bypassPermissions` [take effect only from managed settings, a `--settings` file, or `~/.claude/settings.json`](<https://code.claude.com/docs/en/settings-reference#permissions-defaultmode>).
   * Claude Code refuses a `defaultMode` from the project's `.claude/settings.json` or `.claude/settings.local.json` that selects a more permissive mode than the session you came from was in.
2. The permission mode of the session you came from

When Claude Code refuses a source's mode as too permissive, the next source in the list decides. For example, if you dispatch from a plan-mode session into a directory whose checked-in settings ask for `acceptEdits`, the new session starts in plan mode. If you move that `defaultMode` to `~/.claude/settings.json`, it applies regardless of the permission mode of the session you came from.

Permissiveness runs plan, then Manual and `dontAsk`, then `acceptEdits` and auto, which each count as more permissive than the other, then `bypassPermissions`.

#### Dispatch defaults

To set defaults for every session you dispatch from agent view, pass any of `--permission-mode`, `--model`, `--effort`, or `--agent` when opening it:

```bash theme={null}
claude agents --permission-mode plan --model opus --effort high
```

`--effort` here accepts the same values as the [top-level `--effort` flag](<https://code.claude.com/docs/en/cli-reference#cli-flags>), including `ultracode`.

`--agent` sets the [subagent](<https://code.claude.com/docs/en/sub-agents>) used when a dispatch prompt doesn't name one, either with `@name` or as the first word. It defaults to the [`agent` setting](<https://code.claude.com/docs/en/settings-reference#agent>) if one is set, otherwise the built-in catch-all `claude` agent. Naming a subagent in the dispatch input overrides both.

`claude agents` also accepts `--dangerously-skip-permissions` as shorthand for `--permission-mode bypassPermissions`, and `--allow-dangerously-skip-permissions` to make `bypassPermissions` available in each dispatched session's `Shift+Tab` cycle without starting in that mode. Both match the [top-level CLI flags](<https://code.claude.com/docs/en/cli-reference>).

Pass `--restricted` to start every session you dispatch from the view in [restricted mode](<https://code.claude.com/docs/en/cli-reference#cli-flags>), as if each were launched with the top-level `--restricted` flag. Requires Claude Code v2.1.248 or later.

The active defaults appear in the footer below the dispatch input.

Claude Code refuses `claude --bg --permission-mode bypassPermissions` until you've accepted the bypass disclaimer by running `claude --dangerously-skip-permissions` once interactively, since that mode lets a session you aren't watching act without approval. Passing `--dangerously-skip-permissions` or `--permission-mode bypassPermissions` to `claude agents` shows the same disclaimer when you haven't accepted it before, and accepting applies `bypassPermissions` to the sessions you launch from the view. Passing `--allow-dangerously-skip-permissions` shows the same disclaimer too, and accepting makes `bypassPermissions` available in the `Shift+Tab` cycle of those sessions without starting them in it.

#### What persists across restarts

The permission mode, model, and effort you chose for a background session, along with the [configuration flags it carries](<#what-carries-over-when-you-background>), all persist when the supervisor later [stops and restarts](<#the-supervisor-process>) its process. A session you launched with `claude --bg --dangerously-skip-permissions` or `claude --bg --permission-mode bypassPermissions` stays in `bypassPermissions` after that restart. A model or effort you changed mid-session with `/model` or `/effort` is kept too.

If the session took its effort from your settings rather than from `--effort` or `/effort`, Claude Code reads your settings again each time it starts a process for the session. After you edit the saved effort in `settings.json`, the change reaches sessions you background with `←` or `/bg`, and their later restarts. The saved effort is the [`effortLevel`](<https://code.claude.com/docs/en/settings-reference#effortlevel>) key or a [`modelSettings`](<https://code.claude.com/docs/en/settings-reference#modelsettings>) entry.

Claude Code also keeps a name you set with [`/rename`](<https://code.claude.com/docs/en/commands>) or `Ctrl+R` across that restart, so you can still run [`claude --resume <name>`](<https://code.claude.com/docs/en/sessions#name-your-sessions>) to reach the session.

A prompt you stashed with [`Ctrl+S`](<https://code.claude.com/docs/en/interactive-mode#general-controls>) while attached is kept with the session too. Reopen the session after its process was stopped or restarted, and press `Ctrl+S` to restore the stashed text. Pasted content in the stash doesn't survive the restart.

### Settings, plugins, and MCP servers

Agent view accepts the same configuration flags as `claude` for loading settings, plugins, MCP servers, and additional directories. Agent view applies `--settings`, `--setting-sources`, and `--plugin-dir` to itself and passes every configuration flag through to the sessions you dispatch from it, so a plugin or MCP server you load this way is available in those sessions.

| Flag | Effect |
| :- | :- |
| [`--settings <file-or-json>`](<https://code.claude.com/docs/en/settings>) | Override settings for agent view and dispatched sessions |
| [`--setting-sources <sources>`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) | Load only the named settings sources, in agent view and dispatched sessions |
| [`--add-dir <path>`](<https://code.claude.com/docs/en/permissions#additional-directories-grant-file-access-not-configuration>) | Grant file access to an additional directory |
| [`--plugin-dir <path>`](<https://code.claude.com/docs/en/plugins/create#load-a-directory-or-archive-for-one-session>) | Load a plugin from a local directory |
| [`--mcp-config <file-or-json>`](<https://code.claude.com/docs/en/mcp>) | Load MCP servers from a config file or JSON string |
| `--strict-mcp-config` | Use only the MCP servers from `--mcp-config`, ignoring other MCP configuration. See [Exclusive control with managed-mcp.json](<https://code.claude.com/docs/en/managed-mcp#exclusive-control-with-managed-mcp-json>) for what the flag does under a managed MCP file |

Repeat `--add-dir`, `--plugin-dir`, or `--mcp-config` once per value. `claude agents` doesn't support the space-separated form, such as `--add-dir a b c`.

You can place `--settings`, `--setting-sources`, and `--plugin-dir` before or after `agents`. Keep `--add-dir` and `--mcp-config` after `agents`: if you place either before `agents`, [`claude agents --json`](<#manage-sessions-from-the-shell>) fails with an `unknown option` error.

The following example opens agent view with a settings override and one extra directory:

```bash theme={null}
claude agents --settings ./ci-settings.json --add-dir ../shared-lib
```

`--settings` accepts a file path or an inline JSON string. A file path must point to an existing file; Claude Code exits with a `Settings file not found` error if it doesn't.

## Manage sessions from the shell

Every background session has a short ID you can use from the shell. The ID is printed when you start a session with `claude --bg`, and each session's ID is its directory name under `~/.claude/jobs/`. These commands are useful for scripting or when you don't want to open agent view.

| Command | Purpose |
| :- | :- |
| `claude agents` | Open agent view |
| `claude agents --cwd <path>` | Open agent view scoped to sessions started under `<path>` |
| `claude agents --json` | Print sessions as a JSON array and exit. See [List sessions as JSON](<#list-sessions-as-json>) |
| `claude attach <id\|name>` | Attach to a session in this terminal |
| `claude logs <id\|name>` | Print the session's recent output |
| `claude stop <id>` | Stop a session. Also accepts `claude kill` |
| `claude respawn <id>` | Restart a session, running or stopped, e.g. to pick up an updated Claude Code binary. The restarted session resumes its saved conversation; when none is on disk, it runs its original prompt again as a new conversation |
| `claude respawn --all` | Restart every running session, e.g. to move all sessions onto an updated Claude Code binary at once |
| `claude rm <id>` | Remove a session from the list, along with a worktree Claude created for it when that's safe to delete; see [What deleting a session removes](<#what-deleting-a-session-removes>). The conversation transcript stays on your local machine and remains available through `claude --resume` |
| `claude rm <id> --discard-unpushed <commit>@<worktree-id>` | Delete a session whose delete was refused over unpushed commits, discarding the worktree along with its branch and commits. Pass the exact value that refusal printed; see [What deleting a session removes](<#what-deleting-a-session-removes>). Requires v2.1.260 or later |
| `claude rm <id> --force-remove-worktree <worktree-id>` | Delete a session whose delete was refused because git or the `WorktreeRemove` hook couldn't remove its worktree, deleting the worktree directory anyway and leaving its branch in the repository. Pass the exact value that refusal printed; see [What deleting a session removes](<#what-deleting-a-session-removes>). Requires v2.1.268 or later |
| `claude daemon status` | Print the [supervisor's](<#the-supervisor-process>) state, version, socket directory, and worker count |
| `claude daemon logs` | Follow the supervisor's log file, [`~/.claude/daemon.log`](<#where-state-is-stored>), printing new lines as they arrive until you press `Ctrl+C` |
| `claude daemon stop --any` | Stop the supervisor process and the background sessions it hosts. Pass `--keep-workers` to leave background sessions running so the next supervisor reconnects to them. The next `claude agents` or `claude --bg` starts a fresh supervisor |

`claude attach` and `claude logs` can take part of a session's name in place of the ID, as in `claude logs "auth refactor"`. Passing a name requires Claude Code v2.1.290 or later.

### List sessions as JSON

`claude agents --json` prints active sessions as a JSON array and exits: every live session, plus background sessions that are still working or blocked even when their process has exited. Add `--all` to also include completed background sessions, and `--cwd <path>` to limit the list to sessions started under that directory.

Each entry describes one session:

| Field | Present | Description |
| :- | :- | :- |
| `cwd`, `kind`, `startedAt` | Always | The working directory, `interactive` or `background`, and the start time in Unix milliseconds |
| `id` | Background sessions | Short ID, usable with `claude attach`, `claude logs`, and `claude stop` |
| `state` | Background sessions | One of `working`, `blocked`, `done`, `failed`, or `stopped`. See [Read session state from a script](<#read-session-state-from-a-script>) for what each value means |
| `pid`, `status` | While the process is alive | Process ID and one of `busy`, `waiting`, or `idle` |
| `waitingFor` | When `status` is `waiting` | What the session is blocked on: `permission prompt` for an approval, `input needed` for a question from Claude or an MCP server's input request, `sandbox request`, `worker request`, or `dialog open` |
| `sessionId`, `name` | When set | `sessionId` is the full session UUID, usable with [`claude --resume`](<https://code.claude.com/docs/en/sessions>). An interactive session's `name` is its [default display name](<https://code.claude.com/docs/en/sessions#name-your-sessions>) until you name the session or accept a plan in it |

### Read session state from a script

`claude agents --json` is the supported way to read session state from outside Claude Code, for example from a status bar, a scheduler, or another Claude session that supervises background work. Poll `claude agents --json --all`, which keeps listing sessions whose process has exited, and read each entry's `state`, `status`, and `waitingFor`.

| `state` | What it means |
| :- | :- |
| `working` | A turn is running, or the session is between steps of work it drives on its own, such as a [`/loop`](<https://code.claude.com/docs/en/scheduled-tasks>) iteration or a wait on CI. `status` tells you whether its process is `busy` right now |
| `blocked` | The session is waiting on you: a question it asked, a permission or sandbox decision, an error only you can clear such as an expired login, or its first prompt if you started it without one. When the wait is an open prompt in a live process, `waitingFor` names it |
| `done` | The last turn finished what you asked for and the session is ready for your next prompt, whether or not its process is still alive |
| `failed`, `stopped` | The task ended with an error, or the session was stopped |

A session that finished its turn and is waiting for your next instruction reads `done`, not `blocked`. `blocked` always means the session needs something from you before it can continue.

The files under `~/.claude/jobs/<id>/` are not a stable interface. Values that a session or another program writes to `state`, `detail`, `tempo`, or `needs` are replaced on the next update.

If you want a session to report progress in its own words, have it write a file of its own, for example under `$CLAUDE_JOB_DIR/tmp`, instead of editing `state.json`.

## How background sessions are hosted

Claude Code treats every session listed in agent view as a background session, whether or not you're currently attached to it. By contrast, a session started by running `claude` directly is tied to that terminal and ends when it closes, unless you [send it to the background](<#from-inside-a-session>).

To check which kind of session you're in, run [`/status`](<https://code.claude.com/docs/en/commands>). The `Session kind` row reads `background job · attached` or `background job · unattended` in a background session, depending on whether a terminal is attached, and `interactive` in any other session.

### The supervisor process

The supervisor is a background service that runs your background sessions so they keep working after you close agent view or your terminal. Claude Code starts it the first time you background a session or open agent view, and you don't need to manage it yourself.

Each session is its own Claude Code process under the supervisor, and what happens to that process depends on the session's state:

* **Working, paused on a permission prompt or other dialog, or attached**: the process keeps running. A running subagent, workflow, or monitor counts as working, and so does a pending [session-scoped scheduled task](<https://code.claude.com/docs/en/scheduled-tasks>), such as a `/loop` wakeup.
* **Finished or waiting for your next message, and unattached for about an hour**: the supervisor stops the process to free resources. A session that ended its turn by asking you a question counts as waiting for your next message. The conversation stays on disk, and the next time you attach or reply, the session resumes where it left off. Pin a session with `Ctrl+T` to keep its process running.
* **Exited unexpectedly while the supervisor is running**: the supervisor restarts the process. Ending a session you backgrounded yourself with `←` or `/background`, for example with `kill`, marks it stopped instead of restarting it. For sessions that ended with a shutdown, see [Sessions show as failed or stopped after shutdown](<#sessions-show-as-failed-after-shutdown>).
* **After an auto-update**: the supervisor restarts itself onto the new version and moves idle sessions over in the background. Sessions that are working, waiting on you, or attached aren't interrupted.

When a session's process stops or restarts, the background shell commands, dynamic workflows, and background subagents Claude started in it carry over to its next process; running monitors and shell commands a subagent started stop with the process. Deleting the session stops everything it carried over. To stop all of it with the process instead, set [`CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF`](<https://code.claude.com/docs/en/env-vars#variables>) to `1`.

The supervisor and its sessions authenticate with the same stored credentials as your interactive sessions. For which settings and shell variables reach a session, including `PATH`, see [Settings and provider](<#settings-and-provider>). For gateway endpoints, see [LLM gateway](<#llm-gateway>).

### Where state is stored

Session state is stored under your Claude Code config directory. If you set [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>), the supervisor uses that directory instead of `~/.claude` and runs as a separate instance with its own sessions.

| Path | Contents |
| :- | :- |
| `~/.claude/daemon.log` | Supervisor log |
| `~/.claude/daemon/roster.json` | List of running background sessions, used to reconnect after a restart |
| `~/.claude/jobs/<id>/state.json` | Per-session state shown in agent view. Read it through [`claude agents --json`](<#read-session-state-from-a-script>) instead of parsing the file |
| `~/.claude/jobs/<id>/tmp/` | Per-session scratch directory. Claude's `Write` and `Edit` calls here don't prompt for permission. Removed when the session is deleted |

Each background session has the `CLAUDE_JOB_DIR` environment variable set to its `~/.claude/jobs/<id>` directory, so shell commands the session runs can write temporary files to `$CLAUDE_JOB_DIR/tmp` without colliding with parallel sessions.

To inspect this state without reading the files directly, run `claude daemon status`. It reports whether the supervisor is reachable, its process ID and version, the socket directory, and how many background sessions are live.

The command also warns when the running supervisor is on a different version than the `claude` you invoked, which happens after an update the supervisor hasn't restarted into yet. The warning shows both versions and tells you to run `claude daemon stop --any` to pick up the new version. When Claude Code is installed as an OS service, the suggested command is `claude daemon stop` without the flag.

Sessions survive that version mismatch intact: an older Claude Code version that updates a session's `state.json` preserves fields it doesn't recognize and keeps the session listed. The session list in `roster.json` follows the same rule, so sessions started by the newer version stay reachable and keep accepting input after the supervisor restarts.

### Turn off agent view

To turn off background agents and agent view entirely, set the `disableAgentView` [setting](<https://code.claude.com/docs/en/settings>) to `true` or set the `CLAUDE_CODE_DISABLE_AGENT_VIEW` environment variable. Administrators can enforce this through [managed settings](<https://code.claude.com/docs/en/managed-settings>).

## Troubleshooting

### `claude agents` lists subagents instead of opening agent view

If `claude agents` prints a count followed by your configured subagents and then exits, agent view is unavailable in your environment. Run `claude update` to install the latest version.

If agent view still doesn't open after updating, check whether it has been [turned off](<#turn-off-agent-view>) by a setting or environment variable.

### Agent view opens with no sessions

Before you dispatch your first session, agent view shows the empty section headers with a description under each, plus a one-line explanation above the input, in place of the session list. Type a prompt in the input at the bottom and press `Enter` to dispatch your first session.

### Backgrounding shows a `Background this session?` dialog

If you press `←` to background the current session and Claude Code shows a `Background this session?` dialog, the session has in-flight work that backgrounding would stop, restart, or leave running unattended, and Claude Code asks before it does any of those:

* **Work that can't move**: the session has work that can't move to the background session, such as a running [monitor](<https://code.claude.com/docs/en/tools-reference#monitor-tool>). The dialog names the work Claude Code would stop and, separately, counts the tasks that carry over.
* **A workflow with running subagents**: a [dynamic workflow](<https://code.claude.com/docs/en/workflows>) still has subagents running. The workflow itself carries over, but its running subagents restart from the beginning, and the dialog says how many.
* **Automatic artifact replies**: Claude is [replying to comments on an artifact on its own](<https://code.claude.com/docs/en/artifacts#let-claude-reply-to-comments-on-its-own>). Those replies continue in the background session, and the dialog says so.

Run `/tasks` to see everything that's running, then confirm to background anyway or choose `Stay` to let the work finish first. See [What carries over when you background](<#what-carries-over-when-you-background>) for which kinds of work carry over and which Claude Code stops.

### Prompt rejected as too short

The dispatch input expects a task description, not a conversational opener. A prompt shorter than four characters is rejected with a `Too short` hint so a stray keystroke doesn't start a session. Describe what you want the session to do, such as `investigate the flaky checkout test`.

<h3 id="sessions-show-as-failed-after-shutdown">
  Sessions show as failed or stopped after shutdown
</h3>

Shutting down or restarting your machine stops running background sessions. A session that was waiting on your input stays under `Needs input` when you come back. For any other running session, what agent view shows depends on how long ago it last made progress:

* Within 48 hours, the session shows as failed. Attach or reply to it and it restarts from where it left off.
* Past 48 hours, such as after the machine was off for days, the session shows as stopped with `ended while the background service was off`. Press `Enter` on the row and the footer shows `Press enter again to resume this session (it ended while the background service was off), or ctrl+x to delete it.` Press `Enter` on the same row again to resume its saved conversation. A reply, or `claude attach <id>`, resumes it without that footer prompt.

When [transcript cleanup](<https://code.claude.com/docs/en/settings-reference#cleanupperioddays>) has removed a stopped session's saved conversation, Claude Code refuses to open the row: the message says there is nothing to resume. `claude rm <id>` deletes the row, except in the [kept cases](<#what-deleting-a-session-removes>) described above, and `claude respawn <id>` runs its original prompt again. See [This session's saved conversation is no longer on disk](<https://code.claude.com/docs/en/errors#this-sessions-saved-conversation-is-no-longer-on-disk>).

Sleep alone doesn't stop sessions. Sessions are preserved across sleep and the supervisor reconnects to them on wake.

### Opening a session says the conversation is already open

Two processes can't write to the same transcript. When a stopped session's saved conversation is already open in another live Claude Code process, Claude Code refuses to start the session's own process. What you see depends on what holds the conversation:

* A terminal where you resumed the conversation, for example with `claude --resume` or `/resume`: the row shows `Open in a terminal` with a hint to continue it there, and opening the row shows `Can't open — this session is running in another terminal`. Continue in that terminal, or exit it and open the row again.
* Another non-interactive Claude Code process, for example a background session process for the same conversation that hasn't exited yet: opening the row shows `This conversation is already open in another running Claude session`. Use that process, or wait for it to exit and open the row again.

Claude Code saves a reply you typed with the refused attempt, except one prefixed with `!` or `/`, and sends it the next time the session starts.

### Opening a session says it has no saved transcript

When you open a session that you [backgrounded from another conversation](<#from-inside-a-session>) and that stopped before it ran a turn of its own, Claude Code resumes that conversation. If Claude Code can't find the conversation, it refuses to open the session:

* `claude attach` prints `This session has no saved transcript`.
* Agent view shows `Press enter again to restart this session fresh` below the list.

Press `Enter` on the same row again to restart the session with an empty conversation, or run `claude respawn <id>` from the shell.

See the [error reference](<https://code.claude.com/docs/en/errors#this-session-has-no-saved-transcript>) for details.

### The terminal host died or the session stopped responding

The [supervisor](<#the-supervisor-process>) runs each background session's terminal in its own host process. When that process dies or stops responding, Claude Code shows the reason and offers a restart; in both cases the conversation is saved and the restart resumes it. The [error reference](<https://code.claude.com/docs/en/errors#terminal-host-process-died>) quotes the full messages.

Claude Code never restarts a row running a [shell command](<#run-a-shell-command>), from `Enter` or from `claude attach`, because that would run the command again; the row's message and `claude attach` both say the command isn't run again.

### A session fails before starting with a `possibly low memory` note

When a background session's process exits before it finishes starting and the host is low on memory, the row's status names the exit and adds `possibly low memory — free some up and retry`.

The note is a hypothesis, not a confirmed cause. Claude Code adds it only when the process exited silently, without writing an error and without being stopped by a signal, and the host reported low memory at that moment. When the process did write an error before exiting, the row shows that error instead.

Free up memory on the machine, then attach or reply to the row and the supervisor starts a fresh process for the session. When memory stays low, the supervisor also [stops idle sessions](<#the-supervisor-process>) to free resources on its own, and stops idle pinned sessions too if stopping the others freed nothing.

### Agent view says the background service did not respond

If attaching, peeking, or `claude logs` reports that the background service did not respond, the supervisor process has likely stalled. Stop it and let the next `claude agents` start a fresh one. To keep your background sessions running through the restart, pass `--keep-workers`:

```bash theme={null}
claude daemon stop --any --keep-workers
```

The new supervisor reconnects to the running sessions. Without `--keep-workers`, the command ends the background sessions too. The `--any` flag confirms you want to stop a supervisor that started on demand rather than as an installed service, which is the default.

A supervisor that starts but can't accept connections exits and releases its lock on its own, so the next `claude agents` starts a fresh one without this manual stop. The steps above apply when a running supervisor stalls.

If the command instead exits saying the recorded process couldn't be verified as the supervisor, check the reported process ID: if it's a supervisor you own, stop it yourself, then delete `~/.claude/daemon.lock` so the next `claude agents` starts fresh.

On Windows, if the supervisor doesn't respond to the stop request, the command prints its process ID. End that process with `taskkill /PID <pid>` to finish the recovery. Background sessions are still preserved when you passed `--keep-workers`.

### Dispatch fails with `Could not resolve authentication method`

If a background dispatch fails with `Could not resolve authentication method` while interactive sessions authenticate normally, the worker that received the dispatch didn't pick up credentials. Background sessions get their credentials from the [supervisor](<#the-supervisor-process>), so this error means no stored credential was available to the supervisor process itself. Confirm you have run `/login` or configured an API key, then stop the supervisor:

```bash theme={null}
claude daemon stop --any --keep-workers
```

The next `claude agents` or `claude --bg` starts a fresh supervisor that reads your stored credentials. If you authenticate with an environment variable such as `ANTHROPIC_API_KEY` rather than `/login`, run that next command from a shell where the variable is set.

See the [error reference](<https://code.claude.com/docs/en/errors#could-not-resolve-authentication-method>) for the full list of causes and fixes.

### Background sessions can't read Desktop, Documents, or Downloads on macOS

On macOS, the background session host runs as its own process and requests access to protected folders separately from your terminal. If a background session reports `Operation not permitted` when reading `~/Desktop`, `~/Documents`, `~/Downloads`, or another protected location, grant access in System Settings under Privacy & Security > Files and Folders, or enable Full Disk Access for the entry.

With the native installer, the entry appears as Claude Code and the grant persists across updates. With other install methods such as Homebrew or npm, the entry shows the binary path and may need to be granted again after updating.

### Background sessions can't reach local-network hosts on macOS

On macOS 15 and later, the system blocks a process from reaching devices on your local network until you grant Local Network permission, so a command targeting a LAN address can fail with `connect: no route to host` in a background session even though it works in a foreground terminal. The first command in a background session that connects to a local-network address triggers the macOS Local Network permission prompt for Claude Code. Grant it once and those commands reach LAN hosts the same way they do in a foreground terminal.

### A session is slow to respond after attaching

When a session that has finished or is waiting for your next message stays unattached for about an hour, the supervisor stops its process to free resources. Attaching starts a fresh process from where it left off and switches to the session immediately while the process restarts. Sessions that are working, paused on a permission prompt or other dialog, or [pinned](<#organize-the-list>) aren't stopped this way, so pin a session with `Ctrl+T` to keep it responsive.

While the process starts, Claude Code shows the tail of the session's transcript formatted the way the live session renders it, with markdown, highlighted code blocks, and tool calls as dimmed rows, above a dimmed prompt area with a `Session is starting` note. The live session replaces it as soon as it's ready.

### `.claude/worktrees/` is filling up

Deleting a session in agent view removes the worktree Claude created for it, but [some deletes keep the worktree or leave its directory on disk](<#what-deleting-a-session-removes>), so leftover directories can accumulate. Directories git no longer recognizes don't appear in `git worktree list`, so remove those by hand.

List leftover entries with `git worktree list` in the project directory and remove each with `git worktree remove <path>`. See [Clean up worktrees](<https://code.claude.com/docs/en/worktrees#clean-up-worktrees>).

## Limitations

Agent view is in research preview with the following limitations:

* **Rate limits apply**: background sessions consume your subscription usage the same as interactive sessions, so running ten agents in parallel uses quota roughly ten times as fast as running one.
* **Sessions are local**: background sessions run on your machine. They are preserved across sleep but stop if the machine shuts down.
* **Claude-created worktrees are deleted with the session in agent view**: commit changes before deleting a session that edited files in its own worktree. [Some deletes keep the worktree instead](<#what-deleting-a-session-removes>).
