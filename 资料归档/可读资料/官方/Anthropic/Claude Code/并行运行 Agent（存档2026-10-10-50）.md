# 并行运行agents

> 比较 Claude Code 可以同时承担多个任务的方式：子代理、agent 视图、agent 团队、动态工作流程和项目。

Claude Code 有五种方法可以同时处理多项任务：[子代理](<https://code.claude.com/docs/en/sub-agents>)、[agent 视图](<https://code.claude.com/docs/en/agent-view>)、[agent 团队](<https://code.claude.com/docs/en/agent-teams>)、[动态工作流程](<https://code.claude.com/docs/en/workflows>)和[项目](<https://code.claude.com/docs/en/claude-projects>)。它们的不同之处在于您参与的方式，从亲自引导每次对话到让 Claude 协调一组工作人员，以及工作是在您的计算机上还是在云中运行。

|方法|它给你什么|当|
| :- | :- | :- |
|[子代理](<https://code.claude.com/docs/en/sub-agents>)|一个会话中的委派工作人员在自己的上下文中执行一项副任务并返回摘要|副任务会用您不会再次引用的搜索结果、日志或文件内容淹没您的主要对话|
|[Agent 查看](<https://code.claude.com/docs/en/agent-view>)|用于调度和监视在后台运行的会话的一个屏幕，使用 `claude agents` 打开。研究预览|您有几项独立的任务，想要将它们移交，一目了然地查看状态，并仅在有人需要时介入|
|[Agent 队伍](<https://code.claude.com/docs/en/agent-teams>)|具有共享任务列表和 agent 间消息传递的多个协调会话，由领导管理。实验性且默认禁用|您希望 Claude 将项目拆分为多个部分，分配它们，并使工作人员保持同步|
|[项目](<https://code.claude.com/docs/en/claude-projects>)|claude.ai/code 或桌面应用程序中正在进行的一场对话。 Claude 在云中启动称为线程的并行会话，或者当您询问时，通过远程控制在您的计算机上启动，为每个会话提供项目说明，并向您显示哪些会话需要您的帮助。 Pro 和 Max 的公开测试版|这项工作跨越数天或数周的许多任务，应该在计算机关闭时继续运行，并且您宁愿描述一次也不愿分派和跟踪每个会话|
|[动态工作流程](<https://code.claude.com/docs/en/workflows>)|一个运行多个子代理并交叉检查其结果的脚本，适用于工作量太大而无法一次协调一个回合或需要多次传递的情况|一项工作超出了少数子代理的规模，或者您希望相互验证结果：代码库范围内的审计、500 文件迁移、交叉检查研究或从多个角度起草的计划|

在每种方法中，工作人员都是 Claude 会话。要使用不同的工具，请将其作为 [MCP 服务器 ](<https://code.claude.com/docs/en/mcp>) 公开给 Claude。

另外三个工具支持这项工作，但不是运行 agents 本身的方法：

* [Worktrees](<https://code.claude.com/docs/en/worktrees>) 为每个会话提供单独的 git checkout，因此并行会话每个都编辑自己的文件副本。将它们用于您自己运行的会话。您从 agent 视图 [ 调度的会话在编辑文件 ](<https://code.claude.com/docs/en/agent-view#how-file-edits-are-isolated>) 之前会移动到自己的工作树中，并且您生成的子代理也可以分别获得一个。
* [跨会话消息传递 ](<https://code.claude.com/docs/en/cross-session-messaging>) 允许 Claude 列出您在此计算机上、另一台计算机上或 [ 云中 ](<https://code.claude.com/docs/en/claude-code-on-the-web>) 上的其他 Claude Code 会话并发送消息，因此您自己运行的会话可以在它们之间传递结果和状态。
* [`/batch`](<https://code.claude.com/docs/en/commands>) 是一项 [ 技能 ](<https://code.claude.com/docs/en/skills>)，它具有 Claude 将一个大的更改拆分为 5 到 30 工作树隔离的子代理。它是子代理和工作树的打包使用，而不是单独的协调风格。

其他一些功能无需您驱动每个步骤即可运行 Claude，但它们解决的问题与在 agents 之间拆分工作不同：

* [后台 bash 命令](<https://code.claude.com/docs/en/interactive-mode#background-bash-commands>) 运行一个 shell 命令而不阻止对话。它不会生成 agent。
* [分叉子代理](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>)是继承您的完整对话上下文而不是重新开始的子代理。这是一种生成子代理的方法，而不是单独的表面。从 `/subtask` 开始。 Claude 也会在 [ 分叉模式 ](<https://code.claude.com/docs/en/sub-agents#turn-fork-mode-on-or-off>) 开启时生成一个自身。要将整个会话复制到与其一起运行的新 [ 后台会话 ](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>) 中，请使用 `/fork`。当 [agent 视图关闭 ](<https://code.claude.com/docs/en/agent-view#turn-off-agent-view>) 时，forked-subagent 命令为 `/fork`，并且 `/subtask` 不可用。
* [例程](<https://code.claude.com/docs/en/routines>)按计划在云中运行会话，而不是在您的计算机上并行运行。



**注释：**

同时运行多个会话或子代理会增加令牌的使用量。有关使用情况和速率限制的详细信息，请参阅 [ 成本 ](<https://code.claude.com/docs/en/costs>)。


## 选择一种方法

正确的方法取决于谁协调工作、工作人员是否需要沟通以及他们是否编辑相同的文件：

* **谁协调工作？**
  * Claude 在一次对话中委托并收集结果：[子代理](<https://code.claude.com/docs/en/sub-agents>)
  * 您移交独立任务并稍后再检查：[agent 查看](<https://code.claude.com/docs/en/agent-view>)
  * Claude 计划、分配和监督一组工作人员：[agent 团队](<https://code.claude.com/docs/en/agent-teams>)，实验性且默认禁用
  * 脚本保存计划而不是Claude的逐轮判断：[动态工作流程](<https://code.claude.com/docs/en/workflows>)。请参阅[工作流程与子代理和技能的比较](<https://code.claude.com/docs/en/workflows#when-to-use-a-workflow>)
* **工作人员需要互相交谈吗？** Claude 可以在您自己运行的会话之间通过 [ 跨会话消息传递 ](<https://code.claude.com/docs/en/cross-session-messaging>) 传递结果，包括您从 agent 视图分派的会话。子代理将结果报告给生成它们的对话，并且 agent 查看会话仅向您报告结果。 agent 团队中的队友直接互相发送消息，并且当他们 [ 拥有任务工具 ](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>) 时，共享任务列表。
* **任务是否触及相同的文件？**使用[工作树](<https://code.claude.com/docs/en/worktrees>)隔离工作。您自己运行的子代理和会话都可以使用单独的工作树。 Agent 团队不会在工作树中隔离队友，因此 [ 对工作进行分区 ](<https://code.claude.com/docs/en/agent-teams#avoid-file-conflicts>)，以便每个队友拥有一组不同的文件。

## 检查正在运行的工作

检查正在运行的工作的命令取决于您使用的方法：

* 对于后台会话，`claude agents` 打开 [agent 视图 ](<https://code.claude.com/docs/en/agent-view>)：一个屏幕显示每个会话、其状态以及哪些会话需要您的输入。
* 对于当前会话中的子代理，指定的后台子代理会显示在 @-mention typeahead 中及其状态。 `/agents` 命令打印一条指向子代理文件位置的通知。要[创建和编辑自定义子代理](<https://code.claude.com/docs/en/sub-agents#configure-subagents>)，请询问Claude或直接编辑文件。尽管名称相似，但 `/agents` 与 `claude agents` 是分开的。
* 对于当前会话后台运行的任何内容，`/tasks` 列出每个项目并允许您检查、附加或停止它。该列表还包括已完成的子代理。
* 对于动态工作流程，`/workflows` 列出了正在运行和已完成的运行、每个运行所处的阶段以及已完成的 agents 数量。

有关所有会话的桌面视图，请参阅桌面应用程序中的[并行会话](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>)。

# Run agents in parallel

> Compare the ways Claude Code can take on multiple tasks at once: subagents, agent view, agent teams, dynamic workflows, and projects.

Claude Code has five ways to work on several tasks at once: [subagents](<https://code.claude.com/docs/en/sub-agents>), [agent view](<https://code.claude.com/docs/en/agent-view>), [agent teams](<https://code.claude.com/docs/en/agent-teams>), [dynamic workflows](<https://code.claude.com/docs/en/workflows>), and [projects](<https://code.claude.com/docs/en/claude-projects>). They differ in how involved you stay, from steering each conversation yourself to letting Claude coordinate a group of workers, and in whether the work runs on your machine or in the cloud.

| Approach | What it gives you | Use it when |
| :- | :- | :- |
| [Subagents](<https://code.claude.com/docs/en/sub-agents>) | Delegated workers inside one session that do a side task in their own context and return a summary | A side task would flood your main conversation with search results, logs, or file contents you won't reference again |
| [Agent view](<https://code.claude.com/docs/en/agent-view>) | One screen to dispatch and monitor sessions running in the background, opened with `claude agents`. Research preview | You have several independent tasks and want to hand them off, check status at a glance, and step in only when one needs you |
| [Agent teams](<https://code.claude.com/docs/en/agent-teams>) | Multiple coordinated sessions with a shared task list and inter-agent messaging, managed by a lead. Experimental and disabled by default | You want Claude to split a project into pieces, assign them, and keep the workers in sync |
| [Projects](<https://code.claude.com/docs/en/claude-projects>) | One ongoing conversation at claude.ai/code or in the desktop app. Claude starts parallel sessions called threads, in the cloud or, when you ask, on your computer through Remote Control, gives each one the project's instructions, and shows you which ones need you. Public beta on Pro and Max | The work spans many tasks over days or weeks, should keep running when your machine is off, and you'd rather describe it once than dispatch and track each session |
| [Dynamic workflows](<https://code.claude.com/docs/en/workflows>) | A script that runs many subagents and cross-checks their results, for work too big to coordinate one turn at a time or that needs more than a single pass | A job outgrows a handful of subagents, or you want findings verified against each other: a codebase-wide audit, a 500-file migration, cross-checked research, or a plan drafted from several angles |

In every approach the workers are Claude sessions. To involve a different tool, expose it to Claude as an [MCP server](<https://code.claude.com/docs/en/mcp>).

Three more tools support this work without being a way to run agents themselves:

* [Worktrees](<https://code.claude.com/docs/en/worktrees>) give each session a separate git checkout, so parallel sessions each edit their own copy of the files. Use them for sessions you run yourself. A session you dispatch from agent view [moves into a worktree of its own before it edits files](<https://code.claude.com/docs/en/agent-view#how-file-edits-are-isolated>), and subagents you spawn can each get one too.
* [Cross-session messaging](<https://code.claude.com/docs/en/cross-session-messaging>) lets Claude list and message your other Claude Code sessions on this machine, on another machine, or [in the cloud](<https://code.claude.com/docs/en/claude-code-on-the-web>), so sessions you run yourself can pass findings and status between themselves.
* [`/batch`](<https://code.claude.com/docs/en/commands>) is a [skill](<https://code.claude.com/docs/en/skills>) that has Claude split one large change into 5 to 30 worktree-isolated subagents. It's a packaged use of subagents and worktrees, not a separate coordination style.

A few other features run Claude without you driving each step, but they solve a different problem than splitting work across agents:

* A [background bash command](<https://code.claude.com/docs/en/interactive-mode#background-bash-commands>) runs one shell command without blocking the conversation. It doesn't spawn an agent.
* A [forked subagent](<https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation>) is a subagent that inherits your full conversation context instead of starting fresh. It's a way to spawn a subagent, not a separate surface. Start one with `/subtask`. Claude also spawns one itself where [fork mode](<https://code.claude.com/docs/en/sub-agents#turn-fork-mode-on-or-off>) is on. To copy the whole session into a new [background session](<https://code.claude.com/docs/en/agent-view#from-inside-a-session>) that runs alongside it, use `/fork`. With [agent view turned off](<https://code.claude.com/docs/en/agent-view#turn-off-agent-view>), the forked-subagent command is `/fork` instead and `/subtask` isn't available.
* A [routine](<https://code.claude.com/docs/en/routines>) runs a session on a schedule in the cloud, not in parallel on your machine.



**注释：**

  Running several sessions or subagents at once multiplies token usage. See [Costs](<https://code.claude.com/docs/en/costs>) for usage and rate-limit details.


## Choose an approach

The right approach depends on who coordinates the work, whether the workers need to communicate, and whether they edit the same files:

* **Who coordinates the work?**
  * Claude delegates and collects results inside one conversation: [subagents](<https://code.claude.com/docs/en/sub-agents>)
  * You hand off independent tasks and check back later: [agent view](<https://code.claude.com/docs/en/agent-view>)
  * Claude plans, assigns, and supervises a group of workers: [agent teams](<https://code.claude.com/docs/en/agent-teams>), experimental and disabled by default
  * A script holds the plan instead of Claude's turn-by-turn judgment: [dynamic workflows](<https://code.claude.com/docs/en/workflows>). See [how workflows compare to subagents and skills](<https://code.claude.com/docs/en/workflows#when-to-use-a-workflow>)
* **Do the workers need to talk to each other?** Claude can pass findings with [cross-session messaging](<https://code.claude.com/docs/en/cross-session-messaging>) between sessions you run yourself, including the sessions you dispatch from agent view. Subagents report results back to the conversation that spawned them, and agent view sessions report results only to you. Teammates in an agent team message each other directly and, when they [have the Task tools](<https://code.claude.com/docs/en/tools-reference#task-tool-availability>), share a task list.
* **Do the tasks touch the same files?** Isolate the work with [worktrees](<https://code.claude.com/docs/en/worktrees>). Subagents and sessions you run yourself can each use a separate worktree. Agent teams don't isolate teammates in worktrees, so [partition the work](<https://code.claude.com/docs/en/agent-teams#avoid-file-conflicts>) so each teammate owns a different set of files.

## Check on running work

The command for checking on running work depends on which approach you used:

* For background sessions, `claude agents` opens [agent view](<https://code.claude.com/docs/en/agent-view>): one screen showing every session, its state, and which ones need your input.
* For subagents in the current session, named background subagents appear in the @-mention typeahead with their status. The `/agents` command prints a notice pointing to the subagent file locations. To [create and edit custom subagents](<https://code.claude.com/docs/en/sub-agents#configure-subagents>), ask Claude or edit the files directly. Despite the similar name, `/agents` is separate from `claude agents`.
* For anything running in the background of the current session, `/tasks` lists each item and lets you check on, attach to, or stop it. The list also includes subagents that have finished.
* For dynamic workflows, `/workflows` lists running and completed runs, the phase each is in, and how many agents have finished.

For a desktop view of all your sessions, see [parallel sessions in the desktop app](<https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions>).

## Learn more

Each guide below covers setup and configuration for one approach:

* [Create custom subagents](<https://code.claude.com/docs/en/sub-agents>): define reusable specialists and control which tools they can use.
* [Manage agents with agent view](<https://code.claude.com/docs/en/agent-view>): dispatch sessions, watch their state, and attach when one needs you.
* [Orchestrate agent teams](<https://code.claude.com/docs/en/agent-teams>): set up a lead and teammates, assign tasks, and review their work.
* [Orchestrate dynamic workflows](<https://code.claude.com/docs/en/workflows>): run a bundled workflow or have Claude write one that runs many subagents and verifies their findings against each other.
* [Run parallel sessions with worktrees](<https://code.claude.com/docs/en/worktrees>): start Claude in an isolated checkout, control what gets copied in, and clean up afterward.
