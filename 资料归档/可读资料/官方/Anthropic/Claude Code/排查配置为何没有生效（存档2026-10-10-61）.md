# 调试您的配置

> 诊断为什么CLAUDE.md、设置、挂钩、MCP服务器或技能不生效。使用 /context、/doctor、/hooks 和 /mcp 查看实际加载的内容。

当 Claude 忽略指令或您配置的功能未出现时，原因通常是文件未加载，它从与您预期不同的位置加载，或者另一个文件覆盖了它。本指南展示了如何检查实际加载的 Claude Code 内容，以便您可以缩小适用范围。

有关安装、身份验证和连接问题，请参阅 [安装和登录疑难解答 ](<https://code.claude.com/docs/en/troubleshoot-install>)。

## 查看加载到上下文中的内容

`/context` 命令显示占用当前会话上下文窗口的所有内容，按类别细分：系统提示符、系统工具、MCP 工具、自定义子代理及其加载源、内存文件、技能和对话消息。首先运行它以确认您的 `CLAUDE.md`、规则或技能描述是否存在。 `/context`中的技能部分还包括[捆绑技能](<https://code.claude.com/docs/en/skills#bundled-skills>)，`/skills`未列出。

有关特定类别的详细信息，请使用专用命令进行跟踪：

|命令|演出|
| :- | :- |
| `/memory` |跨用户和项目范围的内存文件位置，可以选择在编辑器中打开每个文件，还可以访问自动内存文件夹和自动内存切换|
| `/skills` |来自项目、用户和插件来源的可用技能|
| `/hooks` |主动挂钩配置|
| `/mcp` |已连接的MCP服务器及其状态|
| `/permissions` |解决了当前有效的允许和拒绝规则|
| `/doctor` |安装检查：安装运行状况、无效的设置文件、未使用的扩展、同一目录中重复的 [ 子代理 ](<https://code.claude.com/docs/en/sub-agents>) 名称以及签入的 `CLAUDE.md` 内容 Claude 可以从代码库中派生，并提供建议的修复|
| `/debug [issue]` |启用会话的调试日志记录并提示 Claude 使用日志输出和设置路径进行诊断|
| `/status` |活动设置来源，包括托管设置是否有效|

如果 `/context` 细分中缺少内存文件，请根据 [CLAUDE.md 文件加载 ](<https://code.claude.com/docs/en/memory#how-claude-md-files-load>) 的方式检查其位置。子目录 `CLAUDE.md` 文件按需加载，而不是在会话开始时加载，因此它们不会出现在该细分中。

如果 `/context` 确认文件已加载，但 Claude 仍未遵循特定指令，则问题可能在于指令的编写方式而不是是否加载。 CLAUDE.md 非常适合为新队友提供各种指导，例如项目约定、构建命令以及文件所属位置。

当指令模糊到足以解释多种方式时，当两个文件给出相互冲突的方向时，或者当文件变得足够长以至于单个规则受到较少关注时，遵守率就会下降。 [编写有效的说明](<https://code.claude.com/docs/en/memory#write-effective-instructions>)涵盖了保持高依从性的特异性、大小和结构模式。



**注释：**

CLAUDE.md 和权限解决不同的问题。 CLAUDE.md 告诉 Claude 你的项目如何运作，以便它做出正确的决策。 [权限](<https://code.claude.com/docs/en/permissions>)和[挂钩](<https://code.claude.com/docs/en/hooks>)强制执行限制，无论Claude如何决定。使用 CLAUDE.md 表示“我们在这里这样做”。使用权限或挂钩来确定安全边界以及任何绝对不能发生的事情，在这些情况下您需要保证而不是指导。


## 检查已解决的设置

设置跨托管、用户、项目和本地范围进行合并。如果存在托管设置，则首先应用。其中，较近的范围优先于较宽的范围，顺序是本地、项目、用户。某些设置也可以通过命令行标志或[环境变量](<https://code.claude.com/docs/en/env-vars>)来设置，它们充当另一个覆盖层。当某个设置似乎不适用时，您设置的值通常会被另一个作用域或环境变量覆盖。

要查找无效的设置文件，请从终端运行 `claude doctor`。它无需启动会话即可打印只读安装和设置诊断信息。要进行全面检查，并在应用修复之前提出修复建议和询问，请在会话中运行 [`/doctor`](<https://code.claude.com/docs/en/commands#all-commands>)。

运行 `/status` 以查看哪些设置源处于活动状态，包括托管设置是否有效。要了解 Claude Code 用于给定密钥的范围，请参阅 [ 设置优先级 ](<https://code.claude.com/docs/en/settings#settings-precedence>)。

## 检查MCP服务器

运行 `/mcp` 以查看每个已配置的服务器、其连接状态以及您是否已批准将其用于当前项目。服务器可以正确定义，但由于以下几个常见原因仍然无法提供工具：

* `.mcp.json` 中的项目范围服务器需要一次性批准。如果提示被忽略，服务器将保持禁用状态，直到您从 `/mcp` 批准它。
* 无法启动的服务器在 `/mcp` 中显示为失败。 `command` 或 `args` 中的相对文件路径是一个常见原因，因为它们根据您启动 Claude Code 的目录而不是 `.mcp.json` 的位置进行解析。
* 显示为已连接但列出零个工具的服务器已成功启动，但未返回工具列表。从`/mcp`中选择**重新连接**。如果计数保持为零，请运行 `claude --debug=mcp` 并在 `~/.claude/debug/<session-id>.txt` 的调试日志中读取服务器的 stderr。

有关配置位置和范围规则，请参阅[MCP](<https://code.claude.com/docs/en/mcp>)。

## 检查挂钩

运行 `/hooks` 以列出为当前会话注册的每个挂钩，并按事件分组。如果您定义的挂钩没有出现，则 Claude Code 未加载它。检查这些原因：

* 该钩子是在独立文件中定义的。挂钩位于 [ 设置文件 ](<https://code.claude.com/docs/en/settings#settings-files>) 中的 `"hooks"` 键下。
* `matcher` 值是一个数组而不是单个字符串。当您启动交互式会话并在 `claude doctor` 中时，Claude Code 将该条目列为无效设置。如果数组位于 `PreToolUse` 或 `PermissionRequest` 下，则该文件的其他挂钩都不会加载。

如果钩子出现但没有触发，则通常是由匹配器引起的。检查一下是否有这些错误：

* `matcher` 字段是使用 `|` 匹配多个工具名称的单个字符串，例如 `"Edit|Write"`。 `,` 分隔符是等效的，因此 `"Edit,Write"` 匹配相同的工具。在 v2.1.191 之前，正则表达式评估中出现了逗号，并且匹配器从未匹配，因此如果您尚未使用 v2.1.191，请使用 `|`。
* 拼写错误的工具名称会生成一个不匹配任何内容的匹配器，因此钩子会默默地失败。

当您编辑 `settings.json` 时，更改会在短暂的文件稳定性延迟后在正在运行的会话中生效，即使您在会话启动后创建文件或项目的 `.claude/` 文件夹本身也是如此。您不需要重新启动。在 v2.1.257 之前，Claude Code 未检测到会话开始后创建的 `.claude/` 文件夹中的编辑。

如果保存几秒后 `/hooks` 仍然显示旧定义，请再次运行 `/hooks` 刷新视图。

如果 `/hooks` 显示钩子但仍然不触发，下一步是观看钩子实时评估。使用 `claude --debug` 启动会话并触发工具调用。调试日志记录每个事件、检查了哪些匹配器以及挂钩的退出代码和输出。请参阅 [调试挂钩 ](<https://code.claude.com/docs/en/hooks#debug-hooks>) 了解日志格式，并参阅 [挂钩故障排除 ](<https://code.claude.com/docs/en/hooks-guide#limitations-and-troubleshooting>) 了解常见故障模式。

## 针对干净的配置进行测试

从 [`claude --safe-mode`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 开始，这将启动一个禁用自定义的会话，包括：

* `CLAUDE.md`
* 技能、插件和挂钩
* MCP 服务器
* 自定义命令和agents
* 自定义输出样式
* 自定义按键绑定

认证、模型选择、内置工具、权限工作正常。如果问题在安全模式下消失，则说明您已将原因缩小到您关闭的一项。要找到它，请使用对该项目的检查，例如 [查看加载到上下文中的内容](<#查看加载到上下文中的内容>)、[检查MCP服务器](<#检查mcp服务器>)或[检查挂钩](<#检查挂钩>)。

安全模式仍会应用组织中的托管挂钩和设置策略。托管插件、技能、`CLAUDE.md` 和 MCP 服务器已关闭。

如果问题在安全模式下仍然存在，或者您的设置本身值得怀疑，请与不从常用设置加载任何内容的会话进行比较。将 [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>) 指向空目录以绕过 `~/.claude` 下的所有内容，并从没有 `.claude` 文件夹、`.mcp.json` 或 `CLAUDE.md` 的目录启动，因此项目配置也会被跳过。

```bash theme={null}
cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude
```

干净的会话没有用户或项目设置、挂钩、MCP 服务器、插件或内存。首次启动时，预计会出现首次运行设置屏幕，从主题选择开始。如果您看到它们，则说明干净的配置目录已生效。稍后使用相同目录启动时会跳过这些屏幕，因为 Claude Code 会在那里保存登录状态。

* 如果您的组织部署了托管设置，则它们仍然适用。 Claude Code 从配置目录外部的位置读取 MDM 配置文件、注册表策略和 `managed-settings.json`，并且 [ 在拥有凭据后再次为干净会话获取服务器管理的设置 ](<https://code.claude.com/docs/en/server-managed-settings#fetch-and-caching-behavior>)
* 系统会提示您重新登录

如果问题在这里消失，则原因在于您的真实 `~/.claude` 或项目 `.claude` 文件中的某个位置。通过将文件复制到临时目录或从项目启动来查找是哪一个，一次重新引入它们。如果它在清理会话中仍然存在，则原因在于您的用户和项目配置之外。运行 `/status` 检查托管设置是否生效，查找影响 Claude Code 的 [ 环境变量 ](<https://code.claude.com/docs/en/env-vars>)，然后参阅 [ 故障排除 ](<https://code.claude.com/docs/en/troubleshooting>)。

## 检查常见原因

大多数配置惊喜都可以追溯到一小组位置和语法规则。在假设错误之前检查这些：

|症状|原因|修复|
| :- | :- | :- |
|钩子永远不会开火|`matcher` 是一个 JSON 数组而不是字符串|使用带有 `\|` 的单个字符串来匹配多个工具，例如 `"Edit\|Write"`。请参阅[匹配器模式](<https://code.claude.com/docs/en/hooks#matcher-patterns>)。|
|钩子永远不会开火|`matcher` 在 v2.1.191 之前的版本上使用 `,` 作为分隔符|Claude Code v2.1.191 或更高版本将 `,` 视为列表分隔符，如 `\|`。早期版本将逗号视为文字字符，因此 `"Edit,Write"` 不匹配任何内容。请改用`\|`，或升级Claude Code。|
|钩子永远不会开火|`matcher` 值为小写，例如 `"bash"`|匹配区分大小写。工具名称大写：`Bash`、`Edit`、`Write`、`Read`。|
|钩子永远不会开火|挂钩在独立文件中定义，而不是在 `settings.json` 中|项目或用户配置没有独立的挂钩文件。在`settings.json`中的`"hooks"`键下定义钩子。只有[插件](<https://code.claude.com/docs/en/plugins/components#hooks>)加载单独的`hooks/hooks.json`。参见[挂钩配置](<https://code.claude.com/docs/en/hooks>)。|
|全局设置的权限或挂钩将被忽略|配置已添加到`~/.claude.json`|`~/.claude.json` 保存应用程序状态，UI 切换。 `permissions`、`hooks` 和 `env` 属于 `~/.claude/settings.json`。这是两个不同的文件。|
|`settings.json` 值似乎被忽略|在`settings.local.json`中设置相同的密钥|`settings.local.json` 覆盖 `settings.json`，并且两者都覆盖 `~/.claude/settings.json`。请参阅[设置优先级](<https://code.claude.com/docs/en/settings#settings-precedence>)。|
|技能未出现在`/skills`中|技能文件位于`.claude/skills/name.md`而不是文件夹中|使用里面有`SKILL.md`的文件夹：`.claude/skills/name/SKILL.md`。|
|技能出现在`/skills`中，但Claude从未调用过它|技能的 frontmatter 中有 `disable-model-invocation: true`，或者其描述与您的请求措辞不符|检查 `/skills` 中的徽章：“仅限用户”标签意味着 Claude 不会自行触发它。参见[技能调用](<https://code.claude.com/docs/en/skills>)。|
|子目录 `CLAUDE.md` 指令似乎被忽略|子目录文件按需加载，而不是在会话开始时加载|子目录文件加载时参见[](<https://code.claude.com/docs/en/memory#how-claude-md-files-load>)。在v2.1.288之前，只有读取工具加载它们。|
|子代理忽略 `CLAUDE.md` 指令|内置探索和计划 agents 跳过 `CLAUDE.md`。自定义子代理以与主对话相同的方式加载它，除非其定义设置了 [`omitClaudeMd`](<https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields>)|对于“探索”或“计划”，请重述委派提示中的说明。对于设置 `omitClaudeMd` 的子代理，请删除该字段。对于任何其他自定义子代理，请将关键指令放入 agent 文件正文中，该文件正文将成为 agent 的系统提示符。请参阅[启动时加载的内容](<https://code.claude.com/docs/en/sub-agents#what-loads-at-startup>)。|
|清理逻辑永远不会在会话结束时运行|未配置 `SessionEnd` 挂钩|在`settings.json`中添加`SessionEnd`钩子。请参阅[挂钩事件列表](<https://code.claude.com/docs/en/hooks#hook-events>)。|
|MCP `.mcp.json` 中的服务器永远不会加载|文件位于 `.claude/` 下，或其服务器位于顶级 `servers` 密钥下，如 VS Code 的 `mcp.json`，而不是 `mcpServers`|项目 MCP 配置位于存储库根目录中，作为 `.mcp.json`，而不是在 `.claude/` 内，服务器位于 `mcpServers` 键下。参见[MCP配置](<https://code.claude.com/docs/en/mcp>)。|
|`settings.json` 中的 `mcpServers` 下添加的 MCP 服务器永远不会出现|`settings.json` 未读取 `mcpServers` 密钥|在存储库根目录的 `.mcp.json` 中定义项目服务器，或为用户范围的服务器运行 `claude mcp add --scope user`。参见[MCP配置](<https://code.claude.com/docs/en/mcp>)。|
|项目 MCP 服务器已添加但未出现|一次性批准提示被驳回|项目范围的服务器需要批准。运行 `/mcp` 查看状态并批准。|
|MCP服务器无法从某些目录启动|`command` 或 `args` 使用相对文件路径|对本地脚本使用绝对路径。 `PATH` 上的可执行文件（例如 `npx` 或 `uvx`）按原样工作。|
|MCP 服务器启动时没有预期的环境变量|服务器的配置条目没有设置它们，并且它们不在环境中Claude Code传递给stdio服务器：它自己的环境，减去它从子进程中删除的[变量](<https://code.claude.com/docs/en/monitoring-usage#administrator-configuration>)|在服务器的 `.mcp.json` 条目内设置每个服务器 `env`，这不依赖于启动环境或工作区信任。|
|`Bash(rm *)` 拒绝规则不会阻止 `/bin/rm` 或 `find -delete`|Bash 规则匹配文字命令字符串，而不是底层可执行文件；请参阅 [Bash 规则不匹配的内容 ](<https://code.claude.com/docs/en/permissions#bash-rule-limits>)|使用 [PreToolUse 挂钩 ](<https://code.claude.com/docs/en/hooks-guide>) 或 [ 沙箱 ](<https://code.claude.com/docs/en/sandboxing>) 进行硬保证。|

# Debug your configuration

> Diagnose why CLAUDE.md, settings, hooks, MCP servers, or skills aren't taking effect. Use /context, /doctor, /hooks, and /mcp to see what actually loaded.

When Claude ignores an instruction or a feature you configured doesn't appear, the cause is usually that the file didn't load, it loaded from a different location than you expected, or another file overrode it. This guide shows how to inspect what Claude Code actually loaded so you can narrow down which applies.

For installation, authentication, and connectivity problems, see [Troubleshoot installation and login](<https://code.claude.com/docs/en/troubleshoot-install>) instead.

## See what loaded into context

The `/context` command shows everything occupying the context window for the current session, broken down by category: system prompt, system tools, MCP tools, custom subagents with the source each loaded from, memory files, skills, and conversation messages. Run it first to confirm whether your `CLAUDE.md`, rules, or skill descriptions are present at all. The skills section in `/context` also includes [bundled skills](<https://code.claude.com/docs/en/skills#bundled-skills>), which `/skills` doesn't list.

For detail on a specific category, follow up with the dedicated command:

| Command | Shows |
| :- | :- |
| `/memory` | Memory file locations across user and project scopes with the option to open each in your editor, plus access to the auto memory folder and the auto memory toggle |
| `/skills` | Available skills from project, user, and plugin sources |
| `/hooks` | Active hook configurations |
| `/mcp` | Connected MCP servers and their status |
| `/permissions` | Resolved allow and deny rules currently in effect |
| `/doctor` | Setup checkup: installation health, invalid settings files, unused extensions, duplicate [subagent](<https://code.claude.com/docs/en/sub-agents>) names in the same directory, and checked-in `CLAUDE.md` content Claude can derive from the codebase, with proposed fixes |
| `/debug [issue]` | Enables debug logging for the session and prompts Claude to diagnose using the log output and settings paths |
| `/status` | Active settings sources, including whether managed settings are in effect |

If a memory file is missing from the `/context` breakdown, check its location against [how CLAUDE.md files load](<https://code.claude.com/docs/en/memory#how-claude-md-files-load>). Subdirectory `CLAUDE.md` files load on demand rather than at session start, so they don't appear in that breakdown.

If `/context` confirms the file loaded but Claude still isn't following a particular instruction, the issue is likely how the instruction is written rather than whether it loaded. CLAUDE.md works well for the kinds of guidance you'd give a new teammate, such as project conventions, build commands, and where files belong.

Adherence drops when an instruction is vague enough to interpret multiple ways, when two files give conflicting direction, or when the file has grown long enough that individual rules get less attention. [Write effective instructions](<https://code.claude.com/docs/en/memory#write-effective-instructions>) covers the specificity, size, and structure patterns that keep adherence high.



**注释：**

  CLAUDE.md and permissions solve different problems. CLAUDE.md tells Claude how your project works so it makes good decisions. [Permissions](<https://code.claude.com/docs/en/permissions>) and [hooks](<https://code.claude.com/docs/en/hooks>) enforce limits regardless of what Claude decides. Use CLAUDE.md for "we do it this way here." Use permissions or hooks for security boundaries and anything that must never happen, where you need a guarantee instead of guidance.


## Check resolved settings

Settings merge across managed, user, project, and local scopes. Managed settings apply first when present. Among the rest, the closer scope overrides the broader one in the order local, then project, then user. Some settings can also be set by command-line flags or [environment variables](<https://code.claude.com/docs/en/env-vars>), which act as another override layer. When a setting doesn't seem to apply, the value you set is usually being overridden by another scope or an environment variable.

To find invalid settings files, run `claude doctor` from your terminal. It prints read-only installation and settings diagnostics without starting a session. For a full checkup that also proposes fixes and asks before applying them, run [`/doctor`](<https://code.claude.com/docs/en/commands#all-commands>) inside a session.

Run `/status` to see which settings sources are active, including whether managed settings are in effect. To understand which scope Claude Code uses for a given key, see [Settings precedence](<https://code.claude.com/docs/en/settings#settings-precedence>).

## Check MCP servers

Run `/mcp` to see every configured server, its connection status, and whether you have approved it for the current project. A server can be defined correctly but still not provide tools for a few common reasons:

* Project-scoped servers in `.mcp.json` require a one-time approval. If the prompt was dismissed, the server stays disabled until you approve it from `/mcp`.
* A server that fails to start shows as failed in `/mcp`. Relative file paths in `command` or `args` are a frequent cause, since they resolve against the directory you launched Claude Code from rather than the location of `.mcp.json`.
* A server that shows as connected but lists zero tools has started successfully but isn't returning a tool list. Select **Reconnect** from `/mcp`. If the count stays at zero, run `claude --debug=mcp` and read the server's stderr in the debug log at `~/.claude/debug/<session-id>.txt`.

For configuration locations and scope rules, see [MCP](<https://code.claude.com/docs/en/mcp>).

## Check hooks

Run `/hooks` to list every hook registered for the current session, grouped by event. If a hook you defined doesn't appear, Claude Code didn't load it. Check for these causes:

* The hook is defined in a standalone file. Hooks go under the `"hooks"` key in a [settings file](<https://code.claude.com/docs/en/settings#settings-files>).
* The `matcher` value is an array instead of a single string. Claude Code lists the entry as an invalid setting when you start an interactive session and in `claude doctor`. If the array is under `PreToolUse` or `PermissionRequest`, none of that file's other hooks load either.

If the hook appears but doesn't fire, the matcher is the usual cause. Check it for these mistakes:

* The `matcher` field is a single string that uses `|` to match multiple tool names, for example `"Edit|Write"`. A `,` separator is equivalent, so `"Edit,Write"` matches the same tools. Before v2.1.191, a comma fell through to regex evaluation and the matcher never matched, so use `|` if you aren't on v2.1.191 yet.
* A misspelled tool name produces a matcher that matches nothing, so the hook fails silently.

When you edit `settings.json`, the change takes effect in the running session after a brief file-stability delay, even if you create the file or the project's `.claude/` folder itself after the session started. You don't need to restart. Before v2.1.257, Claude Code didn't detect edits in a `.claude/` folder created after the session started.

If `/hooks` still shows the old definition a few seconds after you save, run `/hooks` again to refresh the view.

If `/hooks` shows the hook but it still does not fire, the next step is to watch hook evaluation live. Start a session with `claude --debug` and trigger the tool call. The debug log records each event, which matchers were checked, and the hook's exit code and output. See [Debug hooks](<https://code.claude.com/docs/en/hooks#debug-hooks>) for the log format and [hooks troubleshooting](<https://code.claude.com/docs/en/hooks-guide#limitations-and-troubleshooting>) for common failure patterns.

## Test against a clean configuration

Start with [`claude --safe-mode`](<https://code.claude.com/docs/en/cli-reference#cli-flags>), which launches a session with your customizations disabled, including:

* `CLAUDE.md`
* Skills, plugins, and hooks
* MCP servers
* Custom commands and agents
* Custom output styles
* Custom keybindings

Authentication, model selection, built-in tools, and permissions work normally. If the problem disappears in safe mode, you've narrowed the cause to one of the items you turned off. To find it, use the check for that item, such as [See what loaded into context](<#see-what-loaded-into-context>), [Check MCP servers](<#check-mcp-servers>), or [Check hooks](<#check-hooks>).

Safe mode still applies managed hooks and settings policy from your organization. Managed plugins, skills, `CLAUDE.md`, and MCP servers are turned off.

If the problem persists in safe mode, or your settings themselves are suspect, compare against a session that loads nothing from your usual setup. Point [`CLAUDE_CONFIG_DIR`](<https://code.claude.com/docs/en/env-vars>) at an empty directory to bypass everything under `~/.claude`, and launch from a directory that has no `.claude` folder, `.mcp.json`, or `CLAUDE.md` so project configuration is also skipped.

```bash theme={null}
cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude
```

The clean session has no user or project settings, hooks, MCP servers, plugins, or memory. On the first launch, expect the first-run setup screens, starting with theme selection. If you see them, the clean configuration directory is in effect. Later launches with the same directory skip these screens because Claude Code saves onboarding state there.

* Managed settings still apply if your organization deploys them. Claude Code reads MDM profiles, registry policy, and `managed-settings.json` from locations outside the configuration directory, and [fetches server-managed settings](<https://code.claude.com/docs/en/server-managed-settings#fetch-and-caching-behavior>) again for the clean session once it has credentials
* You'll be prompted to log in again

If the problem disappears here, the cause is somewhere in your real `~/.claude` or project `.claude` files. Reintroduce them one at a time, by copying files into the temporary directory or by launching from your project, to find which one. If it persists in the clean session, the cause is outside your user and project configuration. Run `/status` to check whether managed settings are in effect, look for [environment variables](<https://code.claude.com/docs/en/env-vars>) that affect Claude Code, then see [Troubleshooting](<https://code.claude.com/docs/en/troubleshooting>).

## Check common causes

Most configuration surprises trace back to a small set of location and syntax rules. Check these before assuming a bug:

| Symptom | Cause | Fix |
| :- | :- | :- |
| Hook never fires | `matcher` is a JSON array instead of a string | Use a single string with `\|` to match multiple tools, for example `"Edit\|Write"`. See [matcher patterns](<https://code.claude.com/docs/en/hooks#matcher-patterns>). |
| Hook never fires | `matcher` uses `,` as a separator on a version before v2.1.191 | Claude Code v2.1.191 or later treats `,` as a list separator like `\|`. Earlier versions evaluate a comma as a literal character, so `"Edit,Write"` matches nothing. Use `\|` instead, or upgrade Claude Code. |
| Hook never fires | `matcher` value is lowercase, for example `"bash"` | Matching is case-sensitive. Tool names are capitalized: `Bash`, `Edit`, `Write`, `Read`. |
| Hook never fires | Hooks are defined in a standalone file instead of `settings.json` | There is no standalone hooks file for project or user config. Define hooks under the `"hooks"` key in `settings.json`. Only [plugins](<https://code.claude.com/docs/en/plugins/components#hooks>) load a separate `hooks/hooks.json`. See [hook configuration](<https://code.claude.com/docs/en/hooks>). |
| Permissions or hooks set globally are ignored | Configuration was added to `~/.claude.json` | `~/.claude.json` holds app state and UI toggles. `permissions`, `hooks`, and `env` belong in `~/.claude/settings.json`. These are two different files. |
| A `settings.json` value seems ignored | The same key is set in `settings.local.json` | `settings.local.json` overrides `settings.json`, and both override `~/.claude/settings.json`. See [settings precedence](<https://code.claude.com/docs/en/settings#settings-precedence>). |
| Skill doesn't appear in `/skills` | Skill file is at `.claude/skills/name.md` instead of in a folder | Use a folder with `SKILL.md` inside: `.claude/skills/name/SKILL.md`. |
| Skill appears in `/skills` but Claude never invokes it | Skill has `disable-model-invocation: true` in its frontmatter, or its description doesn't match how you phrase the request | Check the badge in `/skills`: a "user-only" label means Claude won't trigger it on its own. See [skill invocation](<https://code.claude.com/docs/en/skills>). |
| Subdirectory `CLAUDE.md` instructions seem ignored | Subdirectory files load on demand, not at session start | See [when subdirectory files load](<https://code.claude.com/docs/en/memory#how-claude-md-files-load>). Before v2.1.288, only the Read tool loaded them. |
| Subagent ignores `CLAUDE.md` instructions | The built-in Explore and Plan agents skip `CLAUDE.md`. A custom subagent loads it the same way the main conversation does, unless its definition sets [`omitClaudeMd`](<https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields>) | For Explore or Plan, restate the instruction in your delegating prompt. For a subagent that sets `omitClaudeMd`, remove the field. For any other custom subagent, put critical instructions in the agent file body, which becomes the agent's system prompt. See [what loads at startup](<https://code.claude.com/docs/en/sub-agents#what-loads-at-startup>). |
| Cleanup logic never runs at session end | No `SessionEnd` hook configured | Add a `SessionEnd` hook in `settings.json`. See the [hook events list](<https://code.claude.com/docs/en/hooks#hook-events>). |
| MCP servers in `.mcp.json` never load | File is under `.claude/`, or its servers sit under a top-level `servers` key, as in VS Code's `mcp.json`, instead of `mcpServers` | Project MCP config goes at the repository root as `.mcp.json`, not inside `.claude/`, with servers under the `mcpServers` key. See [MCP configuration](<https://code.claude.com/docs/en/mcp>). |
| MCP servers added under `mcpServers` in `settings.json` never appear | `settings.json` does not read an `mcpServers` key | Define project servers in `.mcp.json` at the repository root, or run `claude mcp add --scope user` for user-scoped servers. See [MCP configuration](<https://code.claude.com/docs/en/mcp>). |
| Project MCP server added but doesn't appear | The one-time approval prompt was dismissed | Project-scoped servers require approval. Run `/mcp` to see status and approve. |
| MCP server fails to start from some directories | `command` or `args` uses a relative file path | Use absolute paths for local scripts. Executables on your `PATH` like `npx` or `uvx` work as-is. |
| MCP server starts without expected environment variables | The server's config entry doesn't set them, and they aren't in the environment Claude Code passes to stdio servers: its own environment, minus the [variables it strips from subprocesses](<https://code.claude.com/docs/en/monitoring-usage#administrator-configuration>) | Set per-server `env` inside the server's `.mcp.json` entry, which doesn't depend on the launch environment or workspace trust. |
| `Bash(rm *)` deny rule doesn't block `/bin/rm` or `find -delete` | Bash rules match the literal command string, not the underlying executable; see [what a Bash rule doesn't match](<https://code.claude.com/docs/en/permissions#bash-rule-limits>) | Use a [PreToolUse hook](<https://code.claude.com/docs/en/hooks-guide>) or the [sandbox](<https://code.claude.com/docs/en/sandboxing>) for a hard guarantee. |
