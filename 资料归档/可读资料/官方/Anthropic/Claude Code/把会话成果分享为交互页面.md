# 将会话输出共享为工件

> Artifacts 将 Claude Code 的作品转变为 claude.ai 上的实时交互式页面，您可以将其保密、与您的组织共享或发布到公共链接。



**注释：**

工件可在 Pro、Max、Team 和 Enterprise 计划中使用，并且需要使用 [`/login`](<https://code.claude.com/docs/en/setup#authenticate>) 登录的会话。有关全套要求，请参阅[可用性](<#可用性>)。


[ 工件 ](<https://claude.com/features/artifacts>) 是一个实时的交互式网页，Claude Code 从您的会话发布到 claude.ai 上的私人 URL。您在浏览器中打开它，它会随着会话的继续而更新。当您希望其他人也看到它时，请从页眉共享它。

## 何时使用神器

当终端文本对于 Claude 生成的内容来说是错误的媒介时，请使用工件：输出比逐行阅读更容易查看和交互。 Claude 从您的会话可以访问的任何内容构建页面，包括您的代码库和它通过 [ 连接的工具 ](<https://code.claude.com/docs/en/mcp>) 提取的数据，因此页面可以显示需要段落来描述的内容。例如，要求 Claude：

* 通过带注释的差异引导审阅者完成拉取请求
* 根据会话已提取的数据渲染仪表板
* 并排布置多个设计或实现选项
* 保留一个调查时间表，以便在长时间任务运行时填充
* 向队友发送链接，而不是将输出粘贴到 Slack 中
* 发布一个状态板，每次有人打开它时，[都会通过MCP连接器](<#使用-mcp-连接器提取实时数据>)提取新数据

请参阅 [您可以构建什么 ](<#您可以构建什么>) 以获取与这些匹配的提示，并 [使用 MCP 连接器提取实时数据 ](<#使用-mcp-连接器提取实时数据>) 以获取连接器支持的板的提示。

### 神器不是什么

工件是工作的捕获：一个没有后端的独立页面，因此它无法服务多个路由。对于具有后端的托管内部工具，请将其部署在您自己的基础设施上。有关完整的限制，请参阅[页面约束](<#页面限制>)。

## 创建一个工件

当输出适合页面时，Claude 可能会自行发布工件，或者您可以直接索取。要询问，请用简单的语言命名该功能或描述您想要的视觉输出。一个好的候选者是比文本更容易看到的东西，例如带注释的差异、图表或一组要比较的选项。下面的提示是两个示例；请参阅 [您可以构建什么](<#您可以构建什么>) 了解更多模式。

```text wrap theme={null}
Make an artifact that walks through this PR with the diff annotated inline.
```

```text wrap theme={null}
Build a dashboard artifact of last week's deploy failures by service and keep it updated as you investigate.
```

除非您指定位置，否则 Claude 会将页面写入项目外部临时目录中的 HTML 或 Markdown 文件，然后发布它。在您[共享它](<#分享一个神器>)之前，该工件对您保持私密状态。

首次发布后，Claude 打印 URL，并且您的浏览器将打开新页面。

* **重新打开页面**：随时按`Ctrl+]`重新打开会话的最新工件
* **查看此会话的工件**：提示下方的 `⧉` 药丸显示工件的名称，或者当会话有多个工件时显示计数。在[全屏渲染](<https://code.claude.com/docs/en/fullscreen>)中，点击打开[`/artifacts`](<#再次寻找神器>)列表
* **阻止浏览器打开**：在您的环境中设置`CLAUDE_CODE_ARTIFACT_AUTO_OPEN=0`
* **远程控制**：如果您从claude.ai、Claude桌面或Claude移动应用程序通过[远程控制](<https://code.claude.com/docs/en/remote-control>)发送提示，则运行会话的计算机上不会打开任何选项卡。下次 Claude 根据您在终端输入的提示发布工件时，浏览器将在此处打开

Claude 选择工件的标题和与页面内容匹配的浏览器选项卡图标，例如图表或日历。该标题出现在 claude.ai 上的 [ 工件库 ](<#分享一个神器>) 和共享链接中。如果您想要一个特定的标题或选项卡图标，请向 Claude 询问。

如果 Claude 响应无法发布，或者写入没有链接的本地 HTML 文件，则不会为您的会话启用工件。检查[可用性](<#可用性>)要求。如果终端显示`Artifacts need a claude.ai login`，请参阅[该错误的条目](<https://code.claude.com/docs/en/errors#artifacts-need-a-claude-ai-login>)了解如何登录。

### 当Claude Code发布前询问时

Claude 为响应您键入的提示而发布的新工件会在没有权限提示或分类器审查的情况下进行。在这些情况下，Claude Code 首先询问您，或者在 [ 自动模式下 ](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) 让分类器审查发布：

|当|Claude Code 的作用|
| :- | :- |
|会话处于 [ 计划模式 ](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>)|在首次发布每个工件之前询问|
|发布声明页面的运行时功能，例如[连接器调用](<#使用-mcp-连接器提取实时数据>)或[文件下载](<#提供文件下载>)|发布前询问|
|您公开分享了该工件|每个对话在更改之前询问一次|
|您关闭了 [ 功能标志获取 ](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>)|在首次发布每个工件之前询问|
|Claude 轮流发布在您的会话中启动的 [ 计划任务 ](<https://code.claude.com/docs/en/scheduled-tasks>)，而不是您键入的提示|在首次发布每个工件之前询问|
|Claude未经您的批准无法读取该文件|发布前询问。 `Artifact` 工具的允许规则不会跳过此提示|

Claude 读取会话的 [ 工作目录 ](<https://code.claude.com/docs/en/permissions#working-directories>) 中的文件，并在临时目录中写入页面，无需询问。要让 Claude 在没有提示的情况下从另一个文件夹发布，请在启动时使用 [`--add-dir`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 或在会话期间使用 `/add-dir` 将文件夹添加为工作目录。

## 更新工件

要求 Claude 修改页面，或者让长时间运行的任务在取得进展时重新发布。 Claude 编辑基础文件并再次发布到相同的 URL。

```text wrap theme={null}
Add a per-region breakdown below the summary chart and republish.
```

打开该页面的任何人都可以看到更新。每次发布都会成为一个版本，并且可以从页眉中的 **共享** 控件中选择查看者看到的版本。

要从不同会话更新工件，请将 Claude 指定为 URL，或将其附加到 [`/artifacts`](<#再次寻找神器>)。如果没有其中任何一个，新会话将创建一个新工件而不是更新工件。

```text wrap theme={null}
Update https://claude.ai/code/artifact/5fbea6f3-... with today's numbers.
```

## 再次寻找神器

运行 Claude Code 中的 `/artifacts` 以列出您拥有的工件以及与您共享的工件。当前会话的工件排在第一位，位于 **此会话** 下。需要 Claude Code v2.1.208 或更高版本。

选择一个工件，然后按以下键之一：

* **`Enter`**：当它已附加到当前会话时在浏览器中打开它，当它没有附加到当前会话时附加它。在v2.1.216之前，`Enter`在浏览器中打开了它
* **`o`**：在浏览器中打开它
* **`c`**：复制其链接

Claude Code 从您的 claude.ai 帐户中读取列表，因此它可以在新会话中以及在 `/clear` 之后（当链接滚出终端时）运行。

## 分享一个神器

新工件仅对您可见。要共享它，请在浏览器中打开工件并使用页面标题中的 **Share** 控件。标题还链接到您的画廊 [claude.ai/code/artifacts](<https://claude.ai/code/artifacts>)，其中列出了您创建的每个工件。

您组织中的查看者可以查看谁发布了该页面：在组织内共享的工件上，您的姓名位于标题菜单中，而在公共工件上，您的姓名位于组织中登录查看者的页面标题中。未登录或从组织外部打开公共链接的查看者会看到标签 `Content is user-generated and unverified.` 而不是您的姓名。

您可以与谁分享取决于您的计划：

* **在您的组织内**：在团队和企业计划中，向组织中的特定人员或组织中的每个人授予访问权限。查看者以组织成员的身份登录 claude.ai 来查看该页面。
* **公开**：共享互联网上任何人都可以打开的链接，无需登录 claude.ai。在团队和企业计划中，公共共享处于关闭状态，直到所有者 [ 为组织 ](<#控制公共共享>) 启用它。

### 让某人与您一起编辑

默认情况下，您与之共享的人是查看者：他们可以看到您发布的每个版本，但无法更改页面。在团队和企业计划中，您还可以指定某人担任编辑。在共享对话框中，添加一个人并将其角色从**查看者**切换为**编辑者**。

编辑者发布新版本的方式与您[从另一个会话](<#更新工件>)更新工件的方式相同：他们提供Claude工件的URL，或从[`/artifacts`](<#再次寻找神器>)附加它，并且Claude提取当前内容并重新发布其更改。打开页面的每个人都可以实时看到每个更新。

如果编辑者在 Claude 持有该页面的旧副本时进行发布，则 Claude Code 会拒绝基于该副本构建的发布。 Claude 然后将其更改合并到新版本并再次发布。

## 阅读与您分享的工件

当有人与您共享工件时，您可以让 Claude 读取它：将其 URL 提供给 Claude，或从 [`/artifacts`](<#再次寻找神器>) 附加它。

Claude 读取其他人编写的页面的方式与使用 [WebFetch](<https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior>) 读取网页的方式相同：它获取其所询问内容的摘要而不是原始页面，并且摘要报告写入页面的指令而不是转发它们。 Claude Code 还将页面的完整源代码保存到本地文件，Claude 可以在需要确切内容时打开该文件，例如将工件重新发布为 [ 编辑器 ](<#让某人与您一起编辑>)。

在这些情况下，除了您的权限模式或规则要求的任何提示之外，Claude Code 在 Claude 读取工件之前会请求您的批准：

* **无需网络访问的云会话**：对于[云环境](<https://code.claude.com/docs/en/cloud-environments#access-levels>)，这是**无**级别。在[自动模式](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>)下，分类器可以改为批准；在 [Cowork](<https://claude.com/product/cowork>) 会话中，批准权仅属于您。
* **另一个组织的公共神器**：Claude Code首先询问你，即使在自动模式下也是如此。凡是Claude Code无法询问你的地方，比如在`bypassPermissions`模式下，Claude无法读取神器。仅当 [ 功能标志获取 ](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>) 开启时，Claude 才能读取这些工件。
* **未经确认的所有者或网络设置**：当Claude Code无法确认谁制作了工件，或者无法确认云会话的网络设置时，它会询问，并且您的批准涵盖了该请求。
* **计划模式，或功能标志获取已关闭**：在[计划模式](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>)下，或者如果您关闭了[功能标志获取](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>)，Claude Code在工件工具读取组织中其他人制作的工件之前询问。

当Claude读取带有WebFetch的工件时，WebFetch自己的[提示规则](<https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior>)仍然适用。

## 收集对工件的评论

当您在组织内共享工件时，与您共享该工件的人员可以在页面上留下评论，并且您可以让 Claude 阅读这些评论并回复它们。您需要 Claude Code v2.1.221 或更高版本。 Claude读取评论分两种情况：

* **你要求Claude阅读它们**：给Claude工件的URL并请求评论。 Claude 列出每个线程并标记可以编辑发送给它的工件的人的评论。
* **可以编辑工件的人向 Claude** 发送评论：在页面上的线程中，他们将 ** 的评论发送到 Claude**，或在其中提及 `@claude`。不管怎样，他们都会激活线程。

Claude只能回复或解决已激活的话题。其他线程保持打开状态，直到有人在页面上解决它们。观看者通过您看到归因于 Claude 的每条回复。

如果您公开共享工件，则只能通过公共链接进行访问的人看不到其评论，也无法添加任何评论。现有的评论线程保留在工件上，您和其编辑者仍然可以阅读和回复它们。

要亲自征求意见，请给 Claude URL：

```text wrap theme={null}
Read the comments on https://claude.ai/code/artifact/5fbea6f3-... and make the changes the commenters ask for.
```

如果 Claude 告诉您它无法读取评论，请确认您的版本、会话和功能标记设置：

* 您正在运行 Claude Code v2.1.221 或更高版本。
* 自安装 Claude Code 或从 v2.1.221 之前的版本升级以来，您已不再处于第一次会话中。在安装或升级后的[第一次会话中](<https://code.claude.com/docs/en/env-vars#first-session-after-an-install-or-upgrade>)，Claude可能还无法阅读评论；开始一个新的会话并再次询问。
* 您尚未关闭功能标志获取。

### 让Claude自己回复评论

在您的会话发布工件后，Claude Code 会监视该工件以获取评论。当可以编辑该工件的人向 Claude 发送评论时，它会立即到达您的会话，并且 Claude 可以阅读该线程并回复，而无需您询问。

您需要 Claude Code v2.1.228 或更高版本。如果您关闭 [ 功能标记获取 ](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>)，Claude Code 不会查看评论。

您的 [ 权限模式 ](<https://code.claude.com/docs/en/permission-modes>) 决定 Claude 在发送的评论到达时执行的操作：

* **Claude 自行回复**：当您的权限模式允许 Claude 在不询问您的情况下发布回复时，Claude 会读取线程并回复，并在评论要求更改时编辑工件。您会看到 `Auto-replied to comment thread on Artifact: <name>` 或 `Auto-edited Artifact: <name> in response to a comment thread`。
* **Claude等你**：计划外模式，发帖时需要你的批准，你看到`Comments are waiting on Artifact: <name>`。 Claude 然后请求您批准阅读该帖子，并再次发布回复。
* **Claude在计划模式下暂停**：您看到`Comments are waiting on Artifact: <name>`，并且Claude不会回复，直到您离开计划模式并要求它阅读和回复。

Claude 在处理 60 一小时内对该工件发送的评论或线程激活后，也会停止自行回复该工件。您会看到 `Comments are waiting on Artifact: <name>` 一次，随着该小时的评论过期，Claude 会再次出现。

运行 `/tasks` 以查看您的会话正在观看的工件。 `/tasks` 将手表 Claude Code 分组到 **系统任务 ** 行下自行启动。按该行上的 `Enter` 即可列出它们。您要求 Claude 启动的手表出现在 ** 监视器 ** 下。

您可以通过以下任一方式阻止 Claude 自行回复：

* **在空闲提示时按 Ctrl+C 一次**：Claude 暂停回复您的会话正在观看的每个工件。发送下一条消息后，回复将重新开始。
* **停止`/tasks`**中的任务：Claude停止回复该工件，直到您要求它恢复回复。再次发布工件不会再次启动回复，并且当您稍后恢复会话时，停止仍然适用。
* **在 3 秒内按 `Ctrl+X Ctrl+K` 两次 **：[ 停止每个正在运行的后台子代理 ](<https://code.claude.com/docs/en/interactive-mode#general-controls>) 的和弦也会停止 Claude 在会话的其余部分回复每个工件。要求 Claude 恢复回复并不会撤消此停止。

Claude Code 自行启动的手表可能会在工件几个小时没有活动后结束。如需再次启动观看，请再次发布该工件或要求Claude观看。

如果提供评论的服务变得不可用或停止应答，Claude Code 会继续尝试重新连接一段时间，然后停止观看您的会话正在观看的每个工件。

## 使用 MCP 连接器提取实时数据

每次有人查看工件时，工件都可以调用 [MCP 连接器 ](<https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claude-ai>)，因此页面显示当前数据，而不是构建它的会话的快照。来自工件的连接器调用适用于 Pro、Max、Team 和 Enterprise 计划，并且需要 Claude Code v2.1.209 或更高版本。在早期版本中，Claude 发布页面，其中包含会话在构建页面时收集的任何数据。

要创建连接器支持的页面，请在提示中命名连接器和所需的数据：

```text wrap theme={null}
Build a dashboard artifact of our open pull requests that pulls the live list through my GitHub connector when the page loads.
```

Claude 声明页面在发布过程中可以调用哪些连接器，并且页面无法调用该声明之外的连接器。只有来自您的 claude.ai 帐户的连接器才符合资格：Claude 在声明中命名它们，当有人查看该页面时，每个调用 [ 都会通过查看帐户自己的连接 ](<#连接器呼叫如何为查看者提供服务>) 运行到该连接器。您在Claude Code中配置的本地MCP服务器，例如来自`.mcp.json`的服务器，可以在Claude构建页面时提供数据，但发布的页面无法调用它们。

页面在加载时获取数据，并且可以按一定时间间隔或在查看者使用页面上的刷新控件时刷新。响应缓存在查看者的浏览器中，因此重新打开的页面会立即从缓存的响应中呈现，然后使用新结果进行更新。

### 连接器呼叫如何为查看者提供服务

当已发布的页面调用连接器时，该调用将使用查看该页面的人员的帐户，而不是发布该页面的人员的帐户：

* **每个查看者使用自己的连接器**：调用通过查看帐户的连接工具进行，因此打开同一仪表板的两个人可以看到不同的数据，具体取决于他们的帐户可以访问的内容。该页面永远不会看到任何人的凭据； claude.ai 代表该页面进行调用。
* **查看者首先批准访问**：claude.ai 在页面第一次连接器调用之前向每个查看者请求许可。拒绝访问或未连接页面使用的连接器的查看者仍然会看到没有实时部分的页面。
* **操作也使用查看者的帐户**：页面可以提供调用具有副作用的连接器工具的控件，例如发布消息或更新问题。该操作将通过选择控件的人的帐户进行。

当您计划共享连接器支持的页面时，请要求 Claude 在每个实时部分中包含一条后备消息，以命名其所需的连接器。缺少连接的查看者会看到要连接的内容，而不是空白部分。

根据您的计划和组织设置允许，您可以[在您的组织内或公开共享连接器支持的页面](<#分享一个神器>)。对于未登录 claude.ai 或从组织外部打开公共链接的查看者，连接器调用不会运行。该查看者看到的页面没有其实时部分。

### 该页面不向查看者显示实时数据

当连接器支持的页面呈现时，但其活动部分对于组织中的查看者而言仍为空，请解决以下原因：

* **查看器尚未连接连接器**：连接器是针对每个帐户的，因此每个查看器都需要自己连接到页面调用的每个连接器。他们可以在 claude.ai 上的 ** 设置 > 连接器 ** 下添加一个，然后重新加载页面。
* **查看者拒绝了权限请求**：拒绝持续到该页面加载的其余部分。重新加载页面会返回权限请求。
* **组织的连接器调用已关闭**：所有者控制管理设置中的[**启用工件连接器**切换](<#控制来自工件的连接器调用>)。
* **页面调用连接器不公开的工具名称**：受影响的部分对每个人（包括您）都保持为空。当页面命名网关式连接器后面的各个工具而该连接器仅公开其自己的少数工具时，可能会发生这种情况。请Claude修复页面调用的工具名称并重新发布。

当 Claude 发布页面并且该连接器的工具在您的会话中可用时，Claude Code 会检查页面声明的工具名称，警告 Claude 名称不匹配，并在没有名称匹配时拒绝发布。在v2.1.265之前，它未经检查就发布了该页面。

## 提供文件下载

工件可以为查看者提供页面生成的文件，例如表格的 CSV 导出或图表的 PNG。查看器通过页面上的下载控件（例如按钮）保存它。文件下载是 claude.ai 为每个帐户启用的运行时功能，因此 Claude 在构建控件之前会检查您的帐户是否具有该功能。

查看器无法从页面上的普通下载链接或脚本保存文件，因为 claude.ai 上的工件查看器会阻止页面自身启动的任何下载，包括指向 `data:` 或 `blob:` URL 的链接。如果页面具有以这种方式构建的下载按钮，请要求 Claude 使用下载功能重建它们。

要提供文件，请在提示中询问控件和文件格式：

```text wrap theme={null}
Add a button that downloads this table as a CSV file.
```

Claude 将下载功能声明为发布的一部分，与 [ 声明连接器 ](<#使用-mcp-连接器提取实时数据>) 的方式相同。

## 您可以构建什么

工件是单个 HTML 页面，因此您可以在 HTML、CSS 和内联 JavaScript 中表达的任何内容都在范围内。以下模式最常出现。

### 走过一次改变

要求提供一个页面来呈现差异或设计更改，并在相关行旁边添加注释，以便审阅者可以阅读代码旁边的推理，而不是从描述中重建它。

```text wrap theme={null}
Make an artifact that walks through this PR. Render the diff with margin annotations and color-code findings by severity.
```

### 比较替代品

要求在一页上提供多个变体，以便您可以相互评估它们。这适用于布局、副本、API 形状或实施计划。

```text wrap theme={null}
Make an artifact with four distinctly different layouts for the settings panel. Vary density and grouping, and lay them out as a grid with a one-line tradeoff under each.
```

### 使用交互式控件进行调整

请求与您正在调整的内容绑定的滑块、切换开关或输入字段，以便您可以直接探索值而不是描述它们。

```text wrap theme={null}
Build an artifact with sliders for the easing curve, duration, and delay so I can try values on this transition. Show the animation live as I move them.
```

### 将结果带回您的会话

工件可以充当轻量级编辑器，用于做出决定，然后发送回 Claude。请求一个导出控件来生成可以粘贴到终端中的文本，以便与页面交互的结果流回会话中，而不是停留在页面上。

```text wrap theme={null}
Make a triage board artifact with each open issue as a draggable card across Now, Next, Later, and Cut columns. Add a "Copy as prompt" button that gives me the final ordering to paste back here.
```

### 跟踪正在进行的工作

要求 Claude 在长时间任务运行时保持工件最新，以便任何知道链接的人都可以在不阅读终端的情况下进行操作。

```text wrap theme={null}
Turn this migration plan into a checklist artifact. Check items off as you complete them and add a note for anything you skip.
```

## 改进视觉设计

Claude 在构建工件时应用内置设计技巧，因此页面无需额外提示即可获得经过深思熟虑的调色板、版式和布局。该技能还会在您的项目中寻找现有的设计系统，然后再选择自己的设计系统。设计标记是设计系统重用的指定颜色、版式和间距值。为了使工件与您的产品品牌保持一致，请将它们记录在 Claude 可以找到的位置，例如项目的 [CLAUDE.md](<https://code.claude.com/docs/en/memory>) 或存储库中的主题文件：

```markdown theme={null}
## Design system

- Colors: primary #1a4d8f, accent #f59e0b, surface #f8fafc
- Typography: Inter for body, JetBrains Mono for code
- Spacing: 8px scale, 6px border radius
```

Claude 将您的设计系统视为比其自己的选择更高的优先级，并将您的提示视为比两者都更高的优先级。上面的标题和格式是一个示例；任何清晰的颜色、字体和间距列表都可以。

对于排版，Claude 可以从 Google 字体加载字体，工件页面可以从中加载一种外部字体源。 Claude 将任何其他字体内联为 `@font-face` 数据 URI 并为每种字体提供后备堆栈，因此如果字体未加载，页面仍然会呈现。要使用特定字体，请在提示或设计系统中为其命名。

## 从幻灯片、设计或文档模板开始

Claude 无需从头开始构建页面，而是可以从 claude.ai 帐户上的模板之一启动工件：用于演示的 [Claude 幻灯片 ](<https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them#h_11d5a9a5fa>)、用于视觉设计的 [Claude 设计 ](<https://support.claude.com/en/articles/14604416-get-started-with-claude-design>) 或 [Claude Docs](<https://support.claude.com/en/articles/16923645-get-started-with-claude-docs>) 用于其他人将阅读和编辑的文档。每个文件都在 claude.ai 上自己的编辑器中打开，您和您的队友可以直接更改它或询问 Claude，并将其导出为 PowerPoint、PDF 或 Word 等格式。

要从模板开始，请描述您想要的内容，例如“将迁移笔记变成供周四审阅的平台”或“将此计划写为团队的文档”。 Claude 选择匹配的模板，根据您的请求和会话已有的内容填充它，并为您提供链接。对于套牌或设计，您还可以运行 `/slides` 或 `/design` 以及摘要。



**注释：**

  模板处于测试阶段。默认情况下，它们在 Pro、Max 和 Team 计划中处于启用状态。在企业计划中，所有者 [打开每个模板](<https://support.claude.com/en/articles/16994751-artifacts-admin-guide-for-team-and-enterprise-plans>) 下 **组织设置 > 工件**。如果您的组织关闭了幻灯片模板， `/slides` 没有出现；如果它关闭了设计模板， `/design` 不起草设计。两个命令都需要 Claude Code v2.1.265 或稍后以及一个会话 [工件可用](<#可用性>).


### 制作幻灯片

运行 `/slides`，并简要说明该套牌涵盖的内容以及适用人群：

```text wrap theme={null}
/slides a quarterly review of the platform team's reliability work, for the engineering all-hands
```

Claude 创建一个 Claude 幻灯片工件并为您提供链接。在桌面浏览器中打开它以编辑或呈现套牌。如果您在没有简介的情况下运行`/slides`，Claude会在创建任何内容之前询问套牌应该是关于什么的。

### 起草设计画布

要模拟 UI、屏幕流程、登陆页面或海报而不是构建页面，请运行带有摘要的 `/design`。 Claude 在一张画布上起草设计作为画板，并将画布发布为 Claude 设计工件。简要命名您想要绘制的内容：

```text wrap theme={null}
/design a settings screen for a mobile banking app
```

在桌面浏览器中打开已发布的工件以查看画板。选择画板上的一个元素并进行更改，您的编辑会自动保存。您可以将每个画板导出为 PNG 或 PDF。

### 使用 Claude Docs 编写文档

Claude Docs 作为 claude.ai [ 连接器 ](<https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claude-ai>) 而不是命令到达 Claude Code。连接后，`/mcp` 将其列为 `claude.ai Claude Docs`。对供其他人使用的文档的请求将转到 Claude 文档，而不是工件页面：规范、提案或您在会议中完成的计划的撰写。 Claude 为您提供起草文档时的链接。

属于代码库的文档（例如 README）仍然是一个文件。要获取 Claude 的文件，否则将放入 Claude 文档中，命名格式，例如 `.docx` 或存储库中的 Markdown 文件。

要关闭连接器，请将 `claude.ai Claude Docs` 添加到 `deniedMcpServers` 或使用 `/mcp` 切换开关，这两个开关均在 [禁用 claude.ai 连接器 ](<https://code.claude.com/docs/en/mcp#disable-claude-ai-connectors>) 中进行了描述。

## 页面限制

每个工件都是一个独立的页面。 Claude Code 将您发布的文件包装在 HTML 文档 shell 中，并在严格的内容安全策略 (CSP) 下提供服务，该策略决定页面可以执行的操作。

|约束|效果|
| :- | :- |
|外部请求|该页面可以加载来自 Google 字体的字体，以及来自 [ 五个公共 CDN 主机 ](<#将查看者域列入白名单>) 的脚本：cdnjs、unpkg、Tailwind 和 jQuery CDN，以及 jsDelivr 上的选定路径，例如`/npm/`。 CSP 阻止每个外部图像和所有其他外部脚本、样式表和字体，并让 `fetch`、XHR 和 WebSocket 调用仅到达页面自己的来源和 Google 字体主机。因此，Claude 从这些 CDN 之一加载页面所需的任何库，内联所有其他 CSS 和 JavaScript，并将图像嵌入为数据 URI。 [连接器调用](<#使用-mcp-连接器提取实时数据>)通过claude.ai，这使得网络调用本身。|
|无后端|工件是静态页面。它无法验证观众本身的身份。|
|下载|该页面无法自行开始下载。为了让查看者保存页面生成的文件，Claude 声明了下载功能。请参阅[提供文件下载](<#提供文件下载>)。|
|单页|相对链接无法解析，因为页面旁边没有部署任何内容。对于多部分内容，Claude 使用页内锚点而不是单独的文件。|
|源文件类型|发布的文件必须是 `.html`、`.htm` 或 `.md`，并且必须按照其字节顺序标记解码为 UTF-8 或小端 UTF-16。 Markdown 文件使用语法突出显示的代码呈现为样式化文档页面。无法解码或包含替换字符 `U+FFFD` 的文件将被 [ 拒绝，并需要修复 ](<https://code.claude.com/docs/en/errors#the-source-file-is-not-valid-utf-8-text>) 的行和列。|
|源位置|指定网络主机的路径中的文件将被拒绝而不被读取。请参阅 [ 未发布：该文件位于网络共享上 ](<https://code.claude.com/docs/en/errors#not-published-that-file-is-on-a-network-share>)，其路径被拒绝以及 Windows 上的映射驱动器异常。|
|渲染尺寸|呈现的页面必须为 16 MiB 或更小。大型嵌入图像是发布因尺寸问题而失败的常见原因。|

生成工件像任何其他响应一样使用输出令牌，并且样式化页面比与终端文本相同的内容更加令牌密集。用于交互式控件的内联 CSS、JavaScript，尤其是作为数据 URI 嵌入的图像是主要贡献者。要降低工件的令牌成本：

* 对于嵌入光栅图像的图表，首选 SVG 或 HTML 和 CSS
* 省略不需要的交互
* 让页面汇总大型数据集而不是完整内联它们

您的组织是否允许使用工件取决于您组织的策略，该策略 Claude Code 从 `api.anthropic.com` 加载。当 Claude Code 无法加载策略时，工件不可用。当您询问时，Claude 会说明原因。

如果涉及代理、VPN 或网络过滤器，请要求您的 IT 管理员让 `api.anthropic.com` 通过。 Claude Code 在后台不断重试，一旦策略加载并允许，工件就会变得可用。

## 禁用工件

要关闭您自己的会话的工件，无论您的组织的设置如何，请使用以下任一方法：

|哪里|该怎么办|
| :- | :- |
| [`/config`](<https://code.claude.com/docs/en/commands>) |关闭 **Artifacts** 行，这会将 [`"enableArtifact": false`](<https://code.claude.com/docs/en/settings-reference#enableartifact>) 写入您的用户设置|
|[设置文件](<https://code.claude.com/docs/en/settings>)|设置`"enableArtifact": false`。已弃用的 `"disableArtifact": true` 也会关闭工件|
|[环境变量](<https://code.claude.com/docs/en/env-vars>)|设置`CLAUDE_CODE_DISABLE_ARTIFACT=1`|
|[权限规则](<https://code.claude.com/docs/en/permissions>)|将 `Artifact` 添加到 `permissions.deny`|

一旦您在 [`--settings`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) 文件中或使用 `CLAUDE_CODE_DISABLE_ARTIFACT` 关闭工件，或者您的管理员在 [ 托管设置 ](<https://code.claude.com/docs/en/server-managed-settings>) 中将其关闭，则没有任何设置文件会重新打开它们。

您还可以在项目的 `.claude/settings.json` 或 `.claude/settings.local.json` 中设置 `"enableArtifact": false`，以关闭该项目中会话的工件。任一文件中的 `"enableArtifact": true` 都不会重新打开它们。尊重项目和本地设置中的密钥需要 Claude Code v2.1.242 或更高版本。

如果添加不带 `domain:` 部分的 `WebFetch` 拒绝或询问规则，它不会关闭工件或阻止工件读取。 `deny` 或 `ask` 中的 [`WebFetch(domain:claude.ai)` 规则确实适用于工件读取 ](<https://code.claude.com/docs/en/permissions#allow-or-deny-every-fetch>)。

## 管理您组织的工件

团队和企业计划的所有者控制来自 [claude.ai 管理设置 ](<https://claude.ai/admin-settings/artifacts>) 的工件。工件内容存储在 Anthropic 运营的基础设施上，并且仅对发布组织的经过身份验证的成员及其共享人员可见，除非工件是 [ 公开共享的 ](<#控制公共共享>)。

### 启用或禁用工件

要启用或禁用整个组织的工件，请转至 [**组织设置 > 工件 **](<https://claude.ai/admin-settings/artifacts>) 并使用 **工件 ** 切换开关。在具有基于角色的访问控制的企业计划中，您还可以将工件范围限定为特定角色：转至 [**组织设置 > 角色 **](<https://claude.ai/admin-settings/roles>)，编辑角色，然后设置 **工件 ** 权限。

### 控制来自工件的连接器调用

[来自工件的连接器调用](<#使用-mcp-连接器提取实时数据>) 有自己的切换开关，与 **文物** 打开或关闭工件的开关。 Go 到 [**组织设置 > 能力**](<https://claude.ai/admin-settings/capabilities>) 并使用 **启用工件连接器** 切换。相同的切换控制来自 claude.ai 对话中创建的工件的连接器调用。

### 控制公共共享

团队和企业计划中的公共共享默认处于关闭状态。要让成员将工件发布到任何人无需登录即可查看的公共链接，请转至 [**组织设置 > 工件 **](<https://claude.ai/admin-settings/artifacts>)，然后打开 **工件 ** 开关下的 **外部共享 **。将其关闭会阻止通过现有公共链接进行访问，而不会改变每个工件的受众；如果您重新启用它，访问将恢复。

### 设置保留策略

要设置自动删除之前工件的保留时间，请转至 [**组织设置 > 数据和隐私**](<https://claude.ai/admin-settings/data-privacy-controls>)。您可以为仍属于作者私有的工件和已共享的工件设置单独的保留期限。

### 查看审核日志

发布、共享和删除工件均显示在组织的审核日志中的 `claude_artifact_*` 事件类型下，与在 claude.ai 对话中创建的工件相同的系列。

### 将查看者域列入白名单

claude.ai 上的查看器从沙盒 `*.claudeusercontent.com` 源加载每个工件。如果您的组织限制出站网络访问，请将该域与 `claude.ai` 一起添加到您的允许列表中。有关完整列表，请参阅[网络访问要求](<https://code.claude.com/docs/en/network-config#network-access-requirements>)。

从 [Google 字体 ](<#改进视觉设计>) 加载字体的工件也会请求 `fonts.googleapis.com` 和 `fonts.gstatic.com`。两个主机都是可选的。如果您阻止它们，工件将以后备字体呈现。通过快速拒绝而不是静默下降来阻止，以便字体请求立即失败而不是延迟页面的首次渲染。

工件还可以从 `cdnjs.cloudflare.com`、`cdn.jsdelivr.net`、`cdn.tailwindcss.com`、`code.jquery.com` 和 `unpkg.com` 加载 JavaScript 库，例如 React 或图表包，而不是从其他外部主机加载。如果您阻止这些主机，依赖于库的工件部分将不起作用，并且与阻止的字体不同，阻止的库没有后备。这里也使用快速拒绝进行阻止，因此被阻止的库请求会立即失败，而不是挂起直到超时。

# Share session output as artifacts

> Artifacts turn Claude Code's work into live, interactive pages on claude.ai that you can keep private, share with your organization, or publish to a public link.



**注释：**

  Artifacts are available on Pro, Max, Team, and Enterprise plans and require a session signed in with [`/login`](<https://code.claude.com/docs/en/setup#authenticate>). See [Availability](<#availability>) for the full set of requirements.


An [artifact](<https://claude.com/features/artifacts>) is a live, interactive web page that Claude Code publishes from your session to a private URL on claude.ai. You open it in a browser, and it updates in place as the session continues. Share it from the page header when you want someone else to see it too.

## When to use an artifact

Use an artifact when terminal text is the wrong medium for what Claude produced: output that is easier to look at and interact with than to read line by line. Claude builds the page from anything your session can reach, including your codebase and data it pulls through your [connected tools](<https://code.claude.com/docs/en/mcp>), so the page can show things that would take paragraphs to describe. For example, ask Claude to:

* Walk a reviewer through a pull request with annotated diffs
* Render a dashboard from data the session already pulled
* Lay out several design or implementation options side by side
* Keep an investigation timeline that fills in while a long task runs
* Send a teammate a link instead of pasting output into Slack
* Publish a status board that [pulls fresh data through MCP connectors](<#pull-live-data-with-mcp-connectors>) each time someone opens it

See [What you can build](<#what-you-can-build>) for prompts that match these, and [Pull live data with MCP connectors](<#pull-live-data-with-mcp-connectors>) for the connector-backed board's prompt.

### What an artifact is not

An artifact is a capture of work: one self-contained page with no backend, so it can't serve multiple routes. For a hosted internal tool with a backend, deploy it on your own infrastructure instead. See [Page constraints](<#page-constraints>) for the full set of limits.

## Create an artifact

Claude may publish an artifact on its own when the output suits a page, or you can ask for one directly. To ask, name the feature or describe the visual output you want in plain language. A good candidate is anything easier to see than to read as text, such as an annotated diff, a chart, or a set of options to compare. The prompts below are two examples; see [What you can build](<#what-you-can-build>) for more patterns.

```text wrap theme={null}
Make an artifact that walks through this PR with the diff annotated inline.
```

```text wrap theme={null}
Build a dashboard artifact of last week's deploy failures by service and keep it updated as you investigate.
```

Unless you name a location, Claude writes the page to an HTML or Markdown file in a temporary directory outside your project, then publishes it. The artifact stays private to you until you [share it](<#share-an-artifact>).

After the first publish, Claude prints the URL, and your browser opens to the new page.

* **Reopen the page**: press `Ctrl+]` at any time to reopen the session's most recent artifact
* **See this session's artifacts**: a `⧉` pill below the prompt shows the artifact's name, or a count when the session has several. In [fullscreen rendering](<https://code.claude.com/docs/en/fullscreen>), click it to open the [`/artifacts`](<#find-an-artifact-again>) list
* **Keep the browser from opening**: set `CLAUDE_CODE_ARTIFACT_AUTO_OPEN=0` in your environment
* **Remote Control**: if you sent the prompt through [Remote Control](<https://code.claude.com/docs/en/remote-control>) from claude.ai, Claude Desktop, or the Claude mobile app, no tab opens on the machine running the session. The browser opens there the next time Claude publishes the artifact from a prompt you type at the terminal

Claude picks the artifact's title and a browser-tab icon that matches what the page is, such as a chart or a calendar. The title appears in your [gallery of artifacts](<#share-an-artifact>) on claude.ai and in shared links. Ask Claude for a specific title or tab icon if you want one.

If Claude responds that it can't publish, or writes a local HTML file without a link, artifacts aren't enabled for your session. Check the [Availability](<#availability>) requirements. If the terminal shows `Artifacts need a claude.ai login`, see [that error's entry](<https://code.claude.com/docs/en/errors#artifacts-need-a-claude-ai-login>) for how to sign in.

### When Claude Code asks before publishing

A new artifact that Claude publishes in response to a prompt you type goes through without a permission prompt or classifier review. In these cases Claude Code asks you first, or in [auto mode](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>) has the classifier review the publish:

| When | What Claude Code does |
| :- | :- |
| The session is in [plan mode](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>) | Asks before the first publish of each artifact |
| The publish declares runtime capabilities for the page, such as [connector calls](<#pull-live-data-with-mcp-connectors>) or [file downloads](<#offer-a-file-download>) | Asks before that publish |
| You shared the artifact publicly | Asks once per conversation before changing it |
| You turned [feature-flag fetching](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>) off | Asks before the first publish of each artifact |
| Claude publishes in a turn that a [scheduled task](<https://code.claude.com/docs/en/scheduled-tasks>) firing in your session started, rather than a prompt you typed | Asks before the first publish of each artifact |
| Claude can't read the file without your approval | Asks before publishing it. An allow rule for the `Artifact` tool doesn't skip this prompt |

Claude reads files in your session's [working directories](<https://code.claude.com/docs/en/permissions#working-directories>), and in the temporary directory it writes pages to, without asking. To let Claude publish from another folder without the prompt, add the folder as a working directory with [`--add-dir`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) at launch or `/add-dir` during the session.

## Update an artifact

Ask Claude to revise the page, or let a long-running task republish as it makes progress. Claude edits the underlying file and publishes again to the same URL.

```text wrap theme={null}
Add a per-region breakdown below the summary chart and republish.
```

Anyone with the page open sees the update in place. Each publish becomes a version, and from the **Share** control in the page header you can choose which version viewers see.

To update an artifact from a different session, give Claude its URL, or attach it with [`/artifacts`](<#find-an-artifact-again>). Without either, a new session creates a new artifact instead of updating one.

```text wrap theme={null}
Update https://claude.ai/code/artifact/5fbea6f3-... with today's numbers.
```

## Find an artifact again

Run `/artifacts` in Claude Code to list the artifacts you own and the ones shared with you. The current session's artifacts come first, under **This session**. Requires Claude Code v2.1.208 or later.

Select an artifact, then press one of these keys:

* **`Enter`**: opens it in your browser when it's already attached to the current session, and attaches it when it isn't. Before v2.1.216, `Enter` opened it in your browser
* **`o`**: opens it in your browser
* **`c`**: copies its link

Claude Code reads the list from your claude.ai account, so it works in a new session and after `/clear`, when the link has scrolled out of the terminal.

## Share an artifact

A new artifact is visible only to you. To share it, open the artifact in your browser and use the **Share** control in the page header. The header also links to your gallery at [claude.ai/code/artifacts](<https://claude.ai/code/artifacts>), which lists every artifact you have created.

Viewers in your organization can see who published the page: on an artifact shared within your organization, your name is in the title menu, and on a public artifact it's in the page header for signed-in viewers in your organization. A viewer who opens a public link without signing in, or from outside your organization, sees the label `Content is user-generated and unverified.` instead of your name.

Who you can share with depends on your plan:

* **Within your organization**: on Team and Enterprise plans, grant access to specific people in your organization, or to everyone in it. Viewers sign in to claude.ai as members of your organization to see the page.
* **Publicly**: share a link that anyone on the internet can open, with no claude.ai sign-in required. On Team and Enterprise plans, public sharing is off until an Owner [enables it for the organization](<#control-public-sharing>).

### Let someone edit with you

People you share with are viewers by default: they see each version you publish but can't change the page. On Team and Enterprise plans, you can also make someone an editor. In the share dialog, add a person and switch their role from **viewer** to **editor**.

An editor publishes new versions the same way you [update the artifact from another session](<#update-an-artifact>): they give Claude the artifact's URL, or attach it from [`/artifacts`](<#find-an-artifact-again>), and Claude pulls the current content and republishes with their changes. Everyone with the page open sees each update live.

If an editor publishes while Claude holds an older copy of the page, Claude Code refuses a publish built on that copy. Claude then merges its changes onto the newer version and publishes again.

## Read an artifact shared with you

When someone shares an artifact with you, you can have Claude read it: give Claude its URL, or attach it from [`/artifacts`](<#find-an-artifact-again>).

Claude reads a page someone else wrote the way it reads a web page with [WebFetch](<https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior>): it gets a summary of what it asked about rather than the raw page, and the summary reports instructions written into the page instead of relaying them. Claude Code also saves the page's full source to a local file, which Claude can open when it needs the exact content, such as to republish the artifact as an [editor](<#let-someone-edit-with-you>).

Claude Code asks for your approval before Claude reads the artifact in these cases, in addition to any prompt your permission mode or rules call for:

* **Cloud session without network access**: for a [cloud environment](<https://code.claude.com/docs/en/cloud-environments#access-levels>), that's the **None** level. In [auto mode](<https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode>), the classifier can approve instead; in a [Cowork](<https://claude.com/product/cowork>) session, the approval is yours alone.
* **Another organization's public artifact**: Claude Code asks you first, even in auto mode. Where Claude Code can't ask you, such as in `bypassPermissions` mode, Claude can't read the artifact. Claude can read these artifacts only while [feature-flag fetching](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>) is on.
* **Unconfirmed owner or network setting**: when Claude Code can't confirm who made the artifact, or can't confirm a cloud session's network setting, it asks, and your approval covers that one request.
* **Plan mode, or feature-flag fetching turned off**: in [plan mode](<https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode>), or if you turned [feature-flag fetching](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>) off, Claude Code asks before the Artifact tool reads an artifact someone else in your organization made.

When Claude reads the artifact with WebFetch, WebFetch's own [prompting rules](<https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior>) still apply.

## Collect comments on an artifact

When you share an artifact within your organization, the people you share it with can leave comments on the page, and you can have Claude read those comments and reply to them. You need Claude Code v2.1.221 or later. Claude reads the comments in two cases:

* **You ask Claude to read them**: give Claude the artifact's URL and ask for the comments. Claude lists each thread and marks the comments someone who can edit the artifact sent to it.
* **Someone who can edit the artifact sends a comment to Claude**: in a thread on the page, they send a comment with **Send to Claude**, or mention `@claude` in one. Either way, they activate the thread.

Claude can reply to or resolve only an activated thread. Other threads stay open until a person resolves them on the page. Viewers see each reply attributed to Claude, via you.

If you share an artifact publicly, people whose only access is the public link don't see its comments and can't add any. Existing comment threads stay on the artifact, and you and its editors can still read and reply to them.

To ask for the comments yourself, give Claude the URL:

```text wrap theme={null}
Read the comments on https://claude.ai/code/artifact/5fbea6f3-... and make the changes the commenters ask for.
```

If Claude tells you it can't read comments, confirm your version, your session, and your feature-flag setting:

* You're running Claude Code v2.1.221 or later.
* You're not in your first session since you installed Claude Code or upgraded from a version before v2.1.221. In that [first session after an install or upgrade](<https://code.claude.com/docs/en/env-vars#first-session-after-an-install-or-upgrade>), Claude might not be able to read comments yet; start a new session and ask again.
* You haven't turned feature-flag fetching off.

### Let Claude reply to comments on its own

After your session publishes an artifact, Claude Code watches that artifact for comments. When someone who can edit the artifact sends a comment to Claude, it reaches your session right away, and Claude can read the thread and reply without you asking.

You need Claude Code v2.1.228 or later. If you turned [feature-flag fetching](<https://code.claude.com/docs/en/env-vars#features-that-need-feature-flag-fetching>) off, Claude Code doesn't watch for comments.

Your [permission mode](<https://code.claude.com/docs/en/permission-modes>) decides what Claude does when a sent comment arrives:

* **Claude replies on its own**: when your permission mode lets Claude post the reply without asking you, Claude reads the thread and replies, and edits the artifact when the comment asks for a change. You see `Auto-replied to comment thread on Artifact: <name>` or `Auto-edited Artifact: <name> in response to a comment thread`.
* **Claude waits for you**: outside plan mode, when posting the reply would need your approval, you see `Comments are waiting on Artifact: <name>`. Claude then asks you for approval to read the thread, and again to post the reply.
* **Claude pauses in plan mode**: you see `Comments are waiting on Artifact: <name>`, and Claude doesn't reply until you leave plan mode and ask it to read and reply.

Claude also stops replying on its own to an artifact after it handles 60 sent comments or thread activations on that artifact within an hour. You see `Comments are waiting on Artifact: <name>` once, and Claude picks up again as that hour's comments age out.

Run `/tasks` to see the artifacts your session is watching. `/tasks` groups the watches Claude Code started on its own under the **System tasks** row. Press `Enter` on that row to list them. A watch you asked Claude to start appears under **Monitors**.

You can stop Claude from replying on its own in any of these ways:

* **Press Ctrl+C once at an idle prompt**: Claude pauses replying on every artifact your session is watching. Replies start again after you send your next message.
* **Stop the task in `/tasks`**: Claude stops replying on that artifact until you ask it to resume replies there. Publishing the artifact again doesn't start replies again, and the stop still applies when you resume the session later.
* **Press `Ctrl+X Ctrl+K` twice within 3 seconds**: the chord that [stops every running background subagent](<https://code.claude.com/docs/en/interactive-mode#general-controls>) also stops Claude from replying on every artifact for the rest of the session. Asking Claude to resume replies doesn't undo this stop.

A watch that Claude Code started on its own can end after the artifact goes several hours without activity. To start the watch again, publish the artifact again or ask Claude to watch it.

If the service that delivers comments becomes unavailable or stops answering, Claude Code keeps trying to reconnect for a while, then stops watching each artifact your session was watching.

## Pull live data with MCP connectors

An artifact can call [MCP connectors](<https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claude-ai>) each time someone views it, so the page shows current data rather than a snapshot from the session that built it. Connector calls from artifacts are available on Pro, Max, Team, and Enterprise plans and require Claude Code v2.1.209 or later. On earlier versions, Claude publishes the page with whatever data the session gathered while building it.

To create a connector-backed page, name the connector and the data you want in your prompt:

```text wrap theme={null}
Build a dashboard artifact of our open pull requests that pulls the live list through my GitHub connector when the page loads.
```

Claude declares which connectors the page may call as part of publishing, and the page can't call connectors outside that declaration. Only connectors from your claude.ai account qualify: Claude names them in the declaration, and when someone views the page, each call [runs through the viewing account's own connection](<#how-connector-calls-work-for-viewers>) to that connector. Local MCP servers you configure in Claude Code, such as servers from `.mcp.json`, can supply data while Claude builds the page, but the published page can't call them.

The page fetches data when it loads and can refresh on an interval or when a viewer uses a refresh control on the page. Responses are cached in the viewer's browser, so a reopened page renders from the cached responses immediately, then updates with fresh results.

### How connector calls work for viewers

When a published page calls a connector, the call uses the account of the person viewing the page, not the account of the person who published it:

* **Each viewer uses their own connectors**: calls go through the viewing account's connected tools, so two people opening the same dashboard can see different data depending on what their accounts can access. The page never sees anyone's credentials; claude.ai makes the calls on the page's behalf.
* **Viewers approve access first**: claude.ai asks each viewer for permission before the page's first connector call. A viewer who declines, or who hasn't connected a connector the page uses, still sees the page without its live sections.
* **Actions use the viewer's account too**: a page can offer controls that invoke connector tools with side effects, such as posting a message or updating an issue. The action goes through the account of whoever selects the control.

When you plan to share a connector-backed page, ask Claude to include a fallback message in each live section that names the connector it needs. A viewer who's missing the connection then sees what to connect instead of an empty section.

You can [share a connector-backed page](<#share-an-artifact>) within your organization or publicly, as your plan and organization settings allow. Connector calls don't run for a viewer who opens the public link without signing in to claude.ai, or from outside your organization. That viewer sees the page without its live sections.

### The page shows no live data for a viewer

When a connector-backed page renders but its live sections stay empty for a viewer in your organization, work through these causes:

* **The viewer hasn't connected the connector**: connectors are per-account, so each viewer needs their own connection to every connector the page calls. They can add one under **Settings > Connectors** on claude.ai, then reload the page.
* **The viewer declined the permission ask**: a denial lasts for the rest of that page load. Reloading the page brings the permission ask back.
* **Connector calls are turned off for the organization**: an Owner controls the [**Enable artifact connectors** toggle](<#control-connector-calls-from-artifacts>) in admin settings.
* **The page calls tool names the connector doesn't expose**: the affected sections stay empty for everyone, including you. This can happen when a page names the individual tools behind a gateway-style connector that exposes only a few tools of its own. Ask Claude to fix the tool names the page calls and publish it again.

  When Claude publishes the page and that connector's tools are available in your session, Claude Code checks the tool names the page declares against them, warns Claude about names that don't match, and refuses the publish when none do. Before v2.1.265, it published the page without checking them.

## Offer a file download

An artifact can offer viewers a file the page generates, such as a CSV export of a table or a PNG of a chart. The viewer saves it through a download control on the page, such as a button. File downloads are a runtime capability that claude.ai enables per account, so Claude checks whether your account has it before it builds the control.

Viewers can't save a file from an ordinary download link or a script on the page, because the artifact viewer on claude.ai blocks any download the page starts itself, including links to `data:` or `blob:` URLs. If a page has download buttons built that way, ask Claude to rebuild them with the downloads capability.

To offer a file, ask for the control and the file format in your prompt:

```text wrap theme={null}
Add a button that downloads this table as a CSV file.
```

Claude declares the downloads capability as part of publishing, the same way it [declares connectors](<#pull-live-data-with-mcp-connectors>).

## What you can build

An artifact is a single HTML page, so anything you can express in HTML, CSS, and inline JavaScript is in scope. The patterns below come up most often.

### Walk through a change

Ask for a page that renders a diff or a design change with annotations beside the relevant lines, so reviewers can read your reasoning next to the code instead of reconstructing it from a description.

```text wrap theme={null}
Make an artifact that walks through this PR. Render the diff with margin annotations and color-code findings by severity.
```

### Compare alternatives

Ask for several variants on one page so you can evaluate them against each other. This works for layouts, copy, API shapes, or implementation plans.

```text wrap theme={null}
Make an artifact with four distinctly different layouts for the settings panel. Vary density and grouping, and lay them out as a grid with a one-line tradeoff under each.
```

### Tune with interactive controls

Ask for sliders, toggles, or input fields bound to whatever you are adjusting, so you can explore values directly instead of describing them.

```text wrap theme={null}
Build an artifact with sliders for the easing curve, duration, and delay so I can try values on this transition. Show the animation live as I move them.
```

### Bring the result back to your session

An artifact can act as a lightweight editor for a decision you then send back to Claude. Ask for an export control that produces text you can paste into the terminal, so the result of interacting with the page flows back into the session instead of staying on the page.

```text wrap theme={null}
Make a triage board artifact with each open issue as a draggable card across Now, Next, Later, and Cut columns. Add a "Copy as prompt" button that gives me the final ordering to paste back here.
```

### Track work in progress

Ask Claude to keep an artifact current while a long task runs, so anyone with the link can follow along without reading the terminal.

```text wrap theme={null}
Turn this migration plan into a checklist artifact. Check items off as you complete them and add a note for anything you skip.
```

## Improve the visual design

Claude applies a built-in design skill when it builds an artifact, so pages get a deliberate palette, typography, and layout without extra prompting. That skill also looks for an existing design system in your project before choosing its own. Design tokens are the named color, typography, and spacing values your design system reuses. To keep artifacts consistent with your product's branding, record them where Claude can find them, such as the project's [CLAUDE.md](<https://code.claude.com/docs/en/memory>) or a theme file in your repository:

```markdown theme={null}
## Design system

- Colors: primary #1a4d8f, accent #f59e0b, surface #f8fafc
- Typography: Inter for body, JetBrains Mono for code
- Spacing: 8px scale, 6px border radius
```

Claude treats your design system as higher precedence than its own choices, and your prompt as higher precedence than both. The heading and format above are an example; any clear list of colors, fonts, and spacing works.

For typography, Claude can load a typeface from Google Fonts, the one external font source an artifact page can load from. Claude inlines any other typeface as a `@font-face` data URI and gives every typeface a fallback stack, so the page still renders if a font doesn't load. To use a specific typeface, name it in your prompt or your design system.

## Start from a Slides, Design, or Docs template

Instead of building a page from scratch, Claude can start an artifact from one of the templates on your claude.ai account: [Claude Slides](<https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them#h_11d5a9a5fa>) for a presentation, [Claude Design](<https://support.claude.com/en/articles/14604416-get-started-with-claude-design>) for a visual design, or [Claude Docs](<https://support.claude.com/en/articles/16923645-get-started-with-claude-docs>) for a document other people will read and edit. Each opens in its own editor on claude.ai, where you and your teammates change it directly or ask Claude to, and export it to formats such as PowerPoint, PDF, or Word.

To start from a template, describe what you want, such as "turn the migration notes into a deck for Thursday's review" or "write this plan up as a doc for the team". Claude picks the matching template, fills it from your request and from what the session already has, and gives you the link. For a deck or a design you can also run `/slides` or `/design` with a brief.



**注释：**

  Templates are in beta. They're on by default on Pro, Max, and Team plans. On Enterprise plans, an Owner [turns each template on](<https://support.claude.com/en/articles/16994751-artifacts-admin-guide-for-team-and-enterprise-plans>) under **Organization settings > Artifacts**. If your organization has the Slides template turned off, `/slides` doesn't appear; if it has the Design template turned off, `/design` doesn't draft designs. Both commands require Claude Code v2.1.265 or later and a session where [artifacts are available](<#availability>).


### Make a slide deck

Run `/slides` with a brief that says what the deck covers and who it's for:

```text wrap theme={null}
/slides a quarterly review of the platform team's reliability work, for the engineering all-hands
```

Claude creates a Claude Slides artifact and gives you the link. Open it in a desktop browser to edit or present the deck. If you run `/slides` without a brief, Claude asks what the deck should be about before creating anything.

### Draft a design canvas

To mock up a UI, a screen flow, a landing page, or a poster rather than build a page, run `/design` with a brief. Claude drafts the design as artboards on one canvas and publishes the canvas as a Claude Design artifact. The brief names what you want drawn:

```text wrap theme={null}
/design a settings screen for a mobile banking app
```

Open the published artifact in a desktop browser to review the artboards. Select an element on an artboard and change it, and your edits save automatically. You can export each artboard as PNG or PDF.

### Write a document with Claude Docs

Claude Docs reaches Claude Code as a claude.ai [connector](<https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claude-ai>) rather than a command. When it's connected, `/mcp` lists it as `claude.ai Claude Docs`. A request for a document meant for other people then goes to Claude Docs instead of an artifact page: a spec, a proposal, or a write-up of the plan you worked through in the session. Claude gives you the doc's link when it's drafted.

A document that belongs in the codebase, such as a README, stays a file. To get a file for something Claude would otherwise put in Claude Docs, name the format, such as `.docx` or a Markdown file in the repository.

To turn the connector off, add `claude.ai Claude Docs` to `deniedMcpServers` or use the `/mcp` toggle, both described in [Disable claude.ai connectors](<https://code.claude.com/docs/en/mcp#disable-claude-ai-connectors>).

## Page constraints

Each artifact is one self-contained page. Claude Code wraps the file you publish in an HTML document shell and serves it under a strict Content Security Policy (CSP), which shapes what the page can do.

| Constraint | Effect |
| :- | :- |
| External requests | The page can load typefaces from Google Fonts, and scripts from [five public CDN hosts](<#allowlist-the-viewer-domain>): cdnjs, unpkg, the Tailwind and jQuery CDNs, and selected paths on jsDelivr such as `/npm/`. The CSP blocks every external image and all other external scripts, stylesheets, and fonts, and lets `fetch`, XHR, and WebSocket calls reach only the page's own origin and the Google Fonts hosts. Claude therefore loads any library the page needs from one of those CDNs, inlines all other CSS and JavaScript, and embeds images as data URIs. [Connector calls](<#pull-live-data-with-mcp-connectors>) go through claude.ai, which makes the network call itself. |
| No backend | An artifact is a static page. It can't authenticate viewers itself. |
| Downloads | The page can't start a download itself. To let viewers save a file the page generates, Claude declares the downloads capability. See [Offer a file download](<#offer-a-file-download>). |
| Single page | Relative links do not resolve, because nothing is deployed alongside the page. For multi-section content, Claude uses in-page anchors rather than separate files. |
| Source file types | The published file must be `.html`, `.htm`, or `.md`, and must decode as UTF-8, or as little-endian UTF-16 by its byte-order mark. Markdown files render as styled document pages with syntax-highlighted code. A file that doesn't decode, or that contains the replacement character `U+FFFD`, is [refused with the line and column to fix](<https://code.claude.com/docs/en/errors#the-source-file-is-not-valid-utf-8-text>). |
| Source location | A file at a path that names a network host is refused without being read. See [Not published: that file is on a network share](<https://code.claude.com/docs/en/errors#not-published-that-file-is-on-a-network-share>) for which paths are refused and the mapped-drive exception on Windows. |
| Rendered size | The rendered page must be 16 MiB or smaller. Large embedded images are the usual cause when a publish fails for size. |

Generating an artifact uses output tokens like any other response, and a styled page is more token-intensive than the same content as terminal text. Inline CSS, JavaScript for interactive controls, and especially images embedded as data URIs are the main contributors. To reduce an artifact's token cost:

* Prefer SVG, or HTML and CSS, for diagrams over embedded raster images
* Omit interactivity you do not need
* Have the page summarize large datasets rather than inline them in full

## Availability

Artifacts require every condition below. When one is not met, Claude writes a local HTML file or says it cannot publish instead.

| Requirement | Available when |
| :- | :- |
| Plan | Pro, Max, Team, or Enterprise. On Pro and Max plans, artifacts are private to you until you share them, and no admin management applies. On Team and Enterprise plans, artifacts are on by default, and an Owner can [turn them off for the organization](<#manage-artifacts-for-your-organization>) in claude.ai admin settings. |
| Authentication | The session is backed by a claude.ai account: sign in with `/login` in the CLI or desktop app. Claude Tag sessions are signed in through the agent's identity, so no step is needed there. Sessions using an API key, [gateway token](<https://code.claude.com/docs/en/llm-gateway>), or cloud-provider credential cannot publish. |
| Model provider | Anthropic API. Not available on [Amazon Bedrock](<https://code.claude.com/docs/en/amazon-bedrock>), [Google Cloud's Agent Platform](<https://code.claude.com/docs/en/google-vertex-ai>), or [Microsoft Foundry](<https://code.claude.com/docs/en/microsoft-foundry>). |
| Organization policy | Customer-managed encryption keys (CMEK), HIPAA, and [Zero Data Retention](<https://code.claude.com/docs/en/zero-data-retention>) are not enabled for the organization. |
| Surface | Claude Code CLI, or the Claude desktop app version 1.13576.0 or later. [Claude Tag](<https://claude.com/docs/claude-tag/overview>) sessions can also publish artifacts when both Claude Tag and artifacts are enabled for the organization. Sessions served by [`claude remote-control`](<https://code.claude.com/docs/en/remote-control>) can publish artifacts when you started the session yourself. Requires Claude Code v2.1.281 or later. Off by default in the [Agent SDK](<https://code.claude.com/docs/en/agent-sdk/overview>), the GitHub Action, and MCP-server contexts, when you run Claude Code with [`-p`](<https://code.claude.com/docs/en/headless>) from your own terminal or scripts, and when [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](<https://code.claude.com/docs/en/env-vars>) is set. |

Whether artifacts are allowed for your organization comes from your organization's policy, which Claude Code loads from `api.anthropic.com`. When Claude Code can't load the policy, artifacts are unavailable. When you ask for one, Claude says why.

If a proxy, VPN, or web filter is involved, ask your IT admin to let `api.anthropic.com` through. Claude Code keeps retrying in the background, and artifacts become available once the policy loads and allows them.

## Disable artifacts

To turn artifacts off for your own sessions regardless of your organization's setting, use any of:

| Where | What to do |
| :- | :- |
| [`/config`](<https://code.claude.com/docs/en/commands>) | Turn the **Artifacts** row off, which writes [`"enableArtifact": false`](<https://code.claude.com/docs/en/settings-reference#enableartifact>) to your user settings |
| [Settings file](<https://code.claude.com/docs/en/settings>) | Set `"enableArtifact": false`. The deprecated `"disableArtifact": true` also turns artifacts off |
| [Environment variable](<https://code.claude.com/docs/en/env-vars>) | Set `CLAUDE_CODE_DISABLE_ARTIFACT=1` |
| [Permission rule](<https://code.claude.com/docs/en/permissions>) | Add `Artifact` to `permissions.deny` |

Once you turn artifacts off in a [`--settings`](<https://code.claude.com/docs/en/cli-reference#cli-flags>) file or with `CLAUDE_CODE_DISABLE_ARTIFACT`, or your administrator turns them off in [managed settings](<https://code.claude.com/docs/en/server-managed-settings>), no settings file turns them back on.

You can also set `"enableArtifact": false` in a project's `.claude/settings.json` or `.claude/settings.local.json` to turn artifacts off for sessions in that project. An `"enableArtifact": true` in either file doesn't turn them back on. Honoring the key in project and local settings requires Claude Code v2.1.242 or later.

If you add a `WebFetch` deny or ask rule with no `domain:` part, it doesn't turn artifacts off or block artifact reads. A [`WebFetch(domain:claude.ai)` rule in `deny` or `ask` does apply to artifact reads](<https://code.claude.com/docs/en/permissions#allow-or-deny-every-fetch>).

## Manage artifacts for your organization

Owners on Team and Enterprise plans control artifacts from [claude.ai admin settings](<https://claude.ai/admin-settings/artifacts>). Artifact content is stored on Anthropic-operated infrastructure and is visible only to authenticated members of the publishing organization and the people they share it with, unless the artifact is [shared publicly](<#control-public-sharing>).

### Enable or disable artifacts

To enable or disable artifacts for the whole organization, go to [**Organization settings > Artifacts**](<https://claude.ai/admin-settings/artifacts>) and use the **Artifacts** toggle. On Enterprise plans with role-based access control, you can additionally scope artifacts to specific roles: go to [**Organization settings > Roles**](<https://claude.ai/admin-settings/roles>), edit a role, and set the **Artifacts** permission.

### Control connector calls from artifacts

[Connector calls from artifacts](<#pull-live-data-with-mcp-connectors>) have their own toggle, separate from the **Artifacts** toggle that turns artifacts on or off. Go to [**Organization settings > Capabilities**](<https://claude.ai/admin-settings/capabilities>) and use the **Enable artifact connectors** toggle. The same toggle governs connector calls from artifacts created in claude.ai conversations.

### Control public sharing

Public sharing is off by default on Team and Enterprise plans. To let members publish artifacts to public links that anyone can view without signing in, go to [**Organization settings > Artifacts**](<https://claude.ai/admin-settings/artifacts>) and turn on **External sharing** under the **Artifacts** toggle. Turning it back off blocks access through existing public links without changing each artifact's audience; access resumes if you re-enable it.

### Set a retention policy

To set how long artifacts are kept before automatic deletion, go to [**Organization settings > Data and privacy**](<https://claude.ai/admin-settings/data-privacy-controls>). You can set separate retention periods for artifacts that are still private to their author and artifacts that have been shared.

### Review the audit log

Publishing, sharing, and deleting an artifact each appear in your organization's audit log under the `claude_artifact_*` event types, the same family used for artifacts created in claude.ai conversations.

### Allowlist the viewer domain

The viewer on claude.ai loads each artifact from a sandboxed `*.claudeusercontent.com` origin. If your organization restricts outbound network access, add that domain to your allowlist alongside `claude.ai`. See [Network access requirements](<https://code.claude.com/docs/en/network-config#network-access-requirements>) for the full list.

An artifact that loads a typeface from [Google Fonts](<#improve-the-visual-design>) also requests `fonts.googleapis.com` and `fonts.gstatic.com`. Both hosts are optional. If you block them, artifacts render in fallback typefaces. Block with a fast rejection rather than a silent drop so the font request fails immediately instead of delaying the page's first render.

Artifacts can also load JavaScript libraries, such as React or a charting package, from `cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `cdn.tailwindcss.com`, `code.jquery.com`, and `unpkg.com`, and from no other external host. If you block those hosts, the parts of an artifact that depend on a library don't work, and unlike a blocked font, a blocked library has no fallback. Block with a fast rejection here too, so a blocked library request fails at once rather than hanging until it times out.

### List and delete artifacts with the Compliance API

The [Compliance API](<https://docs.claude.com/en/api/compliance>) provides endpoints to list an organization's artifacts, retrieve a specific version's content, and delete an artifact:

| Method | Endpoint |
| :- | :- |
| `GET` | `/v1/compliance/code/artifacts` |
| `GET` | `/v1/compliance/code/artifacts/{artifact_id}/versions/{version_id}` |
| `DELETE` | `/v1/compliance/code/artifacts/{artifact_id}` |

For the request and response schemas, see the [Compliance API reference](<https://docs.claude.com/en/api/compliance/code/artifacts>).
