## 中文全文

# Vercel Webhook 管理的沙箱

端点验证签名并将会话 ID 发送到 Vercel 队列。
 使用者检索当前会话状态并启动命名沙箱。 OS 锁
防止并发作业安装两次或启动重复的执行程序。

## 部署

使用 Node.js 24+ 以及具有沙箱和队列访问权限的专用 Vercel 项目。
请参阅 [ 提供商概述 ](<Vercel 沙箱集成入口.md>)。使用
[共享设置](<Webhook 管理沙箱的总入口.md#设置一次>)创建agent，然后从
此目录运行：

```bash
npm ci
npx vercel link
uv run client.py --create-agent vercel-webhook-example
```

在项目的生产环境变量中配置：

- `OPENAI_API_KEY`：controller/session-read 凭证。
- `OPENAI_AGENT_ID`：共享设置中的agent ID。
- `OPENAI_EXECUTOR_API_KEY`：受限执行者凭证。
- `OPENAI_WEBHOOK_SECRET`：注册端点时由OpenAI生成。

仅对于第一次部署，使用 `pending-webhook-registration` 作为签名 
 值；接收方以 `503` 拒绝它。

```bash
npx vercel --prod
```

Webhook URL 是 `https://YOUR_PROJECT.vercel.app/api/webhook`。 OpenAI 必须能够
 无需登录即可访问它。使用专用项目及其生产URL；
配置部署保护，以便OpenAI可以到达接收器。 Webhook
签名对请求进行身份验证，Vercel 的队列触发器调用使用者。

注册 Webhook，将签名值替换为真实密钥，然后重新部署。
然后使用 [ 客户端并重新连接流 ](<Webhook 管理沙箱的总入口.md#运行并重新连接>)
 与此目录的客户端：

```bash
uv run client.py --agent-id "$OPENAI_AGENT_ID"
uv run client.py --session-id "$SESSION_ID" --input "Run another shell command."
```

环境变量更改需要新的部署。

## 停止或清理

沙箱名称为 `agents-`，后跟 API 会话 ID。在 Vercel
Sandbox 仪表板中停止它，以在回合之间释放计算；删除它及其快照
以进行最终清理。
删除沙箱不会删除保留的快照。同时删除 API 会话。

命名沙箱在运行之间保存文件；必须重新启动进程。
执行程序在首次使用时安装。对于常规使用，请将其烘焙到沙箱 
 快照中以减少连接延迟。在删除 
 示例项目之前删除 OpenAI webhook。

请参阅[应用程序管理模式](<应用管理 Vercel 沙箱样例.md>)以进行直接配置。

# Vercel webhook-managed sandbox

The endpoint verifies the signature and sends the session ID to Vercel Queues.
The consumer retrieves current session state and starts a named sandbox. OS locks
prevent concurrent jobs from installing twice or starting duplicate executors.

## Deploy

Use Node.js 24+ and a dedicated Vercel project with Sandbox and Queues access.
See the [provider overview](<Vercel 沙箱集成入口.md>). Create the agent using the
[shared setup](<Webhook 管理沙箱的总入口.md#set-up-once>), then run from
this directory:

```bash
npm ci
npx vercel link
uv run client.py --create-agent vercel-webhook-example
```

In the project's production environment variables, configure:

- `OPENAI_API_KEY`: controller/session-read credential.
- `OPENAI_AGENT_ID`: agent ID from the shared setup.
- `OPENAI_EXECUTOR_API_KEY`: restricted executor credential.
- `OPENAI_WEBHOOK_SECRET`: generated by OpenAI when registering the endpoint.

For the first deployment only, use `pending-webhook-registration` as the signing
value; the receiver rejects it with `503`.

```bash
npx vercel --prod
```

The webhook URL is `https://YOUR_PROJECT.vercel.app/api/webhook`. OpenAI must be able
to reach it without a login. Use a dedicated project and its production URL;
configure deployment protection so OpenAI can reach the receiver. The webhook
signature authenticates requests, and Vercel's queue trigger invokes the consumer.

Register the webhook, replace the signing value with the real secret, and redeploy.
Then use the [client and reconnect flow](<Webhook 管理沙箱的总入口.md#run-and-reconnect>)
with this directory's client:

```bash
uv run client.py --agent-id "$OPENAI_AGENT_ID"
uv run client.py --session-id "$SESSION_ID" --input "Run another shell command."
```

Environment-variable changes require a new deployment.

## Stop or clean up

The sandbox name is `agents-` followed by the API session ID. Stop it in the Vercel
Sandbox dashboard to release compute between turns; delete it and its snapshots
for final cleanup.
Deleting a sandbox does not delete retained snapshots. Also delete the API session.

Named sandboxes preserve files between runs; processes must be restarted.
The executor is installed on first use. For regular use, bake it into a sandbox
snapshot to reduce connection latency. Remove the OpenAI webhook before deleting the
example project.

See the [application-managed mode](<应用管理 Vercel 沙箱样例.md>) for direct provisioning.
