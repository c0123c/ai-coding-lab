# 线束感知评估示例

与 [插件的线束感知评估 ](<https://github.com/openai/openai-cookbook/blob/5bd6cb40b6b84b69b2032d810610aa85064102df/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals.ipynb>) 食谱配套。
有关每种评估方法的目的和权衡，请参阅食谱。
此 README 逐步完成运行示例所需的步骤。

在运行以下命令之前，从存储库根目录更改到此示例目录：

```bash
cd examples/partners/harness_aware_plugin_evals
```

笔记本电脑`harness_aware_plugin_evals.ipynb`从上到下运行文章，无需API键。
使用`uv run jupyter lab harness_aware_plugin_evals.ipynb`打开它。它从 `uv.lock` 同步其自己的依赖项 
，实时运行直接工具测试，并通过相同的 
 分级器重播 `data/` 下记录的运行。在 `.env` 中设置 `RUN_LIVE=1` 运行独立循环，并通过付费 API
 调用运行 Codex。除非您重复下面的 
“修复它”中的步骤，否则带有服务器指令的 Codex 结果将保持记录。只有实时独立循环和 Codex 运行需要 API 键。

每个安装、配置和运行步骤都是一个 Make 目标。
有关实际命令，请参阅 [Makefile](<https://github.com/openai/openai-cookbook/blob/5bd6cb40b6b84b69b2032d810610aa85064102df/examples/partners/harness_aware_plugin_evals/Makefile>)。

## 先决条件

- [uv](<https://docs.astral.sh/uv/getting-started/installation/>).
- Python 3.11+ (`uv python install 3.11`).
- [Node.js 和 npm](<https://nodejs.org/en/download>)：20.x 行中的 Node.js 20.20.x 或更高版本，或 22.22.0 或更高版本，根据锁定的提示foo 版本的要求。 npm 随 Node.js 一起发货。
- 用于独立循环的 OpenAI API 键和 Codex
- 独立循环和 Codex 可能会产生额外成本。使用本示例中的默认设置，每次运行大约为 $0.01

## 设置

```bash
make setup
```

安装 Python 和节点依赖项，如果需要，从 `.env.example`
 创建 `.env`，将绝对 `CODEX_HOME` 和 `PROMPTFOO_PYTHON` 写入 `.env`，然后 
 生成Codex `config.toml` 与本地市场路径。

然后在`.env`中设置`OPENAI_API_KEY`。独立循环和Codex使用它。

`PROMPTFOO_PYTHON` 必须指向该项目的 virtualenv。 Promptfoo 在其自己的工作线程中运行 
Python 提供程序和断言；如果它选择另一个
解释器，则运行会因缺少导入而挂起，而不是彻底失败。

## 直接工具测试

直接 `resolve` 调用结构化 `indicator` 字段。
没有模型，没有 API 密钥，没有 MCP 服务器。如果任何情况失败，脚本将以非零值退出。

```bash
make level-1
```

## 用于独立循环的 MCP 服务器和 Codex

这些方法通过 `127.0.0.1:8000` 上的 HTTP 调用夹具服务器。它从少数 
 硬编码系列中进行回答，因此它可以离线运行并且不需要 BLS API 密钥。在此目录的 ** 单独终端 **
 中启动它并保持运行：

```bash
make server
```

评估完成后，您可以使用 Ctrl-C 停止它。

## 独立函数调用循环

模型通过promptfoo在一个小的函数调用循环中驱动MCP工具。
需要来自另一个终端的服务器。

```bash
make level-2
```

结果转到 `outputs/l2-results.json`。使用 `npx promptfoo view` 打开迹线。

## 产品线束（Codex）

通过 Codex SDK 提供程序进行相同的查询，并将示例插件安装到本地 `CODEX_HOME` 中 
。需要来自另一个终端的服务器。
安装插件，然后运行promptfoo。

```bash
make level-3
```

结果转到 `outputs/l3-results.json`。使用 `npx promptfoo view` 打开迹线。

在本示例提供的保存的评估结果中，`consumer-price-index` 和 `employment-ambiguous` 在独立循环中通过，在 Codex 下失败。独立循环指示模型不
发明系列 ID 并询问候选人何时打平。没有什么告诉Codex相同，因此它根据自己的知识提供了
CPI系列ID。对于就业案例，Codex 可能会在 
 调用 `resolve` 之前缩小请求范围，然后选择其中一位并列候选人，或者获取两者。确切的路径在运行之间有所不同
，但每次都会检索至少一个系列而不是停下来进行澄清，因此评分器
失败了。

`data/l3-trace-before.json` 下记录的运行得分为 3 分（满分 5 分）。这两种情况都取决于
模型所采用的路径，因此新的运行可能会出现不同的计数。

### 修复它

MCP服务器可以在其`instructions`字段中发布此指南。定义
`server.py`中的文本并将其传递到服务器：

```python
GUIDANCE = """Answer only from this catalog. Call resolve first, passing the indicator the user
asked about without narrowing it. Pass fetch_bls_data only the series IDs that resolve returned,
never one from your own knowledge. If resolve returns no candidate, say the data is unavailable. If
several candidates tie for the best confidence, do not call fetch_bls_data at all. Name them and ask
which one the user wants."""

mcp = FastMCP("BLS evaluation fixture", instructions=GUIDANCE)
```

服务器在 `initialize` 响应中发送 `instructions`。 Codex 读取该字段并将其传递给 
 模型，因此指导到达 Codex，无需对工具或解析器进行任何更改。
重新启动服务器并再次运行 `make level-3`。在包含的记录运行 (`data/l3-trace-after.json`) 中，所有五种情况均通过。
在 ChatGPT 桌面应用程序中可以观察到相同的行为变化。

独立循环忽略该字段并使用其自己的系统提示符。对于这两种方法，相同的
文本位于同一服务器上，并且只有读取它的线束
受到影响。

`CODEX_HOME` 必须是本地的，在安装时生成。否则，Codex
从用户默认主目录开始，插件丢失，并且模型无法
调用`resolve`或`fetch_bls_data`。

# Harness-aware eval example

Companion to the [Harness-aware evaluation of plugins](<https://github.com/openai/openai-cookbook/blob/5bd6cb40b6b84b69b2032d810610aa85064102df/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals.ipynb>) cookbook.
Refer to the cookbook for the purpose and tradeoffs of each evaluation approach.
This README walks through the steps required to run the example.

From the repository root, change to this example directory before running the commands below:

```bash
cd examples/partners/harness_aware_plugin_evals
```

The notebook `harness_aware_plugin_evals.ipynb` runs the article top to bottom without an API key.
Open it with `uv run jupyter lab harness_aware_plugin_evals.ipynb`. It syncs its own dependencies
from `uv.lock`, runs the direct tool tests live, and replays the recorded runs under `data/` through the same
graders. Setting `RUN_LIVE=1` in `.env` runs the standalone loop and Codex with paid API
calls. The Codex result with server instructions remains recorded unless you reproduce the steps in
"Fixing it" below. Only the live standalone loop and Codex runs require an API key.

Every install, config, and run step is a Make target.
See the [Makefile](<https://github.com/openai/openai-cookbook/blob/5bd6cb40b6b84b69b2032d810610aa85064102df/examples/partners/harness_aware_plugin_evals/Makefile>) for the actual commands.

## Prerequisites

- [uv](<https://docs.astral.sh/uv/getting-started/installation/>).
- Python 3.11+ (`uv python install 3.11`).
- [Node.js and npm](<https://nodejs.org/en/download>): Node.js 20.20.x or later in the 20.x line, or 22.22.0 or later, as required by the locked promptfoo version. npm ships with Node.js.
- An OpenAI API key for the standalone loop and Codex
- The standalone loop and Codex can incur additional cost. With the default settings in this example it is roughly $0.01 per run

## Setup

```bash
make setup
```

That installs Python and Node dependencies, creates `.env` from `.env.example`
if needed, writes absolute `CODEX_HOME` and `PROMPTFOO_PYTHON` into `.env`, and
generates Codex `config.toml` with the local marketplace path.

Then set `OPENAI_API_KEY` in `.env`. The standalone loop and Codex use it.

`PROMPTFOO_PYTHON` must point at this project's virtualenv. Promptfoo runs the
Python provider and assertions in its own worker; if it picks another
interpreter, the run hangs on a missing import instead of failing cleanly.

## Direct tool tests

Direct `resolve` calls on the structured `indicator` field.
No model, no API key, no MCP server. The script exits non-zero if any case fails.

```bash
make level-1
```

## MCP server for the standalone loop and Codex

Those approaches call the fixture server over HTTP on `127.0.0.1:8000`. It answers from a handful of
hardcoded series, so it runs offline and needs no BLS API key. Start it in a **separate terminal**
from this directory and leave it running:

```bash
make server
```

You can stop it with Ctrl-C when the evals are done.

## Standalone function-calling loop

A model drives the MCP tools in a small function-calling loop through promptfoo.
Requires the server from the other terminal.

```bash
make level-2
```

Results go to `outputs/l2-results.json`. Open traces with `npx promptfoo view`.

## Product harness (Codex)

The same queries through the Codex SDK provider, with the example plugin installed
into the local `CODEX_HOME`. Requires the server from the other terminal.
Installs the plugin, then runs promptfoo.

```bash
make level-3
```

Results go to `outputs/l3-results.json`. Open traces with `npx promptfoo view`.

In the saved evaluation results supplied with this example, `consumer-price-index` and `employment-ambiguous` pass in the standalone loop and fail under Codex. The standalone loop instructs the model not
to invent series IDs and to ask when candidates tie. Nothing tells Codex the same, so it supplies a
CPI series ID from its own knowledge. For the employment case, Codex may narrow the request before
calling `resolve`, choose one of the tied candidates afterward, or fetch both. The exact path varies
between runs, but each retrieves at least one series instead of stopping to clarify, so the grader
fails it.

The recorded run under `data/l3-trace-before.json` scores three out of five. Both cases depend on
the path the model takes, so a fresh run can land on a different count.

### Fixing it

The MCP server can publish this guidance in its `instructions` field. Define the text in
`server.py` and pass it to the server:

```python
GUIDANCE = """Answer only from this catalog. Call resolve first, passing the indicator the user
asked about without narrowing it. Pass fetch_bls_data only the series IDs that resolve returned,
never one from your own knowledge. If resolve returns no candidate, say the data is unavailable. If
several candidates tie for the best confidence, do not call fetch_bls_data at all. Name them and ask
which one the user wants."""

mcp = FastMCP("BLS evaluation fixture", instructions=GUIDANCE)
```

Servers send `instructions` in the `initialize` response. Codex reads that field and passes it to
the model, so the guidance reaches Codex without any change to the tools or the resolver.
Restart the server and run `make level-3` again. In the included recorded run (`data/l3-trace-after.json`), all five cases pass.
The same behavior change can be observed in the ChatGPT desktop app.

The standalone loop ignores that field and uses its own system prompt. The same
text is on the same server for both approaches, and only the harness that reads it is
affected.

`CODEX_HOME` must be the local one, generated at setup. Otherwise Codex
starts with the user default home, the plugin is missing, and the model cannot
call `resolve` or `fetch_bls_data`.

## Environment

| Variable | Role |
|---|---|
| `OPENAI_API_KEY` | Required for the standalone loop and Codex |
| `MCP_URL` | MCP endpoint for the standalone loop. The server reads it from its process environment |
| `EVAL_MODEL` | Model id for promptfoo |
| `EVAL_REASONING_EFFORT` | Reasoning effort passed to the provider |
| `PROMPTFOO_PYTHON` | Interpreter for promptfoo's Python workers |
| `CODEX_HOME` | Isolated Codex home with the plugin installed |

The standalone loop reads `MCP_URL` from `.env`. The `make server` target does not load `.env`, so when
changing the endpoint, also pass it to the server, for example:

```bash
MCP_URL=http://127.0.0.1:8001/mcp make server
```

Codex reads the URL from the plugin's own `.mcp.json`. Update that URL too so the standalone loop and Codex
connect to the same server.
