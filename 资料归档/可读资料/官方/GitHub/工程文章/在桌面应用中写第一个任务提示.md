# GitHub Copilot 适合初学者的应用程序：编写您的第一个提示

打开新的 AI 工具感觉有点像盯着空白页。您知道自己在某件事上需要帮助，但弄清楚到底要问什么可能是它自己的任务。

好消息是您不需要编写完美的提示即可开始。提示只是对您想要完成的任务的描述。从您所知道的开始，为 Copilot 提供一些背景信息，并随时完善请求。

让我们来看看在 [GitHub Copilot 应用程序 ](<https://github.com/features/ai/github-app?utm_source=blog-copilot-app-ep2&utm_medium=blog&utm_campaign=copilot-app-for-beginners-series>) 中开始第一个任务的样子。

## 从正确的背景开始

在您可以要求 Copilot 进行更改之前，需要进行一些工作。 Agent 会话可以连接到 GitHub 存储库或本地计算机上的文件夹，从而使 Copilot 能够访问任务所需的代码和文件。

在 GitHub Copilot 应用程序主屏幕中，您可以选择以前使用过的项目或添加新项目。

如果您正在处理仅在您的计算机上的代码，则可以添加本地文件夹。无论哪种方式，连接项目都会为会话提供使用代码库所需的上下文。

选择项目后，您就可以编写第一个提示了。

## 用简单的英语描述你想要什么

您不需要学习特殊的语法或找出表达您的请求的完美方式。首先描述您想要做出的改变。

例如：`Add a most-funded sort option to the games list.`

这足以开始了。 Copilot 可以检查项目，找到代码库的相关部分，并处理请求的更改。

如果第一次尝试与您的想法不符，您可以提供更多详细信息或要求更改。提示是一个迭代过程，因此您不必在开始之前预测每个细节。

最好的提示往往是让你感动的提示。

## 当您需要时选择合适的型号

GitHub Copilot 应用程序还允许您选择哪个 AI 模型来处理您的任务。不同的模型有不同的优势，有些模型更适合复杂的推理，而另一些模型可以更快地处理更简单的任务。

如果您刚刚开始，默认模型是一个很好的起点。在使用该应用程序之前，您无需了解可用模型之间的所有差异。

在工作时，当任务需要更复杂的推理或第一种方法无法为您提供所需的结果时，您可以切换模型。将模型选择器视为任务需要时可以使用的另一个工具，而不是在每次会话之前需要配置的东西。

## 使用任何感觉自然的输入

打字并不是编写提示的唯一方法。 GitHub Copilot 应用程序包含内置语音输入，当您大声思考问题或有较长的描述请求时，这会很有用。

您的语音会在提示框中转换为文本，您可以在发送之前在提示框中查看和编辑它。这意味着您可以大声思考，而无需立即承诺您的请求的第一个版本。

有时，解释你想要什么比把它打印出来更容易。语音输入为您提供了另一种将想法融入会议的方式。

## 自定义工作的运行方式

您还可以更改会话处理工作的方式。从会话标题中，您可以选择不同的 agent 或为会话启用远程控制。

可以为不同类型的工作配置不同的agents，因此您可以选择最适合您正在处理的任务的一种。

远程会话为您提供另一种灵活性。您可以从网络访问相同的会话，而不是仅在本地计算机上运行工作。您可以开始一项任务，关闭笔记本电脑，然后稍后从另一台设备返回到会话，而不会丢失您的位置。

在第一次提示之前，您不需要配置这些选项。当您需要更多地控制任务的处理方式时，它们就会出现。

## 从小处开始并迭代

您的第一个提示不必是完美的。从您想要在您已经知道的项目中进行的小更改开始，用简单的语言描述您想要的内容，然后看看会发生什么。

从那里，您可以优化请求、尝试不同的模型或调整会话的运行方式。您使用该应用程序的次数越多，这些选择就会变得越自然。

重要的部分是开始。选择一个项目，给 Copilot 一个任务，然后看看它会带你去哪里。

# GitHub Copilot app for Beginners: Write your first prompt

Opening a new AI tool can feel a little like staring at a blank page. You know you want help with something, but figuring out exactly what to ask can be its own task.

The good news is that you don’t need to write the perfect prompt to get started. A prompt is simply a description of what you want to accomplish. Start with what you know, give Copilot some context, and refine the request as you go.

Let’s walk through what it looks like to start your first task in the [GitHub Copilot app](<https://github.com/features/ai/github-app?utm_source=blog-copilot-app-ep2&utm_medium=blog&utm_campaign=copilot-app-for-beginners-series>).

## Start with the right context

Before you can ask Copilot to make a change, it needs something to work on. Agent sessions can be connected to a GitHub repository or a folder on your local machine, giving Copilot access to the code and files it needs for the task.

From the GitHub Copilot app home screen, you can select a project you’ve worked with before or add a new one.

If you’re working on code that’s only on your computer, you can add a local folder instead. Either way, connecting a project gives the session the context it needs to work with your codebase.

Once your project is selected, you’re ready to write your first prompt.

## Describe what you want in plain English

You don’t need to learn a special syntax or figure out the perfect way to phrase your request. Start by describing the change you want to make.

For example: `Add a most-funded sort option to the games list.`

That’s enough to get started. Copilot can examine the project, find the relevant parts of the codebase, and work on the requested change.

If the first attempt isn’t quite what you had in mind, you can provide additional details or ask for changes. Prompting is an iterative process, so you don’t have to anticipate every detail before you begin.

The best prompt is often the one that gets you moving.

## Choose the right model when you need it

The GitHub Copilot app also lets you choose which AI model handles your task. Different models have different strengths, and some are better suited to complex reasoning while others can handle simpler tasks more quickly.

If you’re just getting started, the default model is a good place to begin. You don’t need to understand every difference between the available models before you can use the app.

As you work, you can switch models when a task requires more complex reasoning or when the first approach isn’t giving you the results you need. Think of the model selector as another tool you can reach for when the task calls for it, rather than something you need to configure before every session.

## Use whatever input feels natural

Typing isn’t the only way to write a prompt. The GitHub Copilot app includes built-in voice input, which can be useful when you’re thinking through a problem out loud or have a longer request to describe.

Your speech is converted into text in the prompt box, where you can review and edit it before sending it. That means you can think out loud without immediately committing to the first version of your request.

Sometimes it’s easier to explain what you want than to type it out. Voice input gives you another way to get that idea into the session.

## Customize how the work runs

You can also change how your session handles the work. From the session title, you can select a different agent or enable remote control for the session.

Different agents can be configured for different types of work, so you can choose the one that best fits the task you’re working on.

Remote sessions give you another kind of flexibility. Instead of running the work only on your local machine, you can access the same session from the web. You can start a task, close your laptop, and return to the session later from another device without losing your place.

These options aren’t things you need to configure before your first prompt. They’re there when you need more control over how a task is handled.

## Start small and iterate

Your first prompt doesn’t need to be perfect. Start with a small change you’d like to make in a project you already know, describe what you want in plain language, and see what happens.

From there, you can refine the request, try a different model, or adjust how the session runs. The more you use the app, the more natural these choices become.

The important part is getting started. Pick a project, give Copilot a task, and see where it takes you.
