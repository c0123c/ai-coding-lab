## 概述

{% data reusables.copilot.cloud-agent.automations-what-is %}

通过手动启动的 {% data variables.copilot.copilot_cloud_agent %} 会话，您每次想要完成工作时都会给 {% data variables.product.prodname_copilot_short %} 一个任务。使用 {% data variables.copilot.copilot_automations %}，您只需定义一次任务，只要 {% data variables.copilot.copilot_automation %} 的触发器触发，{% data variables.product.prodname_copilot_short %} 就会自动运行该任务。

例如，您可以使用 {% data variables.copilot.copilot_automations %} 来：

* **分类传入问题**：根据内容自动将新问题标记为错误、增强或其他。
* **每晚修复失败的测试**：每天晚上，检查 `main` 分支上的失败测试，尝试修复，并打开草稿拉取请求。
* **准备每周发行说明**：起草发行说明并按计划打开拉取请求。

当您创建 {% data variables.copilot.copilot_automation %} 时，您定义：

* 用于标识 {% data variables.copilot.copilot_automation %} 的 ** 名称 **。
* ** 提示 ** 描述您想要 {% data variables.product.prodname_copilot_short %} 执行的任务。
* 一个或多个 ** 触发 **，确定 {% data variables.copilot.copilot_automation %} 何时运行。
* **型号**{% data variables.product.prodname_copilot_short %}使用。
* 可以使用 ** 工具 ** {% data variables.product.prodname_copilot_short %}，它控制它可以在存储库中执行哪些操作。

有关创建和管理 {% data variables.copilot.copilot_automations %} 的说明，请参阅 [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/use-copilot-agents/cloud-agent/create-automations>)。

## 可用性和权限

{% data reusables.copilot.cloud-agent.automations-availability %}

任何对存储库具有 ** 写入权限 ** 的用户都可以在该存储库中创建 {% data variables.copilot.copilot_automations %}。

您可以通过以下方式创建和管理 {% data variables.copilot.copilot_automations %}：

* {% data variables.product.github %} 存储库中的 **{% data variables.copilot.copilot_automations_cap %}** 窗格中的 **Agents** 选项卡。
* {% data variables.copilot.github_copilot_app %} 中的 **{% data variables.copilot.copilot_automations_cap %}** 选项卡。

## 触发器

{% data variables.copilot.copilot_automation %} 在其触发器之一触发时运行。可以使用以下触发器：

* **按计划**：{% data variables.copilot.copilot_automation %} 按循环间隔运行 - 每小时、每天或每周。
* **创建问题时**：每次在存储库中打开问题时都会运行{% data variables.copilot.copilot_automation %}。
* **打开拉取请求时**：每次在存储库中打开拉取请求时，{% data variables.copilot.copilot_automation %}都会运行。
* **同步拉取请求时**：每次将新提交推送到存储库中的拉取请求时，都会运行{% data variables.copilot.copilot_automation %}。

您可以选择为基于事件的触发器配置过滤器：

* 对于当**创建问题**时，添加搜索查询过滤器。
* 对于当 ** 打开拉取请求时 ** 以及当 ** 同步拉取请求时 **，添加搜索查询过滤器和拉取请求中更改的文件的过滤器。

为了降低提示注入的风险，{% data variables.copilot.copilot_automations %} 默认情况下会忽略由没有存储库写入权限的用户触发的事件。这有助于防止不受信任的用户（例如提出问题的外部贡献者）导致 {% data variables.product.prodname_copilot_short %} 采取行动。如果需要，您可以选择允许这些事件。有关更多信息，请参阅[安全与安全](<#安保与安全>)。

## 工具和行动

您在创建 {% data variables.copilot.copilot_automation %} 时选择的 ** 工具 ** 决定了 {% data variables.product.prodname_copilot_short %} 在 {% data variables.copilot.copilot_automation %} 运行时可以执行的操作。

例如，您可能允许 {% data variables.product.prodname_copilot_short %} 推送更改、更新问题标签或创建拉取请求。

选择工具是控制{% data variables.copilot.copilot_automation %}范围的主要方式。仅授予任务所需的工具，以便 {% data variables.product.prodname_copilot_short %} 无法执行您不希望的操作。

您可以手动选择要启用的工具，也可以使用**建议工具**按钮让{% data variables.product.prodname_copilot_short %}根据您的提示建议工具。

{% data variables.copilot.copilot_automation %} 只能在其作用范围内的单个存储库中执行操作。

当 {% data variables.copilot.copilot_automation %} 更改问题时，它可以解释每个更改并评估其置信度，自动应用高置信度更改并建议其他更改供您审核。参见[AUTOTITLE](<https://raw.githubusercontent.com/copilot/concepts/agents/cloud-agent/about-automation-rationale-and-approvals>)。

## 从存储库继承的配置

{% data variables.copilot.copilot_automations_cap %} 将 {% data variables.copilot.copilot_cloud_agent %} 配置用于其作用范围的存储库，包括：

* **自定义说明**。请参阅[AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions>)。
* **Agent skills**。参见[AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills>)。
* **防火墙规则**。请参阅[AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-the-firewall>)。
* **秘密和变量**。请参阅[AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables>)。

{% data variables.copilot.copilot_automations_cap %} 与存储库的内容分开存储。它们不致力于 Git，因此它们不会与您的代码一起进行版本控制，也不会通过拉取请求进行管理。

## 能见度

{% data variables.copilot.copilot_automation %} 对于创建它的用户 ** 来说是 ** 私有的。其他人（包括存储库管理员）无法看到您的 {% data variables.copilot.copilot_automations %}。

但是，{% data variables.copilot.copilot_automation %} 启动的 {% data variables.copilot.copilot_cloud_agent %} ** 会话 ** 对于有权访问存储库的其他人来说是可见的，就像任何其他 {% data variables.copilot.copilot_cloud_agent %} 会话一样。任何可以看到这些会话的人都可以看到提示、会话日志以及任何拉取请求或 {% data variables.product.prodname_copilot_short %} 创建的其他更改。

由于会话及其日志对其他人可见，因此您不应直接在 {% data variables.copilot.copilot_automation %} 的提示中包含机密或其他敏感信息。要授予 {% data variables.product.prodname_copilot_short %} 对敏感值的访问权限，请改用存储库机密。请参阅[AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables>)。

## 安保与安全

{% data variables.copilot.copilot_automations_cap %} 在没有人启动每个任务的情况下运行 {% data variables.product.prodname_copilot_short %}，因此它们会带来一些额外的风险。 {% data variables.product.github %} 提供内置保护来帮助减轻这些风险。

* **归因。** {% data variables.copilot.copilot_automation %} 打开的拉取请求和推送的代码归因于创建 {% data variables.copilot.copilot_automation %} 的用户。与用户自己创建的拉取请求一样，他们无法批准这些拉取请求，这保留了预期的审查控制。
* **最低权限工具。**您可以准确选择{% data variables.copilot.copilot_automation %}可以使用哪些工具，因此您可以将其限制为仅执行任务所需的操作。
* **不受信任的输入。**默认情况下，{% data variables.copilot.copilot_automations %}忽略对存储库没有写访问权限的用户触发的事件，以降低不受信任用户提示注入的风险。
* ** 工作流运行。** 与所有 {% data variables.copilot.copilot_cloud_agent %} 工作一样，{% data variables.product.prodname_actions %} 工作流在具有写入权限的用户批准之前不会在拉取请求上运行。这降低了由 {% data variables.copilot.copilot_automation %} 自动触发工作流程打开拉取请求的风险。

有关 {% data variables.product.github %} 如何减轻 {% data variables.copilot.copilot_cloud_agent %} 风险的更多信息，请参阅 [AUTOTITLE](<https://raw.githubusercontent.com/copilot/concepts/agents/cloud-agent/risks-and-mitigations>)。

## Overview

{% data reusables.copilot.cloud-agent.automations-what-is %}

With a manually started {% data variables.copilot.copilot_cloud_agent %} session, you give {% data variables.product.prodname_copilot_short %} a task each time you want work done. With {% data variables.copilot.copilot_automations %}, you define a task once, and {% data variables.product.prodname_copilot_short %} runs it automatically whenever the {% data variables.copilot.copilot_automation %}'s trigger fires.

For example, you can use {% data variables.copilot.copilot_automations %} to:

* **Triage incoming issues**: automatically label new issues as a bug, an enhancement, or other, based on their content.
* **Fix failing tests nightly**: each night, check for failing tests on the `main` branch, attempt a fix, and open a draft pull request.
* **Prepare weekly release notes**: draft release notes and open a pull request on a schedule.

When you create an {% data variables.copilot.copilot_automation %}, you define:

* A **name** to identify the {% data variables.copilot.copilot_automation %}.
* A **prompt** describing the task you want {% data variables.product.prodname_copilot_short %} to perform.
* One or more **triggers** that determine when the {% data variables.copilot.copilot_automation %} runs.
* The **model** {% data variables.product.prodname_copilot_short %} uses.
* The **tools** {% data variables.product.prodname_copilot_short %} can use, which control what actions it can take in your repository.

For instructions on creating and managing {% data variables.copilot.copilot_automations %}, see [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/use-copilot-agents/cloud-agent/create-automations>).

## Availability and permissions

{% data reusables.copilot.cloud-agent.automations-availability %}

Any user with **write access** to a repository can create {% data variables.copilot.copilot_automations %} in that repository.

You can create and manage {% data variables.copilot.copilot_automations %} from:

* The **Agents** tab in a repository on {% data variables.product.github %}, in the **{% data variables.copilot.copilot_automations_cap %}** pane.
* The **{% data variables.copilot.copilot_automations_cap %}** tab in the {% data variables.copilot.github_copilot_app %}.

## Triggers

An {% data variables.copilot.copilot_automation %} runs when one of its triggers fires. The following triggers are available:

* **On a schedule**: the {% data variables.copilot.copilot_automation %} runs at a recurring interval—hourly, daily, or weekly.
* **When an issue is created**: the {% data variables.copilot.copilot_automation %} runs each time an issue is opened in the repository.
* **When a pull request is opened**: the {% data variables.copilot.copilot_automation %} runs each time a pull request is opened in the repository.
* **When a pull request is synchronized**: the {% data variables.copilot.copilot_automation %} runs each time new commits are pushed to a pull request in the repository.

You can optionally configure filters for event-based triggers:

* For when **an issue is created**, add a search query filter.
* For when **a pull request is opened** and when **a pull request is synchronized**, add a search query filter and a filter for files changed in the pull request.

To reduce the risk of prompt injection, {% data variables.copilot.copilot_automations %} ignore events triggered by users who don't have write access to the repository by default. This helps prevent untrusted users—for example, an external contributor opening an issue—from causing {% data variables.product.prodname_copilot_short %} to take action. You can opt in to allowing these events if you need to. For more information, see [Security and safety](<#security-and-safety>).

## Tools and actions

The **tools** you select when you create an {% data variables.copilot.copilot_automation %} determine what {% data variables.product.prodname_copilot_short %} can do when the {% data variables.copilot.copilot_automation %} runs.

For example, you might allow {% data variables.product.prodname_copilot_short %} to push changes, update issue labels, or create a pull request.

Selecting tools is the main way you control the scope of an {% data variables.copilot.copilot_automation %}. Grant only the tools that the task needs, so that {% data variables.product.prodname_copilot_short %} can't take actions you didn't intend.

You can manually select the tools you want to enable, or you can use the **Suggest tools** button to have {% data variables.product.prodname_copilot_short %} suggest tools based on your prompt.

An {% data variables.copilot.copilot_automation %} can only take action in the single repository it is scoped to.

When an {% data variables.copilot.copilot_automation %} changes an issue, it can explain each change and rate its confidence, applying high-confidence changes automatically and proposing others for your review. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/concepts/agents/cloud-agent/about-automation-rationale-and-approvals>).

## Configuration inherited from the repository

{% data variables.copilot.copilot_automations_cap %} use the {% data variables.copilot.copilot_cloud_agent %} configuration for the repository they are scoped to, including:

* **Custom instructions**. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions>).
* **Agent skills**. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills>).
* **Firewall rules**. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-the-firewall>).
* **Secrets and variables**. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables>).

{% data variables.copilot.copilot_automations_cap %} are stored separately from your repository's contents. They are not committed to Git, so they are not versioned alongside your code or managed through pull requests.

## Visibility

An {% data variables.copilot.copilot_automation %} is **private to the user who created it**. Other people, including repository administrators, can't see your {% data variables.copilot.copilot_automations %}.

However, the {% data variables.copilot.copilot_cloud_agent %} **sessions** that an {% data variables.copilot.copilot_automation %} starts are visible to other people with access to the repository, just like any other {% data variables.copilot.copilot_cloud_agent %} session. Anyone who can see these sessions can see the prompt, the session logs, and any pull requests or other changes {% data variables.product.prodname_copilot_short %} creates.

Because sessions and their logs are visible to others, you should not include secrets or other sensitive information directly in an {% data variables.copilot.copilot_automation %}'s prompt. To give {% data variables.product.prodname_copilot_short %} access to sensitive values, use repository secrets instead. See [AUTOTITLE](<https://raw.githubusercontent.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables>).

## Security and safety

{% data variables.copilot.copilot_automations_cap %} run {% data variables.product.prodname_copilot_short %} without a person initiating each task, so they carry some additional risks. {% data variables.product.github %} provides built-in protections to help mitigate these risks.

* **Attribution.** Pull requests opened and code pushed by an {% data variables.copilot.copilot_automation %} are attributed to the user who created the {% data variables.copilot.copilot_automation %}. As with pull requests that user creates themselves, they can't approve those pull requests, which preserves the expected review controls.
* **Least-privilege tools.** You choose exactly which tools an {% data variables.copilot.copilot_automation %} can use, so you can limit it to only the actions the task requires.
* **Untrusted input.** By default, {% data variables.copilot.copilot_automations %} ignore events triggered by users without write access to the repository, to reduce the risk of prompt injection from untrusted users.
* **Workflow runs.** As with all {% data variables.copilot.copilot_cloud_agent %} work, {% data variables.product.prodname_actions %} workflows don't run on a pull request until a user with write access approves them. This mitigates the risk of a pull request opened by an {% data variables.copilot.copilot_automation %} triggering workflows automatically.

For more information about how {% data variables.product.github %} mitigates the risks of {% data variables.copilot.copilot_cloud_agent %}, see [AUTOTITLE](<https://raw.githubusercontent.com/copilot/concepts/agents/cloud-agent/risks-and-mitigations>).
